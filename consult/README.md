# WB 컨설팅 플래너

컨설팅 학생의 학습 계획·실행과 원장의 배부·점검을 잇는 정적 웹앱이다. task에서 출발했지만
현재 화면과 인증은 별도로 구현돼 있다. 화면은 GitHub Pages `/wb-site/consult/`, API는
`index.html`의 `SYNC_URL`에 지정된 **wb-sync Worker + D1**을 사용한다.

## 현재 화면

| 화면 | 하는 일 |
|---|---|
| 오늘·주간·일정 | 오늘 할 일과 단계 체크, 주간 플래너·월간 일정·시험계획 |
| 로드맵·학사관리 | 학습 목표·로드맵, 학사 일정과 학업자료 관리 |
| 인강·학습 | 인강 플래너·강좌 목차, 학습 플래너·메타수학 요청·인증사진/질문 제출 |
| 학습 배부·학생 현황 | 원장·지정 관리자의 배부·실행 점검, 문화상품권 포인트 처리 |
| 결과지·학생 관리·설정 | 원장의 영어/수학 PDF 결과지, 학생·구독·연락처·보호자 공유·계정 관리 |
| 사용 안내 | 학생의 첫 연결·시간표·목표 설정 안내 |

학생 개인 링크에는 자신의 플래너 화면만 열리고, 관리자는 배부·현황까지 열린다.
결과지·학생 관리·설정은 원장 화면이다. 로드맵은 학생별 사용 조건을 확인한 뒤 표시한다.
API가 인증·앱·소유자 범위를 다시 검사하므로 화면 탭을 숨기는 처리를 권한 검사 대신 쓰지 않는다.

## 로그인과 데이터

- 원장은 **아이디·비밀번호**로 로그인한다. `033_consult_admin_accounts.sql`이 선행이며,
  기존 원장 기기에서 계정을 한 번 설정하면 최대 5대가 각각 90일간 자동 로그인한다.
- 학생은 원장이 발급한 **1회용 연결 코드**로 최종 사용할 브라우저에서
  「이 기기에 학생 플래너 연결」을 누른다. 새 링크의 연결 가능 시간은 24시간이다.
  관리자도 개인 기기 인증을 사용하며 허용 화면과 서버 권한은 학생과 구분된다.
- `/sync`에는 `app:'consult'`와 원장/개인 인증을 보내며 변경 행만 교환한다.
  task는 `app:'task'`다. 브라우저 저장 키도 consult는 `wb_consult_v1` 계열, task는
  `wb_taskboard_v1` 계열로 나뉜다. 서버의 앱·소유자 검사도 함께 유지한다.
- 인증사진·질문 JPEG와 결과지 PDF는 **private R2**에 저장하고 인증된 API로만 조회한다.
  사진을 localStorage나 저장소에 넣지 않는다. 사진 prefix의 90일 보관 규칙을 결과지에 확대하지 않는다.
- 보호자 공유는 학생별 동의·초대 링크를 거친 `/consult-guardian/` 별도 포털이다.
  task 보호자 포털의 표·쿠키를 재사용하지 않는다. 문구·발송·공유 범위는 원장 확인을 거친다.

## 배포와 작업 입구

[`sync/README.md`](../sync/README.md)의 배포 순서가 정본이다. 필요한 마이그레이션과 private R2를
먼저 준비하고 **wb-sync Worker → consult Pages** 순서로 수동 배포한다. 학생 전용 wb-student는
이 플래너의 API가 아니다. 원장 계정은 033, 제출함은 041, 보호자 공유는 042, 결과지는 049가 선행한다.
시크릿 값·학생 개인정보·실제 PDF/JPEG는 저장소·로그에 적지 않는다.

`index.html`이 앱 본체이고 `*.test.cjs`가 순수 로직·화면·인증·공유 계약을 검사한다.
`apps-script.gs`는 **Apps Script 시대의 레거시 참고 파일**이다. 현재 앱은 호출하지 않으며
새 설치에서 시트나 Apps Script를 배포하지 않는다.

저장소 뿌리에서:

```bash
node scripts/check.mjs --only consult
node scripts/check.mjs --only sync
node scripts/check.mjs
```

공유 인증·서버 계약을 고치면 consult와 sync 양쪽을 확인하고, PR 전에는 전체 검사를 통과시킨다.
