# 내신브레인 — 영어 내신 시험대비 앱

이그잼포유(EXAM4YOU) 구매 자료를 구조화해 재원생에게 무료 제공하는 원내 전용 학습 앱.
정본 기획서: `docs/영어내신-학습웹앱-기획서-v1.md` (v1.2 — §14 혁신안 5가지 포함).

**2026-10-12 운영 기준**: 사용자가 학원 내 사용·반출 금지를 확인했다. 중2 → 중3 → 중1 순서로 도입한다.
새 PC 정본 운영과 실제 자료 반입·검증 기준은 `docs/내신브레인-원내PC-실운영-계획.md`를 따른다.
아래의 기존 Drive·Claude·KV 제작 설명은 이전 구성이다. 원내 보관 모드에서는 구매 원천을 외부 AI로 보내지 않는다. 스튜디오의 「PC 자료 불러오기」로 로컬 추출 후보와 원본 PDF를 연결하고 나란히 대조·교정·검수한다. 파일·JSON 입력과 본문 줄 대응은 「고급 입력」에 남아 있으며 자동 승인·게시는 하지 않는다.

학생 연동은 `/?app=naesin`에서 요청 → 교사 승인 → `/naesin/`으로 이어진다. 기존 계정도 영어 시험 API로 재확인하며 독해 프로필 설정·동기화·저장은 실행하지 않는다. 원내 관리 화면의 학생 QR은 영어 힌트를 붙이고 외부 관리 화면에서는 원내 주소를 안내한다.
영어 PC의 학생 Bearer는 영어 API와 명시된 공용 인증·알림 경로만 사용한다. 다른 앱의 학생 API는 403이며, 기존 명부 권한·관리자·일반 Node·워커 계약과 별도 가족·서비스 자격은 유지한다. 자세한 범위는 위 실운영 계획을 따른다.

**최종 도달 목표 3가지** — 모든 설계가 여기로 정렬된다:
① 본문 영→한 해석 ② 백지에 영어 지문 전체 쓰기 ③ 시험 전 단어 100% 완성(안정화).

핵심 데이터 흐름: **PDF(구매 자료) → 로컬 추출 → PC 자료 불러오기 → 원본 PDF 대조·교정·검수 → 팩 검사·게시 → PC DB → 반 배정 → 원내 학생 앱이 인증 후 로드**.
문제 전용 팩은 `contentMode: "questions"`와 빈 `words`·`sentences` 배열을 명시한다. 문항·정답 검사는 동일하게 적용하며 학생 홈은 진단 대신 문제 풀이를 연다. `extract/question_draft.py`는 원내 자료실의 단원별 문항·정답 위치를 미검수 후보로 변환한다. 쪽 구성·공통 지문·소문항 답은 교사가 대조해야 하고, 정답 미대응은 게시를 막는다. 제작 화면의 **검수 완료 문항 게시·반 배정**은 승인·교정 완료 문항만 별도 `-questions` 팩으로 게시하며, 미검토·버림 문항은 제외한다. 기존 반 범위는 유지하고 팩을 추가한다.
워커의 기존 KV 어댑터도 호환되지만 PC 운영 전환 후 두 서버에 학생 기록을 동시에 쓰지 않는다. 팩은 저장소·정적 자산에 절대 없다.

문제 팩에도 승인된 `sentences`를 함께 게시할 수 있다. 같은 단원에서 문제와 본문 암기를 선택하며 빈 본문은 표시하지 않는다. `extract/passage_draft.py`는 워크북 4의 연속 문장 번호와 같은 번호의 해석 정답을 연결한다. 워크북이 없는 본문은 같은 PDF 쪽의 양쪽 열에서 문장 수가 일치할 때만 대응한다. 문장 전체를 하나의 뜻 단위로 보존하며 세부 구문을 추측해 나누지 않는다. 구문 단위가 하나인 문장의 어순 연습은 원문 낱말 배열을 사용한다. 원본·해석·위치 기록은 원내 PC 초안에 보관하고 학생 팩에는 원천 위치를 싣지 않는다.

## 학생 앱 동작 요약

학습용 배정(`mode: practice`)은 최대 500개 팩을 허용한다. 20개를 넘으면 학생은 자기 배정의 `/api/naesin/catalog` 메타 목록에서 교과서·학년·단원을 고른다. 구매 본문과 문제는 선택한 한 단원만 받아 메모리에서 열고, 이전 단원 원문은 교체한다. 실제 날짜가 있는 시험 배정은 기존 20개 상한과 범위 통합 학습을 유지한다. 문장 구두점 수가 서로 다른 병렬 본문은 영어·한글 열을 같은 쪽 단위로 보존하며 화면에 쪽 전체 암기 단위임을 표시한다.

- **진단**: 팩 진입 첫 세션은 2분 사전 인출 진단(4지선다+모름) → 아는 단어는 신규 큐 건너뜀
- **단어**: SRS + 판정 퀴즈(응답마다 확신도 3버튼) · '완료' = 도달 후 **서로 다른 날 3회**
  재도달(안정화 0→3 게이지) · 시험 모드에선 초회 도달 마감 = 시험 D-7
- **본문 암기 — 뜻 먼저, 청크 → 줄 → 단락** (영어를 못 읽는 학생이 기준선이다)
  - **청크 트랙**(단락 단위 3세션): 듣고 짝 맞추기 → 뜻 인출 → 순서 세우기. 영어를 한 글자도
    입력하지 않고 통과할 수 있다. 통과해야 그 단락 문장 사다리가 열린다.
  - **문장 사다리 6단**: 줄 해석(한글 빈칸) → 영어 청크 배열 → 핵심어 빈칸 → 문법 형태 →
    줄 영작 → 단락 백지. 1·3·5단계는 **단서 농도**(cue 3→0: 전사 → 첫 글자+글자 수 →
    첫 글자 → 빈칸만)를 지워 가며 오르고, 틀리면 단서가 늘고 단계는 유지된다.
  - **단락·전체 관문**: 단락 줄거리(한글) → 어색한 곳 찾기 → 단락 백지 → 누적 백지(1일차 →
    1+2일차 → 전체) → 종합 Check.
  - **암기용 한글은 `chunks[].ko`(직독직해)** — `sentences[].ko`(매끄러운 해석)는 한국어
    어순이라 영어 자리와 어긋나므로 표시용으로만 쓴다. 한글 청크는 늘 영어 자리와 짝지어 낸다.
  - 백지가 틀리면 **원인별로 되돌린다**: 누락 → 1단계, 어순 → 2단계, 낱말 → 3단계, 동사 형태 → 4단계.
- **브레인덤프**: 매일 2분, 판정 없는 자유 인출(diff만 표시)
- **성취도 탭**: 단어 안정화·해석 통과·백지 암송 문장별 체크 + **종이 백지시험 ○× 입력**
  (○는 암송 기록으로 환류) + 시험일 설정
- 학습 중 기록은 학생별 localStorage(`wbn.v1:<학생코드>`)에 저장하고 서버와 과별 최신 시각으로 병합한다.
  `state.summary`가 관리 overview의 원천이다. 구매 팩 본문은 기기에 영구 캐시하지 않으며, 연결 이탈·계정 변경 시 화면에서 회수한다.
  미연동 기기는 자체 창작 `pack-sample.json` 체험 모드다.

- **문제 풀이**: 저장 문제는 자료 선택(전체·PRE-STEP·예상문제 1회/2회·문법 객관식/주관식) 후 단일 정답·복수 정답·주관식으로 고른다. 원문 번호와 출처를 표시하고 기존 채점·해설·오답 재시험을 사용한다. 자료 선택은 오늘의 배정 과제나 범위 모의시험을 제한하지 않는다. 주관식은 등록된 허용 답안과 대조하며 자유 서술형 의미 채점을 하지 않는다.
  새 PC 반입 문항은 원천 후보의 `id`를 유지해 전체 연번이 달라져도 오답·검수·신고가 다른 문제로 옮겨가지 않는다. `id` 없는 옛 팩은 유일한 번호의 기존 `i-no` 기록을 유지하고, 동번호가 여러 개면 출처·섹션·번호·각주 복합키로 구분한다. 애매한 옛 번호 기록은 임의로 연결하지 않는다. 공유 팩 검사에서 실제로 풀 수 없는 유형·빈 문제/정답·보기 불일치·중복 식별자를 게시 전에 차단한다.

## 서버 API (naesin-api.mjs)

학생(토큰)
- `GET /pack?id=` → `{pack, updatedAt}` — **자기 유효 시험의 `packIds`에 든 팩만**, 아니면 403
- `GET/PUT /state` → `{state, updatedAt}` — 요청 300KB, 병합 후 256KB(UTF-8 바이트).
  다른 학생 owner는 거절하고, 같은 과는 최신 `savedAt`을 유지한다(동률은 기존 기록). 서버가 보존한 기록이 있으면 PUT 응답의 `state`를 기기가 반영한다. `state.summary`는 서버가
  화이트리스트로 정규화해 저장·출력한다(숫자 강제·문자열 길이 제한) — 학생 기기가 올린 값이
  강사 화면에 그대로 그려지지 않게 하는 관문
- `GET /exam` → `{exam:{examDate, packIds, wordDeadlineDays?}, scope}` — 학생 배정(만료 전) →
  반 배정(`cls:<반>`, 만료 전) → 공통(`default`, 지난 날짜도 유지) → 빈 값.
  응답 scope는 `student`·`class`·`default`·null이다. **만료 = `examDate < 오늘(KST)`** (`resolveExam`).
- `GET /task` → `{task, scope}` — 오늘의 반 과제 → 공통 과제 순서. `task.updatedAt`이 학생 앱 완료 기록의 `taskAt` 원천

관리(PIN)
- 팩: `POST /admin/pack {id, pack}` (4.5MB, packId 일치) · `GET /admin/packs` ·
  `DELETE /admin/pack {id}` — 배정에 쓰이는 팩이면 409 + `scopes`
- 시험: `POST /admin/exam {scope, examDate, packIds, wordDeadlineDays?}` (실제 달력 날짜 검증) ·
  `GET /admin/exams` → `{exams:[{scope, examDate, packIds, expired, …}]}` · `DELETE /admin/exam {scope}`
  scope는 기존 학생 코드·`default`와 `cls:<반>`을 받는다. 반 이름은 NFC·앞뒤 공백만 정규화하며 1~80자, 제어문자는 금지한다. 학생 코드 `cls`는 기존 개별 배정이다.
- 과제: `GET/POST/DELETE /admin/task?scope=cls:<반>` — scope 생략은 기존 `default`. `typeKeys`는 서버 화이트리스트(`TASK_TYPE_KEYS` + `g-<n>`),
  학생 앱 `quizTypes()`·관리 웹 `TYPE_LIST`와 같은 목록이어야 한다
- `GET /admin/overview` → 학생별 `summary`(정규화본) + 과제 완료 열 + 적용 과제 `assignedTask`(없으면 null)
- 교과서 지정표: `GET /admin/books` → `{books, updatedAt}` · `PUT /admin/books {books}` →
  `{books, count, updatedAt}`. `books` 는 `{학생코드: 교과서코드}` 한 칸짜리 표이고 **PUT 은 전체
  교체**다(빈 값 = 지정 해제, 한 줄이라도 형식이 틀리면 전부 거절). 교과서 코드 목록과 대조하지
  않는다 — 목록을 복제하면 desk 자료원장과 갈라진다. KV `naesin:books` 하나, 학생 쪽으로는 안 나간다
- 시험 결과: `POST /admin/result {code, examDate, score, wrongTypes?, memo?}` — 서버가 저장 시점의
  `state.summary` 스냅샷과 시험 범위를 함께 붙인다 · `DELETE /admin/result {code, examDate}` ·
  `GET /admin/results?examDate=` → `{results, analysis}`
- 학생: `GET /result` → `{results, prediction}` — 자기 결과만. `prediction`은 원내 표본 5건
  이상일 때만 나오고(상관은 3건 이상), 아니면 `null`이다
- 문항 신고(정오표): 학생 `POST /report {packId, itemRef, reason, memo?}` — **자기 시험 범위의
  팩만**(아니면 403), 같은 학생·같은 문항의 미처리 신고는 합친다 · 관리
  `GET /admin/reports?packId=` → 문항별로 묶어 건수 내림차순 · `POST /admin/reports/resolve {packId, id|itemRef}`
- 수업 라이브(naesin-live.mjs, 계약 L1): 학생 `GET /live` → `{live:{phase, projector}, scope}` —
  **투사 문제의 `answerKey`는 공개(revealed) 전까지 응답에 없고, 지금 띄운 문제 하나만 내려간다** ·
  학생 `POST /live/answer {ref, key, scope?}` (지금 화면의 문제만, scope 지정 시 자기 적용 세션과 일치해야 한다; 정답 여부는 돌려주지 않는다) · 관리
  `GET /admin/live` → `{live, votes, board, weakest}` (폴링 한 번으로 세션·응답 분포·반 현황) ·
  `POST /admin/live/phase {phase|null}` (endsAt 은 서버가 분 입력에서 계산 — 강사 노트북 시계를 믿지 않는다) ·
  `POST /admin/live/projector {packId, items|null, index?, revealed?}` · `DELETE /admin/live`.
  관리 라이브 요청은 모두 `?scope=cls:<반>`을 받으며 생략은 기존 `default`. 반별 응답·현황·삭제를 분리하고 학생은 현재 반 세션 → 공통 순서로 받는다.
  투사 내용은 학생의 시험 범위 packId와 대조한다. packId 없는 기존 투사 문제는 학생에게 숨기며 강사가 다시 시작해야 한다.
  세션은 `updatedAt` 이 4시간을 넘으면 없는 것으로 본다 — 방치된 단계가 다음 날 학생 화면에 남지 않게.
- 팩 단건: `GET /admin/pack?id=` → `{pack, updatedAt}` — 강사 화면이 즉석 문제를 만들 때 쓴다
  (문제 생성은 학생 앱과 같은 `gen.js` 로 화면에서 한다)
- 제작 스튜디오(naesin-studio.mjs): `POST /admin/job` (원천 텍스트 종류별) · `GET /admin/jobs` ·
  `GET /admin/job?id=[&src=1]` → `{job, gate}` (`src=1`이면 원천까지) · `POST /admin/job/extract {jobId, kind}` ·
  `POST /admin/job/draft {jobId, draft}` (AI 키 없이 쓰는 길) · `POST /admin/job/review {jobId, rows|key,…}` ·
  `POST /admin/job/publish {jobId}` · `DELETE /admin/job {jobId}`.
  **배포 관문은 CLI 검증기와 같은 함수**(`pack-check.js`)를 쓴다 — 규칙을 복제하면 "검증기는
  통과인데 배포가 막히는" 상태가 생긴다. 원천은 `naesin:jobsrc:*`에만 있고 작업을 지우면 함께 지운다.
  로컬 PDF 후보는 원내 PC의 `localPdfReview` capability가 있을 때만 받는다. 「PC 자료 불러오기」는 Node의 원내 관리자 전용 `GET /admin/job/local-review?id=`로 검수 초안·원본 정보를 읽고 `GET /admin/job/local-pdf?id=&source=02|03&sha256=`로 확인값이 같은 원본만 표시한다. 두 경로는 저장·검수 상태를 변경하지 않고 워커에는 없다. 기존과 같은 단어 후보는 재업로드 없이 교정·검수·메모·버전을 유지한다. 원본 위치·검토 표시로 개별 대조하며 학생 팩에서는 해당 메타를 제거한다. 본문 미대응 열과 PDF 표시용 데이터는 브라우저 메모리에만 두고 작업 이동·로그아웃 때 회수한다. 영·한 대응과 청크·핵심어는 교사가 「고급 입력」에서 구성하며 자동 승인하지 않는다.
  학생 필드·배열 형태와 필수 내용을 공용 관문에서 검증한다. 검수 원천·알 수 없는 배열은 새 업로드/발행에서 거절하며 기존 저장 팩을 자동 변경하지 않는다.

공통: 몸통은 파싱 전 `content-length`로 끊는다(팩 4.5MB / 그 외 300KB). 학생 삭제(퇴원)는
`naesin:state:<코드>`·`naesin:exam:<코드>`까지 지운다 — 같은 코드를 재사용해도 앞 학생 기록이
따라오지 않는다. 배포 헤더 규칙은 `reading/_headers` 한 곳에만 있다(`naesin/_headers`는 안내문).

## 팩 제작 파이프라인 (새 출판사·새 과 자료가 오면)

1. **원천**: 이그잼포유 과 단위 시리즈. 파일마다 값이 붙어 있고(5~6.5천원) 과 하나를 통째로
   사면 5만원대라, **무엇을 사야 하는지가 곧 비용 결정**이다. 출판사가 달라도 번호 체계는 같다.

   | 번호 | 자료 | 교사용 | 팩에서 쓰는 곳 |
   |---|---|---|---|
   | — | 교과서본문 | — | `sentences[].en` 정본 대조 |
   | `[01]` | 내용정리 플러스 | | `dialogues` · `sentences[].chunks`(Sentence Study 구문 주석) · `keyExpressions` |
   | `[02]` | 본문 10단계 워크북 | | **`sentences` 정본** + `keywords` · `tokens` · `verbForms` · `grammarChoices` · `oddOneItems` · `checkItems` |
   | `[03]` | WORD TEST | | **`words`**(뜻·품사·예문·영영풀이·다의어·유의반의) |
   | `[04]` | 예상문제 PRE-STEP | ○ | `items` |
   | `[05]` | 예상문제 1회 | ○ | `items` |
   | `[06]` | 예상문제 2회 | ○ | `items` |
   | `[07]` | Grammar Build Up 워크북 | | `patterns`(문법 개념) |
   | `[08]` | Grammar Build Up 객관식 | | `items` |
   | `[09]` | Grammar Build Up 주관식 | | `items` |

   **(교사용) 판은 정답·해설이 들어 있다.** 학생용만 있으면 정답이 밑줄·색·각주 번호로만
   표시돼 텍스트 추출에서 소실되고 역산해야 한다(아래 3의 알려진 난점). 교사용이 함께 있으면
   그 역산이 통째로 없어진다 — **정답이 걸린 자료([04]~[06])는 교사용을 같이 사는 편이 낫다.**
2. **추출** (AI로 PDF 정독 → JSON, 파일별 병렬 권장):
   - `words.json` ← [03] 학습자료부: 단어(뜻·품사·섹션) + 예문 + 영영풀이 + 다의어
     senses + 유의/반의. **정답지(TEST 1·2)와 전수 대조**로 검증.
     `level`(1 기초 · 2 보통 · 3 심화)을 여기서 붙인다 — 중등 필수어휘 여부, 본문 등장 빈도,
     형태 난이도(불규칙·다의·숙어)를 함께 보고 정한다. 근거는 `notes`에 남겨 나중에 검증한다.
     안 붙이면 전부 보통으로 학습되고, 학습 순서가 교재 순 그대로가 된다.
   - `sentences.json` ← [02]: 문장별 en/ko + keywords(워크북2·3 빈칸 정답 쌍) +
     tokens(워크북8 어구) + verbForms + grammarChoices + oddOneItems + checkItems.
     `wordIds`(그 문장에 나오는 `words[].id`)를 같이 적는다 — 단락 단어 게이트(§4.4 v1.3)가
     이 값으로 "이 단락을 읽으려면 어느 단어를 먼저 봐야 하는가"를 판정한다. 안 적으면 앱이
     표제어를 문장에서 찾아 잇는데, 굴절형(take/took)은 놓친다.
     `chunks[]`(끊어읽기 청크+구문 주석)는 [01] Sentence Study에서 — **청크 연결 문자열
     = 정본 en** 이어야 한다(검증기가 확인).
   - `dialogues.json` ← [01]: 대화 스크립트 en/ko + 핵심표현 + 어휘 사이드바 + QA.
   - `patterns.json` ← [07/08] 개념부. `items-*.json` ← 저장 문항(객관식 등 파생 불가분만).
3. **알려진 난점**: 밑줄·색상은 텍스트 추출에서 소실(정답에서 역산) · 복수 정답 표기
   `knocking[knock]`·슬래시는 배열로 파싱 · 정답 연결은 위첨자 각주번호 · 자료 간 문장
   분할이 다를 수 있음([01] 33문장 vs [02] 25문장 → [02]가 정본, [01]은 병합) ·
   원본 오탈자는 교정하지 말고 notes에 기록.
4. **검증**: `node naesin/pack-validate.mjs <팩 디렉터리>` — 오류 0이어야 배포.
5. **업로드**: `/admin/naesin-admin.html` → 파일 전부 선택(브라우저가 병합·재검증) →
   업로드 → 시험 등록. packId 규칙: `<개정>-<출판사저자>-<학년>-L<과>`
   (예: `2022-ne-kimgitaek-m2-L6`).

### 이전 원천 자료 인테이크 — 구글 드라이브에 PDF 그대로

이 절의 Drive·Claude 제작은 이전 구성이다. 현재 원내 PC의 구매 원천은 외부 AI로 보내지 않으며 위의 PC 자료 연결과 실운영 계획을 따른다.

원장이 구매 자료 **PDF 를 드라이브에 올리면**, 그 PDF 를 **Claude Code 세션에서 읽어** 팩 JSON 을
만들고, 관리 웹 제작 스튜디오에 **파일로 넣어** 검수·배포한다. 텍스트로 바꿔 올릴 필요가 없다.

**폴더 규칙의 정본은 `docs/자료-폴더-표준.md` 다** — 앱이 여러 개라 국어·영어가 같은 규칙을 쓴다.
아래는 영어 자리만 발췌한 것이고, 어긋나면 그 문서가 맞다.

```
WB 학습자료/                        ← 드라이브 공유 폴더 하나
  naesin/                           ← 앱 폴더 = 저장소 디렉터리 이름
    2026-2/                         ← 시험기 서랍. 사람 편의라 몇 겹이든, 없어도 된다
      2022-ne-kimgitaek-m2-L6/      ← 폴더 이름이 곧 팩 id. 이 폴더 하나가 팩 하나다
        _meta.txt                   → revision: 2022   (개정만 지면 어디에도 없다)
        00_교과서본문.pdf           → sentences[].en 정본 대조
        01_내용정리.pdf             → dialogues · sentences.chunks
        02_본문워크북.pdf           → sentences (정본) ★필수
        03_단어시험.pdf             → words                  ★필수
        04_예상문제_PRE-STEP.pdf    → items
        04_예상문제_PRE-STEP_교사용.pdf   → 위 문항의 정답·해설
        07_문법워크북.pdf           → patterns
        08_문법객관식.pdf           → items
```

**폴더 이름이 곧 팩 id 다.** 영문·숫자·하이픈만 쓴다(`^[A-Za-z0-9-]{3,60}$`) — 한글·공백·괄호가
들어가면 서버가 거부한다. 이 제한은 **팩 id 폴더에만** 걸린다(위 공유 폴더·서랍·PDF 파일명은 한글 OK).
과 자리는 숫자만이 아니다 — `L6` 외에 Special Lesson 은 `SL`·`SL1`·`SL2`, Special Reading 은
`SR`·`SR1`·`SR2` 다(`ledger-core.js` 의 `UNIT_RE`). `L` 뒤 번호에 0 을 채우지 않는다. 개정 연도는 학년에서 유도하므로(중1·중2=2022, 중3=2015) 사람이
폴더 이름에 손으로 적을 일은 없다. `desk/lib/ledger-core.js` 의 `intakeFolder()` 가 이 경로를
만들고 `packIdFromPath()` 가 되읽는다 — 경로 조각을 역조립하지 않고 **폴더 이름을 그대로** 쓴다.
개정이 학년과 어긋나면 id 를 만들지 않는다(빈 문자열).

**파일 앞 두 자리가 계약이다** — 이그잼포유 시리즈 번호를 그대로 쓰고, 그 번호로 어느 추출
종류에 들어갈지가 정해진다. 뒤 한글 이름은 자유.

- **교사용은 `_교사용` 접미**로 같은 번호 옆에 둔다(`04_예상문제_PRE-STEP_교사용.pdf`).
  같은 번호끼리 짝지어 읽어 정답을 확정한다 — 학생용만 있으면 정답을 역산해야 한다.
- `00_` 은 교과서본문 자리다(이그잼포유의 첫 항목). 여러 자료가 한 파일에 묶여 있으면
  번호를 이어 붙인다 — `01+02_통합.pdf`. 그 밖의 자료는 `99_`.
- **`02_본문워크북` 과 `03_단어시험` 은 둘 다 있어야 한다.** 학생 앱이 `pack.words` 와
  `pack.sentences` 를 전제로 홈·단어·본문·성취도를 그리기 때문에, 한쪽이 비면
  `pack-check` 가 배포를 막는다(오류 `words 가 비었음` / `sentences 가 비었음`).
- 그 둘만 있으면 나머지(`00`·`01`·`04`~`09`)는 없어도 팩이 나온다 — 나중에 채워 다시 올리면
  그 부분만 더해진다.

**교과서 코드(packId 의 가운데 조각)** — 정본은 `desk/lib/ledger-core.js` 의 `TEXTBOOKS` 다.
**개정 연도는 학년의 속성이다**: 중1·중2 는 2022 개정 10종, **중3 은 아직 2015 개정이고 12종**이다
(2026-09-18 이그잼포유 자료실 확인). 라인업 자체가 달라서 학년을 보지 않고 `2022-` 를 붙이면
중3 packId 가 통째로 틀린다 — 저자가 두 라인업에 다 있는 교과서(YBM 박준언·동아 윤정미·
동아 이병민)는 경로 파싱이 정상으로 통과해 **조용히** 틀린 값이 나온다. `revisionFor()` 가 이걸 막는다.

**왜 서버가 아니라 Claude Code 세션인가.** 원장이 Claude Max 를 쓰고 있어 구독 안에서
처리하는 것이 추가 요금 0 이다. 서버 AI 추출(`/job/extract`)은 호출마다 API 요금이 따로
나가므로 **무인 운용이 필요할 때를 위한 선택지로만 남겨 두었다**(스튜디오 화면에서도 접혀 있다).
PDF 를 서버가 파싱하지 않는 이유는 그대로다 — 워커에 PDF 파서를 두면 CPU 한도에 걸린다.

**세션에서 하는 일**: PDF 를 읽어 `pack-schema.md` 모양의 JSON 을 만들고,
`node naesin/pack-validate.mjs <디렉터리>` 로 오류 0 을 확인한 뒤 파일을 원장에게 넘긴다.
종류별로 나눠 만들어도 되고(`words.json`·`sentences.json`…) 통짜 하나여도 된다 —
스튜디오가 여러 파일을 한 초안으로 합친다.

**원천 PDF 는 어디에도 커밋되지 않는다.** 드라이브와 원장 기기에만 있고, 저장소에는
산출물(팩 JSON)조차 올라가지 않는다(팩은 KV 로만 간다, §9.3).

**현재 제작 스튜디오(`/admin/naesin-studio.html`)의 교사 순서**: 작업을 열고 → **PC 자료 불러오기**
→ **원본 PDF와 후보를 나란히 대조** → 오류·누락을 편집해 저장하거나 맞는 행을 승인
(`j`/`k` 이동, `a` 승인, `x` 버림, `e` 편집) → 모든 미검수·검사 오류를 해소한 뒤 배포.
PDF 후보는 일괄 승인하지 않는다. 본문은 「고급 입력」에서 교사가 영어·한글 줄 대응과
직독직해 청크·핵심어를 직접 구성해야 한다. 자동 검사 관문은 CLI와 같은 `pack-check.js`를 쓰며
PDF를 표시하거나 자동 검사를 통과한 것만으로 교사 대조를 대신하지 않는다.
**배포는 학생에게 서빙이 아니다** — 시험 범위에 넣어야 받는다(운영 화면의 팩 커버리지 카드가
어느 쪽이 빠졌는지 짚어 준다).

KV 업로드 설명은 2026-09-03 기록이다. 현재 실자료 반입·검수·게시 여부의 증거는

**본문 단어 · 난이도 · 자기 평가 제거(2026-09-04, §4.4 v1.3)** — 원장 방향 셋을 한 번에 반영했다.

*단어를 알아야 문장을 안다.* 종전 게이트는 **전 단어(77개)를 다 끝내야** 본문이 열려, 영어 기초가
부족한 학생에게는 벽이었다. 이제 **단락 단위**다 — 그 단락 문장에 나오는 단어를 한 번씩 보면 그
단락 본문이 열린다. 어느 단어가 어느 단락에 나오는지는 팩의 `sentences[].wordIds`가 정본이고,
없으면 표제어를 문장에서 찾아 잇는다(옛 팩 호환). 기준을 '도달'이 아니라 '한 번 학습'으로 둔 것이
중요하다: 도달은 철자 인출이라 영어를 쓸 줄 알아야 하고, 그러면 이 기능이 도우려던 학생이 도로
막힌다. 제대로 외웠는지는 전역 게이트(5·6단계·실전 모의)가 그대로 묻는다.
**뜻 세우기(청크 트랙)는 단어 게이트를 받지 않는다** — 못 읽는 학생의 첫 자리를 막으면 안 된다.

*난이도.* `words[].level` 1 기초 · 2 보통 · 3 심화. 팩 제작 때 붙이고(추가 구매 0원, 런타임 비용 0),
안 붙은 팩은 전부 보통으로 읽는다. 학습 순서는 **단락 순 → 난이도 → 교재 순**이다. 난이도를 단락보다
위에 두지 않은 이유: 전 단락의 기초 단어를 다 훑을 때까지 본문이 한 줄도 안 열려 진도감이 사라진다.
본문에 안 나오는 단어(대화문·시험 대비 어휘)는 맨 뒤 — 본문 진도를 막지 않는다.

*자기 평가 제거.* 문항마다 묻던 확실함/애매함/추측함 3버튼을 없앴다. 중학생, 특히 기초가 부족한
학생일수록 자기 평가가 실제 실력과 어긋나고, 빨리 넘기려고 아무 버튼이나 누르면 그 값이 그대로
복습 계획에 들어간다. 같은 판단을 **기록으로** 한다 — 이미 도달한 단어를 틀리면 그것이 과신이고
(2계단 후퇴), 찍어서 맞히는 것은 철자 인출 자리에서 걸러진다. 문항당 탭이 하나씩 줄었다.

부수 효과 하나를 실측으로 잡았다: 단락 게이트가 들어오자 2과 범위의 꼬리(누적 백지·종합 Check)가
시험 다음 날로 밀렸다. 원인은 `planRange`가 과별 꼬리 날수를 **최대값**으로 잡아 "두 과 누적을 같은
날 본다"고 가정한 것이었는데, 단락마다 끝나는 날이 갈라지면서 그 전제가 깨졌다. 합으로 바꾸고,
다음 두 단락을 막고 있는 단어는 하루 신규 상한의 고른 분배보다 먼저 꺼내도록 바닥을 두어
14일 완주(단어 16/16 안정화 · 문장 10/10 암송 · 누적 4 · 종합 Check 16/16)를 되찾았다.

끝난다. 그때까지 쓰지 않던 자료 두 가지(어색한 곳 찾기 6문항, 종합 Check 40슬롯)도 제자리를 얻었다.
하루 부담은 평균 47세션·최대 61세션(대부분 단어)이고, 분량이 많으면 학습 안내문에 실제 숫자가 뜬다.

**팩 제작 스튜디오(2026-09-03, 기획서 §15-2)** — 팩 하나를 사람이 반나절에 만들면 다출판사
확장이 불가능하다. 원천 텍스트를 붙이면 AI가 초안을 내고, 사람은 **자동 대조가 잡은 행만** 보고
배포한다. 검사 규칙은 `pack-check.js` 하나로 합쳐 CLI 검증기·관리 업로드·스튜디오 배포가
같은 판정을 내린다(테스트가 CLI와 배포 관문의 결과를 직접 비교한다). 규칙도 이때 촘촘해졌다 —
청크 연결이 정본과 다르면 오류, 어색한 문장 찾기의 `correction`을 되돌려 정본이 되지 않으면 오류
(문항 자신의 정답 근거를 검사한다), 종합 Check는 슬롯별로 풀 수 있는지까지 본다. 첫 팩의 일기
날짜였던 `dayGroup` 화이트리스트(`8/1`…)는 뺐다 — 다른 출판사 팩이 전부 실패했을 값이다.
운영 화면에는 두 카드가 붙었다: **팩 커버리지**(시험 범위 ↔ 업로드된 팩을 양방향 대조 —
서버가 없는 팩 등록과 배정된 팩 삭제를 모두 막으므로 실제로 나는 구멍은 "올렸는데 어느 시험에도
안 넣은 팩"이다)와 **문항 신고**(학생이 수업 중 발견한 오류를 문항별로 묶어 건수 순으로).

**교과서별 자료 준비(2026-10-11)** — 팩 커버리지는 *이미 등록된 시험*만 보므로 "시험을 등록하기도
전에 어느 교과서 자료부터 모을까"에 답하지 못했다. 그 답은 재원생이 실제로 쓰는 교과서에만 있어서
**학생 → 교과서 코드** 한 칸(`naesin:books`)을 두고, 학생이 많은 (교과서×학년) 조합부터 세워
팩이 0개인 조합과 만들 드라이브 폴더 이름(`docs/자료-폴더-표준.md`의 팩 id 접두사)을 보여 준다.
판정은 전부 `coverage.js`가 하고 화면은 그리기만 한다. 설계에서 **하지 않기로 한 것**이 핵심이다:

- **학교를 기록하지 않는다.** 학교명은 개인정보 성격이고(절대 규칙 1), 학교↔교과서↔학년↔과는
  desk 자료원장(`desk/lib/ledger-core.js`)이 이미 '구매 범위'의 정본으로 들고 있다. 같은 이름의
  다른 사실을 두 곳에 두면 갈라진다. 학생 단위로 두면 전학·교과서 변경도 그 학생만 고치면 된다.
- **과(Lesson)를 단정하지 않는다.** 어느 과가 시험 범위인지는 학교가 정한다 — 그 판정은 기존
  팩 커버리지 카드가 계속 담당한다. 그래서 폴더 이름도 접두사까지만 준다.
- **교과서 코드 목록과 대조하지 않는다.** 목록을 복제하면 desk와 갈라진다(`visang-`/`bisang-`
  드리프트가 그 사고였다). 문법만 보고, 오타는 "학생 N명인데 팩 0개" 조합으로 드러나게 한다.
- **모르는 것은 경고하지 않는다.** 교과서·학년을 못 읽은 학생은 경고가 아니라 '보류'로 센다 —
  거짓 경고가 한 번 나오면 원장이 이 카드를 안 믿는다. 대신 '보류 N명'을 같은 카드에 세운다.

PUT은 지정표 전체 교체라 (ㄱ) 명부를 못 받았으면 저장 버튼을 막고 (ㄴ) 지정이 풀리는 학생 수를
세어 되묻는다 — 되돌릴 길이 원장의 기억뿐이기 때문이다. 퇴원 처리는 이 맵에서도 학생을 지운다
(맵 한 레코드라 학생별 키를 지우는 기존 방식으로는 닿지 않는다 — 안 지우면 퇴원생이 조합에 남아
수집 순서를 흔든다).

`examFor` 는 서버 `resolveExam` 과 **같은 해석**이어야 한다 — 만료를 개별 배정에만 걸고 반 공통은
지난 날짜여도 살아 있는 배정으로 본다. 한때 반 공통도 만료면 배정 없음으로 봤는데, 그러면 서버가
아직 그 팩을 주고 있는 학생의 교과서 불일치를 **조용히 넘긴다** — 경고를 놓치는 쪽이라
'모르면 침묵' 원칙이 아니라 버그였다(테스트 둘이 그 버그를 고정하고 있었다).

팩이 0개인데 그 교과서의 **다른 학년** 팩은 있는 조합에는 어느 학년 팩이 있는지 한 줄을 붙인다 —
중2 때 지정하고 중3 이 된 학생의 낡은 지정이 '먼저 만들 자료' 1위로 서는 것을 알아보게 한다.
틀렸다고 단정하지는 않는다(그 교과서가 그 학년에 정말 없는지는 코드표의 질문이다).

**강사 라이브 보드·타임박스·투사 모드(2026-09-03, 기획서 §15-3)** — 관리 웹은 결과 집계용이라
수업 중 강사가 보는 화면이 없었다. 학생 상태는 이미 주기적으로 서버에 올라가므로 **5초 폴링**으로
반 현황을 낸다(WebSocket 을 워커에 띄우는 비용이 5초 지연보다 크다). 정렬은 정체 오래된 순 —
강사가 먼저 가 봐야 할 학생이 위로 와야 화면을 볼 이유가 생긴다. 정체는 학생이 올린 `idleSec` 에
그 뒤 흐른 시간을 더해 센다(앱을 덮으면 갱신이 멈춘다).
**타임박스**는 강사가 세운 단계를 학생 태블릿 상단 띠로 알리지만 **화면을 대신 넘기지 않는다** —
학생이 「이 단계로 이동」을 눌러야 옮겨진다(잘못 눌린 단계가 학습을 망치지 않게). 예외는 하나,
러너가 닫혀 있고 홈에 멍하니 있으면 3초 뒤 스스로 옮긴다.
**투사 모드**는 TV에 문제를 띄우고 답만 태블릿에서 받는다 — 그래서 `GET /live` 응답에 정답이 없다.
문제 생성은 학생 앱과 같은 `gen.js` 로 강사 화면에서 한다(서버에 규칙을 복제하면 학생이 푸는 문제와
TV에 띄우는 문제가 조용히 갈라진다). 결과는 기존 오답노트·학습 로그로 들어간다.

**같이 고친 것 두 가지**(둘 다 라이브 검증 중에 드러났다):
- **학원 달력(KST)**: 서버는 시험 만료·과제 날짜를 늘 KST 로 판정하는데 학생 앱만 기기 시간대로
  견주고 있었다. 시간대가 어긋난 태블릿에서 **배정된 과제가 조용히 안 뜨고** D-day 도 하루
  어긋났다. 서버가 준 날짜와 견주는 자리를 모두 `kstDate`·`kstDaysUntil` 로 바꿨다(엔진의
  '다른 날' 판정은 학생 자기 날짜라 기기 로컬 그대로 둔다 — 별개 문제다).
- **상단 띠의 임자**: 저장 표시가 성공할 때마다 `showBanner('')` 로 남의 안내까지 지웠다 —
  「선생님께 전달했어요」가 1초 뒤 사라졌다. 띠에 임자를 적어 자기가 띄운 것만 지운다.

**AI 비용(2026-09-03, 기획서 §13-8 확정)** — 팩 제작은 **원장 Claude Max 구독 안에서** 한다.
Claude Code 세션이 PDF 를 읽어 팩 JSON 을 만들고, 앱은 검수·배포만 맡는다. **추가 요금이 없다.**

서버 AI 추출(`/job/extract`)은 무인 운용을 위한 선택지로 남아 있고, 켤 때를 위해 한도가
걸려 있다 — **하루 80회**(`NAESIN_AI_DAILY`), 장부는 학생용 AI 한도와 분리(팩 하나 만들다
학생들의 연상 만들기가 막히면 안 된다). 서버에 `ANTHROPIC_API_KEY` 가 없으면 이 경로는
`no-key` 로 내려가고 나머지 전부가 그대로 동작한다.

한도를 붙이면서 드러난 결함도 함께 고쳤다 — 한도를 **추출 한 번마다** 세고 있었는데
`extract()` 는 원천 조각 수만큼 API 를 부른다. 긴 원천 하나가 한 칸만 쓰고 다섯 번 부르는
셈이라, 한도가 실제 비용의 몇 분의 일만 막고 있었다. 이제 **호출 한 번마다** 센다.

**학생은 AI 를 부르지 않는다** — 내신브레인에 학생이 트리거하는 AI 호출은 한 곳도 없다
(이미지 생성도 없다). 팩을 받아 기기에서 풀고 기기에서 채점한다. 학생이 AI 를 쓰는 것은
워드브레인(연상 만들기·문장 짓기·대화 미션)이고 그건 별도 한도(`ai-quota.mjs`)다.

**밤 9시 푸시가 내신도 본다(2026-09-11)** — 종전 푸시는 워드브레인 복습만 보고, 물 줄 단어가
없으면 그 학생을 건너뛰었다. 내신만 남은 학생은 시험이 코앞이어도 아무 알림을 못 받았다.
파일럿 판정 기준이 '시험 범위 완성률'이라 매일 밤 한 번 부르는 것이 그 지표에 바로 걸린다.

판정(`naesinNightDue`)은 **학생이 올린 요약만으로** 한다 — 푸시는 구독자 수만큼 도는 자리라
여기서 팩까지 읽으면 KV 왕복이 인원수만큼 늘어난다. 셋을 모두 만족할 때만 부른다:
유효한 시험이 있고(범위가 비지 않음) · 안정화 못 한 단어나 백지 못 넘긴 문장이 남았고 ·
오늘(KST) 학습 기록이 없다. 범위 요약(`summary.range`)이 있으면 그것이 기준이다.

`sendNightPushes`는 `naesin` 어댑터를 선택으로 받는다 — 안 넘기면 예전 그대로 워드브레인만 본다.
내신 때문에 보낸 건수를 `naesinOnly`로 따로 돌려주므로, 규칙이 실제로 걸리는지 로그로 확인된다.
알림 본문은 아직 비어 있다(payload 암호화 전) — 어느 쪽 때문에 울렸는지는 학생이 화면에서 가른다.
