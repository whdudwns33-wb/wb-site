# WB 업무지시서 (Work Order & Check)

직원에게 업무지시서를 보내고, **지시한 항목이 실제로 어디까지 진행됐는지 계속 확인**하는 도구입니다.
단순 체크가 아니라 **미착수 → 진행중 → 완료 / 막힘** 4단계로 상태가 보이고,
직원에게는 **"이 일을 어떻게 하는지" 가이드**가 함께 나갑니다.

- 주소: `https://<사이트주소>/task/`
- 설치·가입·앱 다운로드 없음. 링크만 있으면 폰에서 바로 씁니다.
- 파일 3개: `index.html`(앱), `apps-script.gs`(동기화), `README.md`(이 문서)

---

## 1. 어떻게 쓰나

### 원장님 (관리자)

| 화면 | 하는 일 |
|---|---|
| **직원 관리** | 직원 등록 → **개인 링크** 발급 (전체 링크 한 번에 복사 가능) |
| **오늘** | **빠른 추가** — 한 줄 쓰고 엔터. 저장하면 카톡에 붙여넣을 문구가 바로 나옵니다 |
| **지시서 작성** | 직접 작성하거나, **AI가 짜준 JSON** 또는 **카톡 문장**을 붙여넣어 한 번에 등록 |
| **오늘 / 주간 플래너** | 직원별 진행 상태를 그대로 확인 |
| **직원 현황** | 막힘 알림, **직원이 추가한 업무 모아보기**, 전체 수행률, 직원별 진행 상황, **오늘 마감 브리핑** 생성 |

탭의 **빨간 숫자**는 지금 원장님이 봐야 할 건수입니다 — 막힘 신고 + 예정 시각이 지난 미완료.

### 직원

원장님이 보내준 **개인 링크**를 열면 끝입니다. 비밀번호 없이 본인 할 일만 보입니다.

- 업무를 눌러 펼치면 **📘 이렇게 하세요** 가이드와 **단계 목록**이 나옵니다
- **＋ 업무 추가** 로 지시받지 않은 일(급한 방문 응대 등)을 스스로 적을 수 있습니다.
  본인이 추가한 것은 수정·중단이 자유롭고, **원장님이 내린 지시는 내용을 고칠 수 없습니다** (체크·메모·막힘만).
  원장님 화면에는 `직원 추가` 배지로 구분되어 보입니다
- 단계를 하나씩 체크하면 진행률이 올라가고, 다 채우면 **자동으로 완료** 처리됩니다
- 수량이 있는 업무(예: 12명 전화)는 **＋ / −** 로 진행 수량을 올립니다
- 막히면 **🚧 막혔어요** 버튼 → 원장님 화면에 즉시 표시됩니다
- 못 끝낸 일은 다음날 **⚠ 미완료** 표시로 따라옵니다

> 폰 브라우저에서 **홈 화면에 추가**해두면 앱처럼 열립니다.

## 2. AI에게 업무를 맡기는 법 ⭐

원장님이 구두로 지시하던 걸 그대로 Claude에게 말하면 됩니다.

> "스터디포스 구독한 학생들한테 CS 전화 돌려야 해. 김선생이 화요일 금요일에 하고."

그러면 담당·단계·수행 가이드·목표 수량까지 정리해서 아래 형식으로 만들어 줍니다.
앱 → **지시서 작성 → 📋 JSON 붙여넣어 등록하기** 에 그대로 붙여넣으면 끝입니다.

```json
{
  "assignments": [
    {
      "staff": "김선생",
      "title": "스터디포스 구독 CS 전화 (1차)",
      "detail": "이번 주 신규 구독 12명 대상",
      "guide": "1) 명단은 구독원장 시트에서 뽑습니다\n2) 첫 인사 멘트: ...\n3) 미접속 7일 이상이면 사용법 재안내\n4) 부재 시 문자 발송 후 다음날 재시도",
      "steps": ["구독 명단 뽑기", "전화 스크립트 확인", "1차 전화 돌리기", "부재중 문자 발송", "결과 기록"],
      "target": 12,
      "unit": "명",
      "time": "15:00",
      "priority": "high",
      "repeat": "days",
      "days": [2, 5],
      "carry": true
    }
  ]
}
```

| 항목 | 설명 |
|---|---|
| `staff` | 직원 이름. 등록 안 된 이름이면 등록할지 물어봅니다 |
| `title` | 업무 이름 (체크 단위) |
| `detail` | 한 줄 설명 |
| `guide` | **수행 가이드.** 직원이 처음 봐도 할 수 있게 절차·멘트·판단기준 |
| `steps` | 단계 목록. 넣으면 워크플로우로 관리됩니다 |
| `target` / `unit` | 목표 수량 (예: `12`, `"명"`). 없으면 생략 |
| `time` | 예정 시각 `"15:00"` — 지나면 원장님 탭에 빨간 숫자 |
| `priority` | `"high"` 면 ⭐중요 |
| `repeat` | `once` / `daily` / `weekday` / `days` |
| `days` | `repeat`이 `days`일 때 요일 (0=일 … 6=토) |
| `start` / `end` | `"2026-07-30"` 형식. 생략하면 오늘부터 |
| `carry` | `true`면 못 끝냈을 때 다음날로 이월 (기본 true) |

`steps`나 `target` 중 하나만 넣어도 되고, 둘 다 없으면 그냥 단순 체크 업무가 됩니다.

## 1-1. 급한 지시를 바로 넣는 두 가지

**① 빠른 추가 (권장)** — 오늘 화면 위 입력창

직원 칩으로 담당을 고르고 한 줄 쓰고 엔터. 저장되면 **카톡에 붙여넣을 문구**가 바로 뜹니다.
카톡을 먼저 보내지 말고 여기 적은 다음 그 문구를 보내면, 기록과 전달이 한 번에 끝납니다.

```
4시반까지 결석생 보호자 확인 전화
→ [16:30] 결석생 보호자 확인 전화
```

**② 카톡 문장 붙여넣기** — 지시서 작성 → `💬 카톡 문장 붙여넣기`

이미 카톡으로 보내버린 지시를 옮길 때 씁니다. 한 줄에 한 건이고, 이름·시간·날짜를 알아서 뽑습니다.

```
혜지쌤 오늘 3시까지 상담건 0729-A 보호자께 전화 부탁해요
윤지쌤 내일 교재 재고 확인해주세요
```
→ 김혜지 / 15:00 / 오늘 · 서윤지 / 교재 재고 확인 / 내일

**해석 규칙**

| 쓰는 말 | 결과 |
|---|---|
| `혜지쌤` `김혜지` `혜지 선생님` | 담당 배정 |
| `3시` `오후 3시` `3시반` `15:00` `10시 30분` | 시간 (한 자리 시각은 오후로 봅니다 — `3시` → 15:00) |
| `오늘` `내일` `모레` `금요일` `8월 3일` | 날짜 |
| `긴급` `급하게` `중요` `바로` | ⭐중요 표시 |

이름을 못 찾은 줄은 **담당 없음**으로 표시되고, 그 상태에서는 등록 버튼이 잠깁니다.
문장에 이름을 넣고 다시 해석하세요.

## 2-1. 등록을 자동화하는 3가지 방법

**① 원클릭 링크 (가장 간단)**

지시서를 링크에 담아 보낼 수 있습니다. 원장님은 링크를 누르고 **확인 화면에서 등록**만 누르면 끝입니다.
복사·붙여넣기가 필요 없습니다.

```
https://<사이트주소>/task/#add=<base64로 인코딩한 assignments JSON>
```

- 지시서는 `#` 뒤에 담기므로 서버 기록에 남지 않습니다
- **원장 화면에서만** 동작합니다. 직원 링크로 열면 무시됩니다
- 등록 전에 반드시 확인 화면이 뜹니다 (누가 몇 건, 새로 생길 직원은 누구)
- 앱을 이미 열어둔 상태에서 눌러도 동작합니다

**② 외부 자동화에서 밀어 넣기 (n8n · Make · 스크립트)**

구글 시트를 연결했다면 Apps Script 주소가 곧 등록 API입니다.

```
POST https://script.google.com/macros/s/.../exec
Content-Type: text/plain;charset=utf-8

{ "secret": "wb-2026", "mode": "add", "assignments": [ { "staff": "김혜지", "title": "...", ... } ] }
```

응답: `{"ok":true,"added":3,"createdStaff":[]}`
직원은 **이름으로** 찾고, 없으면 만듭니다. 등록된 업무는 45초 안에 직원 폰에 반영됩니다.

**③ 드라이브에 파일만 놓으면 자동 등록 (손 안 대는 방식)**

구글 드라이브에 `WB_지시서입력_*.json` 이름으로 파일이 놓이면 Apps Script가 알아서 읽어 등록합니다.
원장님이 붙여넣을 필요가 없습니다.

설치 — Apps Script에서 **트리거(시계 아이콘) → 함수 `importFromDrive` → 분 단위 → 10분 간격**
처음 실행할 때 드라이브 접근 권한을 한 번 승인합니다.

- 처리한 파일은 이름 끝에 `__처리완료` 가 붙어 다시 등록되지 않습니다
- 형식 오류면 `__처리완료_오류.json` 으로 바뀌고 시트 `_import로그` 에 사유가 남습니다
- `_import로그` 시트에 시각·파일명·등록건수·새로 만든 직원이 기록됩니다

**④ 정해진 주기에 자동 발행**

`apps-script.gs` 아래쪽 `WEEKLY_SET` 에 업무를 적고, Apps Script에서
**트리거(시계 아이콘) → 함수 `publishWeekly` → 주 단위 → 월요일 오전** 으로 걸어두면
매주 자동으로 발행됩니다. 원장님이 아무것도 안 해도 됩니다.

> 매일·매주 **똑같이** 반복되는 업무는 여기 넣을 필요가 없습니다. 지시서의 `반복` 설정(평일/요일 지정)만으로
> 이미 매일 자동으로 생성됩니다. `WEEKLY_SET` 은 **그 주마다 대상이나 수량이 바뀌는 업무**에 쓰세요.

## 3. 처음 시작 (5분)

1. `https://<사이트주소>/task/` 접속 → 관리 비밀번호 설정
2. **설정** 에서 구글 시트 연결 (아래 4번) — **직원 링크를 뿌리기 전에 먼저 하세요**
3. **직원 관리** 에서 직원 등록
4. **전체 링크 한 번에 복사** → 각자에게 카카오톡 전송
5. **지시서 작성** 에서 업무 등록 (직접 또는 AI JSON)

> 2번을 먼저 해야 하는 이유: 동기화 설정을 마치면 **개인 링크 안에 설정이 함께 담겨** 나갑니다.
> 직원은 링크만 누르면 연결까지 끝나고, 폰을 따로 만질 필요가 없습니다.
> 설정 전에 뿌린 링크는 연결이 안 되니 다시 보내주셔야 합니다.

## 4. 구글 스프레드시트 연결 (사실상 필수)

연결하지 않으면 데이터가 **각자 브라우저 안에만** 저장되어, 직원이 체크한 결과가 원장님 화면에 나타나지 않습니다.

1. [sheets.new](https://sheets.new) 로 새 스프레드시트 생성 (예: `WB 업무지시서`)
2. **확장 프로그램 → Apps Script**
3. 편집기 내용을 지우고 `task/apps-script.gs` 내용을 **전부 붙여넣기**
4. 맨 위 `var SECRET = 'wb-2026';` 값을 원하는 비밀키로 변경 후 저장
5. **배포 → 새 배포 → 유형: 웹 앱**
   - 실행 계정: **나**
   - 액세스 권한: **모든 사용자**
   - 배포 → 권한 승인 → **웹 앱 URL**(`.../exec`) 복사
6. 앱 **설정** 에 URL과 비밀키 입력 후 저장

연결 후 스프레드시트에는
- **`체크현황`** 시트 — 날짜·직원·업무·**상태**·**진행**·완료시각·메모가 표로 쌓입니다
- `_data` 시트 — 앱 원본 데이터 (직접 수정하지 마세요)

시트에 쌓이므로, 원장님이 이미 쓰시는 다른 자동화에서 이 데이터를 읽어 쓸 수도 있습니다.

## 4-1. 누가 무엇을 할 수 있나

| | 원장님이 내린 지시 | 직원이 추가한 업무 |
|---|---|---|
| 체크 · 단계 · 수량 · 메모 · 막힘 신고 | 직원 ✅ / 원장 ✅ | 직원 ✅ / 원장 ✅ |
| 내용 수정 (제목·가이드·단계·시간·반복) | 직원 ❌ / 원장 ✅ | 직원 ✅ / 원장 ✅ |
| 중단 | 직원 ❌ / 원장 ✅ | 직원 ✅ / 원장 ✅ |

지시 내용이 고정되어야 "그렇게 안 시켰는데요"가 생기지 않고, 가이드에 넣은 선
(검사 결과 문의는 원장님께 넘긴다, 부정 후기에 답글 달지 않는다 등)이 유지됩니다.

지시가 현실과 안 맞으면 직원은 **🚧 막힘**이나 메모로 올리고, 원장님이 고치는 흐름입니다.
직원이 조용히 고쳐버리면 원장님은 무엇이 안 맞는지 알 수 없기 때문입니다.

## 5. 알아두실 점

- **원장 복구 링크를 즐겨찾기에 저장해 두세요.** 설정 → `🔑 원장 복구 링크 복사` 로 만듭니다.
  접속 정보와 비밀번호가 함께 담겨 있어, 폰에서 열 때나 브라우저 데이터가 지워졌을 때
  **그 링크 한 번으로 복구**됩니다. 일반 주소를 저장하면 되살릴 방법이 없습니다.
  이 링크를 가진 사람은 원장 화면을 열 수 있으니 직원에게 보내지 마세요.
- 브라우저 데이터가 지워져도 **데이터는 구글 시트에 남습니다.** 빈 상태가 시트를 덮어쓰지 않도록
  합치기 방식으로 동기화합니다.
- **관리 비밀번호는 간단한 잠금장치입니다.** 방문자가 실수로 원장 화면에 들어오는 걸 막는 수준이며,
  기술적으로 뚫으려는 사람을 막지는 못합니다. 개인 링크(`?u=...`)도 아는 사람만 여는 방식입니다.
- 그래서 **학생 이름·생년월일·검사 결과는 지시서 본문이나 가이드에 쓰지 마세요.**
  `3시 김OO 학생`처럼 가려 쓰거나 학생 코드를 쓰시길 권합니다.
- **개인 링크에는 동기화 비밀키가 담겨 있습니다.** 단톡방에 섞어 뿌리지 마시고 1:1로 보내세요.
- 등록한 지시는 **직원 관리 → 지시 목록 관리 → 수정** 으로 언제든 고칠 수 있습니다.
  제목·가이드·단계·시간·반복·수량 전부 바뀌고, 직원 화면에 바로 반영됩니다.
  단계는 **순서를 그대로 두고 글자만 고치면** 그날 체크해둔 진행 상태가 유지됩니다.
  중간에 단계를 끼워 넣으면 그 뒤 순서가 밀리면서 진행 상태도 밀립니다.
- 지시를 **중단**해도 지난 기록은 남습니다 (직원 관리 → 지시 목록 관리).
- **설정 → 내보내기**로 전체 데이터를 백업할 수 있습니다.
- 검색엔진에는 노출되지 않도록 `noindex` 처리되어 있습니다.

## 7. 기기 (태블릿 대장)

원내 태블릿을 대장으로 관리하고, 점검할 일을 **업무지시서로 바로 내려보내는** 화면입니다.
**원장 화면 전용**입니다 (이유는 아래 7-3).

### 7-1. 쓰는 순서

1. **기기 탭 → ＋ 기기 추가** — 한 줄에 한 대씩 붙여넣습니다. `번호, 모델명, 일련번호` 순서이고 쉼표나 탭으로 나눕니다. 번호를 비우면 `A001`부터 자동으로 붙습니다.
2. **📋 실사 지시서 발행** — 아직 점검 안 한 기기만 골라 25대씩 끊어 담당자 할 일로 등록합니다. 기기 번호가 단계로 들어가 하나씩 체크됩니다.
3. **기기를 눌러 펼치고 결과 입력** — 모델·OS·크롬 버전, 배터리·충전·화면·잠금 상태, 배치와 담당자, 위치를 넣고 **[실사 완료로 저장]**.
4. **🚨 이상 기기 조치 / 🔒 개인정보 기기 점검** — 필요할 때 발행합니다.

> ⚠️ **실사 입력은 점검 대상이 아닌 다른 기기에서 하세요.** 대상 태블릿을 초기화하면 그 안의 브라우저 데이터가 사라집니다. (데이터는 서버에 있어 복구되지만 번거롭습니다)

### 7-2. 자동으로 올라오는 것

| 상태 | 판정 |
|---|---|
| 배터리 부풀음 · 충전 불가 · 화면 파손 | **이상** — 탭에 빨간 숫자, 격리 대상 |
| 런처 잠금(엠베스트 등) | 확인필요 |
| Advanced2인데 크롬이 138 미만 | 확인필요 — 138로 업데이트하면 풀립니다 |
| 아직 점검 안 함 | 확인필요 |

**배치를 정하면 티어가 따라옵니다** (교사→T · 학생→S · 센터/공용→B · 격리→C). 둘을 따로 적게 하면 어긋나기 때문입니다.

**개인정보 취급 기기**(센터 대기실 문진 등)로 표시하면 주 1회 점검이 반복 발행됩니다 — 키오스크 모드 확인, 인터넷 기록 삭제, 갤러리에 찍힌 문진표 삭제.

### 7-3. 왜 원장 화면에만 있나

동기화 서버는 개인 링크의 `__프리픽스__<값>` 쓰기를 **`<값>`이 본인 staffId일 때만** 허용합니다. 기기 번호는 staffId가 아니라서, 직원 링크에서 대장을 열면 **저장이 조용히 실패**합니다. 그래서 아예 열지 않고, 직원에게 필요한 기기 정보는 업무지시서로 내려보냅니다.

→ 관리자 선생님이 실사를 도우실 때는 **원장 화면(관리 비밀번호)** 으로 들어가셔야 합니다.

### 7-4. 왜 별도 앱으로 안 나눴나

이 저장소는 **기능이 아니라 "누가 쓰는가 + 어느 백엔드를 쓰는가"** 로 앱을 나눕니다. `apps/picture-test`가 따로 있는 것도 그림검사여서가 아니라 대상이 외부고 백엔드가 다르기 때문입니다.

기기 관리는 쓰는 사람(원장·관리자)과 백엔드(sync)가 업무지시서와 같고, 핵심 기능이 **지시서 발행**입니다. 나누면 그 연결이 함수 호출에서 API 계약으로 바뀌고, 직원 명단도 복제해야 합니다.

**다음 중 하나라도 걸리면 그때 분리합니다.**

1. 학생·학부모가 직접 쓰게 될 때 (예: 대여 신청) — 권한 모델이 달라집니다
2. 기기 사진·스캔 이력처럼 `checks`에 넣기 무거운 데이터가 필요할 때
3. `index.html`이 400KB를 넘고 로딩이 체감될 때 — 그 전에 **기기 화면 지연 로딩**으로 먼저 대응합니다

### 7-5. 저장 위치

기기 한 대는 `checks` 테이블에 `__asset__<번호>|all` 키로 들어갑니다. 출결(`__st__`)·온라인프로그램(`__op__`)이 쓰는 방식과 같아 **백엔드 배포 없이** 동작합니다. 삭제는 키를 지우지 않고 지움 표시만 남깁니다 — 키를 지우면 델타 동기화로 되살아나기 때문입니다.
