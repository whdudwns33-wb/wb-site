## 학생별 상담 현황·상담 세션 (2026-10-29 · 운영 배포 완료)

사이드바 `상담 현황`에서 학생별 월 정규 상담·주 미트 상담·주 플래너 확인·월 플래너 설계의 완료/목표 횟수를 확인한다. 학생의 `상담 세션` 탭에서 적용 시작일과 각 목표 횟수를 정하고, 회차를 예정→완료/불참/취소로 기록한다. 기존 `상담 관리`의 주기·기록·학부모 소통, 월간 계획, 진로·과목 설계는 유지한다. 예전 기록은 새 서비스 횟수로 추정하지 않는다.

- 기간: 월간은 해당 달, 주간은 월요일~일요일이다. 한국시간 기준일이 속한 주를 그대로 사용하므로 월·연도를 넘어가는 주도 분리하지 않는다. 적용일 이전에는 목표 미설정이며, 0회와 미설정을 구분한다. 목표는 기간 전체 횟수로 표시하며 중도 변경을 일할 계산하지 않는다.
- 저장: `student.consult.care.policies[]`에 관리 기준 이력, `sessions[]`에 회차별 버전을 추가한다. `sessionId`는 같은 회차, `id`는 저장 버전, `previousId`는 편집 기준 버전이다. 이전 전사·요약을 덮지 않으며 최신 버전만 횟수에 포함한다. 취소·불참·예정은 완료 횟수에서 제외한다. 다른 기기의 동시 수정 또는 이전 버전 편집은 저장을 거절한다.
- 기록: 날짜·시간·방식·Meet 링크, 아젠다, 플래너 확인/설계와 대상·변경 내용, 전사 원문, 요약, 결정 사항, 후속 조치·확인일을 따로 보관한다. 완료에는 요약이 필요하고, PLAUD 요약은 원문 검토 체크가 필요하다. 미래 회차의 완료 표시는 막는다. 기존 대시보드의 마지막 상담일에는 완료된 새 회차도 반영한다.
- 파일: UTF-8 TXT/MD/SRT/VTT 전사문, TXT/MD 요약, 아래 JSON 양식을 1MB 이내로 읽는다. 전사 150,000자·요약 30,000자·회차당 파일 이력 10개를 제한한다. 먼저 브라우저 초안에 읽고 사용자가 저장할 때 공용 상담 자료에 반영한다. 출처·녹음 ID·원문 링크·파일 이름·가져온 시각을 남기며 같은 PLAUD 녹음 ID가 다른 회차/학생에 이미 연결되면 거절한다. 이름으로 학생을 자동 매칭하지 않는다.
- 백업: 내보내기·복원 검증에 새 구조를 포함한다. 병합은 같은 회차의 현재 기록을 우선 표시하면서 다른 기기 버전도 이력에 보존한다. 동일 자료 재가져오기는 중복을 만들지 않는다. 상담 세션 2,000버전·관리 기준 200개 한도이며 저장 한도/서버 충돌 시 기존 기록을 유지한다.

### PLAUD·어사이드 연동 범위

2026-10-29 연결된 PLAUD 커넥터의 사용자 조회가 성공했다. 실제 녹음·전사·요약을 조회하거나 운영 학생에게 연결하지 않았다. 커넥터의 `get_transcript`(페이지 단위 전사)와 `get_note`(요약·노트)는 Codex/어사이드에서 선택한 녹음 ID를 읽는 경로이며, 워크벤치 브라우저에 커넥터 인증정보를 넣지 않는다. 이번 UI는 PLAUD 내보내기 파일과 전사/요약 붙여넣기·연동 JSON 가져오기를 지원한다. 앱 자체의 PLAUD 로그인·백그라운드 동기화나 Meet 예약·녹음 생성은 구현하지 않는다.

어사이드 자동화는 사용자가 별도로 구성한다. `이 학생의 입력 양식 받기`가 다음 구조의 파일을 만든다. `studentId`는 현재 학생의 정확한 식별자이고 `session`에는 제목·날짜·유형·방식·전사·요약·출처·후속 조치 등을 넣는다. 다른 학생 ID, 기존 `sessionId`/버전 ID 주입, 미지원 키는 거절한다. 가져온 완료/검토 표시는 항상 예정·미검토로 바꿔 저장 전에 다시 확인한다. 기록 원문을 공개 문서나 로그에 출력하지 않는다.

```json
{
  "schema": "wb-care-session-v1",
  "studentId": "synthetic-student-id",
  "session": {
    "title": "주간 상담",
    "date": "2026-10-29",
    "kind": "주간 미트 상담",
    "mode": "Google Meet",
    "source": "PLAUD",
    "sourceId": "synthetic-recording-id",
    "transcript": "전사 원문",
    "summary": "검토할 요약",
    "followUp": "담당자·할 일·확인일"

```

누적 전사·요약은 현재 공용 JSON과 브라우저 캐시에 저장되므로 파일당 제한 외에도 기존 저장소 용량 제한(서버 요청 본문 8MB·브라우저별 저장 한도)이 적용된다. 저장이 거절되면 이전 기록을 유지한다. 장기 대용량 원문 보관은 별도 첨부 저장소로 분리해야 한다.

기존 워크벤치 MCP의 `workbench_get_student(section=all)`로 새 `consult.care`를 포함해 읽을 수 있다. 기존 `workbench_save_student`는 학생 전체 기록과 `expected_revision`을 요구하므로, 나머지 필드를 보존하고 검증한 새 버전만 추가해야 한다. 이번 작업에서 MCP 쓰기·실제 상담 자료 업로드·자동화 예약은 실행하지 않았다.

검증: 전체 워크벤치 214개 검사와 최신 main 343개 검사, 실명 검사 0건(기존 시드 14명·공개 파일 52개)을 통과했다. 합성 학생에서 목표 설정→미트 상담·플래너 확인/설계→전사/요약 입력→미검토 완료 차단→완료 저장→수정 저장(횟수 중복 없음)→월간 계획 왕복→전체 현황→새로고침→다른 학생 분리를 확인했다. REA `ev_7962f5ab6bf7ef1c9dd740786e6f6657b98575b9e2890f8d4b50f9faa542aca6`, 390px 다크 화면에서도 38단계 완료·저장 버전 2개·회차 1개·페이지 오류 0건(`ev_48837387d48553902f4fe31b161e3e9eb4f45f8ca24378bf510d790f3a684dec`). 파일 읽기·학생 오배정 방지·가져오기 충돌·저장 실패·백업 왕복은 합성 자동 테스트로 검증했다. 스크린샷은 만들지 않았다. 오디오/PDF/DOCX 직접 추출, 실제 학교/상담 자료 업로드는 검사하지 않았다.

## 전북대 2027 정시 환산식 (2026-10-27 · 운영 배포 완료)

정시 반영방법의 계산 방식에서 `전북대 2027 공식 수능 환산식`을 선택한다. 공식 모집요강 인쇄 38·40~46쪽을 기준으로 인문·자연·수학교육·과학교육·의약계열·지역의사·체육교육·스포츠과학 산식 유형을 구분한다. 국어·수학은 표준점수, 탐구는 대학 변환표준점수 2과목 평균을 사용한다. 모집단위별 수능 배점(500/800/1000), 영어·한국사 가산점 배율, 해당 과학 과목 10% 가산, 최종 소수 셋째 자리 반올림을 적용한다. 수능 부분만 계산하며 학교폭력 조치·면접·실기·지원자격과 최종 전형총점은 자동 적용하지 않는다.

모집단위·전형·군과 선택 유형의 원문 일치 확인은 필수다. 학과 이름으로 유형을 추정하지 않으며 유형·학과·전형·군 변경 시 확인을 해제한다. 탐구 점수는 시험의 원래 표준점수와 분리한 `regular.conversion`에 보관하고 원래 시험을 수정하지 않는다. 공식 표의 상태·학년도·발표일·출처·URL·확인일, 과탐 가산점 포함 여부, 과목·백분위별 값을 확인한다. 과탐 가산점이 이미 포함된 값은 중복 가산하지 않는다. 과목 종류·중복 행·누락값도 검증한다.

공식 요강은 **2026-12-11 수능 성적 발표 이후** 2027학년도 변환표를 공지한다고 명시한다. 그 이전 날짜, 다른 학년도, 출처/원문/확인일 누락, 미발표 상태, 해당 과목·백분위 값 부재는 **계산 보류**다. `enter.jbnu.ac.kr` HTTPS 원문만 허용하며 보간·원래 표준점수 대입·전년도 표 재사용을 하지 않는다. 값을 입력했다고 공식 공표 사실을 자동 검증하는 것은 아니므로 원문 확인 책임은 남는다.

기존 일반 가중합·수시·저장 지원안·변경 이력·보고서는 자동 변환하지 않는다. 새 방식은 원장이 반영방법을 명시적으로 저장한 뒤 새 후보 또는 기존 후보의 명시적 근거 갱신에만 적용된다. 과거 보고서 사본은 유지한다. 변환표 미확인 후보도 보류 사유와 함께 저장·보고서 조회가 가능하며 합격을 보장하지 않는다.

`official-rules.test.mjs`는 모집요강의 공식 계산 예시 7개를 새 엔진으로 검증한다. **예시에 쓰인 변환값은 2026 표 기준**이므로 테스트에서만 가상의 미래 확인 시각/표로 재현하며 실제 2027 표로 등록하지 않는다. 날짜·출처·누락·선택과목·가산점 중복·잘못된 행 입력도 검사한다. 운영 상담 DB에는 테스트 학생이나 대학 노트를 추가하지 않는다. 브라우저 검증도 별도 합성 DB에서 수행한다.

## 계정 로그인·공용 상담 저장·API·MCP (2026-10-23)

사용자 요청으로 동등한 관리자 계정 두 개를 초기화했다. 계정 식별자·임시 비밀번호·학생 자료는 공개 소스나 인계서에 넣지 않는다. 최초 로그인은 비밀번호 변경·로그아웃만 허용하며, 기존과 다른 12~128자 비밀번호로 변경해야 앱과 API/MCP를 사용할 수 있다. 계정 화면 `/account`에서 비밀번호 변경·로그아웃·연결 키 발급/해제·관리자 목록을 제공한다.

- `account-host.mjs`가 실제 PC 서버다. `serve.mjs`는 암호화 형식 검사·합성 테스트용이고 직접 실행은 명시적 테스트 환경변수 없이는 거절한다. 암호화 두 파일은 갱신하지 않았고 계정 인증 후에만 메모리에서 복호화해 앱을 제공한다. 최초 비밀번호와 별개인 원래 앱 복호화 키는 Windows DPAPI CurrentUser로 보호한 `protected/app-key.dpapi`에 둔다. 다른 Windows 사용자로 파일만 복사해서는 복호화할 수 없다.
- `host-store.mjs`는 Node 기본 SQLite를 사용한다. `protected/accounts.sqlite`에 계정·세션·API 키 지문과 상담 버전들을 저장한다. 비밀번호는 [OWASP 권고](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)의 scrypt(N=2^17, r=8, p=1)와 계정별 무작위 salt로 해시하며 평문을 저장하지 않는다. 상담 스냅샷은 HKDF로 구분한 AES-256-GCM 키와 매번 새 IV로 암호화한다. 로그인 실패 잠금과 동시 KDF 수 제한을 적용한다.
- 세션은 8시간 유효한 Secure·HttpOnly·SameSite=Strict 호스트 쿠키다. Host/Origin·JSON·CSRF를 검사한다. 비밀번호 변경은 기존 세션과 API 연결 키를 모두 해제한다. API/MCP 키는 30일 유효하고 최초 발급 응답에서만 원문을 보여 준다. 로그·URL·공개 파일에 키를 적지 않는다.
- 두 관리자는 같은 서버 상담 자료를 조회·수정한다. `shared-client.js`가 기존 동기식 저장/실패 계약에 맞춰 서버가 저장을 확정한 뒤 기기 사본을 갱신한다. revision 조건부 저장으로 다른 관리자의 변경을 덮어쓰지 않는다. 학생 단건 API/MCP 수정도 기존 전체 필드를 보존해야 한다. 변경 전후 스냅샷은 삭제하지 않는다.
- 기존 브라우저 원본과 보호된 이전 백업을 보존한 채 공용 저장 자료의 전체 구조 일치를 확인했다. 기기 자료가 서버와 다르고 최초 서버 연결인 경우 별도 기기 사본을 보관하고 어느 자료를 사용할지 선택하도록 중단한다. 사용자 확인 없이 서로 다른 기기 자료를 덮어쓰지 않는다. 기기 저장은 백업 캐시이며 공용 정본은 PC 서버다. GitHub Pages의 예전 주소는 기존 기기 저장 방식으로 남는다.
- 기존 암호화 앱의 두 저장 지점만 실행 시 검증해서 공용 저장에 연결한다. 다음 빌드에서 이 저장 계약이 바뀌면 시작을 거절하고 자동 동기화가 이전 릴리스로 복구한다. 이 경우 어댑터를 수정·검증한 뒤 새 빌드를 적용한다. 서버 코드와 npm 잠금 파일은 작업 브랜치에서 관리하고 PC 런타임에 함께 반영한다. 프런트엔드 프레임워크는 추가하지 않았다.

### API 계약

아래 자료 API는 로그인 완료 세션 또는 `Authorization: Bearer <개인 연결 키>`가 필요하다. 쿠키를 사용하는 변경 요청은 같은 Origin과 `/api/auth/me`의 CSRF 값을 `X-CSRF-Token`으로 전달한다. 연결 키로 계정 비밀번호나 다른 연결 키를 관리할 수는 없다.

| 요청 | 기능 |
|---|---|
| `POST /api/auth/login` | `{username,password}` 로그인, 세션 쿠키와 변경 필요 여부 반환 |
| `GET /api/auth/me` | 현재 계정과 CSRF 확인 |
| `POST /api/auth/password` | `{currentPassword,nextPassword}` 변경, 기존 세션·API 키 해제 |
| `POST /api/auth/logout` | 현재 세션 해제 |
| `GET /api/summary` | 현재 revision·학생·보고서·정시 지원안 건수 |
| `GET /api/workspace` | `{revision,sha256,data}` 공용 자료 전체 조회 |
| `PUT /api/workspace` | `{revision,data}` 전체 저장, 버전이 다르면 409 |
| `GET /api/students?query=&offset=0&limit=20` | 학생 검색·페이지 조회, 최대 100명 |

| `GET/POST /api/account/tokens` | 브라우저 계정에서 연결 키 목록·발급, POST는 `{name}` |
| `DELETE /api/account/tokens/{id}` | 본인 연결 키 해제 |
| `GET /api/admin/users` | 동등한 관리자 목록 |
| `GET /api/openapi.json` | 인증된 API 기본 명세 |

### MCP 연결

공식 SDK의 [Streamable HTTP](https://ts.sdk.modelcontextprotocol.io/server)를 사용한 주소는 `https://workbench.wbcowork.com/mcp`다. 비밀번호 변경 후 `/account`에서 발급한 개인 연결 키를 Bearer 헤더로 넣는다. 임시 비밀번호나 기존 암호화 비밀번호를 MCP 설정에 쓰지 않는다. 현재는 직접 Bearer 설정이 가능한 클라이언트와 stdio를 지원하며 OAuth 자동 로그인·앱 등록 흐름은 구현하지 않았다.

## 수정 → 빌드 → 배포

모든 명령은 이미 준비된 `WB_PASSWORD` 환경변수를 사용한다. 비어 있으면 중단하고 알린다.
비밀번호를 채팅으로 묻거나 명령 문자열·파일·로그·화면에 쓰지 않는다.

```bash
# 1) 비밀번호 확인 후 workbench/src/app.html 또는 데이터 수정
node workbench/src/check-password.mjs  # 먼저 "비밀번호 확인 ✓" 여야 한다
# 2) 실명 검사 (공개 파일에 학생 실명 0건이어야 함 — 통과 못 하면 커밋 금지)
node workbench/src/check-names.mjs   # → "실명 검사 ✓ — 0건" (이름은 비공개 시드에서 읽음)
# 3) 평문 데이터를 바꿨다면 아래 백업 절차의 재암호화·커밋·푸시를 먼저 완료
# 4) 빌드 후 로컬 화면 확인 (아직 배포하지 않음)
node workbench/src/build.mjs   # "복호화 검증: 일치 ✓" 확인
# ⚠ build.mjs 의 "일치 ✓" 는 비밀번호가 틀려도 뜬다 — 진짜 검증은 check-password.mjs 뿐이다.
```

원장이 명시적으로 **"배포해"라고 한 뒤에만** 다음을 진행한다:

1. 작업 브랜치에 변경 소스와 `workbench/index.html`·`workbench/bulk.enc.json`을 커밋·푸시한다.
2. 최신 `origin/main`을 가져와 별도 배포 브랜치(worktree 사용 권장)를 만든다. 빌드 산출물 **두 파일만** 복사하고 PR의 변경 파일도 두 개뿐인지 확인한다.
3. PR을 열어 checks가 모두 통과하면 스쿼시 병합한다. **main에 직접 푸시하지 않는다.** 병합 권한이 없으면 PR 주소만 보고한다.
4. 병합 1~2분 뒤 라이브 `index.html`과 `bulk.enc.json?v=<빌드 태그>`의 SHA-256을 로컬 두 파일과 대조한다. 둘 다 일치해야 배포 완료다.
5. PC 운영 주소는 `WB_Workbench_Sync`가 위 「PC 서버와 Cloudflare」 절차로 같은 두 파일을 반영한다. 즉시 반영하려면 예약 작업을 실행하고 해시를 대조한다. GitHub와 PC 동기화는 별도 실행이므로 `sync-status.json`도 확인한다.

## 원장 백업 자동 반영 (Drive → 시드 → 재배포)

원장이 앱의 "백업 내보내기"로 만든 `wb-consulting-backup-*.json`을 Google Drive `WB_워크벤치_백업`
폴더에 올리면, 매일 아침 루틴이 새 파일을 감지해 반영한다. 수동으로 할 때:

```bash
node workbench/src/check-password.mjs
node workbench/src/seed-from-backup.mjs <백업파일.json>   # private-seed.json 전체 갱신 (학생 전체 상태 + 수동 DB extras)
node workbench/src/check-names.mjs
node workbench/src/backup-encrypt.mjs seed
git add workbench/backup/private-seed.enc.json
git commit -m "workbench: 학생 시드 백업 갱신"
git push origin claude/agent-performance-optimization-rj8ql6
node workbench/src/build.mjs   # 백업 푸시 후 재빌드
# 화면 확인 → "배포해" 승인 → 위 두 파일 PR 절차 → backup/last-drive-import.json 갱신
```

시드는 새 기기(또는 로그아웃 상태 기기)에 전체 상태를 채워 주고, 이미 쓰던 기기에는 신규 학생·신규
DB 항목만 추가된다(로컬 입력 보호). 이미 쓰던 기기를 백업 시점으로 완전히 맞추려면 앱의
"가져오기 → 전체 복원"으로 백업 파일을 직접 읽힌다.

`private-seed.json`·`bulk-data.json`을 수정했다면 **재빌드보다 먼저** `node workbench/src/backup-encrypt.mjs`를
변경 대상에 맞춰 `seed`·`bulk`·`all`로 실행하고, 해당 `workbench/backup/*.enc.json`을 작업 브랜치에 커밋·푸시한다.
평문은 gitignored라 기기·컨테이너가 초기화되면 사라진다 (2026-09-16 실제 소실).

## 설계 원칙

- **단일 HTML.** 프레임워크·외부 CDN 없음 (CSP·오프라인 안정성).
- **공개 소스에 개인정보 0.** 학생 데이터는 빌드 때 주입되어 암호문으로만 나간다.
  런타임 데이터 정본은 사용자 브라우저 `localStorage`(키 `wb-consulting-v1`).
- **비밀번호는 코드에 없다.** 이미 준비된 `WB_PASSWORD` 환경변수로만 사용하며 값을 문서·명령 문자열에 넣지 않는다.
- 외부 서비스(Perplexity·Gamma·진학사·어디가)는 앱이 직접 호출하지 않는다 — 앱은 프롬프트를 조립만 한다.
- 입결 대량 데이터는 약관상 평문 재배포 금지 — 암호문 밖으로 꺼내지 않는다.

## 수시 상담 로컬 구현 (2026-10-15 · 미배포)

`수시 상담·가능권 분석`은 학생 선택 → 모집학년도·내신 체계/평균·성적 근거 입력 → 조건별 후보와 제외 사유 → 지원안 저장으로 이어진다.
기존 6장 카드·일정·최저·상담 기록 복사를 재사용한다. 전형·학년도가 다른 지원안은 별도 카드이며, 동일 카드를 다시 추가해도 원장 입력을 덮어쓰지 않는다.

| 저장 위치 | 내용·보존 기준 |
|---|---|
| `student.consult.susi` / `susiDecisions` | 상담 입력, 학년도·대학·학과·전형별 검토/제외 사유. 병합 가져오기는 현재 입력 우선 |
| `student.apply[]` | `admissionYear`, `evidence`, `consultation` 추가. 기존 학년도 없는 카드는 별도 선택으로 유지 |
| `db.adiga[]` | 기존 메모에 학년도·출처·확인일·원문과 전형 조건 추가. 이전 필드와 작성일 보존 |

입결의 5/9등급 체계는 자료 자체 또는 같은 학과·전형·결과학년도의 명시적 근거로만 확인한다. 미확인/불일치/범위 오류는 수치 비교하지 않는다.
교과의 등급 차이도 대학별 환산이나 합격 판정이 아니다. 종합·논술·실기 평가는 등급 차이로 판정하지 않으며, 지원자격·최저는 원장이 별도로 확인한다.
외부 데이터 자동 수집·재게시를 추가하지 않았다. 수시와 정시를 묶는 통합 상담 보고서는 아래 로컬 구현 절을 따른다.

합성 브라우저에서는 학생/학년도 분리·지원 저장/중복·제외/해제·노트 편집·URL 검증·재접속과 390/1280px 문서 넘침을 확인했다. 실제 화면 확인은 원장이 한다.

## 정시 상담 로컬 구현 (2026-10-15 · 미배포)

`정시 상담`은 별도 실제 시험 입력 → 대학 반영 근거 확인 → 후보 비교·저장 → 가나다군 지원안·변경 이력으로 이어진다.
학평·모평·수능, 가채점/확정 성적을 구분하고 각 과목의 원점수·표준점수·백분위·등급을 입력한다. 내신이나 다른 지표로 과목 점수를 추정하지 않는다.

| 저장 위치 | 내용·보존 기준 |
|---|---|
| `student.consult.jeongsi` | 선택한 `admissionYear`·`examId`, 별도 `exams[]`·`plans[]`·`history[]`. 기존 수시 입력과 분리 |
| `plans[]` | 대학·학과·전형·학년도·시험·모집군별 후보/지원안/제외. `examSnapshot`·`ruleSnapshot`·`resultSnapshot`과 판단 사유 보존 |
| `history[]` | 시험 저장/수정·지원안 지정/전환/제외·명시 재계산의 `before`/`after`를 독립 복사. 이후 편집으로 과거 기록을 바꾸지 않음 |
| `db.adiga[].regular` | 모집군, 확인한 반영방법·지표·비율·탐구 방식·영어/한국사 등급별 가감점·미지원 조건. 기존 노트 필드 보존, 수시 자동 근거에서는 제외 |

계산은 **백분위 또는 표준점수 한 지표의 국어·수학·탐구 단순 가중합**, 탐구 상위 1과목/2과목 평균, 영어·한국사 등급별 가감점만 지원한다.
결과는 입력 반영식의 상담용 참고점수이며 대학 공식 환산점수·합격 판정이 아니다. 선택과목 가산점·변환표준점수·대학별 반올림 등 미지원 조건,
반영방법/필수 성적/출처·원문·확인일이 미확인이면 계산을 보류하고 사유를 표시한다. 계산 보류 상태도 후보로 저장할 수 있다.

같은 학년도·시험·군에는 지원안 하나만 두며, 변경 시 기존 지원안을 후보로 돌린 이력을 남긴다. 다른 시험의 지원안을 한 조합으로 섞지 않는다.
시험·반영 근거 수정은 저장 당시 스냅샷을 보존한다. 변경된 근거로 지원안을 지정하려면 사유를 적어 명시적으로 재계산해야 하며, 기존 지원안은 후보로 돌아간다.
지원 기록이 연결된 시험의 모집학년도는 수정할 수 없고 새 시험으로 등록한다. 백업 내보내기·전체 복원은 정시 상태를 포함하며,
병합 가져오기는 현재 설정·같은 ID 기록을 우선하고 새 ID 기록을 더한다. 같은 시험·군의 중복 지원안은 기존 것을 유지하고 가져온 쪽의 후보 전환 이력을 남긴다.

정시 기능 단계에서는 합성 자동 검증 **61개(7파일)**, 통합 보고서 구현 단계에서는 **92개(10파일)**를 통과했다. 전체 상담 흐름 재점검은 **109개(11파일)**, 기기 기억 개선 후에는 **117개(12파일)**를 통과했다. 실행 명령은 다음과 같다.

```bash
node --test workbench/src/achievement.test.mjs workbench/src/adiga.test.mjs workbench/src/susi.test.mjs workbench/src/check-names.test.mjs workbench/src/jeongsi-core.test.mjs workbench/src/jeongsi-store.test.mjs workbench/src/jeongsi-ui.test.mjs workbench/src/report-core.test.mjs workbench/src/report-store.test.mjs workbench/src/report-ui.test.mjs workbench/src/persistence.test.mjs workbench/src/remember.test.mjs workbench/src/search.test.mjs
```

합성 브라우저의 정시 주요 흐름도 통과했고 추가 모집군·빈 선택·손상 기록 확인도 통과했다. 실제 학생 데이터와 스크린샷은 사용하지 않았다.
정시까지 포함한 이전 로컬 빌드 태그는 `e379335f`다. 당시 비밀번호·비공개 백업 일치·실명 0건·복호화 검증과 로컬 두 파일 해시 대조를 통과했다. 수시 빌드 `b7aa839c`도 이전 기록으로 유지한다. 통합 보고서를 포함한 최신 빌드 검증은 아래 절에 기록한다. 원장 화면 확인은 대기 중이며, 라이브는 v39 그대로다.

## 통합 상담 보고서 로컬 구현 (2026-10-15 · 로컬 빌드 완료·미배포)

학생·모집학년도와 선택 시험을 정해 수시/정시 기록을 수집하고, 원장 결론·다음 할 일을 적어 미리보기 후 저장한다.
선택한 학년도의 수시 카드와 검토/제외 사유를 포함하며 학년도 없는 기존 카드는 별도로 둔다. 정시는 선택 시험의 지원안과 같은 학년도의 다른 시험 지원안을 나눠 표시한다.
다른 학년도 자료는 이번 내용에 섞지 않고 제외 건수만 알린다. 시험 미선택은 수시 중심 보고서이며 정시 점수를 임의로 가져오지 않는다.

| 저장·검증 항목 | 계약 |
|---|---|
| `student.consult.reports[]` | 보고서 제목·결론·다음 할 일과 당시 수집 자료를 독립 사본으로 추가한다. 재저장도 새 버전이며 과거 보고서를 수정하지 않는다. |
| `rptCollect` | 원자료를 변경하지 않는 순수 수집. 원장 판단·기존 내신·시험/근거/점수 사본을 보존하고 새 합격 판정·정시 재계산을 하지 않는다. |
| 출처·최저 | 학년도·출처·확인일·원문 주소의 누락/오류는 미확인. 수시 최저는 별도 `mockRef`와 대조하며 선택한 실제 정시 시험과 동일한 기준으로 취급하지 않는다. 원장 확인 상태 없는 기존 최저는 미확인이다. |
