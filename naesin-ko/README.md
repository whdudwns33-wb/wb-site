# 국어브레인 — 국어 내신 시험대비 앱

족보닷컴 구매 자료(또는 강사 자체 제작 정본)를 구조화해 재원생에게 원내 전용으로 제공하는 학습 앱.
내신브레인(영어)의 **형제 앱**이고 같은 서버·같은 학생 토큰을 쓴다.
정본 기획서: `docs/국어내신-학습웹앱-기획서-v1.md` (v1.0).

**최종 도달 목표 3가지** — 모든 설계가 여기로 정렬된다:
① 구절→개념 적용(지문을 보고 표현법·시어 의미·화자 태도를 근거와 함께 판별)
② 서술형 조건 충족 답안 ③ 작품 정본 정착(주석 복원·안정화).

> 영어의 "백지 영작"에 해당하는 목표는 국어에 없다. 국어 지필 문항은 예외 없이 **지문을 제시하고**
> 적용을 묻기 때문에, 훈련도 지문이 있는 상태로 한다(반응 일치성, 기획서 §1.4-7).

```

  grade.js          채점 — 한국어 정규화·루브릭 서술형·주석 복원 커버리지     [WBKOGRADE]
  gen.js            문항 생성 — 정본 → 5지선다·부정발문·<보기>·OX 런타임 생성 [WBKOGEN]
  pack-check.js     팩 검증 규칙 (CLI·관리 웹 공용 — 스키마의 실행 가능한 정의) [WBKOCHECK]

  pack-schema.md    팩 스키마 정의
  pack-validate.mjs 팩 검증기 CLI
  *.test.cjs        각 모듈 테스트 (node로 바로 실행)
reading-server/
  naesin-ko-api.mjs         /api/naesin-ko/* 라우트 (worker.mjs·server.mjs 양쪽에 등록)
  public/naesin-ko-admin.html  관리 웹 — 팩 업로드·시험 등록·과제 배정·오버레이·서술형 검토
```

핵심 데이터 흐름: **자료 → [추출·검증] → 팩 JSON → 관리 웹 업로드 → KV(`naesinko:pack:<id>`)
→ 학생 앱이 인증 후 로드**. 팩은 저장소·정적 자산에 절대 없다.
`concepts.json`만 예외 — 자체 창작이라 커밋하고 정적으로 서빙한다(`concepts.test.cjs`가 그 전제를 지킨다).

## 학생 앱 동작 요약

- **사다리 5단계**: 읽기(본문·날개풀이·구조도·TTS) → 개념 빈칸(SRS) → 구절 적용(생성 문항)
  → 주석 복원(힌트 없이 쓰기) → 서술형.
  **3·4단계 화면에서는 날개풀이가 보이지 않는다** — 그게 곧 정답이라 인출이 성립하지 않는다.
- **작품 완료** = 적용 정답률 기준(기본 80%) + 주석 복원 통과 + 서술형 통과. 4단계 하나로 선언하지 않는다.
- **게이트**는 어휘가 아니라 **적용 정답률**이다. 어휘·개념어는 시험기간 관문이 아니라 상시 큐다
  (국어 어휘·문법은 벼락치기가 안 된다는 통설, 기획서 §1.4-6).
- **D-21 플랜**: intake(D-21~15) → apply(D-14~8, 서술형 착수) → restore(D-7~4) → mock(D-3~2) → taper(D-1).
  서술형 배점이 30% 이상인 시험은 서술형을 D-21부터 낸다.
- **서술형 3층 채점**: 루브릭 규칙(1층 — 조건·요소·문장 완결) → AI 닫힌 판정(2층, Phase 2) → 강사 확정(3층).
  핵심어만 나열한 답안은 통과하지 않는다.
- **학교 오버레이**: 정본의 정답을 학교 선생님 해석으로 덮어쓴다. 채점기·생성기가 그 값을 따른다.
- 상태는 localStorage(`wbk.v1`) 정본 + 서버 백업. **요약·서술형 답안·오버레이는 state와 분리**된
  별도 키에 저장한다 — 관리 overview가 state를 통째로 읽지 않게(기획서 §8 저장 예산).

## 서버 API (naesin-ko-api.mjs)

학생(토큰): `GET /pack?id=` → `{pack, updatedAt}` · `GET/PUT /state`(`{state, summary}`, 256KB)
· `GET /exam` → `{exam, scope}` · `GET /task` → `{task, scope}` · `GET /overlay` → `{overlay, scope}`
· `GET/POST /review` → `{reviews, updatedAt}`

관리(PIN): `POST /admin/pack {id, pack}` (4MB, packId 일치 검증) · `GET /admin/packs`
· `POST /admin/exam {scope, examDate, packIds, profile}` · `GET/POST /admin/task`
· `GET/POST /admin/overlay` · `GET/POST /admin/review` · `GET /admin/overview`

## 팩 제작 파이프라인

1. **원천**: 족보닷컴 시리즈 4종 — 이해완성(작품 정본·빈칸), 직전 요약노트(체크리스트·어휘·빈칸판),
   단원집중(객관식 21 + 서술형 2, 선지별 해설), 서술형 공략(서술형 25). 출판사가 달라도 틀이 같다.
   **또는** 강사 자체 제작 정본(라이선스 경로에 따라, 기획서 §10-1).
2. **추출**: PDF는 복사 금지 플래그가 있지만 **텍스트 레이어 추출은 된다**(`pdftotext -layout`).
   텍스트에 없는 것은 빈칸(흰 상자)·연결선·구조도·★·밑줄 — 도형 정보라 렌더링(비전)으로 보정한다.
   추출은 오프라인 Node 스크립트로 하고 관리 웹은 JSON 업로드·검증만 맡는다.
3. **알려진 난점**: 학생용/선생님용 지면 대조로 빈칸 정답 복원 · 음영 정답 글자 판독 오류 ·
   같은 작품의 세트별 기호 위치 차이 · 2단 조판 읽기 순서 · **개정·출판사·작가·학기 미표기**(자료마다 다름) ·
   **서술형 루브릭은 27문항 중 20문항을 사람이 저작해야 한다**(검수 비용의 최대 항목).
4. **검증**: `node naesin-ko/pack-validate.mjs <팩 디렉터리>` — 오류 0이어야 배포.
5. **업로드**: `/admin/naesin-ko-admin.html` → 파일 전부 선택(브라우저가 병합·재검증) → 업로드 → 시험 등록.
