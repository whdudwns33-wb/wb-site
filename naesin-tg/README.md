# 탐구브레인 — 사회·과학 내신 시험대비 앱

족보닷컴 구매 자료(사회·과학 문제지와 요점정리)를 **지면 그대로** 재원생에게 원내 전용으로 보여 주고,
답만 화면에서 받아 채점·오답·시험 계획을 맡는 앱. 내신브레인(영어)·국어브레인의 형제 앱이고 같은 서버·같은 학생 토큰을 쓴다.
기획서: `docs/탐구내신-학습웹앱-기획서-v0.md`.

국어브레인과 가장 다른 점: **자료를 뜯어 다시 조립하지 않는다.** 쪽을 그림으로 바꿔 올릴 뿐이라 문항 생성기·팩 검증기가 없고,
대신 **채점을 서버가 한다** — 정답은 제출 전에 어떤 응답에도 실리지 않고, 정답·해설 쪽도 제출 전에는 403 이다.

## 구성

```
naesin-tg/
  index.html          학생 앱 (탭: 오늘·개념·문제·오답·성취도 + 풀이 화면: 한 문제씩[문항 영역] 또는 쪽 화면, 오른쪽 답안 칸)
  manifest.webmanifest · sw.js   홈 화면 설치(PWA). SW 는 셸만 캐시하고 /api/(문제지·쪽 그림·정답)는 건드리지 않는다
  sheet-sample.json   자체 창작 체험 문제지(전기 6문항, SVG 3쪽) — 저장소에 있는 유일한 문제지
  extract/
    build-sheet.mjs   PDF → 올릴 문제지 파일(쪽마다 JPEG). 오프라인 도구, poppler 필요
    make-sample.mjs   sheet-sample.json 을 다시 만든다
    upload-sheets.mjs 문제지 파일 여러 개를 운영에 닫힌 채로 올린다(관리 웹 대신 터미널, enroll.mjs 와 같은 관리 로그인)
reading-server/
  naesin-tg-api.mjs            /api/naesin-tg/* (worker.mjs·server.mjs 양쪽에 등록)
  public/naesin-tg-admin.html  관리 웹 — 올리기·정답 입력·열기/닫기·시험 배정·과제·반별/학생별 현황·서술형 확정
```

## 자료를 넣는 순서

1. 저장소 **밖** 작업 폴더에서 `node naesin-tg/extract/build-sheet.mjs <PDF> --id sc-m2-7-1-top-1` → `<id>.sheet.json`.
   PDF 도, 이 파일도 커밋하지 않는다(절대 규칙 1). 외부 AI 로 보내지 않는다.
2. 관리 웹에서 그 파일을 고른다. **여러 개면 한꺼번에 고른다**(⌘A, 국어 관리 웹과 같다) — 모두 닫힌 채로 올라가고 이미 있는 문제지는 건너뛴다. 터미널에서 올릴 수도 있다:
   `ADMIN_PIN=… node naesin-tg/extract/upload-sheets.mjs <폴더> [--first id,id] [--dry]` — 모두 **닫힌 채로**,
   서버에 이미 있는 id 는 건너뛴다(정답·「열기」를 지우지 않게. 덮어쓰려면 `--force`). 그다음 관리 웹에서 하나씩 연다.
   (관리 웹에서 하나씩 올릴 때는) 과목·학년·단원·단계, **정답·해설이 시작하는 쪽**, 문항 수를 확인한다.
3. 번호별로 유형(객관식·단답·서술형), 있는 쪽, 정답을 넣는다. 객관식은 `3`, 복수 정답은 `1,3`, 단답은 `도체|전도체`.
   정답 자동 읽기는 없다 — 족보닷컴 지면은 정답의 동그라미 숫자가 글자층에 없다(2026-11-12 실측).
4. 「정답을 확인했고 학생에게 엽니다」를 켜고 저장. 정답이 비었거나 쪽 그림이 빠지면 서버가 열기를 거절한다.
5. 자료를 고르고 시험일을 넣어 배정한다(대상을 비우면 반 공통).
6. 숙제는 「과제 내기」 — 문제지(읽기 자료 제외) 1~10개 + 제목 + 마감일 + 대상(전체 / 반 / 학생 코드 여럿).
   시험 범위 밖 문제지도 과제로 주면 그 학생에게 열린다. 과제는 여러 건 동시에 걸 수 있고, 지워도 풀이 기록은 남는다.

## 학생 앱이 하는 일

- 시험 범위나 과제로 받고 열린 자료만 보인다. 읽기 자료(요점정리·노트)는 「개념」, 문제지는 「문제」에 단계별로.
- 풀이 화면: 문제지에 **문항 영역(`crops`)이 문항마다 다 있으면 한 문제씩**(쪽 그림에서 그 문항만 잘라 그림, 「3 / 25」·이전·다음·번호 단추).
  하나라도 없으면 예전 쪽 화면(전체 / 왼쪽 단 / 오른쪽 단). 「지면 전체」↔「한 문제씩」으로 오갈 수 있다. 문항 순서는 지면 그대로, 섞지 않는다.
  영역은 `build-sheet.mjs` 의 `cropsFromWords` 가 글자층의 「N.」 머리 좌표로 잡는다(2단, 「[3~4]」 공통 자료는 해당 문항마다 위에 붙임, 다음 단으로 넘어간 문항은 이어 붙임).
  서버는 정답·해설 쪽을 가리키는 영역을 거절한다. 관리 웹은 「문항 영역 n / N」과 「문항 영역 지우기」(쪽 화면으로 되돌리기)만 있다 — 영역 편집기는 아직 없다.
  답은 1.2초 뒤 서버에 임시 저장돼 기기를 바꿔도 이어 푼다.
- 「오늘」 맨 위는 과제(마감 이른 순, 마감 지나면 빨강, 다 내면 ✓, 마감 7일 뒤 숨김), 그 아래 시험 범위.
- 제출은 한 번. 제출하면 ○✕·정답·해설 쪽이 열린다. 서술형은 모범답안을 보고 스스로 표시하고 강사가 확정한다.
- 틀린 문제는 **틀린 날과 다른 날** 다시 맞혀야 오답에서 지워진다.

## 서버 API

학생: `GET /sheets` → `{sheets, exam, scope, progress, today, tasks, examIds}` · `GET /sheet?id=` → `{sheet, my, answers?}`(answers 는 제출 뒤에만)
· `GET /page?id=&n=` → `{page:{n,data}}` · `PUT /draft` · `POST /submit` → `{result}` · `POST /retry` → `{retry}` · `POST /essay`

관리: `GET /admin/sheets` · `POST /admin/sheet {id, sheet}` · `POST /admin/page {id, n, data}`(1.4MB) · `POST /admin/sheet-delete`
· `GET/POST /admin/exam` · `GET /admin/tasks` → `{tasks}`(과제마다 `status: {targets, submitted, missing}`) · `POST /admin/task {id?, title, due, sheetIds, target}` · `POST /admin/task-delete {id}` · `GET /admin/class?cls=` → `{class, classes}`(cls 를 비우면 반 목록만) · `GET /admin/overview` · `GET /admin/student?code=&id=` · `POST /admin/essay`

아직 없는 것: 실제 족보닷컴 문제지로 한 시험(계정에 내려받기 권한이 없었다) · 과제 고치기 화면(서버는 `id` 로 고치기를 받는다) · 알림·반복 과제 ·
인쇄 · 이용권이 끝났을 때 자료를 지우는 절차.

반별 현황(2026-11-13): 분모는 **등록 학생 가운데 그 반 전원**(앱을 안 연 학생도 "안 냄"). 번호별 오답률은 **처음 제출 때** 틀린 수 ÷ 제출 수 — 뒤에 다시 맞혀도 처음 틀린 것으로 센다(수업에서 다룰 번호를 고르는 용도). 서술형은 빠진다.

백업(2026-11-13): 야간 스냅샷·관리 내려받기의 `naesinTg` 칸에 학생 기록·시험 배정·과제·문제지 목록(메타)이 담긴다.
문제지 본문(강사가 넣은 정답 포함)과 쪽 그림은 구매 자료라 담지 않는다 — 복구할 때는 원본 문제지 파일을 다시 올리고 정답을 다시 넣는다.
