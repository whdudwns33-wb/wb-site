# 학원 앱 기능 요청·연결 계약 v0.2

상태: 담당 세션 미전달. 실제 학원 앱 주소·저장소·API·담당자는 미확인이다.
원문 v0.1은 수정하지 않았다. 이번 문서는 블렌디드 앱 구현에 맞춘 후속 요청서다.

## 학원 앱에 요청할 기능

1. 학생 상세에 블렌디드 이용/연결 상태, 과목별 담당, 권한 있는 플래너 이동 링크.
2. 상담 ID·일시·담당·다음 확인일, 리포트 ID·버전·발행/철회 상태와 원본 이동 링크. 상담 원문이나 내부 메모를 복사/편집하지 않는다.
3. 안정 학생/강사 ID와 서비스 상태. 실명 일치로 합치지 않는다. 현재 플래너 계정은 로컬 ID이며 external_id는 미연결이다.
4. 학생별 보호자 관계·확인된 연락처·수신 동의·차단·철회·원본 revision·변경 시각을 서버 간 조회할 최소 인터페이스.
5. 강사 원본 소관, 신규 강사 등록 매핑, 비활성/담당 과목·기간 변경을 전달할 인터페이스.
6. 검토 대기·연결 오류·발송 실패/결과 불명만 표시할 운영 현황. 출결·수강료·보강·수업 원장을 변경하지 않는다.
7. 원본 기능 복원에 따라 주간·월간 학습 리포트도 상담 리포트와 구분하여 연결한다. 최신 발행본/철회 상태와 공개 링크만 표시하고 내부 메모는 가져오지 않는다.
8. ‘일정·학사’의 시험·수행평가를 학원 일정과 연결할 때 원본 일정 ID·소관·수정 권한을 정한다. 현재는 블렌디드 직접 입력 일정이며 학원 일정을 자동 복제하지 않는다.

## 공통 화면 톤 요청 (2026-10-19)

학원 → 블렌디드 플래너 → 연결 화면을 한 서비스처럼 보이게 맞춘다. 현재 적용 기준은 `blended/ui.css`와 `navigation.js`다. 남색 본문(#1b3a5c), 보라색 주요 동작(#6d28d9), 밝은 중립 배경(#f7f7fa), 동일한 한글 시스템 글꼴, 44px 이상 주요 조작, 모바일 입력 16px을 사용한다. 과목·완료·오류 색상은 의미를 유지한다.

학원 앱에는 같은 브랜드 표시, 현재 학생·역할 맥락, ‘오늘 / 주간 / 일정·학사 / 상담·리포트 / 전체 메뉴’ 명칭, 연결 전후 돌아갈 경로를 적용하도록 요청한다. 내부 메모와 공개 내용의 명칭도 통일한다. 학원 원본과 기존 consult 자체는 이번 배포에서 수정하지 않았다. 실제 학원 앱 주소·소스와 연결 관계를 확인한 뒤 그 앱의 기능을 유지하며 반영한다.

## 연결 계약 (제안, 운영 API 아님)

| 방향 | 최소 데이터 | 검증 |
|---|---|---|
| 학원 → 플래너 학생 | sourceStudentId, app=blended, revision, serviceActive, changedAt | 안정 ID 매핑, 오래된 revision 거부, 종료 시 조회/수정/발송 차단 |
| 학원 → 플래너 강사 | sourceTeacherId, plannerTeacherId, active, subject, starts, ends, revision | 동일 이름으로 결합 금지, 기간/과목별 현재 권한 검사 |
| 학원 → 발송 경로 | sourceStudentId, guardianId, relationshipVerified, contactRevision, consentRevision, eligible, blocked, checkedAt | 브라우저에서 임의 번호/URL을 받지 않음, 발송 직전 원본 재조회 |
| 플래너 → 학원 | consultationId, heldAt, authorId, nextCheck, reportId, version, status, publishedAt, deliveryState, sourceRef | 내부 메모/상담 원문/토큰 제외, 원본 ID/version 기준 |

모든 이벤트는 원본 ID·revision·eventId를 갖추고 중복/역순 이벤트를 안전하게 거부한다.
서명/서비스 인증·실제 endpoint·재처리 방식은 학원 앱 소스 확인 후 확정한다.
학생과 보호자의 읽기 API는 직접 URL 접근에서도 인증·관계·서비스 활성·동의를 다시 검사해야 한다.

## 발송 단일 경로

현재 실제 발송은 서버에서 연결 대기로 거부한다. 제공자 키/발송 SDK/임의 전화번호 입력칸은 없다.
발송 구현 전 확인할 조건:

- 원장 승인, 최신 유효 보고서 버전, 학생 서비스/담당 활성.
- 원본 보호자 관계·최신 번호·수신 동의·차단 상태를 발송 직전에 다시 조회. 오래된 캐시로 대체하지 않는다.
- `(reportId, version, guardianId, approvedChannel)`에 서버 UNIQUE 키. 연락처 revision을 예약/최종 전송 단계에서 비교하고 바뀌면 재검사한다. 번호 변경만으로 같은 버전을 자동 재발송하지 않는다.
- 예약과 제공자 요청은 단일 책임 경로. 학원 앱/플래너 양쪽에서 동시에 보내지 않는다.
- pending → submitting → accepted → delivered/failed/unknown. unknown은 자동 submit으로 돌아가지 않으며 제공자 조회 후에만 확정한다.
- acknowledged는 보호자 명시 확인이며 수신/이해를 추정하지 않는다. accepted를 도착/읽음으로 표시하지 않는다.
- SOLAPI 계정을 사용할 경우 사용자 지정대로 운영 PC 중계기만 기존 환경변수 키로 호출한다. NAS/플래너에 키를 복사하거나 새 키를 만들지 않는다.

계약 시험은 최신 동의/연락처 재검사, 서비스 종료, 최신 버전, 같은 멱등 키, 결과 불명의 자동 재발송 금지를 확인한다.
실제 제공자 예약 원장·콜백 검증·중복 발송 방지는 미연동이며 운영 발송 완료로 보고하지 않는다.
