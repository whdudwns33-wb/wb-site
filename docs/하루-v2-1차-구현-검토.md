# 하루 v2 공개 안내 1차 구현·검토

기준일: 2026-10-11. 표시 이름은 원장 답변대로 **삼육중 및 영재원 대비**를 유지한다.

## 1. 범위와 상태

최신 main `1390c07`에서 새 작업 트리·브랜치 `codex/haru-v2-public-20261011`를 만들었다. 기존 작업 트리와 미커밋 변경은 건드리지 않았다. 루트 AGENTS.md → haru/README.md → haru/AGENTS.md 및 개편 지시서와 추가 붙여넣기 지시문을 읽었다.

이번 범위는 PR-0 기준선·안전장치, PR-1A 두 핵심 영역의 공개 데이터, PR-2 홈·독립 안내의 로컬 구현이다. PR 번호는 작업 단계명이며 GitHub PR을 게시했다는 뜻이 아니다. **이번 작업은 push·머지·운영 배포를 실행하지 않는다.** 운영 DB 생성·이관·초기화, 학생 기록·토큰·크론 변경, 실제 상담·발송·원서 대행도 실행하지 않는다.

main의 최신 운영 결정은 학생 운영 Worker+KV 유지, PC 터널은 원장·강사 관리용이다(`로컬-서버-외부공개-터널.md`). 이전 지시서의 D1·전면 PC 이관 제안은 이번에 채택하지 않았다.

## 4. v1 보호 목록과 회귀

기존 학생·보호자·준비 안내 HTML, strings/plan/mastery/srs/cause/probe/preview, facts/atoms/플랜, pack-check, haru-api/haru-score, 관리 화면, worker/wrangler를 보존한다. `/haru/`는 그대로 열리고 `/haru/v2/`로 강제 이동시키지 않는다. 공유 `wbr.auth`, 기존 `/api/haru/*`, `haru:*`, `2027-pilot`의 계약을 바꾸지 않는다.

v2 코드는 학생 API·fetch·로컬 저장소·SW 등록을 쓰지 않는다. 공개 데이터와 생성 HTML에는 학생·보호자 정보, 운영 토큰·정답·해설·운영 팩을 넣지 않는다. 기존 pack-check·서버의 정답 제거 경로를 우회하지 않는다. OMR·채점·재학습·공유 인증 관련 기존 검사를 전체 검사에 포함한다.

실제 운영 학생 수·KV 콘텐츠 공급량·충분성·담당별 사용 현황·다른 WB 앱의 실시간 연결은 **미검증**이다. 샘플이나 소스에 모듈이 있다는 사실로 운영 공급이 충분하다고 판단하지 않는다.

## 5. 검사 결과와 캡처

변경 전 `node scripts/check.mjs`: **294/295 통과, 기존 실패 1개**. `reading-server/sec-headers.test.mjs`의 Windows 파일 경로 구분자 때문에 분할 지문 장기 캐시 헤더 검사가 실패했다. 경로 정규식이 `/`와 `\`를 모두 처리하도록 고쳤고 단독 재검사에서 통과했다.

최종 전체 검사: **296/296 검사 파일 통과, 기존 실패 0개·신규 실패 0개(33.0초)**. 새 공개 안내 세부 5개 검사, 기존 안내 세부 7개 검사 및 새 세 주소의 HTTP/보안 헤더를 확인했다. `node reading-server/build-dist.mjs`도 통과하고 dist의 v2에는 공개 파일 7개만 있다. 보호 목록의 소스 diff가 비어 있음을 확인했다.

브라우저 확인: 세 페이지 모두 320px·390px·1280px에서 DOM 가로 넘침 없음. 긴 기관명 줄바꿈, 학년/분야 필터 빈 결과·전체 복원·새로고침, 직접 안내 이동·상담 링크·기존 샘플 경로를 확인했다. 표시 이름과 전용 페이지의 현재 메뉴 강조가 유지된다. 페이지 오류 로그 없음. 기본 환경은 다크 모드이며 라이트/다크 색 값은 기존 정본과 같다.

캡처는 로컬 `haru/.impeccable/review/v2/`에 JPEG로 보관한다. `{home,samyook,gifted}-{desktop,320,390}-top.jpg`는 실제 첫 화면, 같은 이름에서 `-top`을 뺀 파일은 전체 페이지다. 필터·빈 결과·긴 기관명은 별도 캡처다. 캡처 도구에서 일부 썸네일/축소가 발생해 정상 크기·내용을 직접 연 뒤 독립 검수에 전달했다. 실패한 캡처를 검수 근거로 사용하지 않는다. 이미지 파일은 공개 배포·커밋 대상이 아니다.

JS 미사용 시 정적 본문·목록과 기준일 상태가 남고, 두 SW 오프라인 검사에서 새 안내를 구 앱 HTML로 대체하지 않음을 확인했다. 실제 휴대전화 단말·전화 발신·접수·운영 재배포는 이번 검사 범위가 아니다.

## 6. 로컬 실행과 검토

작업 트리 `wb-site-haru-v2-public`에서 실행한다.

```powershell
node haru/v2/build.mjs
node scripts/check.mjs
python -m http.server 8941 --bind 127.0.0.1
```

검토 주소:

- http://127.0.0.1:8941/haru/v2/
- http://127.0.0.1:8941/haru/v2/samyook/
- http://127.0.0.1:8941/haru/v2/gwangju-gifted/

정적 검토 서버는 이 PC에서만 접속한다. 운영 로그인·API 실험용이 아니다. 다른 기기의 주소나 실제 배포 주소로 안내하지 않는다. 프로세스를 끄면 로컬 주소가 닫힌다. 기존 학생 샘플은 `?preview=1`에서만 자체 예시를 보며 운영 학생 코드를 입력하지 않는다.

## 8. 되돌리기

운영 반영 전에는 이번 로컬 커밋을 `git revert <이번 작업 커밋>`으로 되돌리고 `node reading-server/build-dist.mjs`로 정적 산출물을 다시 조립한다. 새 v2 경로·복사 목록·SW 제외 규칙·문서와 Windows 캐시 보완이 함께 이전 기준으로 돌아간다. 학생 데이터나 KV를 복원하는 절차는 필요하지 않다. 다른 작업 트리나 사용자 변경에 `reset --hard`·일괄 삭제를 사용하지 않는다.

아직 운영 배포하지 않았으므로 현재 운영 사이트를 롤백할 작업은 없다. 후속 출시에서 원문과 기존 SW 설치 기기의 새 안내 접근을 다시 확인한다.

### 최종 독립 화면 검수

finish reviewer는 정상 첫 화면 캡처 9개와 상세 캡처·코드를 검토해 `ship`으로 판정했다. 기존 읽기 안내의 글꼴·색·정보 위계, 두 영역의 직접 진입, 모바일 줄바꿈, 필터 복원과 기존 학습실 연결이 이번 표면 계약에 맞고 남은 필수 수정은 없었다. 신규 이미지·폰트·장식을 추가할 필요가 없다는 판단이다.
