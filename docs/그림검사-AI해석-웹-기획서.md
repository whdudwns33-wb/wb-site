# 그림검사 AI 해석 웹 기획서

> WB 웩슬러브레인센터 | 아동 맞춤 그림검사(투사검사) AI 해석 서비스
> 문서 버전 v1.0 · 작성일 2026-07-27

---

## 0. 한 줄 요약

**아이가 그린 그림(HTP·KFD·DAP·자유화)을 업로드하면, AI가 관찰 요소를 자동으로 뽑아 아동 발달 단계에 맞는 해석 초안을 생성하고 → 전문 심리사가 검수·확정한 뒤 → 학부모에게 쉬운 요약 리포트로 전달하는 웹 서비스.**

핵심 원칙: **AI는 "해석 초안"을 빠르게 만드는 엔진, 전문가는 "확정 게이트", 학부모는 "쉬운 요약"의 소비자.** 어떤 화면에서도 "진단"이라는 단어를 쓰지 않는다.

---

## 1. 배경 & 문제 정의

### 1.1 현재 상황
- WB 웩슬러브레인센터는 광주 유일 웩슬러(K-WISC) 공식 검사·해석 센터로, 전문 심리사 1:1 해석 상담이 핵심 강점.
- 그림검사(투사검사)는 아동의 정서·성격·가족관계를 파악하는 보조 도구로 상담 현장에서 자주 쓰이지만, **해석이 심리사의 경험에 전적으로 의존**해 시간이 오래 걸리고 표준화가 어렵다.
- 학부모는 "우리 아이 그림이 무슨 의미인지" 궁금해하지만, 결과를 이해하기 쉬운 언어로 받기 어렵다.

### 1.2 해결하려는 문제
| 대상 | Pain Point | 이 서비스가 주는 것 |
|------|-----------|-------------------|
| **심리사(전문가)** | 해석 초안 작성에 시간 소요, 관찰 포인트 누락 위험 | AI가 관찰 요소·가설을 자동 추출한 초안 → 검수만 하면 됨 |
| **학부모** | 전문 용어 이해 어려움, 결과 접근성 낮음 | 확정된 해석을 아이 눈높이·부모 눈높이로 쉽게 풀어 전달 |
| **센터 운영** | 검사→해석→상담 리드가 흩어짐 | 업로드 리드가 정식 검사·상담으로 자연 전환 |

### 1.3 왜 지금 / 왜 WB인가
- WB는 이미 **검사·해석·상담 전 과정과 HubSpot CRM, 상담 flow, 개인정보 가드**를 갖춘 조직 → 그림검사 해석 웹을 기존 파이프라인에 얹기 유리.
- "광주 유일 공식 웩슬러 센터"의 전문성 브랜드 위에 AI 해석 도구를 얹어 차별화.

## 2. 목표 & 성공 지표(KPI)

### 2.1 목표
1. 심리사 해석 초안 작성 시간 **50% 이상 단축**.
2. 그림검사 업로드 → 정식 검사/상담 예약 **전환 리드 창출**.
3. 학부모 만족도 향상(쉬운 리포트) 및 재방문·소개 유도.

### 2.2 KPI
- **North Star**: 월간 확정 해석 리포트 발급 수.
- 선행지표: 그림 업로드 수, AI 초안→전문가 확정 소요 시간(중앙값), 초안 채택률(수정 없이 확정 비율).
- 전환지표: 업로드 후 30일 내 정식 검사/상담 예약 전환율.
- 품질지표: 전문가가 AI 초안을 "재작성"한 비율(낮을수록 좋음), 학부모 리포트 CSAT.

## 3. 타깃 사용자 (듀얼 유저)

### 3.1 전문가(심리사) — 1차 사용자
- 그림을 보고 AI가 뽑은 관찰 요소·가설을 **검토·수정·확정**한다.
- 최종 해석의 책임 주체. 학부모 노출은 전문가 확정 없이는 불가능.

### 3.2 학부모 — 2차 사용자(소비자)
- 확정된 해석을 **쉬운 요약 리포트**로 받는다.
- 필요 시 스스로 아이 그림을 올려 "참고용 미리보기"를 받고, 정식 상담으로 연결된다.

### 3.3 (선택) 관리자 — 센터 운영자
- 업로드·해석·리드 현황 대시보드, 리포트 이력, 개인정보 관리.

## 4. 다루는 검사 종류

| 코드 | 검사명 | 관찰 축 | 아동 적용 포인트 |
|------|--------|--------|----------------|
| **HTP** | 집–나무–사람 (House-Tree-Person) | 집=가정·안정감, 나무=성장·생명력, 사람=자아상 | 가장 기본. 정서·성격의 전반 스캔 |
| **KFD** | 동적 가족화 (Kinetic Family Drawing) | 인물 배치·거리·행동·생략 | 아이가 인식하는 가족 관계·자기 위치 |
| **DAP** | 인물화 (Draw-A-Person) | 신체 부위·비율·세부 묘사 | 자아상·발달 수준·정서 상태 |
| **자유화·기타** | 자유화, 빗속의 사람(PITR) 등 | 주제 선택·색·구성 | 스트레스 대처·창의성·확장 관찰 |

> 각 검사는 **공통 관찰 프레임 + 검사별 전용 프레임**으로 구성한다(§7 참고).

## 5. 핵심 사용자 플로우

### 5.1 전체 파이프라인 (핵심)

```
[1] 업로드          [2] AI 자동 해석        [3] 전문가 검수·확정      [4] 학부모 요약 발급
─────────────      ──────────────────     ─────────────────────    ────────────────────
 그림 사진/스캔  →   관찰 요소 자동 추출   →   심리사 검토 화면       →   쉬운 리포트 생성
 검사종류·아동     AI 해석 초안 생성        (수정/승인/반려)          (아이·부모 눈높이)
 메타(나이/성별)   가설·근거 제시          확정 = 게이트 통과         PDF·웹 링크 공유
 동의(개인정보)    ⚠ 진단 아님 명시        전문가 코멘트 추가          정식 상담 CTA
```

### 5.2 전문가 플로우 (내부)
1. 대기열에서 업로드 건 선택 → AI 초안 로드.
2. AI가 표시한 **관찰 요소(위치·크기·필압·생략 등)** 를 이미지 위에서 확인.
3. 각 가설에 대해 **채택 / 수정 / 삭제**, 근거 코멘트 추가.
4. **확정** 버튼 → 이 순간부터 학부모 리포트 생성 가능(게이트).
5. 확정본은 상담 자료로 자동 연동(선택: 상담 flow/HubSpot).

### 5.3 학부모 플로우 (공개)
1. 랜딩에서 검사 안내 확인 → 그림 업로드(또는 센터가 대신 업로드).
2. 개인정보·아동정보 수집 동의(필수).
3. **즉시**: "참고용 미리보기"(면책 강조, 관찰 중심의 순한 코멘트만).
4. **확정 후**: 전문가가 검수·확정한 정식 요약 리포트 알림 → 열람.
5. 리포트 하단 "정식 검사/1:1 해석 상담 예약" CTA.

> **안전 설계**: 학부모에게 "즉시 자동 해석"을 보여주더라도, 그것은 **관찰 중심의 순한 미리보기**이며 정서·병리 관련 강한 표현은 **전문가 확정 후에만** 노출한다.

- "우리 아이 그림 이야기" 톤. 강점 먼저, 관찰된 특징, 부모 팁, 다음 단계(상담) 안내.
- 병리·진단 언어 배제, "이런 점이 관찰돼요 / 이렇게 도와주세요" 프레이밍.

## 7. AI 해석 엔진 설계

### 7.1 3단계 파이프라인

```
(a) 이미지 관찰 추출  →  (b) 규칙+지식 기반 가설 매핑  →  (c) 대상별 자연어 생성
Vision 모델            검사별 해석 프레임              전문가용/학부모용 톤 분기
```

**(a) 관찰 요소 추출 (Vision)**
- 그림에서 정량·정성 특징을 구조화: 위치(용지 내 배치), 크기/비율, 필압·선의 질, 세부 묘사 유무, 생략된 부위, 색 사용, 대상 간 거리(KFD), 지붕/문/창/굴뚝 등 HTP 요소.
- 출력은 **구조화된 JSON**(예: `{element:"집.문", present:true, size:"작음", note:"손잡이 없음"}`).

**(b) 해석 가설 매핑**
- 검사별 **해석 프레임(지식 베이스)** 을 룰/근거와 함께 관리(예: "나무 밑동 상처 = 과거 상처 경험 가설(약)"). 각 가설에는 **신뢰도(강/중/약)** 와 **근거 문헌/원칙** 태그.
- ⚠ **단정 금지**: 모든 가설은 "가능성/경향"으로 표현. 연령·성별·상황 메타로 보정(예: 어린 연령대의 신체 생략은 발달상 정상 범위일 수 있음 → 자동 완충 문구).

**(c) 대상별 자연어 생성**
- **전문가용**: 관찰 근거 + 가설 + 신뢰도 + 확인 질문(상담에서 물어볼 것) 제안.
- **학부모용**: 확정된 항목만, 강점 우선·순화·행동 팁 중심. 부정 표현은 중립·성장 관점으로 리프레이밍.

### 7.2 프롬프트/모델 전략
- Vision 관찰 추출과 해석 생성을 분리(관찰의 재현성·검증성 확보).
- 해석 생성은 **검사별 시스템 프롬프트 + 지식베이스 + 안전 가드(진단 금지·단정 금지·연령 보정)** 를 주입.
- **Claude 최신 모델(예: claude-opus-5 / claude-sonnet-5)** 을 기본으로 사용. 초안 생성은 상위 모델, 대량·정형 처리는 경량 모델로 비용 최적화.
- 모든 산출물에 **면책 메타**(진단 아님, 참고용, 전문가 확정 필요) 강제 포함.

### 7.3 품질/피드백 루프
- 전문가의 "채택/수정/삭제" 액션을 로깅 → 가설 신뢰도·프롬프트 개선에 활용.
- 자주 삭제되는 가설은 지식베이스에서 강등, 자주 채택되는 표현은 승격.

## 8. 안전 · 윤리 · 법적 가드레일 (필수)

> 아동 심리검사는 민감정보. 이 섹션은 "있으면 좋은" 것이 아니라 **출시 전제 조건**.

1. **진단 아님 원칙**: 모든 화면·리포트·PDF에 "본 해석은 참고용이며 의학적·심리학적 진단이 아닙니다. 정확한 평가는 전문가 대면 검사가 필요합니다." 고정 노출.
2. **전문가 확정 게이트**: 정서·병리 관련 강한 해석은 전문가 확정 전 학부모에게 노출 금지. 자동 미리보기는 관찰 중심의 순한 코멘트로 제한.
3. **단정·낙인 방지**: "~이다/~장애" 금지 → "~경향/가능성/관찰됨"으로 표현. 부정 표현 자동 순화.
4. **아동·개인정보 보호**:
   - 그림 이미지·아동 정보는 민감정보로 취급, 수집 시 **명시적 동의**(보호자).
   - 저장 최소화·암호화, 보존 기간·파기 정책 명시, 접근 권한 최소화(전문가/관리자만).
   - 학부모 리포트 링크는 만료·인증(예: 발급번호+생년 확인) 처리.
   - WB의 개인정보 가드(privacy-guard) 원칙 준수: 아동 이름·생년월일·검사결과를 외부 URL/템플릿 변수에 노출 금지.
5. **위기 신호 에스컬레이션**: 자해·학대·심각한 정서 신호가 의심되면 자동 해석을 중단하고 **전문가 즉시 검토** 플래그 + 안내(전문 상담 연결).
6. **데이터 사용 투명성**: AI 학습·개선에 데이터를 쓸지 여부를 동의에서 분리 선택.
7. **감사 로그**: 누가 언제 무엇을 확정/발행했는지 추적.

```
                          image(암호화 스토리지 키), meta(용지방향 등),
                          consent_id, status(uploaded→ai_drafted→reviewing→confirmed→published)
Observation             : id, submission_id, element, attributes(json), source(ai/expert)
Hypothesis              : id, submission_id, text, confidence(강/중/약),
                          basis, status(ai_suggested/accepted/edited/rejected), expert_note
Interpretation          : id, submission_id, expert_id, summary_expert, summary_parent,
                          confirmed_at
ParentReport            : id, submission_id, share_token, expires_at, viewed_at, cta_clicked
Consent                 : id, guardian, scope(analysis/store/improve), signed_at
AuditLog                : actor, action, target, timestamp
```

## 10. 기술 스택 & 아키텍처

### 10.1 원칙
- **기존 정적 사이트(index.html)와 브랜드/톤 유지**, 앱 영역은 별도 경로(`/apps/picture-test`)로 확장.
- 아동 민감정보 처리 → **서버 필요**(정적만으로 불가). 이미지·개인정보는 클라이언트에만 두지 않는다.

### 10.2 권장 스택
- **프론트**: 기존 스타일 재사용(Noto Sans KR, navy/blue/coral). 공개 페이지는 가볍게(정적 + 최소 JS), 콘솔은 SPA(React 등) 고려.
- **백엔드**: Node/Next API 또는 Python(FastAPI). 인증·권한(전문가/관리자/학부모), 파일 업로드, 상태 머신.
- **AI**: Claude API(Vision + 텍스트 생성). 관찰 추출/해석 생성 분리 호출.
- **스토리지**: 이미지 = 비공개 오브젝트 스토리지(암호화, 서명 URL), 데이터 = 관계형 DB.
- **연동**: HubSpot(리드), 상담 flow, 알림(카톡/알림톡)은 WB 기존 승인 기반 발송 원칙 준수(자동 발송 금지, 후보 생성).

### 10.3 아키텍처 다이어그램

```
학부모/전문가 브라우저
        │
        ▼
  웹앱(공개 랜딩 + 업로드 + 리포트 / 전문가 콘솔)
        │  REST/GraphQL
        ▼
  백엔드 API ── 상태머신(uploaded→…→published)
    │     │           │
    │     │           └── Claude API(관찰추출→해석생성, 안전가드)
    │     └── 암호화 오브젝트 스토리지(그림 이미지)
    └── DB(제출/관찰/가설/해석/동의/감사로그)
        │
        └── (승인 후) HubSpot 리드 · 상담 flow · 알림 후보
```

## 11. WB 기존 시스템 연동

- **리드 유입**: 학부모 업로드 = 잠재 고객. 동의 시 HubSpot 리드로 등록(승인 기반), 채널·유입 태깅.
- **상담 연결**: 확정 해석 = 상담 자료로 자동 첨부(consult 흐름). 상담 예약 CTA로 전환.
- **발송 원칙 준수**: 리포트 발급·알림은 **자동 발송이 아니라 후보 생성 → 승인 후 발송**(WB notify 원칙). 아동 이름·생년·검사결과는 템플릿 변수로 넣지 않음.
- **개인정보 가드 연동**: privacy-guard 규칙(전화번호·검사결과·상담원문 노출 차단)을 발행 전 자동 점검.
