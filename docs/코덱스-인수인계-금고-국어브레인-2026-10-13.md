## 0. 세 줄 요약

1. **국어브레인은 운영 결함 여섯이 닫힌 상태로 배포돼 있다**(#439·#441). 그 여섯은 기획 단계
   항목이 아니라 **지금 코드에 있던 구멍**이었다 — 가장 큰 것은 재원생이면 누구나 남의 시험 범위
   팩을 받을 수 있던 것과, 오답노트가 족보 발문을 베껴 KV·야간 백업·학생 태블릿까지 복제한 것이다.
2. **금고는 설계가 확정됐고 코드는 시작하지 않았다.** 설계 심사 세 렌즈가 모두
   `fix-design-first` 를 냈고 blocker 10건이었다 — 그 처방을 설계로 못 박은 것이 §1.5 의
   「착수 전에 정해 둔 네 줄」이다. **원장 확인 4건이 끝나기 전에는 착수하지 않는다.**
3. **지금 바로 집을 수 있는 것은 금고가 아니다** — 아래 §3 의 셋이다.

## 1. 손대지 말 것 — 먼저 읽는다

### 금고(A.5) 코드는 시작하지 않는다

정본은 `docs/로컬-서버-외부공개-터널.md` **§1.5**(이 저장소 56행부터)다. 그 절의 소제목 여덟 개가
설계 전부이고, 그중 둘이 관문이다.

- **「금고가 주는 것과 주지 않는 것」** — 금고는 자료가 *쉬는 곳*(at rest)만 우리 PC 로 옮긴다.
  **전송 경로에서 Cloudflare 를 빼지 못한다**(학생이 열 때마다 팩이 워커를 지난다). 원장이 "아예
  만지지 않는다"를 기대했다면 금고가 아니라 B(전부 이관)다. **이 구분을 원장에게 확인받지 못했다.**
- **「남은 것 (코드 쓰기 전)」** — 원장 확인 4건. 하나도 안 끝났다.

### 운영 KV 의 기존 발문을 지우지 않는다

`GET/POST /api/naesin-ko/admin/scrub`(`reading-server/naesin-ko-api.mjs:506`)가 준비돼 있고
GET 은 세어만 본다. **운영 데이터 삭제는 원장 확인 사항**(`CLAUDE.md` 작업 규칙 7)이라 아직
누르지 않았다. 코덱스도 누르지 않는다.

### 저장소 전체 목록에서 집지 말 것

`코덱스-인수인계-남은작업-2026-10-11.md` 의 **「그 뒤 바뀐 것 — 집기 전에 이것부터 읽는다」**
절이 그 목록을 쓸 때 주의할 점을 담고 있다. 특히 「자료 폴더 표준 대조 테스트」는 이미 닫혔다
— 다시 집으면 중복 테스트를 만든다.

## 2. 지금 어떻게 돼 있는가

### 접합부 — 금고가 붙을 자리는 한 군데다

```
worker.mjs:255   function naesinKoStore(env) { … }     ← 금고가 갈아 끼울 자리
worker.mjs:794   if (p.startsWith('/api/naesin-ko/'))  ← 유일한 호출자
server.mjs:228   const naesinKoStore = { … }           ← 로컬 서버 쪽 같은 계약
server.mjs:637   if (p.startsWith('/api/naesin-ko/'))
```

`naesin-ko-api.mjs` 가 쓰는 `store.*` 메서드는 **21개**다. 그중 금고로 가는 **라이선스 6칸**:

| 칸 | KV 키 |
|---|---|
| `getPack` / `putPack` | `naesinko:pack:<id>` |
| `getPackIds` / `putPackIds` | `naesinko:packs` |
| `getPending` / `putPending` | `naesinko:pending:<id>` |

나머지는 학생·교사 기록이라 **KV 에 그대로 남는다**. 단 **오버레이 2칸은 미정**이다(§1.5 의
「어느 칸이 금고로 가는가 — 원장 결정 대기」). 오버레이의 `answers[]` 에 문항 정답 문자열이
들어가므로, 정답을 라이선스 자료로 보면 6칸이 아니라 **8칸**이다. 설계 심사는 8칸을 권했다.

### 2026-10-11 에 닫은 여섯

| 무엇 | 자리 | PR |
|---|---|---|
| 팩 **시험 범위 게이트** — `GET /pack` 이 인증만 보고 내줬다 | `naesin-ko-api.mjs:68` `examPackIds()` · `:158-159` 판정 | #439 |
| 몸통 상한 — 국어 분기에만 `content-length` 가드가 없었다 | `naesinKoBodyLimit` 을 워커·로컬 양쪽에서 쓴다(`server.mjs:337`·`:637`) | #439·#441 |
| 팩 수신 실패 안내·재시도 | `index.html:394` `packFail()` · `:380` `applyPack()` · `:365` `busy()` | #439·#441 |
| 단원 전환(범위가 여러 단원일 때) | `index.html` 의 `data-unit` 버튼 — 체험 모드에서도 남는다 | #439·#441 |
| **오답노트가 발문을 베끼던 것** | `index.html:976` `markWrong()` → 좌표만 · `:992` `wrongLabel()` · `:1006` `scrubWrong()` · 서버 `naesin-ko-api.mjs:28` `scrubWrongLabels()` | #441 |
| 루브릭 초안 영구 보관 | `naesin-ko-admin.html` 의 `rbSweep`(2주 기한) + 내려받기 경고 두 겹 | #441 |

자세한 설명은 `naesin-ko/README.md` 「현재 상태」의 표에 있다.

### 밟으면 터지는 자리 — 세 관문

1. **`store.*` 를 하나 더하면 두 어댑터에 같이** 넣어야 한다. `override.test.mjs:143-144` 가
   워커·로컬 양쪽에 있는지 검사한다 — 한쪽만 더하면 빨간다(그 검사가 막으려는 것이 "로컬에서
   다 확인하고 배포한 뒤 운영에서만 500"이다).
2. **워커 import 그래프에 `node:` 모듈을 넣을 수 없다.** `override.test.mjs` 가 금지한다.
   `await import('node:crypto')` 는 그 정규식을 **피해 가지만 런타임에서 깨진다** —
   테스트 초록 + 배포 성공 + 운영만 500. 암호는 `crypto.subtle` 로 한다(선례
   `admin-auth.mjs:9` · `vocab-api.mjs:481`, 상수시간 비교는 `admin-auth.mjs:12-18` `safeEqual`).
3. **`worker.mjs:1151` 이 `detail: String(e.message)` 를 응답에 싣는다.** `/api/` 전체를 감싼
   단 하나의 catch 다. 금고 클라이언트가 예외를 던지면 그 메시지가 요청자에게 나간다 — 금고가
   JSON 이 아닌 본문(프록시 오류 HTML·잘린 팩)을 주면 **파싱 오류 메시지가 지문 조각을 품는다.**
   그래서 §1.5 ②가 센티넬(`e.wbStatus`·`e.wbSafeMessage`)을 요구한다.

추가로 `scripts/pages-noindex.test.mjs`(#442)가 저장소 전체 `.html` 에 `meta robots noindex` 를
요구한다 — HTML 을 새로 만들거나 옮기면 이 검사를 먼저 본다.

## 3. 바로 집을 수 있는 것 — 결정이 필요 없다

순서대로. 셋 다 금고와 무관하고, 원장 결정을 기다리지 않는다.

### ① `/admin/scrub` 에 관리 웹 버튼 (S)

#441 이 라우트만 만들었고 화면이 없다. 지금은 원장이 PIN 으로 직접 호출해야 쓸 수 있다.
"먼저 GET 으로 규모를 보고 POST 로 지운다"는 흐름이라 **버튼 두 개짜리 카드**가 맞다.

- 자리: `reading-server/public/naesin-ko-admin.html` (카드 추가)
- 라우트: `GET /api/naesin-ko/admin/scrub` → `{dryRun:true, records, touched, labels}` ·
  `POST` → `{dryRun:false, …}`
- 지우기는 **되돌릴 수 없다.** 버튼에 그 사실과 "먼저 세어 보기"를 화면에 적는다.
  GET 결과를 보여 준 뒤에만 POST 버튼이 열리게 하는 쪽이 안전하다.

### ② 지문 보드 카드 + 렌더러 모듈 분리 (M)

저장소 전체 목록의 국어브레인 2건 중 하나다. 그 목록의 항목 본문에 자리가 적혀 있고 **행번호가
밀렸으니** 그대로 믿지 말고 다시 찾는다. 렌더러(`markUp`·`poemHtml`·구조도)가 아직
`naesin-ko/index.html` 안에 인라인이라, 꺼내려면 새 모듈 `naesin-ko/render.js` +
`render.test.cjs` 를 만들고 `build-dist.mjs` 의 국어 파일 목록과 SW 셸 목록에 등록해야 한다
(하우스 스타일: `'use strict'` + IIFE + `module.exports` 가드).

### ③ 루트·운영앱 문서·CI 묶음 (S~M, 12건)

저장소 전체 목록의 「전사 규칙·미결(루트)」 남은 4건과 「학원 운영 앱」 8건. 전부 문서·워크플로우
수정이라 앱 코드에 손대지 않고, 두세 개 PR 로 묶을 수 있다. 그 목록의 「그 뒤 바뀐 것」에
**실측으로 고친 숫자와 추가로 발견한 형제 하나**가 적혀 있으니 같이 읽는다.

## 4. 막힌 것 — 원장 결정이 선행

§1.5 「남은 것」과 같은 내용이다. 코덱스가 풀 수 없다.

| | 무엇을 정해야 하는가 | 안 정하면 |
|---|---|---|
| 1 | 금고는 **at rest 한정**이다 — 그것이 의도인가 | 금고를 다 만든 뒤 "이게 아니었다"가 될 수 있다 |
| 2 | **오버레이 2칸**을 금고로 보낼 것인가(6칸 ↔ 8칸) | 나중에 계약이 "원내 디스크에만"을 요구하면 처음부터 다시 한다 |
| 3 | 집·학원 PC 를 **동시에 켜 둘 시간대**가 실제로 있는가 | §1.5 ③의 '쓰기 1대 + 지연 복제'가 선택이 아니라 전제가 된다 |
| 4 | **운영 KV 기존 발문 청소** 승인 | 어제까지 쌓인 발문이 KV 에 남는다(야간 백업은 10일이면 밀려 나간다) |

그 밖에 금고 착수 전 남은 코드 작업 셋도 §1.5 「남은 것」에 있다 — 관리 웹(`/admin/*`)에도
Access, 학생 기기 청소 수단(팩 전환 시 이전 칸 비우기 + 「이 기기에서 지우기」), 국어 `state`
화이트리스트.

## 5. 작업 방식 — 이 줄기에서 지킨 것

루트 `CLAUDE.md` 규칙에 더해, 이 줄기에서 쓴 방식이다. 이어받을 때 같이 지키면 좋다.

- **테스트가 실제로 깨지는지 확인한다.** 새 검사를 넣은 뒤 **일부러 되돌려 빨간 것을 보고** 다시
  돌려놓는다. `naesin-ko/app.test.cjs` 8개와 `override.test.mjs` 의 몸통 상한 검사는 그렇게 확인했다.
- **손으로 눌러서는 못 만나는 결함은 코드 모양으로 못 박는다.** 배경 재시도가 공부 도중 팩을
  갈아 끼우는 결함은 몇 분 뒤에 일어나 손으로는 재현되지 않는다 — `app.test.cjs` 가 "팩은
  `applyPack` 한 곳에서만 끼운다"를 정적으로 검사한다.
- **운영 주소로 확인한다.** 배포 뒤 `https://wb-reading.whdudwns33.workers.dev` 에서
  ① 새 코드가 실제로 서는지 ② 인증 없이 아무것도 안 나가는지(`401`) ③ 형제 앱 8개가 멀쩡한지를
  본다. 토큰이 필요한 판정(배정된/안 배정된 학생)은 운영에서 밖에서 확인할 수 없으므로 로컬에
  같은 코드를 띄워 학생 둘로 밟는다.
- **자체 창작 데이터만 쓴다.** 검증에 쓴 것은 `naesin-ko/pack-sample.json` 복제본뿐이다
  (절대규칙 1).
