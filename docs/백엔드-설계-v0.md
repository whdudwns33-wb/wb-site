# 백엔드 설계 v0

> 그림검사 AI 해석 웹 · 서버/API/데이터/보안 설계
> 연결: 엔진 프롬프트 스펙 v0 · 프로토타입 출력 계약 · 법률·윤리 가이드 v0.
> **구현 착수 전 설계 초안.** 아동 민감정보를 다루므로 보안·데이터 거주지가 최우선 제약.

---

## 0. 설계 제약 (먼저 고정)

1. **아동 민감정보** → 정적 사이트만으로 불가, **서버 필수**. 이미지·개인정보를 클라이언트에만 두지 않음.
2. **데이터 거주지: 한국 리전** (DB·스토리지·로그). 검사 자료를 **일반 공개 AI(오픈 챗봇)에 업로드 금지** → Claude API를 데이터보존 최소(zero-retention/DPA) 조건으로 사용.
3. **전문가 확정 게이트**는 백엔드 상태머신으로 강제 — 승인 없이는 학부모 리포트 API가 데이터를 반환하지 않음.
4. **위기 라인**은 자동 해석과 분리된 우선 경로.
5. 기존 정적 사이트(`index.html`)·프로토타입(`apps/picture-test`)과 브랜드 유지, 앱 백엔드는 `/api/*`로 확장.

## 1. 아키텍처 개요

```
┌─ 브라우저 ──────────────────────────────────────────────┐
│  공개(학부모): 랜딩·업로드·리포트   전문가 콘솔   관리자 대시보드 │
└───────────┬───────────────────────┬──────────────┬──────┘
            │ HTTPS/JSON             │ (인증)        │ (인증)
┌───────────▼───────────────────────▼──────────────▼──────┐
│                    API 서버 (Node/TypeScript)            │
│  라우팅·인증(RBAC)·검증(zod)·상태머신·감사로그            │
└──┬─────────────┬────────────────┬───────────────┬───────┘
   │             │                │               │
┌──▼──┐   ┌──────▼──────┐   ┌─────▼─────┐   ┌─────▼───────┐
│ DB  │   │ 오브젝트     │   │ 작업 큐    │   │ Claude API  │
│(PG) │   │ 스토리지     │   │(파이프라인)│   │ (Vision/텍스트)│
│한국 │   │ 암호화·서명URL│  │ S0~S3 워커 │   │ zero-retention│
└─────┘   └─────────────┘   └───────────┘   └─────────────┘
                                    │
                          (승인 후) HubSpot 리드 · 상담 flow · 알림 후보
```

### 기술 스택 (권장)
| 계층 | 선택 | 이유 |
|------|------|------|
| API | **Node + TypeScript** (Fastify/Next API) | 프로토타입 JS·Claude SDK와 정합, 빠른 개발 |
| DB | **PostgreSQL** (한국 리전 관리형) | 관계형·트랜잭션·상태머신·감사로그 |
| 스토리지 | S3 호환 오브젝트 스토리지 (한국 리전, KMS 암호화) | 이미지 비공개·서명 URL |
| 큐 | 초기 **DB 기반 잡 테이블**(또는 Redis) | 파이프라인 비동기 처리, MVP는 단순하게 |
| AI | **Claude API** (Opus 5 초안 / Sonnet·Haiku 정형) | Vision + 텍스트, 프롬프트 캐싱(KB) |
| 인증 | 세션/JWT + RBAC(parent/expert/admin) | 역할별 접근 통제 |

> 대안: Python(FastAPI). 팀 역량에 맞춰 선택. 관리형 스택(Supabase 등) 사용 시에도 **한국 리전·민감정보 요건**을 반드시 확인.

## 2. 상태 머신 (제출 1건의 생명주기)

```
created ─► consent_pending ─► uploaded ─► processing
                                             │
              ┌──────────────────────────────┤
              ▼ (crisis=urgent)              ▼ (정상)
          escalated                       reviewing ──► confirmed ──► published
              │                                │            │
              └───────────── 전문가 검토 ───────┘        (학부모 열람)
  기타: rejected(반려) · expired(링크만료) · purged(파기)
```

- `processing`: S0→S1→S2→S3(초안·미리보기) 실행. 완료 시 `reviewing`.
- **`published` 상태에서만** 학부모 정식 리포트 API가 데이터 반환.
- 각 전이는 **감사로그** 기록. 되돌릴 수 없는 전이(파기)는 별도 승인.

## 3. 데이터 모델 (PostgreSQL 개략)

```sql
-- 아동(식별 최소화: 실명 대신 별명)
child(id, alias, birth_year, sex, context_note, guardian_contact_enc, created_at)

-- 제출
submission(id, child_id, test_type,               -- HTP/KFD/DAP/FREE
           status,                                 -- 상태머신 값
           image_key,                              -- 스토리지 키(비공개)
           meta_json, consent_id, created_at, purge_at)

-- 동의(버전·범위 분리)
consent(id, guardian_verified_bool, scope_json,    -- analysis/store/improve
        policy_version, signed_at, ip_hash)

-- S1 관찰
observation(id, submission_id, element, attributes_json, note,
            source,                                 -- ai/expert
            vision_confidence)

-- S2 가설 (콘솔이 직접 사용)
hypothesis(id, submission_id, element, observation, text,
           confidence,                             -- high/mid/low
           age_adjustment, caveats_json,
           status,                                 -- ai_suggested/accepted/edited/rejected
           edited_text, expert_note, needs_expert_check)

-- S3 해석
interpretation(id, submission_id, expert_id,
               summary_expert, parent_preview, summary_parent,
               confirmed_at)

-- 학부모 리포트(접근 제어)
parent_report(id, submission_id, share_token, expires_at, viewed_at, cta_clicked)

-- 위기 이벤트
crisis_event(id, submission_id, level, flags_json,
             handled_by, action_taken, created_at)

-- 사용자(전문가/관리자)
app_user(id, role, name, email, auth_ref, active)

-- 감사로그(불변)
audit_log(id, actor_id, action, target_type, target_id, meta_json, created_at)

-- 파이프라인 잡
job(id, submission_id, stage, status, attempts, error, run_at)
```

- 민감 필드(보호자 연락처 등) **컬럼 암호화**, 이미지는 스토리지에서 **KMS 암호화**.
- `purge_at` 도래 시 배치가 이미지·개인정보 **복구 불가 파기**.

## 4. API 설계 (핵심 엔드포인트)

### 공개(학부모)
| 메서드 · 경로 | 설명 |
|---|---|
| `POST /api/submissions` | 제출 생성(검사종류·아동메타·동의) → `submission_id`, 상태 `consent_pending` |
| `POST /api/submissions/:id/consent` | 동의 확정(만14세 보호자 인증 포함) → `uploaded` 준비 |
| `POST /api/submissions/:id/image` | 이미지 업로드(또는 presigned PUT 발급) → `processing` 트리거 |
| `GET /api/submissions/:id/preview` | 학부모 **참고용 미리보기**(순한 버전, 확정 전만) |
| `GET /api/reports/:token` | 학부모 정식 리포트 — **published 상태 + 토큰·생년 확인** 시에만 반환, 만료 체크 |

### 전문가(인증 필요, role=expert)
| 메서드 · 경로 | 설명 |
|---|---|
| `GET /api/console/queue` | 검수 대기열(`reviewing`, `escalated`) |
| `GET /api/console/submissions/:id` | 이미지 서명URL + observations + hypotheses 로드 |
| `PATCH /api/console/hypotheses/:hid` | 가설 **채택/수정/삭제** + 코멘트 |
| `POST /api/console/submissions/:id/confirm` | **확정 게이트** → parent_report 생성 잡 + `published` |
| `POST /api/console/submissions/:id/escalate` | 위기 처리·조치 기록 |

### 관리자(role=admin)
| 경로 | 설명 |
|---|---|
| `GET /api/admin/dashboard` | 업로드·해석·리드·소요시간 지표 |
| `GET /api/admin/consents`, `POST /api/admin/purge/:id` | 동의 관리·파기 |

> 응답 스키마는 엔진 스펙의 `hypotheses[]`와 동일 → **프로토타입 콘솔 UI 무변경**으로 실제 데이터 교체 가능.

## 5. 파이프라인 (비동기 워커)

```
image 업로드 완료
   └─ job(S0) 안전·품질  ─┬─ crisis=urgent → status=escalated, 전문가 알림, 중단
                          └─ ok → job(S1)
   job(S1) Vision 관찰추출  → observation[] 저장
   job(S2) KB 매핑+안전규칙 → hypothesis[] 저장 (연령보정·caveat·근거수준)
   job(S3a) 전문가 초안 + 학부모 미리보기 생성 → status=reviewing
--- 전문가 확정 ---
   job(S3c) 학부모 정식 리포트 생성(accepted만) → status=published
```

- **Claude 호출 규칙**: S1은 tool-use로 **구조화 출력 강제**, S3은 상위 모델. KB·시스템 프롬프트는 **프롬프트 캐싱**으로 비용 절감. 타임아웃·재시도(지수 백오프), 실패 시 `job.error` 기록 후 전문가 알림.
- **가드레일 필터**(S2/S3 후처리): 금지어("진단/장애/확진") 차단, 근거수준 미표기·연령보정 누락 시 발행 차단.

## 6. 보안 · 개인정보 (구현 체크리스트)

- [ ] **전송/저장 암호화**: TLS, 스토리지 KMS, 민감 컬럼 암호화.
- [ ] **이미지 접근**: 비공개 버킷 + **단기 만료 서명 URL**, 직접 URL 노출 금지.
- [ ] **RBAC**: parent(자기 제출만)·expert·admin. 원자료 접근은 전문가·필수 인력 최소화.
- [ ] **학부모 리포트 링크**: 토큰 + 2차 확인(생년) + 만료. 아동 이름·생년·결과를 URL/템플릿 변수에 넣지 않음.
- [ ] **동의 분리·버전관리**: analysis/store/improve 별도, 정책 버전 기록. 만14세 미만 보호자 인증. 거부·5일 미확인 시 파기.
- [ ] **보존·파기**: `purge_at` 배치로 자동 파기(백업 포함), 파기 이력 감사로그.
- [ ] **감사로그 불변**: 확정·발행·열람·파기·접근 기록.
- [ ] **AI 데이터 처리**: Claude API zero-retention/DPA, 검사자료를 공개 챗봇에 업로드 금지.
- [ ] **위기 대응**: escalated 시 자동 노출 차단 + 담당자 알림 + 112/119 프로토콜(사람이 신고 판단, 신고의무 인지).
- [ ] **데이터 거주지**: 전 구성요소 한국 리전.

## 7. WB 기존 시스템 연동 (승인 기반)

- `published` + 동의 시 → **HubSpot 리드 후보 생성**(자동 등록이 아니라 승인 후), 채널·유입 태깅.
- 확정 해석 → **상담 자료 후보**로 consult flow 연계.
- 알림(카톡/알림톡)은 **후보 생성 → 승인 후 발송**(WB notify 원칙). 아동 이름·생년·결과는 템플릿 변수 금지 → privacy-guard 통과.

## 8. 단계별 구현

**MVP(1차)** — HTP만, 단일 API 서비스 + DB 잡 큐(비동기 최소), 전문가 콘솔 API, 수동 발행.
- 목표: 업로드→S1~S3→콘솔 검수→확정→학부모 PDF. 보안·동의·감사로그·위기 라인 포함.

**2차** — 공개 업로드 + 미리보기 + 리드 연동, KFD·DAP 추가, 큐/워커 분리.

**3차** — 자유화·PITR, 관리자 대시보드·분석, 피드백 루프(전문가 액션 로그로 KB·프롬프트 개선), 부하 대응.

## 9. 개략 비용·성능 메모
- 건당 Claude 호출 ≈ S1(vision) + S3a + (확정 후)S3c → 3~4회. KB 프롬프트 캐싱으로 입력 토큰 절감.
- 초기 트래픽 낮음 → 단일 인스턴스 + 관리형 DB로 충분. 스토리지·전송이 주 비용.
