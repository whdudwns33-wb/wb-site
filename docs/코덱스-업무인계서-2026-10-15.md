### 2-4. 원장 PC — WB1(운영)·WB2(코드 작업)

정확한 폴더 경로·역할은 **10-14 문서 §2·§3** 이 정본이다. 그 위에 더해 둘 것:

- **WB1 국어 관리**: `reading-server/start-admin.ps1` → `127.0.0.1:8891`, 사용자 로그온 예약 작업. 자료 `db.json`(+`backups\`)에는 **관리 화면에서 올린
  국어 팩 본문**이 들어 있다. 기동 자격증명은 그 Windows 사용자에게 묶인 DPAPI 파일이다(**복사·커밋·출력 금지**, 다른 PC·SYSTEM 에서는 풀리지 않는다).
  로그는 같은 폴더 `logs\` 에 회전 없이 쌓인다.
- **운영 checkout 은 서버가 그 자리 코드를 바로 쓴다**: 정적 화면·JS 는 요청마다 그 폴더에서 읽으므로 **즉시**, 서버 코드는 다음 재시작 때 운영에 들어간다.
  거기서 브랜치를 바꾸거나 파일을 고치면 그 순간 화면과 서버가 어긋난다 — **손대지 않는다.** 갱신은 §7 절차로, 원장 확인 뒤에만.
- **WB1 영어 원내 서버**(미병합 브랜치 문서 기준)의 자료 폴더에는 구매 원본·영어 학생 기록이 있다 — 열지 않는다.
  **WB1 에서 8890·8891 로 아무것도 띄우지 않는다.**
- **WB1 의 운영 자료는 열지도 읽지도 않는다.** 코덱스도 외부 AI 다 — 읽은 내용은 모델 제공자에게 간다. 자료 폴더·자격증명 파일·운영 checkout 은
  "바꾸지 않는다"가 아니라 **"열지 않는다"**.
- **WB2**: 코드 작업 전용 clone. 운영 서버를 옮기거나 WB1 데이터 폴더에 연결하지 않는다.
- **WB1 관리 `db.json` 과 학생 워커 KV 는 별개다. 자동 동기화가 없다.** 학생에게 나갈 팩은 운영 워커의 `/admin` 에 올린다.

### 3-1. 코덱스를 어디서·어떻게 돌리나

| 어디 | 무엇에 쓰나 | 지킬 것 |
|---|---|---|

WB1 의 읽기 확인 예: `Get-ScheduledTask -TaskPath '\WB 앱\' | Select-Object TaskName,State` · `Invoke-WebRequest http://127.0.0.1:8891/api/health -UseBasicParsing`.

**설치·로그인**(공식 문서는 2026-10 현재 `https://learn.chatgpt.com/docs/` — `developers.openai.com/codex` 에서 옮겨졌다):

```powershell
powershell -ExecutionPolicy ByPass -c "irm https://chatgpt.com/codex/install.ps1 | iex"   # 설치·업데이트 (또는 npm install -g @openai/codex)
codex login            # 브라우저에서 ChatGPT 로그인. 확인: codex login status
```

- SSH 로만 붙은 PC 에서는 브라우저 콜백을 못 받는다 — `codex login --device-auth`(ChatGPT 보안 설정에서 기기 코드 로그인을 먼저 켠다) 또는
  `ssh -L 1455:localhost:1455 <별칭>` 뒤 `codex login`. **`~/.codex/auth.json` 을 다른 PC 에서 복사하지 않는다**(비밀번호처럼 다룬다).
- 저장소 **루트**에서 `codex` 를 띄운다. **Node 22.13 이상**(desk·crm·sync 테스트가 플래그 없는 `node:sqlite` 를 쓴다 — `node -v` 로 확인). npm 의존성은 없다.

**AGENTS.md 크기 상한 — 앱 폴더 AGENTS.md 는 자동으로 다 읽히지 않는다**

- 코덱스는 프로젝트 AGENTS.md 들을 **합쳐서 32 KiB**(`project_doc_max_bytes` 기본값)까지만 읽는다. 루트 AGENTS.md 가 약 27~28 KB 라
  `codex --cd haru` 처럼 앱 폴더에서 띄우면 그 앱 AGENTS.md 는 **앞 4~5 KB 만** 붙어 「고칠 때 깨지는 자리」 절이 잘린다(공식 config 문서의 "파일마다"라는
  표현과 달리 실제로는 합산이다 — codex-rs `agents_md.rs`, 2026-10 확인).
- 그래서 **루트에서 띄우고, 고칠 앱의 AGENTS.md 는 직접 열어 읽는다.** 또는 각 PC 의 `~/.codex/config.toml` 에 `project_doc_max_bytes = 65536`.
- 처음 띄울 때 "이 폴더를 신뢰" 질문에서 **신뢰**를 고른다. `trust_level = "untrusted"` 면 프로젝트 AGENTS.md 를 하나도 읽지 않는다(같은 소스 기준).
- `AGENTS.override.md` 를 만들지 않는다 — 그 폴더의 AGENTS.md 를 통째로 대체한다. `scripts/docs-sync.test.mjs` 가 저장소 어디에든 있으면 빨갛게 한다.
- 루트 AGENTS.md(=CLAUDE.md)에 크게 더하지 않는다 — 넘치면 맨 끝 절부터 잘린다. 고친 뒤 `cp CLAUDE.md AGENTS.md`.

**Windows 샌드박스에서 알아 둘 것**

- 기본(Auto)은 작업 폴더 쓰기 + 승인 요청이다. `.git` 은 읽기 전용이라 commit·branch·push 마다 승인이 뜨는 것이 정상이다.
  fetch·push·gh·curl·npx 처럼 바깥 네트워크가 필요한 명령도 승인이 필요할 수 있다 — 막히면 결과를 추정하지 말고 승인을 요청한다.
  **`--yolo`·`danger-full-access` 는 원장 PC 에서 쓰지 않는다.**
- 로컬 서버를 실제로 띄우는 테스트: main 기준 5개(`reading-server` 의 admin-only·portal-family·sec-headers·store·student-lifecycle) + Windows 에서만
  `start-admin.test.mjs`(PowerShell·DPAPI 시험 자격증명). PR #447 은 셋(host-bind·tunnel/run-server·tunnel/app-copy)을 더한다. 일부는 `0.0.0.0` 에 붙어 처음 실행 때 Windows 방화벽
  창이 뜰 수 있다 — **허용하지 말고 닫는다**(테스트는 127.0.0.1 로 붙는다). 샌드박스 안에서 실패하면 WB2 에서만 샌드박스 밖 실행을 승인해 다시 돈다.
  실패를 무시해 초록으로 만들지 않는다.
- MXC 샌드박스에서는 명령이 끝나면 띄운 자식 프로세스도 멈춘다 — 미리보기 서버는 **원장이 별도 창에서** 띄운다(코덱스는 명령만 알려 준다).
- 코덱스는 PowerShell 로 명령을 친다. 루트 AGENTS.md 의 `PORT=… node …`·`for f in …; do` 줄은 bash 다 — `node scripts/check.mjs --only <앱>` 이나
  `$env:HOST='127.0.0.1'; $env:PORT='18898'; node …` 로 바꿔 쓴다.

**Codex 클라우드를 쓸 때**: ChatGPT 로그인만 된다(이메일·비밀번호 계정은 MFA 필수). 인터넷은 끄거나 "Package managers" 정도로만(PR 검사의 워커 dry-run 이
`registry.npmjs.org` 만 쓴다). **이 저장소의 키를 클라우드 환경 변수·시크릿에 넣지 않는다** — 키는 GitHub 저장소 시크릿 → 워커 시크릿으로만 흐른다(루트 규칙 5).

### 3-2. GitHub

- 저장소 `https://github.com/whdudwns33-wb/wb-site` (public). `gh auth status` 가 미로그인이면 **원장 계정으로**
  `gh auth login --hostname github.com --git-protocol https --web`. 다른 PC 의 토큰을 복사하지 않는다. 공개 저장소라 clone·검사는 로그인 없이 된다.
- **gh 로그인은 원장(저장소 관리자) 계정이다.** 코덱스는 `gh secret`·`gh variable`·`gh workflow run`·저장소 설정 변경·`gh api` 쓰기를 하지 않는다.
- 흐름: 작업 브랜치(`codex/<주제>-<YYYYMMDD>`) → `node scripts/check.mjs` → PR → `checks.yml` 초록 → 스쿼시 병합(제목에 `(#번호)`).
- main 직접 푸시 금지는 스스로 지킨다(브랜치 보호 설정은 §9). **병합 주체는 원장이 정한다 — 정하기 전에는 PR 주소만 알리고 병합하지 않는다.**
- 로컬의 원격 브랜치 목록은 금방 낡는다 — 판단 전에 `git fetch --prune`.

### 3-4. Cloudflare — 대시보드와 wrangler

- 코덱스는 대시보드에 들어가지 않는다. 원장이 하는 일: Zero Trust·Access 정책, 터널 경로, 워커 시크릿 확인, D1 복구점, API 토큰 교체.
  코덱스는 무엇을 누를지 문서로 안내하고 결과(화면 문구·상태 코드)만 받는다.
- **`wrangler login` 자격증명**은 복사·출력하지 않는다(`wb-sync` 수동 배포가 이것으로 돈다). 코덱스는 운영 계정으로
  `wrangler deploy`·`d1 execute --remote`·`secret put/delete/list`·`kv`·`r2` 를 치지 않는다 — 명령을 써 주고 원장이 친다.

### 3-5. 원장 PC 끼리 · 포트

- WB2 는 SSH 별칭으로 들어간다(별칭·호스트는 원장 메모 — `ssh -L 18898:127.0.0.1:18898 <별칭>` 으로 미리보기를 다른 PC 브라우저에서 본다).
- 실제 데이터 없는 로컬 미리보기는 `127.0.0.1:18898` + 임시 `DATA_DIR` + 시험용 PIN(운영 값 아님) — 명령은 10-14 §4.
- 포트: `reading-server/server.mjs` 기본값은 **8890·모든 주소**(관리 전용이면 127.0.0.1)이고 루트 AGENTS.md 예시도 8890 이다. `desk/dev-server.mjs` 기본은 8891,
  `crm/dev-server.mjs` 는 8892. WB1 은 8890·8891 을 운영이 쓴다 — **원장 PC 에서는 늘 `$env:HOST='127.0.0.1'; $env:PORT='18898'` 처럼 먼저 준다.**

### 3-6. 공개 문서에 없는 값은 어디서

PC 별 폴더, SSH 별칭·실제 호스트, 관리 호스트 주소, 드라이브 파일 위치, 허용 이메일은 **원장 비공개 메모**(원장 드라이브, 원내 계정만 — 이름·위치는 원장이 알려 준다)에 둔다.
메모가 없거나 낡았으면 세션 시작 때 원장에게 묻는다: ① 이 PC 가 WB1/WB2 중 무엇이고 작업 폴더는 어디인가 ② 다른 PC 접속 방법 ③ 필요한 드라이브 파일 위치
④ gh·wrangler 로그인 상태. 답 가운데 공개해도 되는 것(예/아니오·커밋 번호)만 이 문서 §11 에 적고, 나머지는 그 메모에 적는다.

## 5. 배포와 확인

| 무엇 | 트리거 | 확인 | 주의 |
|---|---|---|---|
| PR 검사 `checks.yml` | PR · main 이외 브랜치 푸시 | 전체 검사 + 워커 세 개 번들 dry-run(시크릿 안 씀) | `wb-sync`·`wb-student` 번들은 검사하지 않는다 |
| `wb-reading` `deploy-reading.yml` | main 푸시 중 `reading/`·`reading-server/`·`vocab/`·`naesin/`·`haru/`·`naesin-ko/`·`hanja/`·`chunk/`·`letter/`·`shared/` 변경 | Actions 실행 기록 | 손으로 적은 테스트 목록이라 새 테스트가 빠질 수 있다 · **토큰이 없으면 경고만 내고 초록으로 끝난다** · `vocab-age/` 만 바꾸면 워커 사본은 안 바뀐다 |
| `wb-desk`·`wb-crm` | main 푸시 중 `desk/**`(+`shared/external-links.js`)·`crm/**`(md 제외) | 워크플로우 끝의 `/api/health` | D1 마이그레이션을 매번 돌린다 |
| GitHub Pages | **main 의 모든 푸시** | Actions `pages-build-deployment` | task·consult 화면이 바로 바뀐다 |
| `wb-sync`·`wb-student` | **수동** — 원장 PC, `sync/README.md`·`sync/PORTAL_RELEASE_RUNBOOK.md` | `/health` | 수동 도구는 wrangler 버전을 고정하지 않는다(워크플로우는 `wrangler@4.129.0`) |
| WB1 국어 관리 서버 | main 병합과 **무관** | 관리 화면 | §7 절차, 원장 확인 뒤 |

- **`wb-sync` 를 바꾸는 PR**: checks 초록 → PR 브랜치가 최신 main 을 품는지 확인(`git fetch origin` 뒤 `git merge-base --is-ancestor origin/main HEAD`,
  아니면 main 을 합쳐 다시 초록) → 원장 PC 에서 **그 PR 의 최종 커밋**으로 마이그레이션 → `wb-sync`(필요하면 `wb-student`) 배포 → `/health` →
  곧바로 스쿼시 병합(Pages). 그 사이 다른 sync PR 을 병합·배포하지 않는다(옛 브랜치에서 배포하면 운영 워커가 되돌아간다). 순서가
  "마이그레이션 → Worker → Pages" 라 이 경우만 병합 전 배포를 허용하고, 실행은 원장이 한다.
- **수동 실행(workflow_dispatch)에는 main 가드가 없다** — 배포·시크릿 워크플로우 모두. 작업 브랜치를 고르면 병합 안 된 YAML·코드가 운영 시크릿과 함께 돈다
  (2026-10-13 에 작업 브랜치에서 시크릿 워크플로우가 돈 선례). 수동 실행은 main 에서, 원장 확인 뒤에만.
- 배포 워크플로우는 **동시 실행을 막지 않는다**. 병합은 앞 배포가 끝난 뒤에 한다. 겹쳤으면 마지막 성공 실행의 커밋과 main HEAD 가 같은지 본다.
- 워커 롤백 문서는 없다. 코드 문제는 해당 스쿼시 커밋을 되돌리는 PR → 초록 → 병합이 기본이다(대시보드 이전 버전으로 되돌리기는 원장이).
- 검사: `node scripts/check.mjs`(병렬). 저장 완료를 확인하는 검사가 병렬에서 가끔 실패한다 — 실패 출력을 남기고 `--serial` 로 다시 돈다.
