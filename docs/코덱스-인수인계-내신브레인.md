## 이 저장소에서 실제로 났던 사고 넷 — 모든 과제에 적용된다

착수 전에 반드시 읽는다. 전부 2026-10-11~12 에 실제로 겪은 것이다.

### ① `server.mjs` 학생 저장 핸들러의 구조분해 함정

`reading-server/server.mjs` 의 `POST /api/admin/students` 는 본문을 **구조분해**한 뒤 `...prev` 와 섞는다:

```js
const { code, name, grade, cls, level } = await readBody(req);
db.students[c] = { ...prev, code: c, name, grade: grade || '', ... };
```

`...prev` 는 **구조분해되지 않은 키만** 지켜 준다. 구조분해된 키(`name`·`grade`·`cls`·`level`)는
다른 화면이 그 필드를 안 보내고 저장하면 **조용히 지워진다**. 그래서 학생 레코드에 새 칸을
더하지 않고 앱 전용 레코드(`naesin:books` 같은 것)를 따로 둔다.

### ② 테스트가 버그를 고정해 둔 경우가 있다

`naesin/coverage.js` 의 만료 해석이 서버 `resolveExam` 과 달랐는데, **테스트 둘이 그 틀린
동작을 고정**하고 있었다. 테스트가 초록이라고 맞다는 뜻이 아니다 — 계약을 서버 코드에서
직접 확인하고, 어긋나면 **테스트도 같이 고친다**.

### ③ `worker.mjs` 와 `server.mjs` 중 한쪽만 고치면 로컬에서만 되는 기능이 된다

저장소 어댑터가 둘이다(워커 = KV, 로컬 = `db.json`). 퇴원 처리에서 `naesin:books` 를
`worker.mjs` 에만 넣고 `server.mjs` 를 빠뜨리면 로컬에서 유령 학생이 남는다. **양쪽을 같이 고친다.**

### ④ 저장소 테스트는 워커를 번들하지 않는다

`removed += 1` 한 줄이 `worker.mjs` 번들을 깨뜨렸는데 **테스트 299/299 는 전부 통과**했다.
`checks.yml` 의 dry-run 이 잡았다. `worker.mjs` 를 고치면 반드시:

```
cd reading-server && npx --yes wrangler@4.129.0 deploy --dry-run --outdir=/tmp/wb-bundle
```

`Total Upload: ...` 가 나와야 통과다.

### 쓸 API
`readiness.js` 가 내보내는 것:
- `readiness(summary, {dday, weights})` → `{score, weakest, axes, need, shortfall}`
- `classReadiness(rows, opts)` → `{n, threshold, rate, reached, average, median, shortfall, students}`
- `pilotVerdict(cls, startedDaysBefore)` → `{eligible, rate, threshold, passed}`

입력 `summary` 는 `engine.rangeSummary` 의 반환값 그대로다. 관리 웹은 이미 학생별
`summary` 를 `/api/naesin/admin/overview` 로 받고 있다(`naesin-admin.html:1025` 부근 `OV`).

### 지켜야 할 것
- **`rate` 가 머리 숫자다** — 임계(70%) 이상 **학생 비율**. `average` 도 같이 보여 주되
  판정 숫자로 쓰지 않는다. 이유는 `readiness.js` 머리말에 적혀 있다(평균은 잘하는
  두세 명이 반쪽짜리 파일럿을 통과시킨다).
- **`absent: true` 인 축을 0% 로 그리지 않는다.** 재료가 없어 빠진 축이다. 0% 로 그리면
  거짓이고, 원장이 이 카드를 안 믿게 된다.
- **`shortfall` 은 추정이 아니라 확정된 미달이다** — 그렇게 보이게 그린다(붉게).
- 학생 기기가 올린 값을 그리는 곳이라 `esc()`·`num()` 을 반드시 통과시킨다(절대 규칙 4).

### 테스트
`naesin/admin-coverage.test.cjs` 가 전례다 — **화면 원본에서 로직을 떼어 와** 돌린다
(테스트에 복사해 두면 화면이 바뀌어도 통과한다). 고정할 것:
`absent` 축을 0으로 그리지 않는지 · `rate` 를 머리 숫자로 쓰는지 · 반 필터가 집계에 걸리는지.

### 하면 안 되는 것
**재사용 의향 1문항을 만들지 않는다.** 기획서의 판정 기준 두 번째 항목(「다음 시험에도
쓰겠다」)인데, **학생·가정에 묻는 문구**라 CLAUDE.md 규칙 7 로 원장 승인이 필요하다.

## 과제 2 — 시험 배정을 반별로 (`scope=cls`)

**크기** M · **막힌 것** 없음

### 왜
시험 `scope` 가 `'default'`(반 공통) 아니면 **학생 코드**뿐이다. 반 단위가 없다.
학원 한 반에 **학교가 섞이는** 현실에서 실제로 터지는 자리고, #440 의 커버리지 카드가
드러낸 문제와 같은 결이다.

### 건드릴 자리
| 자리 | 무엇 |
|---|---|
| `reading-server/naesin-api.mjs:257` | `resolveExam(store, code, now)` — **폴백 순서의 정본** |
| `reading-server/naesin-api.mjs:651` | `scope !== 'default' && !CODE_RE.test(scope)` → 400. **여기가 반을 막는 자리** |
| `reading-server/naesin-api.mjs:21` | `CODE_RE = /^[A-Za-z0-9-]{3,20}$/` |
| `reading-server/naesin-api.mjs:276` · `:679` | `examRow` — `scope === 'default'` 분기 |
| `naesin/coverage.js` 의 `examFor` | **서버와 같은 해석이어야 한다**(사고 ② 가 난 자리) |
| `reading-server/public/naesin-admin.html` 의 `scopeLabel`·시험 등록 폼 | 반을 고를 수 있게 |
| `reading-server/server.mjs`·`worker.mjs` 의 `naesinStore` | `getExam`/`putExam` 키 공간(사고 ③) |

### 지켜야 할 계약 — 어기면 무엇이 깨지나
`resolveExam` 의 현재 해석을 그대로 옮긴다:

```js
const live = (rec) => isObj(rec) && !(typeof rec.examDate === 'string' && rec.examDate < today);
if (CODE_RE.test(code)) { const mine = await store.getExam(code); if (live(mine)) return {exam: mine, scope:'student'}; }
const def = await store.getExam('default');
if (isObj(def)) return { exam: def, scope: 'default' };   // ← 반 공통은 만료여도 그대로 준다
```

**만료를 개별 배정에만 걸고 반 공통은 지난 날짜여도 준다**(학생 앱이 '시험 종료 · 자율
학습'으로 보여 준다). 반을 끼우면 폴백이 **학생 → 반 → 반 공통**이 되는데, 만료 해석을
반에 어떻게 걸지 정하고 **`coverage.js` 의 `examFor` 와 `GET /api/naesin/pack` 의 서빙
제한까지 같은 해석으로** 맞춘다. 어긋나면 **학생 화면에는 범위로 보이는데 서버가 막는다.**

### 함정
- 학생의 반(`cls`)은 **자유 입력**이다(`server.mjs` 의 `summarize` 가 `stu.cls` 를 그대로
  통과시킨다). scope 키로 쓰려면 정규화가 필요하고, `'default'` 와 학생 코드 꼴
  (`CODE_RE`)과 **충돌하지 않는 접두사**를 써야 한다(예: `cls:A반`).
- 기존 배정이 깨지지 않는지 본다 — `listExamScopes` 가 키를 접두로 훑는다.
- 래핑 계약(절대 규칙 4): `/exam` → `{exam, scope}`. **`scope` 값이 늘어나면 클라이언트와
  같이 맞춘다** — 학생 앱이 `scope` 로 분기하는 곳이 있는지 확인한다.

1. 고치기 전에 이 문서 + `naesin/README.md` 를 읽는다.
2. 고친 뒤 **`node scripts/check.mjs`** — 초록이 아니면 PR 을 올리지 않는다.
3. **새 로직에는 테스트를 같이 만든다**(`.test.cjs`/`.test.mjs`). `check.mjs` 가 저절로 찾는다.
4. **main 에 직접 밀지 않는다.** main 푸시 = 배포. 작업 브랜치 → PR → `checks.yml` 초록 → 스쿼시 머지.
5. 시크릿·개인정보는 저장소에 두지 않는다. **테스트 픽스처는 자체 창작만**
   (실제 학교명·실명을 쓰지 않는다 — 두 PR 에서 실제로 치웠다).
6. `CLAUDE.md` 와 `AGENTS.md` 는 같은 파일이어야 한다 → `cp CLAUDE.md AGENTS.md`.
7. 사람 확인: 운영 데이터 삭제 · 시크릿 교체 · **가정에 나가는 문구·링크** · 라이선스 자료.

## 자주 쓰는 명령

```
node scripts/check.mjs                      # 저장소 전체 (1분 안쪽)
node scripts/check.mjs --only naesin        # 내신만 (25/25)
node naesin/readiness.test.cjs              # 준비도 (15건)
node naesin/coverage.test.cjs               # 커버리지
node naesin/pack-validate.mjs <팩 디렉터리>  # 팩 검증 — 오류 0이어야 배포
cd reading-server && npx --yes wrangler@4.129.0 deploy --dry-run --outdir=/tmp/wb-bundle
```

## 추천 순서

**과제 1 → 2 → 3 → 4**. 5번은 정의부터.

1번이 먼저인 이유: 파일럿이 Phase 2 전체의 관문인데 **지금 판정할 자가 없다.** 계측기는
이미 들어갔으니 화면 배선만 하면 라이선스 회신이 오는 순간 파일럿을 돌릴 수 있다.
그리고 1번은 **라이선스에 묶이지 않는다** — 팩 콘텐츠를 건드리지 않는다.
