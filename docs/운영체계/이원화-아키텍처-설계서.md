# WB 운영 시스템 이원화 아키텍처 설계서

- 버전: v1.1 (2026-08-11)
- 관리 주체: 이 문서의 변경·해석·중재는 wb-site 저장소(Claude 세션)에서 관리한다.
- 적용 대상: 아카플로우(SaaS) · acaflow-mini(원내 관제) · WB 업무지시서 앱(현장 실행) · 컨설팅 플래너 앱

## 0. 한 줄 원칙

> **"학생이 누구인가"의 변경은 아카플로우에서만, "학생에게 무엇을 했는가"의 기록은 업무지시서 앱에서만.**

이 경계 하나로 두 시스템은 영원히 겹치지 않는다. 아래 전부는 이 원칙의 구체화다.

## 1. 시스템별 역할 정의

| 시스템 | 역할 | 데이터 성격 | 접근 환경 | 소유 데이터(정본) |
|---|---|---|---|---|
| **아카플로우 (SaaS)** | 원천 대장 | 실제 개인정보 포함 | 웹 (계약 계정) | 학생 등록·퇴원, 반 배정, 수납, 연락처 |
| **acaflow-mini** | 원내 관제탑 | 아카플로우의 읽기 사본 + 화면 | 원내 PC (로컬 Flask) | 시간표 뷰, 충돌 검사 결과, 권한별 조회 설정 |
| **업무지시서 앱** | 현장 실행 | 공개 정적 코드 + 인증된 비공개 운영 데이터 | 모바일·PC, 개인 링크 | 지시·체크, 출퇴근, 수업 출결, 피드백, 연락 기록, 위험 경보, private roster, 교재 DB |
| **컨설팅 플래너 앱** | 학생 자기관리 | 이름·플래너 내용만 | 모바일, 학생 개인 링크 | 일·주·월 플래너, 월간 목표 |

보조 시스템:
- **B 파이프라인** (`_generation_db`, DOCX 생성): 아카플로우 CSV를 읽는 또 하나의 소비자. 업무지시서 앱과 산출물이 겹치는 부분(강사별 지시서)은 장기적으로 앱 쪽으로 수렴을 검토하되, 당장은 병행 허용.
- **자체 등하원 프로그램**: 등하원 출결의 정본. 앱의 수업 출결(출석/지각/결석)은 "수업 중 기록"으로 목적이 다르며 서로 대체하지 않는다.

## 3. 주간 데이터 다리 (Bridge) 사양

### 3.1 흐름 (단방향 고정)

```
[매주 월 06:30] 아카플로우 → WB_AcaFlow_Weekly_Sync → _generation_db/master/*.csv
        ↓ (추출 스텝 — 신설)
   wb_roster_extract.csv  (검증된 화이트리스트 필드만)
        ↓ (전달: Claude 채팅 또는 Drive)
   비공개 변환기가 private roster와 대조 → 변경 제안 → 원장 승인
        ↓
   D1 교체·read-back 검증 → 앱 원생 탭·연락 카드·경보가 최신 명단으로 동작
```

**역방향 금지**: 앱의 어떤 기록도 아카플로우·mini로 자동 반입하지 않는다.

### 3.2 추출 파일 계약 (mini/파이프라인 쪽 구현 사양)

- 파일명: `wb_roster_extract.csv` (UTF-8, 헤더 필수)
- 컬럼 (아래 필드만 — 화이트리스트 방식, 그 외 컬럼은 다리에서 폐기):

| 컬럼 | 필수 | 예 | 비고 |
|---|---|---|---|
| name | ✔ | 예시학생 | 아카플로우 표기가 정본 |
| external_student_no | 조건부 | A12345 | 실제 Excel에 포함된 것이 확인될 때만 비공개 ID 매핑에 사용. 앱 문서에는 저장하지 않음 |
| grade | ✔ | 중1 | 표시·검토용. 학생 식별의 단독 키로 사용하지 않음 |
| teacher | ✔ | 최인찬 또는 김동현·정다원 | 겸임은 가운뎃점 구분 |
| subject | ✔ | 국어 | |
| status | 권장 | 재원/퇴원/휴원 | 없으면 "명단에 있음=재원"으로 간주 |
| changed | 권장 | 2026-08-15 | 상태 변경일 (퇴원월 판정용) |

- **넣지 말 것**: 전화번호, 생년월일, 학교명, 주소, 수납 정보, 보호자 정보. (다리 코드에서도 방어적으로 드롭한다.)

### 3.3 대조·반영 규칙

1. **매칭 키**: 기존 WB stable `studentId`를 유지하고, 아카플로우 학생번호가 추출되면 Git 제외 비공개 매핑으로 연결한다. 이름·학년은 자동 병합의 최종 키로 쓰지 않는다.
2. **표기 정본**: 화면 표기는 아카플로우를 따른다. 이름 정정·학년 승급에도 같은 `studentId`를 유지한다. 동명이인·ID 충돌은 자동 처리 금지 → 대표 확인.
3. **신규**: extract에 있고 roster에 없음 → 신규 후보로 제시하고, 담당·과목·첫 등원일을 확인한 뒤 원장 승인으로 `start = 당월`을 반영한다.
4. **퇴원**: extract에서 사라졌거나 status=퇴원 → **자동 반영 금지.** 실적표의 퇴원은 반드시 사유와 함께 기록하는 것이 원칙이므로, "퇴원 후보"로 대표에게 보고하고 사유를 받아 `end`·`reason`을 채운다.
5. **담당 변경**: 변경 미리보기에 표시하고 원장 승인 후 반영한다 (실적표의 "내 학생" 집계가 바뀌므로).
6. 학생 원문은 Git에 커밋하지 않는다. 반영은 비공개 importer의 dry-run·승인·D1 replace·read-back 검증으로 진행하고 비식별 건수만 감사 로그에 남긴다.

### 3.4 장애·예외 시나리오

| 상황 | 동작 |
|---|---|
| 월요일 동기화 실패 (CSV 미생성) | 다리 스킵. roster는 전주 상태 유지 — 앱은 정상 동작 (다리는 없어도 되는 부가 경로) |
| extract 컬럼 누락·형식 오류 | 반영하지 않고 오류 보고. 부분 반영 금지 (반쪽 명단 방지) |
| 대량 변경 (재원생의 20% 초과 변동) | 자동 반영 중단 → 대표 확인 (동기화 오류 가능성) |
| 외부 학생번호 누락 | 이름·학년만으로 자동 병합하지 않음 → 대표가 기존 학생인지 신규 후보인지 확인하고 신규 후보는 승인 후 생성 |
| 동명이인·복수 매칭·ID 매핑 충돌 | 자동 병합·신규 생성 금지 → 기존 WB `studentId`를 대표가 확인 |

## 4. 개인정보 경계 (하드 제약)

- 업무지시서·컨설팅 앱의 정적 코드는 **공개 GitHub Pages 오리진**이다. 학생 데이터는 정적 JSON에 두지 않고 인증된 Worker/D1에서 담당 범위만 내려준다.
- 금지: 전화번호, 주소, 생년월일, 학교명, 성적 수치, 검사 결과·지능지수·진단 표현, 가정사, 건강 정보.
- 스터디포스 구독생 관련은 앱에 `SF-0NN` 코드만.
- 이 경계 때문에 "완전 통합"은 설계상 불가하며, 이원화는 임시 상태가 아니라 **의도된 최종 구조**다.

## 6. 변경 관리

- 이 문서와 `직원-가이드북.md`, `mini-개선-참고.md`가 기준 문서다. 세 문서의 개정은 wb-site 저장소 PR로만 한다.
- mini 쪽 설계 변경 중 **다리 계약(3.2절)에 닿는 변경**은 반드시 이 문서 개정과 함께 진행한다. 그 외 mini 내부 개선은 자유.
- 분쟁 시(어디에 기록하지? 어느 표기가 맞지?) 판정 기준: 0절 한 줄 원칙 → 2절 매트릭스 순.
