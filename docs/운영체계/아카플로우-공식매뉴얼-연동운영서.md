# 아카플로우 공식 매뉴얼 요약과 WB 연동 운영서

- 버전: v1.0 (2026-08-15)
- 목표: 공개 API가 없어도 아카플로우와 WB 앱 사이의 반복 입력을 줄이고, 학생·보호자 정보가 섞이거나 중복되지 않게 운영한다.
- 공식 매뉴얼 시작점: <https://docs.acaflow.co.kr/>

## 1. 가장 중요한 결론

아카플로우 전체를 WB로 복제하지 않는다. 두 시스템의 정본을 나누고 필요한 값만 옮긴다.

| 정보 | 정본 | 다른 시스템으로 옮기는 방법 |
|---|---|---|
| 학생번호·이름·학년·재원상태·반·보호자 연락처 | 아카플로우 | 명부 `.xls`/CSV 가져오기 또는 로그인된 Chrome 연결 |
| 수납·청구·결제 | 아카플로우 | WB에는 상태 요약만 필요할 때 읽기 후보로 표시 |
| 수업 지시·출결·메모·피드백 | WB | 아카플로우에는 필요한 요약만 사람이 확인 후 입력 |
| 보강·회차제 | WB | 보호자 안내는 WB의 별도 동의와 승인 템플릿으로 발송 |
| 교재 주문·출고 | WB | 아카플로우 학생 정체성과 연결하되 주문 원장은 WB |
| 차량 노선·탑승·하차 | WB | 연락처는 동의된 오늘 본인 노선 기사에게만 제한 제공 |

자동으로 하지 않는 것:

- 이름만 보고 학생을 합치거나 새 학생을 생성하지 않는다.
- 퇴원·휴원·반 이동·학생 삭제·수납 변경을 화면 자동화로 저장하지 않는다.
- 아카플로우 문자와 WB 솔라피에서 같은 안내를 동시에 보내지 않는다.
- 브라우저 로그인 정보·쿠키·비밀번호를 WB 서버로 복사하지 않는다.

### 시험·성적표·상담·과제

공식 매뉴얼의 `시험&성적표`, `상담&과제` 메뉴는 결과와 상담 기록의 원무 공유에 사용한다. WB는 당장 이 원문을 양방향 복제하지 않는다. 2단계에서는 WB 수업 요약을 아카플로우 입력 폼에 미리 채우고, 선생님이 확인 후 저장하는 방식만 허용한다.

상품 안내에는 일반 공개 API 명세가 없고 프랜차이즈·단체의 API 연동은 별도 상담 항목으로 안내된다: <https://acaflow.co.kr/pricing>. 따라서 공개 API가 생기기 전까지는 공식 내보내기 파일과 로그인된 브라우저의 명시적 사용자 작업을 사용한다.

## 3. 연동 방식: 쉬운 순서대로

### 1단계 — 파일 한 번 선택

1. 아카플로우에서 `전체 수강생 목록.xls` 또는 CSV를 내려받는다.
2. WB `원생` 화면의 `아카플로우 보호자 연락처 가져오기`에서 파일을 선택한다.
3. WB가 성명·학년·보호자 연락처만 브라우저 메모리에서 읽는다.
4. 현재 WB stable `studentId`와 정확히 연결된 행만 미리 보여준다.
5. 새 연락처는 기본 선택, 번호 변경은 관리자 직접 선택 후 저장한다.
6. 저장해도 수업 피드백·보강·회차·차량 알림 동의는 자동으로 켜지지 않는다.

파일 원문은 업로드·localStorage 저장·Git 커밋·로그 출력하지 않는다. 동명이인, 명단 미연결, 잘못된 번호, 파일 내 중복은 저장하지 않는다.

현재 지원 형식은 아카플로우가 실제 내려주는 XML 기반 `.xls`와 CSV다. `.xlsx`는 1단계에서 불필요한 라이브러리를 추가하지 않기 위해 제외한다.

### 2단계 — Chrome 복사·붙여넣기

별도 확장 프로그램을 설치하지 않고 로그인한 아카플로우 탭과 Chrome의 기본 클립보드를 이용한다.

- 가져오기: 아카플로우 학생 목록의 머리글과 행을 함께 복사한 뒤 WB에서 `Chrome에서 복사한 명부 붙여넣기`를 누른다. WB는 탭 구분 표를 1단계와 같은 미리보기 규칙으로 확인한다.
- 내보내기: WB 수업 카드에서 `아카플로우 코멘트용 복사`를 누른 뒤 아카플로우 `학생별 레포트`의 `코멘트` 또는 내부용 `출결메모` 칸에 붙여넣는다. 실제 WB 담당자 이름도 함께 복사되므로 5개 처리 계정과 혼동하지 않는다. 아카플로우 레포트에는 별도 저장 버튼이 없으므로 붙여넣는 즉시 공동 작업자에게 공유되며, 출결은 아카플로우의 출결 칸에서 별도로 선택한다.
- **입력할 학생·날짜·칸과 출결 상태는 사람이 확인한다.** 학생별 레포트에는 별도 저장 버튼이 없으므로 WB는 아카플로우 화면을 자동 클릭하지 않는다.
- 비밀번호·쿠키·세션 토큰은 읽거나 전송하지 않는다.
- 연락처 원문은 작업 중 메모리에만 두고 콘솔·DOM 속성·영구 저장소에 남기지 않는다.
- 클립보드 권한이 없거나 표 복사가 어려우면 `.xls` 파일 가져오기를 사용한다.

현재 이 방식이면 설치 없이 양방향 반복 입력을 줄일 수 있다. 같은 작업을 하루 여러 번 반복해 복사·붙여넣기조차 병목이 된다는 운영 근거가 쌓일 때만 Chrome 확장 프로그램을 추가한다.

### 3단계 — 계약 API

아카플로우가 공식 API 명세·권한·웹훅 서명·수정시각을 제공할 때만 Chrome 읽기를 교체한다. API가 생겨도 stable ID 매핑, 미리보기, 대량 변경 차단, 삭제 금지, 사람의 최종 승인 원칙은 유지한다.

## 4. 학생 연결 규칙

연결 키는 D1 비공개 `acaflow_student_links`의 `(externalStudentNo → WB studentId)`다. 연락처를 처음 확인 저장할 때 두 값을 한 트랜잭션으로 연결하며, 한번 연결된 학생번호를 다른 학생에게 재사용하지 않는다.

- 기존 연결이 있으면 이름이나 학년이 바뀌어도 같은 WB studentId를 유지한다.
- 첫 연결 후보는 이름·학년으로 찾을 수 있지만 관리자가 연락처 저장을 확인해야 학생번호 연결이 확정된다.
- 동명이인은 아카플로우 학생번호와 현재 명단을 함께 확인한다.
- 학생번호가 없는 자료는 자동 신규 생성·병합하지 않는다.
- 보호자 번호가 바뀌면 모든 목적별 동의를 재확인한다.
- 신규 등록과 `신규 학생 적응 관리`는 별개다. 기존생을 명단에 추가했다고 신규생으로 분류하지 않는다.

외부 학생번호 매핑은 비공개 D1에 두며 공개 Pages 코드나 파일에 넣지 않는다.

### 담당 강사 5계정 제한 대응

아카플로우는 대표를 포함해 강사 계정 5개만 사용하고 요금제를 올리지 않는다. 따라서 아카플로우의 `담당 강사`와 실제 수업 담당자가 다를 수 있으며, 이 차이를 오류로 보거나 자동으로 맞추지 않는다.

| 구분 | 의미 | 정본 |
|---|---|---|
| 아카플로우 처리 계정 | 5개 좌석 중 학생 원무를 입력·확인하는 계정 | 아카플로우 |
| 실제 수업 담당자 | 수업 지시·출결·보강·피드백을 수행하는 선생님 | WB `teacherIds` |

연동 규칙:

- 학생 연결은 아카플로우 담당 강사명이 아니라 외부 학생번호와 WB stable `studentId`로 한다.
- 아카플로우 담당 강사 열이 달라도 보호자 연락처 가져오기와 학생 연결을 막지 않는다.
- 아카플로우 담당 강사 변경으로 WB `teacherIds`를 추가·삭제하지 않는다.
- WB 수업 담당자 변경으로 아카플로우의 5개 처리 계정을 자동 변경하지 않는다.
- 화면에는 필요할 때 `실제 수업 담당`과 `아카플로우 처리 계정`을 따로 표시한다. `담당 불일치` 대신 `계정 공유 운영`으로 표시한다.
- 아카플로우에 WB 수업 요약을 채울 때 본문에 실제 담당 선생님 이름을 넣을 수 있지만, 로그인 계정의 권한을 실제 담당자 권한으로 간주하지 않는다.
- 승인·알림·학생 범위는 계속 WB의 실제 `teacherIds`와 관리자 권한으로 판정한다.

이렇게 하면 계정 5개를 유지해도 강사 수가 늘어날 수 있고, 아카플로우 계정 배치가 바뀌어도 학생의 실제 담당 수업이 잘못 이동하지 않는다.

## 5. 충돌과 실패 처리

| 상황 | 처리 |
|---|---|
| 같은 학생의 번호가 달라짐 | `번호 변경 · 선택 필요`; 자동 덮어쓰기 금지 |
| 이름이 같은 학생이 둘 이상 | 저장 중단; 학생번호로 관리자 확인 |
| 아카플로우에는 있으나 WB 명단에 없음 | `명단 연결 안 됨`; 기존생/신규생을 관리자가 결정 |
| WB에는 있으나 아카플로우 파일에 없음 | 자동 퇴원 금지 |
| 저장 도중 일부 네트워크 실패 | 성공/실패 건수를 분리 표시; 재실행 시 동일 번호는 건너뜀 |
| Chrome 화면 구조 변경 | 자동 입력 중지; 파일 경로 사용 |
| 다른 관리자가 동시에 수정 | 서버 revision 충돌을 표시하고 최신값을 다시 확인 |

## 6. 개인정보와 발송 원칙

- 보호자 전화번호는 인증된 Worker/D1의 학생 ID별 비공개 연락처로 최소 저장한다.
- 관리자 화면에서도 필요한 경우 마스킹해 보여주고 공개 정적 파일에는 넣지 않는다.
- 연락처 저장은 발송 동의가 아니다. 수업 피드백, 보강, 회차, 차량은 목적별 동의를 각각 확인한다.
- 알림톡 `accepted`는 공급자 접수이며 단말 도착·열람 완료가 아니다.
- `unknown`, `dispatching`, 결과 미확정은 중복 위험 때문에 자동 재발송하지 않는다.

## 7. 매일 쓰는 가장 쉬운 절차

지금은 다음만 기억하면 된다.

1. 학생·보호자 정보는 아카플로우에서 고친다.
2. 아카플로우 명부를 내려받는다.
3. WB 원생 화면에서 파일을 한 번 선택한다.
4. `새 연락처`만 먼저 저장하고 `번호 변경`은 확인 후 선택한다.
5. 실제 카톡을 보낼 학생은 목적별 동의를 따로 켠다.
6. 수업·보강·회차·교재·차량 기록은 WB에서 처리한다.

Chrome에서는 학생 목록을 복사한 뒤 WB의 `Chrome에서 복사한 명부 붙여넣기`를 누르면 2~3번이 끝난다.

## 8. 구현 완료 기준

- 실제 아카플로우 `.xls`가 개인정보 출력 없이 파싱된다.
- 이름·학년으로 후보를 찾되 stable studentId 없는 행은 저장하지 않는다.
- 변경 전화번호는 기본 선택되지 않는다.
- 연락처 저장 시 모든 알림 동의는 꺼진 상태거나 identity mismatch로 재동의를 요구한다.
- 파일 원문과 전화번호가 로그·Git·localStorage에 남지 않는다.
- Chrome 복사·붙여넣기는 로그인 정보에 접근하지 않고, 명시적 클릭과 최종 사용자 저장을 요구한다.
- 파일 경로와 Chrome 경로가 같은 미리보기·검증 규칙을 사용한다.
