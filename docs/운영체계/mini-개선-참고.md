# acaflow-mini 개선 참고 문서 — 업무지시서 앱과의 경계·계약

- 버전: v1.1 (2026-08-11)
- 대상: acaflow-mini 개발 담당(김기홍 / 담당 에이전트)
- 상위 문서: `이원화-아키텍처-설계서.md` (경계·다리 계약의 정본. 충돌 시 그쪽이 우선)

---

## 1. 확정된 결론 (2026-08-01)

**흡수/통합하지 않는다. "데이터만 공유"로 확정.**

- mini = 원내 관제탑: 아카플로우 마스터 데이터의 조회·시간표·충돌 검사·권한별 화면
- 업무지시서 앱 = 현장 실행: 지시·체크·출결·피드백·연락·경보 (모바일, 이름만)
- 근거: ① 실제 중복은 학생 명단 하나뿐이고 다리로 해소됨 ② 스택이 정반대(로컬 Flask+로그인 vs 서버리스+개인링크)라 통합 비용 > 이득 ③ 업무지시서 앱은 공개 오리진이라 실개인정보 반입이 불가능 — 이원화는 임시가 아니라 의도된 최종 구조다.

## 2. 상대 시스템(업무지시서 앱) 정확한 사실

mini 쪽 설계 판단 시 아래를 전제로 삼을 것 (과거 문서에 축소·오기가 있었음):

- 소스는 공개 GitHub 저장소 `whdudwns33-wb/wb-site`에 있다. 정적 코드는 공개지만 원생 명단·학생별 교재 배정은 인증된 Worker/D1 `private_rosters`에만 둔다. `task/textbooks.json`에는 학생 정보가 없는 공개 교재 카탈로그만 둔다.
- 기능 범위: 업무 지시·체크 외에 출퇴근, 수업별 학생 출결, 학부모 피드백 자동 생성, 교재 DB·발주, 원생 실적표(유지율), 학부모 연락 기록, 위험 학생 조기 경보, 카카오 알림톡 알림.
- 학생은 변경되지 않는 WB `studentId`로 식별한다. 아카플로우 학생번호가 추출되면 비공개 매핑으로 연결하며, 이름·학년만으로 동명이인을 자동 병합하지 않는다.

## 3. mini가 만들지 말아야 할 것 (앱이 이미 소유)

아래 기능은 mini에 중복 구현하지 않는다. 요구가 생기면 앱 쪽 개선으로 넘긴다:

- 업무 지시·체크리스트·이월 / 강사 출퇴근
- 수업 중 출결·태도 기록, 학부모 피드백 문구
- 학부모 연락 이력, 위험 학생 경보, 유지율 실적표
- 교재 발주 워크플로
- 강사 대상 모바일 화면 전반 (mini는 원내 PC 조회에 집중)

## 4. mini가 맡아야 할 것 + 신규 계약 1건

### 4.1 기존 역할 (계속 강화)
- 아카플로우 주간 동기화 사본의 품질 (누락·중복·형식 검증)
- 시간표 조회·수업 충돌 검사 (충돌 확정 결과만 앱 지시서에 반영되는 상류 역할)
- 권한 3단계 조회 화면
- 아카플로우로의 쓰기(신규 등록 엑셀 붙여넣기) 절차 개선

### 4.2 신규: 주간 로스터 추출 스텝 (다리 계약)

`WB_AcaFlow_Weekly_Sync` 직후 실행되는 추출 스텝을 추가한다.

- 산출: `wb_roster_extract.csv` (UTF-8, 헤더 필수)
- 컬럼: `name, grade, teacher, subject` (필수) + `status, changed` (권장). **그 외 컬럼 금지** — 특히 전화번호·생년월일·학교·수납·보호자 정보는 절대 포함하지 않는다 (수신 측도 드롭하지만 송신 측에서 원천 차단이 원칙).
- teacher 겸임 표기: 가운뎃점 구분 (`김동현·정다원`)
- 전달: 당분간 수동 (대표가 Claude 채팅에 전달). 자동화 시 Drive 폴더 투입 방식을 협의.
- 이 계약(파일명·컬럼)을 바꿀 때는 반드시 설계서 3.2절 개정과 동시에 진행한다.

### 4.3 개선 로드맵 제안 (우선순위순)

1. **추출 스텝 구현** (4.2) — 다리의 mini 쪽 절반. 작고 효과 큼.
2. **동명이인 처리**: 학생번호·WB `studentId` 매핑 충돌을 동기화 시점에 검출·경고. 이름·학년만 같은 행은 상류에서 자동 병합하지 않는다.
3. **표기 정규화**: 이름 앞뒤 공백·전각문자 정리. 아카플로우 표기가 전체 시스템의 정본이 된다.
4. **변경 리포트**: 주간 동기화 시 전주 대비 diff(신규/퇴원/담당변경) 요약 생성 — 다리 대조를 mini가 절반 미리 해주는 효과.
5. **충돌 검사 결과의 외부화**: 확정 시간표를 사람이 읽을 수 있는 형태(주간 표)로 내보내기 — 지시서 발행 시 참고 자료.
6. (장기) B 파이프라인(DOCX 지시서)과 앱 지시서의 관계 정리 — 앱이 강사 전원에게 정착하면 DOCX 생성은 축소 검토.

## 5. 하지 말 것 (하드 제약)

- 앱(공개 오리진)으로 실개인정보를 보내는 어떤 형태의 연동도 설계하지 않는다.
- 앱 → 아카플로우/mini 방향의 자동 쓰기를 만들지 않는다 (다리는 단방향).
- 추출 CSV에 화이트리스트 외 컬럼을 "편의상" 추가하지 않는다.

## 6. 소통 채널

- 경계·계약 관련 질문/변경 제안 → 대표를 통해 wb-site Claude 세션으로.
- mini 내부 구현(스택·DB·UI)은 이 문서의 제약 안에서 전적으로 mini 쪽 재량.
