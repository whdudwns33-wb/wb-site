# 코워크 `agent-studyforce-manager` 스킬 개정안 — 수행 탭 도입에 맞춘 모집단 분리

- 버전 v0.1 (2026-09-09) · 대상: 코워크(Claude Cowork) 스킬 `agent-studyforce-manager/SKILL.md`
- 배경: 업무지시서 앱 **수행 탭**(`task/perf-panel.js`, 기획서 §5 제안 C)이 재원생의 스터디포스·클래스카드 일일 수행을
  `__perfday__`에 기록하고 같은 어휘(`completed/partial/not_completed/unknown`, `no_login/no_assignment/account_issue/…`,
  P0·P1·P2)로 신호와 조치를 만든다. 같은 학생을 두 곳에서 판정하면 둘 다 못 믿게 되므로 **모집단을 나눈다**.
- 적용 시점: 원장이 수행 탭에서 첫 스탬프를 찍는 날. 그날부터 아래 개정이 유효하다. 스킬 파일은 저장소 밖(코워크 동기화
  폴더)에 있어 여기서는 바꿀 문구만 적는다 — 아래 블록을 그대로 붙여 넣는다.

## 1. 한 줄 원칙 (스킬 "역할" 절 맨 위에 추가)

> **재원생의 일일 수행 판정은 업무지시서 앱 수행 탭이 정본이다.** 이 에이전트는 **비재원 구독생**(학원 재원이 아닌 스터디포스 구독 학생)의
> 수행 판정과, 전체 구독생의 **명단·결제 대조**만 맡는다. 재원 + 구독 병행 학생은 수행 탭이 판정하고 여기서는 결제·명단만 본다.

## 2. "일일 관리 흐름" 5~9단계 교체

| 기존 | 개정 |
|---|---|
| 5. 20:30 기준으로 수행 결과를 확인한다. | 5. 20:30 기준으로 **비재원 구독생**의 수행 결과를 확인한다. 재원생 행은 `perf_tab`으로 표기하고 판정하지 않는다. |
| 6. 학생별 상태를 기록한다. | 6. 비재원 구독생만 상태를 기록한다. |
| 7. 미수행 학생을 후속조치 등급으로 나눈다. | 7. 비재원 구독생만 P0~P3으로 나눈다. 재원생의 P0·P1은 수행 탭이 조치 카드로 만든다. |
| 8. 학습관리자 전달 후보를 만든다. | 8. 비재원 구독생만. |
| 9. 알림관리자 발송 후보를 만든다. | 9. 비재원 구독생만. 재원생 보호자 연락은 수행 탭 조치(`contact`)가 한 채널로 처리하므로 여기서 만들지 않는다(같은 P0에 두 경로 금지). |

## 3. "20:30 점검" 표 위에 추가할 문단

```text
재원 여부 판정: 기준 명단 행의 학생이 학원 재원생(아카플로우 명단)이면 `population: enrolled`, 아니면 `population: external`.
enrolled 행은 20:30 점검 대상에서 제외하고 `status: perf_tab`으로 둔다(누락이 아니다).
external 행만 기존 표대로 completed / partial / not_completed / unknown 을 판정한다.
```

## 4. "상태값" 표에 한 줄 추가

| 상태 | 의미 |
|---|---|
| perf_tab | 재원생 — 일일 수행·후속은 업무지시서 앱 수행 탭이 담당. 이 에이전트는 명단·결제만 대조 |

## 5. "코워크 전달 기준" 보완 (agent-academy-daily 22:40 회수)

22:40 일일 회수는 재원생 스터디포스·클래스카드 수행을 이 에이전트의 산출물에서 찾지 않는다. 필요하면 원장이 수행 탭
원장 카드(직원별 조치·스탬프·미확인 셀)를 보고 브리핑에 옮긴다. 기획서 §7 결정 5(코워크 PC 읽기용 링크 발급 여부)가 정해지기
전까지는 회수 보고서의 "스터디포스 점검 결과" 절을 **비재원 구독생만**으로 한정한다.

## 6. 바꾸지 않는 것

- 13:00 점검(명단 존재·신규 등록 반영·계정 사용 가능·과제 존재·보호자 연락 기준)은 전체 구독생에 대해 그대로 한다. 이 결과 중
  `no_assignment`·`account_issue`는 원장이 수행 탭 20:30 입력의 `why` 칩으로 옮겨 적는다(수행 탭은 13:00 절차를 기록하지 않는다 — 제안 C.3).
- 구독 엑셀이 명단·금액·결제의 유일한 진실이라는 원칙, 계정 생성·비밀번호 저장·직접 발송 금지, 학생·보호자 번호 병합 금지는 그대로다.
- 판정 어휘(상태값·원인 코드·P등급)는 바꾸지 않는다 — 수행 탭이 같은 어휘를 쓰므로 두 산출물을 나란히 읽을 수 있어야 한다.
