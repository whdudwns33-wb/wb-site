# 코워크 `agent-studyforce-manager` 스킬 개정안 — 프로그램데스크 도입에 맞춘 역할 분리

- 버전 v0.2 (2026-09-09) · 대상: 코워크(Claude Cowork) 스킬 `agent-studyforce-manager/SKILL.md`
- 배경: 별도 사업용 앱 **WB 프로그램데스크**(`desk/`, `https://wb-desk.whdudwns33.workers.dev/`)가 구독·이용 학생 전체의
  명단·계정·일일 수행·후속 연락을 담당한다. 수행 판정 어휘(`completed/partial/not_completed/unknown`, 원인 코드, P0·P1·P2)는
  이 스킬과 같으므로 두 곳이 같은 학생을 판정하면 둘 다 못 믿게 된다. **판정은 앱이, 이 스킬은 결제·명단 대조만.**
- 적용 시점: 원장이 프로그램데스크 수행 화면에서 첫 스탬프를 찍는 날. 스킬 파일은 저장소 밖(코워크 동기화 폴더)에 있어
  여기서는 바꿀 문구만 적는다 — 아래 블록을 그대로 붙여 넣는다.

## 1. 한 줄 원칙 (스킬 "역할" 절 맨 위에 추가)

> **구독 학생의 일일 수행 판정·후속 조치·보호자 연락은 프로그램데스크 앱이 정본이다.** 이 에이전트는 구독 엑셀과 결제 기록을
> 기준으로 **명단·금액·결제 상태 대조**와 신규·중지 후보 분류만 맡는다. 20:30 수행 점검·`followup_candidate`·`carryover_candidate`는
> 만들지 않는다.

## 2. "일일 관리 흐름" 교체

| 기존 | 개정 |
|---|---|
| 3. 13:00 기준으로 명단/신규등록/계정/과제/연락기준을 점검한다. | 3. 13:00 기준으로 **명단·신규등록·결제**를 점검한다. 계정·과제 존재 여부는 앱의 학생 화면(프로그램별 계정 상태)이 정본이므로 여기서 다시 묻지 않는다. |
| 5~9. 20:30 수행 확인 → 학생별 상태 → 후속 등급 → 학습관리자·알림관리자 후보 | 삭제. 대신 5. 앱과 엑셀의 명단 차이(엑셀에만 있음 / 앱에만 있음 / 금액 불일치)를 `program_check_needed`로 보고한다. |
| 10. 결제/구독 불일치 → 결제서비스관리자 후보 | 유지 |

## 3. "20:30 점검"·"20:30 결과 변환 규칙"·"후속조치 등급" 절

세 절을 통째로 다음 한 문단으로 바꾼다.

```text
수행 점검·후속 등급·발송 후보는 프로그램데스크 앱이 만든다(수행 화면의 조치 카드, 연락 기록).
이 에이전트는 수행 상태를 기록하지 않는다. 앱의 주간 수행 요약이 필요하면 원장이 앱 관리 화면의 내보내기(JSON)를 전달한다.
```

## 4. "상태값" 표

수행 관련 값(정상수행·부분수행·미수행·미확인·today_pending·account_issue·no_assignment)을 지우고 명단·결제 값
(신규등록·금액확인필요·연락처확인필요·중지후보·program_check_needed)만 남긴다.

## 5. 바꾸지 않는 것

- 구독 엑셀이 명단·금액·결제의 유일한 진실이라는 원칙, 계정 생성·비밀번호 저장·직접 발송 금지, 학생·보호자 번호 병합 금지.
- 앱의 학생 명단은 엑셀을 정본으로 사람이 옮긴다(앱 관리 화면에서 직원이 등록). 자동 가져오기는 만들지 않는다 — 두 명단의 차이를
  드러내는 것이 이 에이전트의 남은 일이다.
