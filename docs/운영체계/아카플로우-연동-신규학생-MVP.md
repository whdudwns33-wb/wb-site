# 아카플로우 연동·신규 학생 관리 MVP

- 버전: v0.1 (2026-08-11)
- 대상: WB 업무지시서 앱, 아카플로우, acaflow-mini
- 전제: 요청의 “아카들로우”는 기존 운영 문서와 공식 제품명이 일치하는 **아카플로우(ACAFlow)**를 뜻한다고 가정한다. 실제 계약 URL이 다르면 구현 전에 다시 확인한다.

## 1. 결정 요약

1. 학생 등록·퇴원·반 배정의 정본은 계속 아카플로우다.
2. WB 앱은 아카플로우를 직접 수정하지 않고, 필요한 최소 명단만 단방향으로 받는다.
3. 공개 API가 확인되기 전에는 로그인 자동화나 화면 스크래핑을 만들지 않는다.
4. 1차 연동은 **아카플로우 학생 명부 Excel → 비공개 변환 → 변경 미리보기 → 승인 → D1 private roster 반영**이다.
5. 신규 학생 관리는 새 DB나 별도 워크플로 엔진을 만들지 않고, 기존 `tasks`와 `checks`를 재사용한다.
6. 첫 등원일은 등록월에서 추정하지 않는다. 담당자 또는 관리자가 확인한 `firstClassDate`를 정확히 입력한다.
7. 학부모 발송은 보호자 연락처·동의·승인 템플릿·멱등 발송 이력이 모두 갖춰진 경우에만 별도 버튼으로 실행한다. MVP에서는 자동 발송하지 않는다.

## 2. 공식 기능에서 확인된 것과 확인이 필요한 것

공식 공개 문서에서 확인된 기능:

- 학생 명부 Excel 다운로드
- 신규생 등록 시 학생번호 자동 부여
- 등록일 및 수강등록일 관리
- PAD 입실시간 기록
- 수강반 개강일·주간 시간표 관리
- 기존 프로그램과 API 연동은 별도 상담·맞춤 구축

아직 확인되지 않은 것:

- 일반 사용자가 쓸 수 있는 공개 API 또는 웹훅
- 학생 명부 Excel에 학생번호·등록일·수강등록일·첫 PAD 입실일이 실제 포함되는지
- 증분 변경 시각이나 삭제/휴원 상태를 안정적으로 제공하는지

따라서 **개인정보를 제거한 익명 샘플 Excel 1부의 헤더를 확인하기 전에는 자동 필드 계약을 확정하지 않는다.**

공식 참고:

- 학생 명부 Excel: https://docs.acaflow.co.kr/student-list
- 신규생·학생번호: https://docs.acaflow.co.kr/student-registration
- 일괄등록·등록일: https://docs.acaflow.co.kr/bulk-student-registration
- 학생 통합조회: https://docs.acaflow.co.kr/consult-manage
- API 맞춤 구축 안내: https://acaflow.co.kr/pricing

## 3. 1차 연동: 사람이 승인하는 단방향 다리

### 3.1 흐름

```text
아카플로우 학생 명부 Excel
  → 원내 PC의 비공개 변환기
  → 허용 열만 남김
  → 현재 private roster와 dry-run 비교
  → 신규/담당변경/휴원·퇴원 후보 보고
  → 원장 승인
  → 기존 import-private-roster로 D1 교체 및 read-back 검증
  → WB 앱 원생·시간표·신규 학생 섹션 갱신
```

### 3.2 허용 데이터

| 항목 | 처리 |
|---|---|
| 아카플로우 학생번호 | Excel에 있으면 비공개 매핑에만 보존 |
| 이름·학년 | 앱 표시 및 기존 stable `studentId` 대조 |
| 담당·과목·수강반 | 담당 학생 필터와 수업 준비에 사용 |
| 재원·휴원·퇴원 상태 | 변경 후보 생성 |
| 등록일·수강등록일 | 참고값. 첫 등원일로 자동 사용하지 않음 |
| 전화번호·주소·학교·수납·성적 | WB 명단 추출에서 제거 |

기존 WB `studentId`는 유지한다. 아카플로우 학생번호가 확인되더라도 기존 학생 ID를 새 번호로 갈아끼우지 않고, Git에 포함되지 않는 비공개 매핑으로 연결한다. 동명이인이나 매핑 충돌은 자동 병합하지 않는다.

### 3.3 적용 규칙

- 신규: 아카플로우에만 있는 학생은 신규 후보로 만든다. 담당자·과목·첫 등원일 확인 후 반영한다.
- 담당 변경: 변경 미리보기에 표시하고 승인 후 반영한다.
- 휴원·퇴원: 자동 종료하지 않는다. 사유와 적용일을 확인한 뒤 반영한다.
- 대량 변경: 전체 재원생의 20%를 넘으면 적용을 멈춘다.
- 오류: 일부만 반영하지 않는다. 전체 검증 성공 후 한 번에 교체한다.
- 감사: 건수와 비식별 변경 유형만 로그에 남기고 학생명·연락처는 배포 로그에 남기지 않는다.

### 3.4 주기

- 초기 2주: 필요할 때 수동 실행해 결과를 대조한다.
- 안정화 후: 매주 월요일 06:30 추출, 08:00 전 관리자 승인.
- 공개 API 계약 후: 읽기 전용 증분 가져오기로 바꾸되 승인 단계와 대량 변경 차단은 유지한다.

## 4. 신규 학생 섹션

### 4.1 화면 목적

담당자가 “누가 언제 처음 오고, 지금 무엇이 빠졌는지”를 한 화면에서 확인한다. 전체 명단을 다시 보여주는 화면이 아니라 **첫 등원 전부터 D+14까지의 적응 관리 화면**이다.

상단에는 네 숫자만 둔다.

- 오늘 첫 등원
- 기한 지남
- 관리 중
- 완료

카드는 다음 순서로 정렬한다.

1. 오늘 첫 등원
2. 기한이 지난 학생
3. 7일 이내 첫 등원 예정
4. D+1~D+14 관리 중
5. 완료(기본 접기)

각 카드에는 이름·학년·담당·`D-3`, `첫날`, `D+7` 배지·전체 진행률만 먼저 보이고, 세부 체크는 펼쳤을 때 보인다. 첫 등원일 카드는 색과 함께 **“오늘 첫 등원” 문구**를 표시해 색에만 의존하지 않는다.

### 4.2 14일 고정 관리 단계

| 시점 | 내부 체크 | 학부모 발송 후보 |
|---|---|---|
| 준비 | 반·시간·담당 확인, 교재 준비, 보호자 연락처·동의 확인 | 첫 수업 안내 |
| 첫날 | 입실 확인, 선생님 인계, 교재 전달, 귀가 특이사항 확인 | 첫 등원 확인 |
| D+1 | 첫 수업 기록 확인, 막힘·불편 확인 | 첫 수업 피드백 |
| D+7 | 출결·숙제·수업 적응 확인 | 필요할 때만 적응 안내 |
| D+14 | 미해결 항목 확인, 일반 관리로 전환 | 필요할 때만 마무리 안내 |

14일 뒤에는 자동 삭제하지 않고 “완료”로 접어 감사 이력을 남긴다. 휴원·퇴원·등록 취소가 확인되면 남은 내부 알림과 발송 버튼을 중지한다.

### 4.3 기존 데이터 재사용 방식

신규 테이블을 만들지 않는다. 신규 학생 한 명당 기존 `tasks`에 `once` 업무 5개를 생성한다.

```jsonc
{
  "studentOnboardingVersion": 1,
  "onboardingRunId": "onb-...",
  "studentId": "student-...",
  "studentName": "표시 이름",
  "firstClassDate": "2026-08-18",
  "onboardingStep": "prepare | day0 | d1 | d7 | d14",
  "start": "각 단계의 실행일",
  "repeat": "once",
  "staffId": "주 담당자"
}
```

- 완료·막힘·메모는 현재 `checks`를 그대로 쓴다.
- 담당 선생님 개인 링크에는 자기 학생 업무만 내려간다.
- 관리 담당과 원장은 서버가 확인한 권한일 때만 전체 신규 학생 섹션을 본다.
- 학생 이름이 바뀌어도 집계는 `studentId`와 `onboardingRunId`로 유지한다.
- 첫 등원일 변경은 아직 완료하지 않은 단계의 날짜만 다시 계산하고, 이미 완료된 이력은 보존한다.

### 4.4 생성 방법

원생 탭에 `신규 관리 시작` 버튼을 둔다.

1. private roster에서 학생 선택
2. 첫 등원일 선택(필수)
3. 주 담당자 선택(기본값은 roster 담당자)
4. 교재 준비 필요 여부와 안내 발송 여부 확인
5. 미리보기 후 5개 업무 생성

아카플로우 연동에서 신규 후보가 들어오면 이 폼을 자동으로 열 수는 있지만, 첫 등원일이 확정되지 않은 상태에서는 업무를 생성하지 않는다.

## 5. 학부모 알림 안전장치

- 브라우저는 전화번호를 요청에 넣지 않는다.
- 서버가 비공개 보호자 연락처에서 번호와 동의를 확인한다.
- 발송 문구는 승인된 카카오 템플릿 변수만 사용한다.
- `disableSms: true`로 알림톡 실패 시 임의 문자 대체발송을 막는다.
- 같은 학생·같은 단계·같은 템플릿은 멱등키로 중복 발송하지 않는다.
- 발송 성공·거절·확인 불가를 구분해 기록한다.
- MVP는 버튼을 누르는 명시 발송만 허용한다. 자동 발송은 최소 4주간 수동 운영 이력이 안정된 뒤 별도 승인한다.
- 이름 문자열 대신 `studentId`로 보호자 연락처를 연결하는 이관이 끝나기 전에는 신규 학생 자동 발송을 켜지 않는다.

아카플로우 자체 문자/카톡과 WB 솔라피가 같은 안내를 중복 발송하지 않도록, 안내 종류마다 발송 시스템을 하나만 지정한다. 1차 권장안은 학생 등록·수납·출결 자동 문자는 아카플로우, WB 수업 피드백·신규 적응 체크는 WB 솔라피다.

## 6. 2차 연동: 계약 API가 확인된 뒤

공급사가 읽기 API를 제공하고 계약상 허용될 때만 추가한다.

- 방향: 아카플로우 → WB 읽기 전용
- 인증정보: Cloudflare Worker secret에만 저장
- 식별: `(source='acaflow', externalStudentId)`를 private mapping으로 사용
- 증분: 공급사의 수정 시각 또는 cursor를 사용
- 삭제: 물리 삭제 대신 휴원·퇴원 후보 처리
- 실패: 이전 정상 명단 유지, 부분 적용 금지
- 웹훅: 공식 서명 검증·재시도 명세가 있을 때만 사용

브라우저 ID/비밀번호 자동입력, DOM 스크래핑, 개인 PC 쿠키 복사는 구현하지 않는다.

## 7. 구현 순서와 완료 기준

### 1단계 — 연동 계약 확정

- 실제 제품 URL 확인
- 개인정보를 제거한 학생 명부 Excel 헤더 확인
- 학생번호와 등록일 포함 여부 확인
- 익명 샘플로 dry-run 결과 검증

완료 기준: 동일 학생 ID 유지, 동명이인 fail-closed, 전화번호 등 금지 열 0건, read-back 일치.

### 2단계 — 신규 학생 섹션 MVP

- `신규 학생` 탭과 4개 KPI
- 첫 등원일 강조 및 5단계 카드
- 원생 선택·첫 등원일·담당자 입력 폼
- 개인 링크 담당 범위 제한
- 완료·막힘·메모 동기화

완료 기준: 390px 모바일과 820px 패드에서 가로 넘침 없음, 담당 외 학생 미노출, D0가 항상 최상단, 날짜 변경·휴원·퇴원 시 발송 차단.

### 3단계 — 알림톡 연결

- 첫 안내/첫 수업 피드백용 승인 템플릿 확정
- 보호자 연락처를 `studentId` 기준으로 이관
- 본인 테스트 수신처 → 동의된 내부 파일럿 1명 → 전체 순으로 확대

완료 기준: 승인 템플릿 불일치 0, 동의 없는 발송 0, 중복 발송 0, 거절 사유가 운영 화면에 안전한 코드로 남음.
