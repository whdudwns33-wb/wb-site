# AI 해석 엔진 · 프롬프트 스펙 v0

> 그림검사 AI 해석 웹 · 엔진 설계 문서
> 지식베이스(HTP / KFD·DAP·자유화 v0)를 실제 파이프라인·프롬프트·출력 스키마로 연결.
> **구현 전 초안 — 프롬프트 문구·스키마는 개발/심리사 검토 후 확정.**

---

## 0. 설계 원칙 (딥리서치 결론 반영)

투사검사는 타당도가 낮아 **단일 지표 자동 결론은 위험**하다. 따라서 엔진은:

1. **관찰(재현 가능)과 해석(가설)을 분리** — Vision이 "무엇이 그려졌나"를, 별도 단계가 "무엇을 시사할 수 있나"를 담당.
2. **모든 해석에 근거수준(강/중/약) + 연령보정 + 안전 경고를 강제 부착.**
3. **전문가 확정 게이트 필수** — 학부모 노출 전 심리사 승인 없이는 정식 해석 미공개.
4. **위기 신호는 별도 라인으로 즉시 에스컬레이션** (자동 해석보다 우선).

---

## 1. 파이프라인 개요

```
입력: 그림 이미지 + 메타(검사종류, 나이, 성별, 상황)
  │
  ├─▶ [S0] 안전·품질 게이트 (이미지 품질 / 위기 신호 1차 스캔)
  │
  ├─▶ [S1] 관찰 추출 (Vision)        → observations[] (구조화 JSON)
  │
  ├─▶ [S2] 가설 매핑 (KB + 규칙)     → hypotheses[] (가설·근거수준·연령보정·경고)
  │
  └─▶ [S3] 대상별 생성
          ├─ expert_draft (근거·확인질문)
          └─ parent_preview (순한 관찰 중심, 확정 전용)

  → [게이트] 전문가 검수·확정 → parent_report (정식, 확정 후)
```

모델: 초안 생성(S1·S3)은 **상위 모델(Claude Opus 5 / Sonnet 5)**, S2 정형 매핑·S0 스캔은 경량 모델로 비용 최적화.

---

## 2. [S1] 관찰 추출 (Vision)

**목표**: 해석 없이 "무엇이 어떻게 그려졌는가"만 구조화. 해석 언어 금지.

### 시스템 프롬프트 (초안)
```
당신은 아동 그림검사의 '관찰 기록자'입니다. 그림에서 보이는 시각적 특징만
객관적으로 기술하세요. 심리적 해석·진단·추측은 절대 하지 마세요.
검사 종류: {test_type}. 아동: 만 {age}세 {sex}.
아래 요소 카테고리에 대해 보이는 그대로 JSON으로 출력하세요.
불확실하면 confidence를 "low"로. 없는 요소는 present:false.
```

### 출력 스키마
```json
{
  "test_type": "HTP",
  "image_quality": { "ok": true, "issues": [] },
  "observations": [
    {
      "element": "house.roof",       // KB의 element 키와 매핑
      "present": true,
      "attributes": { "size": "large", "detail": "plain" },
      "note": "지붕이 집 전체보다 크게 그려짐",
      "vision_confidence": "high"
    }
  ],
  "crisis_flags": []                  // 예: "self_harm_imagery", "violence"
}
```
> element 키는 지식베이스 표의 관찰요소와 1:1 매핑(예: `house.door`, `tree.root`, `person.hand`, `kfd.distance`, `pitr.umbrella`).

## 3. [S2] 가설 매핑 (지식베이스 + 규칙 엔진)

**목표**: 각 관찰을 KB에서 조회해 가설·근거수준을 붙이고, 안전 규칙으로 보정.

### 처리 규칙 (코드 + LLM 혼합)
1. **KB 조회**: observation.element → KB 항목(가설, 근거수준, 연령규준, 경고) 매핑.
2. **연령 보정**: `age < age_norm.normal_below`이면 → 병리 가설 강등 + "발달상 정상 범위 가능" 문구 자동 삽입.
   - 예: 만 8세 `person.hand` 생략 → confidence를 낮추고 보정 문구.
3. **단일 지표 억제**: 한 가설의 신뢰도가 '약'이고 뒷받침 관찰이 없으면 → "단독 근거 불충분" 태그.
4. **DAP 분리**: 발달·지능 지표(중~강)와 정서 지표(약~중)를 별도 필드로.
5. **색채·자유화**: 색 기반 가설은 신뢰도 상한 '약' + "개인·문화 의미 확인 필요" 강제.

### 출력 스키마 (앱/콘솔이 그대로 사용)
```json
{
  "hypotheses": [
    {
      "id": "person.hand",
      "observation": "손 생략",
      "hypothesis": "행위·대인접촉에 대한 위축·불안 가능성",
      "confidence": "low",              // 연령 보정으로 mid→low 강등
      "age_adjustment": "만 9세 미만에서는 발달상 정상 범위일 수 있음",
      "caveats": ["단일 지표 진단 금지", "귀찮음 등 대안 설명 가능"],
      "needs_expert_check": true,
      "kb_source": "HTP-v0"
    }
  ],
  "crisis_assessment": { "level": "none" }  // none / watch / urgent
}
```

## 4. [S3] 대상별 자연어 생성

### 4-1. 전문가용 초안 (expert_draft)
```
당신은 아동 심리평가 보조 도구입니다. 아래 hypotheses를 근거로
전문가가 '검수'할 초안을 작성하세요. 규칙:
- 각 항목을 "관찰 → 가설(신뢰도) → 상담에서 확인할 질문" 형식으로.
- 단정 금지. "진단"이라는 단어 사용 금지.
- 약한 근거는 명확히 '약'으로 표시하고 대안 설명 병기.
- 마지막에 "타 검사·면담 통합 필요" 문구 포함.
```
출력: 관찰 근거 + 가설 + 신뢰도 + **확인질문(PDI 제안)** + 종합 코멘트.

### 4-2. 학부모용 미리보기 (parent_preview) — 확정 전, 순한 버전
```
당신은 학부모에게 전할 '참고용 미리보기'를 씁니다. 규칙:
- 강점을 먼저, 따뜻하고 쉬운 말로.
- 정서·병리 관련 강한 표현 금지(관찰 중심만).
- "전문가 확정 후 정식 해석 제공" 안내 포함.
- 진단·단정·불안 유발 표현 금지.
```

### 4-3. 학부모용 정식 리포트 (parent_report) — **확정 후에만 생성**
```
전문가가 확정한 항목(accepted/edited)만 사용. rejected 제외.
구조: 강점 → 관찰된 특징 → 집에서 돕는 법 → 다음 단계(상담).
낙인·병리 언어를 성장 관점으로 리프레이밍.
하단에 면책 문구(참고용·진단 아님) 고정.
```

## 5. [S0] 안전·위기 라인 (자동 해석보다 우선)

- **이미지 품질**: 저품질이면 재촬영 안내, 해석 진행 보류.
- **위기 신호 탐지**(반복적 자해·폭력 이미지, 극단적 절망 표현 등):
  - `level: urgent` → 자동 해석 중단, **전문가 즉시 검토 플래그**, 학부모 자동 노출 차단.
  - 법·윤리 가이드의 신고 프로토콜(112 아동학대 / 119 자해)로 연결.
- 위기 판단도 **AI 단독 결론 금지** — 전문가에게 "확인 필요"로 전달.

## 6. 앱/프로토타입 연동 (출력 계약)

현재 프로토타입 `apps/picture-test`의 전문가 콘솔은 S2의 `hypotheses[]`를 그대로 렌더:
- `observation` → 관찰 핀 라벨
- `hypothesis`/`confidence` → 가설 카드 + 강/중/약 배지
- `age_adjustment` → 연령보정(⚖) 박스
- 전문가 `채택/수정/삭제` → S3 parent_report 입력(rejected 제외)
- 확정 → parent_report 생성 게이트 해제

> 즉, **프로토타입 UI를 바꾸지 않고** 목업 데이터를 이 스키마의 실제 엔진 출력으로 교체하면 동작.

---

## 7. 안전 메타규칙 (전 단계 공통, 하드코딩)

1. "진단/장애/확진/치료" 단어 출력 금지 → 검증 필터로 차단.
2. 모든 해석은 "~가능성/경향" 가설 언어.
3. 근거수준 미표기 출력 금지.
4. 연령 보정 미적용 시 발행 차단.
5. 확정 전 정식 해석의 학부모 노출 금지.
6. 색채·자유화 단독 가설 신뢰도 상한 '약'.
