# 어사이드 지시서 — Cloudflare Tunnel 상태 점검

작성 2026-10-12

원장 PC 에서 도는 에이전트(어사이드)에게 **그대로 붙여넣는** 점검 지시다.
클라우드 세션은 그 PC 에 닿지 않으므로 이 점검은 그쪽에서 해야 한다.

설계·결정의 정본은 `docs/로컬-서버-외부공개-터널.md` 다. 어긋나면 그 문서가 맞다.

## 붙여넣을 지시

````
# WB 로컬 서버 터널 점검

## 배경
원내 PC 를 Cloudflare Tunnel 로 외부 공개하는 작업이다. 결정 둘이 이미 내려져 있다:
**① 터널은 원장·강사 전용이고, 학생은 계속 Cloudflare 워커(wb-reading)를 쓴다.**
**② 이 서버는 운영 자료를 가져와 보기만 하는 읽기 전용 검토용이다.**
둘 다 코드가 강제한다 — 플래그 두 개다:
- `WB_ADMIN_ONLY=1` → 학생 로그인(`/api/login`·`/api/login/status`)을 아예 내주지 않는다.
- `WB_READONLY=1` → 쓰기 메서드(POST·PUT·PATCH·DELETE)를 403 으로 거부한다
  (관리 로그인·`/api/admin/import` 만 예외). `db.json` 도 가져오기 때만 쓴다.

**아무것도 바꾸지 않는다. 읽고 보고만 한다.** 설정 변경이 필요하면 무엇을 왜 바꿔야
하는지 적어서 원장 확인을 받는다.

## 1. 터널이 있는가
```
cloudflared tunnel list
cloudflared tunnel info <터널이름>
```
보고할 것: 터널 이름·ID · 커넥터가 붙어 있는가 · 마지막 연결 시각

## 2. Windows 서비스로 돌고 있는가
```
sc query cloudflared
```
보고할 것: STATE 가 RUNNING 인가 · 자동 시작인가
(재부팅하면 꺼지는 상태면 원내 운영에 못 쓴다)

## 3. 설정 파일이 무엇을 공개하고 있는가
```
type C:\Windows\System32\config\systemprofile\.cloudflared\config.yml
cloudflared tunnel ingress validate
```
보고할 것: hostname · service(어느 로컬 포트로 보내는가) · ingress 규칙 전부
**경로별로 쪼개져 있으면 그대로 적어라** — 정본 문서 §5 가 쪼개지 말라고 적어 둔 자리다.

## 4. DNS 가 연결돼 있는가
```
nslookup <공개hostname>
```
보고할 것: CNAME 이 `<터널ID>.cfargotunnel.com` 을 가리키는가

## 5. 로컬 서버가 어떻게 떠 있는가 ★가장 중요
서버를 띄우는 명령·스크립트·작업 스케줄러 항목을 찾아 **환경변수를 그대로** 적어라.
확인할 것:
- `WB_ADMIN_ONLY` 가 **1/true/yes/on** 중 하나로 설정돼 있는가
  → 안 켜져 있으면 **터널 주소에서 학생 로그인이 열린다.** 가장 위험한 구멍이다.
- `WB_READONLY` 가 **1/true/yes/on** 중 하나로 설정돼 있는가
  → 안 켜져 있으면 이 주소에서 올린 팩·시험 배정이 운영(KV)과 **갈린다.**
- `PORT` · `DATA_DIR` · `ADMIN_PIN`(값은 적지 말고 설정 여부만)

서버가 떠 있으면 기동 로그에 이 두 줄이 있는지 본다:
```
[관리 전용] WB_ADMIN_ONLY=on — 학생 로그인(/api/login·/api/login/status)을 내주지 않습니다
[읽기 전용] WB_READONLY=on — 자료를 바꾸는 요청을 받지 않습니다 (관리 로그인·가져오기만 예외, db.json 도 가져오기 때만 씁니다)
```
한 줄이라도 없으면 그 모드가 아니다. 켠 상태의 기동 명령은 이 꼴이어야 한다:
```
WB_ADMIN_ONLY=1 WB_READONLY=1 PORT=8890 ADMIN_PIN=<pin> DATA_DIR=<dir> node reading-server/server.mjs
```

그리고 모드가 실제로 먹는지 **읽기로** 확인한다(쓰기를 시도하지 마라):
```
curl -s http://localhost:<PORT>/api/health
```
`"readonly": true` 가 있으면 켜진 것이다. 없으면 꺼져 있다.

## 6. 보안 헤더가 실제로 붙는가
로컬에서:
```
curl -sI http://localhost:<PORT>/
```
여섯 개가 다 있어야 한다:
- `X-Robots-Tag: noindex, nofollow, noarchive`
- `Content-Security-Policy`
- `X-Frame-Options: DENY`
- `Referrer-Policy: no-referrer`
- `X-Content-Type-Options: nosniff`
- `Permissions-Policy`

없으면 보고하라. 이 서버는 `reading/_headers` 를 파싱해 붙이고, noindex 가 없으면
기동을 거부하게 돼 있다 — 헤더가 없는데 떠 있다면 그 자체가 이상한 상태다.

## 7. Cloudflare Access 가 걸려 있는가 ★보안의 핵
Cloudflare Zero Trust 대시보드에서 그 hostname 에 **Access 애플리케이션**이 있는지 본다.
- 정책이 **원장·강사 이메일만** 허용하는가
- 아니면 누구나 열리는가

그리고 **인증을 안 한 상태에서** 밖에서 열어 본다(시크릿 창 또는 다른 기기):
```
curl -sI https://<공개hostname>/
curl -s -o nul -w "%{http_code}" https://<공개hostname>/api/login
```
기대값:
- Access 가 걸려 있으면 로그인 화면으로 가거나 302/403 이다. **200 이면 구멍이다.**
- `/api/login` 은 `WB_ADMIN_ONLY` 가 켜져 있으면 **403** 이어야 한다.

## 8. 데이터가 어느 쪽인지
`DATA_DIR` 안의 `db.json` 이 있는지, 마지막 수정 시각이 언제인지 본다.
**운영 워커는 KV, 이 PC 는 db.json 이라 두 데이터가 다르다.** 로컬에서 팩을 올리면
운영에 없다. db.json 에 실제 운영 데이터가 들어 있는지(학생 수·팩 수) 세어 보고하라.

## 보고 양식
1. 터널: 이름·ID·커넥터 상태·서비스 RUNNING 여부
2. 공개 hostname 과 ingress 규칙
3. `WB_ADMIN_ONLY` 설정 여부 (★)
4. `WB_READONLY` 설정 여부와 `/api/health` 의 `readonly` 값 (★)
5. 보안 헤더 6종 중 빠진 것
6. Cloudflare Access 정책 유무와, 인증 없이 접근했을 때의 응답 코드 (★)
7. `/api/login` 응답 코드
8. db.json 존재·수정 시각·대략의 내용 규모
9. 바꿔야 한다고 판단한 것 (바꾸지 말고 적기만)

## 하지 말 것
- 설정·정책·서비스를 **바꾸지 않는다.**
- `ADMIN_PIN`·비밀번호·토큰 **값을 보고서에 적지 않는다.** 설정됐는지만 적는다.
- 공개 hostname 을 외부에 공유하지 않는다.
- db.json 을 복사·전송하지 않는다.
````

## 점검 결과로 갈리는 것

| 결과 | 그다음 |
|---|---|
| `WB_ADMIN_ONLY` 가 안 켜져 있다 | **먼저 켠다.** 그 전에는 터널 주소를 아무에게도 주지 않는다 |
| `WB_READONLY` 가 안 켜져 있다 | **먼저 켠다.** 그 전에 이 주소에서 올린 것이 있으면 무엇인지 적는다 — 운영(KV)과 갈린 자료다 |
| Access 없이 200 이 열린다 | **터널을 내린다.** Access 정책을 걸고 다시 올린다 |
| 보안 헤더가 없다 | 서버가 `reading/_headers` 를 못 읽고 있다는 뜻 — 기동 경로를 확인한다 |
| db.json 에 운영 데이터가 있다 | 운영(KV)과 **갈라진 상태**다. 어느 쪽을 정본으로 할지 정해야 한다 |
| 서비스가 자동 시작이 아니다 | 재부팅하면 꺼진다 — 원내 운영에 못 쓴다 |

## 남은 설계 결정 — 끝났다 (2026-10-12)

**(ㄱ) 읽기 전용 검토용**으로 정했고 코드도 들어갔다.

- `POST /api/admin/import` — 운영에서 export 한 스냅샷을 이 서버로 되읽는다. 덮기 전에 되돌릴
  스냅샷을 먼저 만들고, 되읽을 수 없는 칸(haru·letter)은 `skipped` 로 알리고, 올려 둔 팩 본문은
  지우지 않는다. **워커에는 이 라우트가 없다**(운영을 덮어쓰는 길을 만들지 않는다).
- `WB_READONLY=1` — 그 결정을 서버가 강제한다(위 5번).

그래서 이 점검에서 **이 PC 에서 자료를 올릴 필요는 없다.** 운영 주소의 관리 웹에서 올리고,
이 서버에는 export → import 로 가져와 본다.
