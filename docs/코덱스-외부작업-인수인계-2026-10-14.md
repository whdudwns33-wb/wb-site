## 3. 운영은 WB1에 유지한다

- 학생 앱: https://wb-reading.whdudwns33.workers.dev/naesin-ko/ . Cloudflare Worker + KV.
- 원장·강사 관리: https://korean-admin.wbcowork.com/admin/naesin-ko-admin.html .
  Cloudflare Access → 기존 `wb-apps-wb1` Tunnel → **WB1 `127.0.0.1:8891`**.
- Windows 예약 작업: `\WB 앱\WB 국어 관리자 서버`. 사용자 로그인 때 숨김 기동하며 재시작 설정이 있다.
- WB1 실제 데이터: `%LOCALAPPDATA%\WB\korean-admin-server\db.json`.
- WB1 기동 자격증명: `%LOCALAPPDATA%\WB\naesin-server\admin.credential.xml`.
  해당 Windows 사용자에게 묶인 파일이다. 외부 작업 환경으로 복사하거나 Git에 넣지 않는다.
- WB2는 코드 작업 PC다. 운영 서버를 WB2로 옮기거나 WB1과 같은 데이터 폴더로 연결하지 않는다.

**학생 Worker/KV와 WB1의 관리용 `db.json`은 별도다. 자동 동기화는 없다.**
WB1 관리 화면에서 올린 자료가 학생 Worker에 자동 반영되는 것으로 설명하면 안 된다.
외부 관리 화면은 현재 기존 원장 1명 허용 Access 정책을 유지한다. 다른 사람을 추가하거나 우회하지 않는다.
WB1과 터널이 켜져 있어야 외부 관리 화면을 이용할 수 있다.

검수용 `127.0.0.1:18895`·`:18896` 서버는 WB1의 일회성 합성 자료 환경이다.
그 임시 스크립트·데이터·화면 캡처는 clone에 포함되지 않으며 운영 주소로 쓰지 않는다.

## 4. wb2 또는 새 clone에서 개발하기

wb2에는 Git·Node·GitHub CLI가 있다. GitHub CLI 계정 로그인은 별도로 확인한다.
`gh auth status`가 미로그인이면 원장 계정으로 `gh auth login --hostname github.com --git-protocol https --web`을
실행해 인증한다. WB1의 키나 토큰을 복사하지 않는다. GitHub 인증 전에도 공개 저장소 clone·수정·검사는 가능하다.

다른 컴퓨터에 처음 받을 때:

```powershell
git clone https://github.com/whdudwns33-wb/wb-site.git
Set-Location wb-site
git switch -c codex/ko-followup origin/main
```

이미 준비된 wb2 clone에서는:

```powershell
Set-Location 'C:\Users\wb\Projects\wb-site'
git status --short
git branch --show-current
git fetch origin main
git merge --ff-only origin/main
```

수정 중인 파일과 브랜치를 먼저 확인한다. `reset --hard`나 `clean`으로 사용자 작업을 지우지 않는다.
Node 22 이상으로 다음 검사를 실행한다(설치할 npm 의존성 없음).

```powershell
node scripts/check.mjs
```

이번 WB1 인수인계 검사는 `node scripts/check.mjs --serial` **309/309** 통과했다.
병렬 실행에서는 파일 저장 완료를 확인하는 두 검사에서 간헐 실패가 있었고,
wb2 새 clone도 병렬 308/309 뒤 해당 가족 연결 검사 단독 실행은 통과했다.
같은 문제가 나면 실패 출력을 보존해 원인을 확인하고 `--serial`로 전체를 다시 검사한다.
검사를 생략하거나 실패를 무시해 초록으로 만들지 않는다.

실제 데이터 없이 학생 체험·관리 로그인 화면을 로컬에서 볼 때는 기존 서버를 쓴다:

```powershell
$env:HOST = '127.0.0.1'
$env:PORT = '18898'
$env:DATA_DIR = Join-Path ([IO.Path]::GetTempPath()) ('wb-ko-dev-' + [guid]::NewGuid().ToString('N'))
$env:WB_ADMIN_ONLY = ''
$env:ADMIN_ID = ''
$env:ADMIN_PASSWORD = ''
$env:ADMIN_PIN = 'local-preview-not-production'
node reading-server/server.mjs
```

- 학생 체험: `http://127.0.0.1:18898/naesin-ko/` . 새 브라우저 프로필에서 열면 자체 창작 체험 팩만 사용한다.
- 관리: `http://127.0.0.1:18898/admin/naesin-ko-admin.html` . 위 시험 PIN으로 로그인하며 실제 학생은 없다.
- SSH 터미널에서 서버를 켜고 다른 PC의 브라우저로 볼 때는 별도 터미널에서
  `ssh -L 18898:127.0.0.1:18898 wb2` 후 그 PC의 `http://127.0.0.1:18898/naesin-ko/`를 연다.
  `wb2` 별칭이 없는 환경은 자기 SSH 설정의 실제 호스트를 쓴다.
