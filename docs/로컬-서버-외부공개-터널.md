# 원내 PC 를 서버로 — Cloudflare Tunnel 외부 공개

원장 요청: "클라우드플레어로 외부에서 접속하고 이 컴퓨터를 서버로."
**결정: A — 터널은 원장·강사 전용. 학생은 계속 운영 워커를 쓴다** (2026-10-11 원장 승인).
cloudflared 절차는 같은 날 Cloudflare 공식 문서에서 확인한 것이다.

---

## 0. 결론 셋

1. **도메인 하나가 선행 조건이다.** 지금 `wrangler.toml` 어디에도 `routes`·`custom_domain` 이 없고
   `*.workers.dev` 만 쓰고 있다 — Cloudflare 에 등록된 도메인(zone)이 없다는 뜻이다. 도메인 없이 쓰는
   퀵 터널은 **재시작마다 주소가 바뀌어** 태블릿에 설치된 PWA·저장된 주소가 전부 끊긴다(§3).
2. **데이터가 둘로 갈린다.** 운영 워커는 KV, 이 PC 서버는 `<DATA_DIR>/db.json` 이다.
   ~~옮기는 코드가 없다~~ → **2026-10-12 결정 ㄱ(읽기 전용 검토용)으로 가져오기를 만들었다**:
   `POST /api/admin/import` (로컬 서버 전용, 워커에는 없다). 운영에서 export 해 이 서버로
   되읽는다. 되읽을 수 없는 칸(haru·letter)은 조용히 넘기지 않고 `skipped` 로 알린다 — §1-ㄱ.
3. **보안 헤더는 고쳤다.** 이 서버는 noindex·CSP·X-Frame-Options 를 아무것도 안 붙이고 있었다.
   localhost 전용이라 티가 안 났을 뿐이고, 터널을 붙이면 그대로 공개된다(§2).

## 1. 먼저 정해야 할 것 — 데이터를 어느 쪽에 둘 것인가

| | 운영 워커 `wb-reading` | 이 PC (Node 서버) |
|---|---|---|
| 저장소 | Cloudflare KV | `<DATA_DIR>/db.json` 파일 하나 |
| 학생 기록·시험 범위·팩 | 여기 있다 (지금 쓰는 것) | 빈 상태로 시작한다 |
| 켜고 끔 | 항상 켜짐 | PC 가 꺼지면 앱이 안 열린다 |
| 라이선스 자료 | KV | 원내 디스크 (밖으로 안 나간다) |

**지금 학생 기록은 KV 에 있다.** 터널만 붙이고 학생들이 새 주소를 쓰면 그 기록이 안 보인다.
일부는 워커 주소, 일부는 터널 주소를 쓰면 **기록이 두 갈래로 쌓인다** — 되돌리기 어렵다.

### 결정 — A (확정)

**운영은 워커에 그대로 두고, 터널은 원장·강사 전용으로만 쓴다**(관리 웹·팩 제작 검수).
학생은 계속 워커 주소를 쓴다. 데이터가 갈라지지 않고, 자료 수집·팩 제작을 PC 에서 하는
지금 흐름과 맞는다.

접지 않고 남겨 둔 갈래(나중에 다시 볼 때를 위해):

- **B. 전부 PC 로 이관.** 워커 `/api/admin/export` → `db.json` 인데 **import 경로가 없다.**
  먼저 만들어야 하고(반일 규모), 이관 중 학생 기록이 멈춘다. PC·인터넷이 끊기면 학생 앱
  전체가 멈춘다는 점도 같이 받는다.
- **C. 둘 다 운영.** 같은 학생이 양쪽에 다른 진도를 갖게 된다. 권하지 않는다.
- **A.5 「금고」 — 라이선스 자료만 PC, 학생 기록은 KV.** (2026-10-11 설계·심사까지 마침, 착수 안 함)
  A 와 B 사이다. 학생 기록 12칸(`naesinko:state:*`·`summary:*`·`review:*`·`overlay:*`·`exam:*`·
  `task:*`)은 KV 에 그대로 두고, **라이선스 6칸**(`getPack`/`putPack`·`getPackIds`/`putPackIds`·
  `getPending`/`putPending`)만 PC 로 뺀다. `worker.mjs` 의 국어 분기(`naesinKoStore`)가 메서드 단위로
  이미 갈라져 있어 접합부가 한 군데뿐이다. 학생은 계속 워커 주소를 쓰고 워커가 PC 를 대신 호출한다
  (오리진 하나 — CORS·토큰이 안 갈라진다). `KO_VAULT_URL` 이 없으면 **KV 로 폴백하지 않고 503** 으로
  막는 것이 핵심이다 — 폴백을 두면 시크릿 하나 지우는 순간 족보 본문이 조용히 KV 에 눕는다.

  **지금 안 하는 이유.** ① 금고가 사는 근거는 "라이선스 자료가 제3자 인프라에 at rest 로 안 눕는다"
  하나인데, 권리 두 갈래가 2026-09-03 회신으로 이미 해소됐다(`naesin-ko/README.md`). 풀린 위험에
  가용성을 지불하는 셈이다. ② A 를 고른 이유의 절반인 §6 「PC 가 꺼져도 수업은 안 멈춘다」를
  금고가 깨뜨린다 — 그 팩을 처음 받는 학생은 그날 그 작품을 못 한다(기기 사본을 두지 않는 한).
  ③ `WB_ADMIN_ONLY` 와 기술적으로 충돌하지는 않는다(그 가드는 `/api/login`·`/api/login/status` 둘만
  막고, 금고는 학생 토큰을 검증하지 않는 서버 간 호출이다) — 어긋나는 것은 코드가 아니라 A 의 논거다.

  **다시 볼 조건.** 족보닷컴 이용권이 끝나거나, 범위가 좁아져 "원내 디스크에만 둔다"가 계약 요구가
  될 때. 그때 선행 조건은 이 문서 §3 과 같다 — **도메인 등록이 먼저다**(설계 심사도 독립적으로 같은
  결론에 닿았다). 함께 정해야 할 것: 학생 기기에 팩 사본을 둘 것인가(두면 가용성이 풀리고 라이선스
  자료가 학생 태블릿에 눕는다 — 원장 결정 사항), 금고를 두 대로 둘 것인가(집·학원, 생활 패턴이
  상보적이라 동시에 꺼지는 창이 좁다), 백업 복제 대상(클라우드 동기화 폴더는 쓰지 않는다 — KV 에서
  뺀 자료를 두 번째 제3자 클라우드에 다시 상시 복제하는 일이 된다).

  설계 중에 찾은 **운영 코드 결함들은 금고와 무관하게 이미 고쳤다** — 국어 `/pack` 시험 범위 게이트
  부재(영어에는 있었다)·국어 분기 몸통 상한 부재·팩 수신 실패 시 거짓 안내·시험 범위가 여러 단원일 때
  첫 단원만 열리던 문제.

### ㄱ — 읽기 전용 검토용으로 쓴다 (2026-10-12 결정, 가져오기 구현됨)

로컬 서버는 **운영 자료를 보기만** 하는 자리다. 운영에서 export 해 가져온다:

```bash
# ① 운영에서 뜬다 (관리 토큰 필요)
curl -H "Authorization: Bearer <관리토큰>" \
  https://wb-reading.whdudwns33.workers.dev/api/admin/export > snap.json

# ② 이 PC 서버로 되읽는다 — confirm 이 없으면 거절한다
curl -X POST http://localhost:8890/api/admin/import \
  -H "Authorization: Bearer <로컬관리토큰>" -H "Content-Type: application/json" \
  -d "$(python3 -c "import json,sys;print(json.dumps({'confirm':'replace','snapshot':json.load(open('snap.json'))}))")"
```

**구현이 지키는 것 넷** (`reading-server/admin-import.test.mjs` 가 고정한다):

1. **워커에는 이 라우트를 만들지 않는다.** 운영 데이터를 덮어쓰는 길을 열면 그게 가장 큰
   사고다. `server.mjs` 안에만 있어 구조적으로 로컬 전용이고, 테스트가 `worker.mjs` 에
   그 경로가 생기는 것도 막는다.
2. **덮기 전에 스냅샷을 만든다.** 못 만들면 덮지 않는다(500) — 되돌릴 길 없이 지우지 않는다.
   응답의 `backupDay` 로 `GET /api/admin/export?backup=<날짜>` 하면 되돌릴 수 있다.
3. **되읽을 수 없는 칸을 알린다.** `haru`·`letter` 는 dump 꼴이 저장 꼴과 달라
   (haru 는 `paperkeyIds`·`planIds` 가 없고, letter 의 `images` 는 배열인데 저장은 맵)
   그대로 넣으면 그 앱이 깨진다. `skipped` 로 이유까지 돌려준다.
4. **본문(팩·단어장)을 지우지 않는다.** 스냅샷은 라이선스 본문을 일부러 뺀다. 그 자리를
   빈 값으로 덮으면 올려 둔 팩이 사라지므로, 본문 칸은 건드리지 않고 나머지만 덮는다.

**가장 조용한 함정 — 제자리에서 고쳐야 한다.** `server.mjs` 가 기동 때
`const db = getDb()` 로 저장소 객체의 참조를 붙들고, `haruRoot()`·`letterRoot()` 어댑터도
그 참조를 닫아 둔다. 가져오기가 `db` 를 재할당하면 모듈 안만 새 객체가 되고 **서버는 옛 객체를
계속 본다** — 200 을 받는데 명부가 비어 있는 상태다. 테스트가 가져온 뒤 **다른 라우트로**
읽어 확인한다(일부러 재할당으로 바꿔 실패하는 것도 확인했다).

아직 안 한 것: **쓰기 차단.** (ㄱ)을 끝까지 강제하려면 로컬에서 쓰기를 막는 플래그가 필요하다
(가져오기만 예외). 지금은 가져오기만 있고, 로컬에서 작업하면 여전히 갈라질 수 있다.

### A 를 코드로 강제한다 — `WB_ADMIN_ONLY`

설정만으로 "학생은 안 쓴다"고 두면, 주소가 한 번 새면 그때부터 조용히 갈라진다. 그래서
서버가 거부하게 했다.

```
WB_ADMIN_ONLY=1
```

- `/api/login` 과 `/api/login/status` 가 **403** 을 돌려준다. 토큰은 서명이 아니라 각 저장소에
  든 난수라, 워커가 내준 학생 토큰도 여기서는 검증되지 않는다 — **이 서버에 학생 기록이 생길
  길이 없다.**
- 관리 로그인·관리 웹은 그대로다. 관리 화면들이 학생 앱의 공용 로직 모듈(`/naesin/gen.js` ·
  `/chunk/lessons.js` · `/haru/plan.js` …)을 직접 불러 쓰기 때문에 **그 경로는 막지 않는다** —
  막으면 모드를 켠 순간 관리 웹이 깨진다.
- 기동 때 `[관리 전용]` 한 줄을 찍는다. 터널을 붙인 뒤 이 줄로 확인한다.
- `reading-server/admin-only.test.mjs` 가 양쪽 모드를 실제 HTTP 로 확인한다(거부·관리 웹 생존·
  기본 모드 무영향).

## 2. 이미 고친 것 — 보안 헤더 (코드 반영 완료)

배포 `reading/_headers` 는 전 경로에 이 여섯을 붙인다:
`Content-Security-Policy` · `X-Frame-Options: DENY` · `Referrer-Policy: no-referrer` ·
`X-Content-Type-Options: nosniff` · `X-Robots-Tag: noindex, nofollow, noarchive` · `Permissions-Policy`

**Node 서버는 하나도 안 붙이고 있었다.** `desk/dev-server.mjs`·`crm/dev-server.mjs` 는 `noindex` 를
붙이는데 학생 앱 전부와 관리 웹을 서빙하는 이 서버만 빠져 있었다.

- `reading-server/sec-headers.mjs` — `reading/_headers` 를 **파싱**해 `/*` 블록을 그대로 쓴다.
  값을 베껴 적지 않는다(절대 규칙 3: 정본은 그 파일 하나). noindex 가 없으면 서버가 뜨지 않는다.
- `reading-server/server.mjs` — 핸들러 맨 앞에서 한 번 건다. 라우팅 분기마다 쓰지 않아 빠지지 않는다.
- `reading-server/sec-headers.test.mjs` — 서버를 실제로 띄워 정적·앱·관리·API·404 **다섯 갈래**에서
  여섯 헤더가 정본과 같은지, 경로별 `Cache-Control` 이 보존되는지 확인한다.

## 3. 터널 두 갈래

| | 퀵 터널 | 네임드 터널 |
|---|---|---|
| 도메인 | **불필요** | **필수** (Cloudflare 에 zone 등록) |
| 주소 | `무작위.trycloudflare.com` — **재시작마다 바뀐다** | 고정 (`wb.내도메인/`) |
| 접근 제어 | **URL 아는 사람 누구나** | Cloudflare Access 로 막을 수 있다 |
| 동시 요청 | 200 in-flight 초과 시 429 | 제한 없음 |
| 용도 | Cloudflare 문서상 **테스트·개발 전용**, SLA 없음 | 운영 |

학생 태블릿에 PWA 가 설치돼 있고 주소가 저장돼 있으므로 **주소가 바뀌는 퀵 터널은 쓸 수 없다.**
원장 혼자 잠깐 확인하는 용도로만 쓴다(`cloudflared tunnel --url http://localhost:8890`).

**도메인 하나(연 1~2만원대)를 Cloudflare 에 등록하는 것이 사실상 필요하다.** 그러면 네임드 터널 +
Access 가 열리고, 덤으로 `wb-reading.whdudwns33.workers.dev` 대신 쓸 주소도 생긴다.

## 4. 네임드 터널 — Windows 서비스로 (공식 문서 절차)

관리자 권한 CMD 에서. `<터널이름>`·`<터널ID>`·`wb.내도메인` 은 바꿔 넣는다.

```bat
rem ① cloudflared 를 C:\Cloudflared\bin\cloudflared.exe 로 두고 그 폴더에서 실행
cloudflared.exe service install
mkdir C:\Windows\System32\config\systemprofile\.cloudflared

rem ② 로그인 — 브라우저가 열리고 도메인을 고르면 cert.pem 이 받아진다
cloudflared.exe login
copy C:\Users\%USERNAME%\.cloudflared\cert.pem C:\Windows\System32\config\systemprofile\.cloudflared\cert.pem

rem ③ 터널 만들기 — <터널ID>.json 자격증명이 생긴다
cloudflared.exe tunnel create <터널이름>
copy C:\Users\%USERNAME%\.cloudflared\<터널ID>.json C:\Windows\System32\config\systemprofile\.cloudflared\<터널ID>.json

rem ④ DNS 연결
cloudflared.exe tunnel route dns <터널이름> wb.내도메인

rem ⑤ 규칙 검사
cloudflared.exe tunnel ingress validate
```

`C:\Windows\System32\config\systemprofile\.cloudflared\config.yml`:

```yaml
tunnel: <터널ID>
credentials-file: C:\Windows\System32\config\systemprofile\.cloudflared\<터널ID>.json

ingress:
  - hostname: wb.내도메인
    service: http://localhost:8890
  - service: http_status:404
logfile: C:\Cloudflared\cloudflared.log
```

레지스트리 `HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Services\Cloudflared` 의 `ImagePath` 를
이 한 줄로 바꾼다(공백 하나만 틀려도 서비스가 안 뜬다):

```
C:\Cloudflared\bin\cloudflared.exe --config=C:\Windows\System32\config\systemprofile\.cloudflared\config.yml tunnel run
```

`sc start cloudflared` / 설정 바꾼 뒤엔 `sc stop cloudflared` → `sc start cloudflared`.
**Windows 는 cloudflared 가 자동 갱신되지 않는다** — 수동으로 올려야 한다.

### 서버는 이렇게 띄운다 (서비스 설치 전 확인용)

```bat
set ADMIN_ID=<아이디>
set ADMIN_PASSWORD=<비밀번호>
set DATA_DIR=C:\WB_server_data
set PORT=8890
set WB_ADMIN_ONLY=1
node reading-server\server.mjs
```

`WB_ADMIN_ONLY=1` 을 빠뜨리면 A 안의 전제가 깨진다 — 기동 로그에 `[관리 전용]` 줄이 찍히는지
확인한다. 서비스로 돌릴 때는 이 환경변수도 서비스 계정 쪽에 들어가야 한다.

관리 로그인이 없으면 서버가 뜨지 않는다(의도된 동작). **값을 저장소 파일이나 배치 파일에
적어 커밋하지 않는다** — 절대 규칙 1.

## 5. 관리 웹에는 Cloudflare Access 를 같이 건다

터널만 붙이면 `/admin/*` 이 인터넷에서 열린다. 관리 PIN 한 겹뿐이고, 그 하나로 학생 기록 전체가
열린다. Zero Trust → Access → Application 으로 **`wb.내도메인/admin/*` 에 정책**을 건다
(허용: 원장·강사 이메일. 수단: 이메일 OTP 또는 Google).

그러면 관리 웹은 **Access 통과 → 관리 로그인** 두 겹이 된다. 무료 티어가 있고 한도는 50명
수준으로 알려져 있으나 3자 출처라, 쓰기 전에 Cloudflare 가격 페이지에서 확인한다.

A 안에서는 **호스트 전체에 Access 를 걸어도 된다** — 학생이 이 주소를 쓰지 않으므로 원장·강사
이메일만 허용하면 끝이다. 그게 가장 단단하다.

### ingress 를 경로별로 쪼개지 말 것

cloudflared 의 ingress 규칙은 `path`(Go 정규식)로 경로를 가릴 수 있다. 그래서 "`/admin/` 만
통과"로 짜고 싶어지는데, **권하지 않는다.** 관리 화면이 학생 앱의 공용 모듈을 불러 쓰므로
허용목록에 그 경로들을 전부 적어야 하고, 관리 화면에 모듈이 하나 추가되는 날 **그 화면만
조용히 깨진다**(원인을 찾기 어려운 쪽의 고장이다). 경계는 `WB_ADMIN_ONLY` 가 코드로 지키게 두고
ingress 는 호스트 하나 → `http://localhost:8890` + catch-all 404 로 단순하게 둔다.

## 6. 남는 위험 — 터널을 켜기 전에 읽는다

- **라이선스 자료.** `db.json` 에 이그잼포유 팩·교재 코칭 원문이 산다. 터널은 그 디스크를 외부
  요청에 연결하는 일이다. 인증은 그대로 걸리지만 노출면이 원내 LAN → 인터넷으로 넓어진다.
  A 안 + 호스트 전체 Access 로 두면 그 면이 원장·강사 이메일로 좁혀진다.
- **가용성.** PC 가 꺼지거나 집·학원 인터넷이 끊기면 그 주소는 죽는다. A 안에서는 관리 웹만
  못 쓰는 것이라 수업은 멈추지 않는다 — B 안이면 정전이 곧 수업 중단이다.
- **백업.** `db.json` 파일 하나가 전부다. `/api/admin/backup-now` 와 `listBackups` 가 있지만
  **같은 디스크에 쌓인다** — 디스크가 죽으면 같이 죽는다. 이관할 거면 외부 백업을 먼저 정한다.
- **자동 갱신 없음.** Windows cloudflared 는 수동 업데이트다. 분기마다 올릴 사람을 정한다.
