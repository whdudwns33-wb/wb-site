# 직원 출근 로그인 / 퇴근 로그아웃

일반 직원의 기존 개인 기기 인증 위에 일일 근무 세션을 추가한다. 관리자 개인 링크와 원장 인증은 기존 접속·출퇴근 방식을 유지한다. 학원 IP, 위치 또는 집에서의 접속 제한은 적용하지 않는다.

## 사용과 보존 규칙

- `출근하고 로그인`: 서버가 숫자 4자리 개인 비밀번호를 검증한 뒤 서버 시각으로 최초 출근을 기록한다. 새로고침·재로그인은 이미 기록된 출근 시각을 변경하지 않는다.
- `퇴근하고 로그아웃`: 작성 중인 수업 메모와 미전송 변경을 먼저 저장한다. 저장 실패 시 퇴근 처리하지 않는다. 열린 입력 팝업은 먼저 저장하고 닫아야 한다.
- 화면 종료, 인터넷 끊김, 자정 세션 만료는 자동 퇴근이 아니다. 퇴근을 놓친 기록은 관리자가 확인·수정한다. 해당 날짜에 이미 퇴근했다면 임의로 다시 출근 기록을 덮어쓰지 않는다.
- 일일 로그아웃은 기기 연결, 기존 출퇴근 기록, 로컬 데이터와 보존된 미전송 복구 자료를 삭제하지 않는다. 영구 기기 연결 해제와 구분한다.
- 기존 직원 출퇴근 내보내기·관리자 수정 기능은 그대로 사용한다. 일반 직원은 출퇴근 기록을 수정할 수 없다.

## 직원 정보 관리

출퇴근 조회는 `직원 관리 → 전체 출퇴근 이력 (최근 14일)` 또는 `직원 현황`의 같은 버튼을 사용한다. 기본은 오늘의 전체 직원이며 날짜·직원별 필터와 전체 14일 보기를 제공한다. 출근·퇴근·근무시간·상태를 분리하고, 퇴근 미기록과 확인이 필요한 시각을 별도 색/문구로 표시한다. 기록 없음은 결근 판정이 아니다. 조회 필터는 출퇴근 원본을 변경하지 않는다. 월별 전체 내보내기는 기존 급여용 CSV를 이용한다.

관리자의 직원 관리에서 `연락처 · 로그인 관리`를 연다. 연락처, 출근 로그인 적용 여부, 새 개인 비밀번호를 설정한다. 원문 비밀번호는 조회할 수 없다. 전화번호를 변경하는 것만으로 비밀번호가 자동 변경되지는 않는다.

적용 여부는 `staff_private_profiles.login_enabled`로 지정한다. 미설정 직원·신규 직원에게 자동 적용하지 않는다. 신규 직원에 적용하려면 비밀번호를 먼저 설정하고 출근 로그인을 활성화한다. 관리 권한은 서버의 기존 allowlist가 정본이며, 관리자에게는 이 설정과 무관하게 기존 방식이 적용된다.

## 보안과 API

- `staff_private_profiles`: 관리자 전용 연락처, 개별 salt, PBKDF2-SHA256(100,000회) 검증값. 서버 전용 pepper는 `WB_STAFF_PIN_PEPPER` secret으로 관리한다. generic staff 동기화에 포함하지 않는다.
- 실패 시도는 DB에서 원자적으로 예약한다. 5회 실패 후 5분간 재시도를 제한한다. 4자리 비밀번호는 추측에 취약하므로 기존 개인 기기 bearer 인증을 반드시 함께 요구한다.
- `staff_work_sessions`: 무작위 토큰의 해시만 저장한다. 직원, 기기 토큰 해시, 한국 날짜, 자격증명 revision, 데이터 세대에 연결하고 한국 시각 자정에 만료한다. 브라우저에는 탭의 sessionStorage에만 보관한다.
- `POST /staff-work-session`: `status`, `login`, `logout`. 인증은 기존 `auth`에 일일 토큰인 `workSession`을 추가한다.
- `POST /staff-profile`: 관리자만 `list`, `update`, `reset_pin` 가능. `expectedRevision`을 통해 동시 수정 충돌을 막는다.
- `STAFF_WORK_LOGIN_REQUIRED`(409)는 근무 잠금이다. 기기 인증 실패·데이터 충돌 복구와 구분하며 기존 개인 토큰을 지우지 않는다.

## 배포·운영

1. Git 밖 접근 제한 디렉터리에 운영 DB를 백업하고 별도 DB에 복원 검증한다.
2. `073_staff_work_login.sql` 마이그레이션 적용 후 비공개 프로필을 `login_enabled=0`으로 준비한다. 실제 연락처·PIN·해시는 저장소에 넣지 않는다.
3. `WB_STAFF_PIN_PEPPER`를 secret으로 설정하고 `WB_STAFF_WORK_LOGIN_ENABLED=true`인 Worker를 배포한다.
4. 새 Pages 화면·버전을 확인한 뒤 적용할 일반 직원 프로필만 활성화한다. 이 순서로 구버전 UI가 먼저 잠기는 것을 방지한다.
5. 프로필 건수와 해시 검증, 관리자 예외, 기존 계정·기기 토큰·출퇴근 보존 여부를 재조회한다. 운영 확인을 위해 직원 계정으로 가짜 출근·퇴근을 만들지 않는다.

긴급 원복은 일반 직원의 `login_enabled`를 0으로 돌리거나 Worker 스위치를 끈다. 테이블·기록·기기 토큰을 삭제하지 않는다. pepper를 무작정 교체하면 모든 PIN 검증이 실패하므로 기존 pepper를 보존한다.

테스트: `node --test task/*.test.cjs`, `node --test sync/*.test.mjs`, `git diff --check`. 브라우저 시험은 합성 데이터와 가짜 API를 사용하며 실제 메시지를 발송하지 않는다.
