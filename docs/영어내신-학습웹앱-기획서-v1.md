# 영어 내신 학습 웹앱 기획서 — 단어·본문 암기 + 문제 풀이 (가칭: WB 내신브레인)

> WB 독해력학원 · 웩슬러브레인센터 | 중등 영어 내신 시험대비 웹앱
> 문서 버전 v1.1 · 작성일 2026-09-02
> 이그잼포유(EXAM4YOU)에서 구매한 교과서별 시험대비 자료를 **재원생에게 무료로** 제공하는 **원내 전용** 학습 웹앱.
> 기능 축은 두 개다: **① 단어·본문 암기 ② 문제 풀이.** 외부 배포는 하지 않는다.
> v1.1 — 원장 확정 반영: **최종 도달 목표 3가지**(본문 영→한 해석 / 백지 영어 지문 쓰기 / 시험 전 단어 100% 완성)와 **연습 모드·시험 모드 이원화** (§1.2, §4.2, §4.4).

### 최종 도달 목표 (v1.1 확정)

학생이 이 앱으로 도달해야 하는 상태는 세 가지다. 모든 기능 설계는 이 세 목표를 향해 정렬된다.

1. **본문 해석** — 영어 본문을 보고 한글로 해석할 수 있다.
2. **백지 영작** — 백지 상태에서 영어 지문을 그대로 쓸 수 있다.
3. **단어 선행 완성** — 영어 단어는 **시험 전에** 학습이 전부 끝나 있다.

그리고 사용 시점이 두 가지다: 시험기간의 시험대비뿐 아니라, **시험 전 평상시에 아직 학습이 안 된 학생이 연습하는 용도**가 함께 있다(§4.5 연습 모드).

## 0. 한 줄 요약

**"PDF 묶음을 나눠 주고 끝나는 시험대비"를 "구조화된 데이터 위에서 암기→풀이→오답→재시험이 자동으로 도는 시험대비"로 바꾼다.**
이그잼포유 자료 6종(1개 과 기준 약 1,600문항)을 분석한 결과, 자료의 본질은 **단어 마스터(77개)·본문 문장 마스터(25문장)·문법 패턴(2개)이라는 적은 원천 데이터가 30여 가지 문항 형식으로 변주된 것**이다. 따라서 문항 1,600개를 통째로 옮기는 게 아니라 **마스터 데이터를 정본으로 만들고, 단순 변주 문항은 자동 생성하며, 고유 문항만 저장**한다. 학교마다 출판사가 다르므로 콘텐츠는 **(교과서, 학년, 과) 단위 "레슨 팩"**으로 관리하고, 학생에게는 자기 학교 교과서의 팩만 보인다.

핵심 원칙 네 가지:
1. **암기와 풀이는 한 루프다.** 문제에서 틀린 단어·문장이 암기 큐로 자동 유입되고, 암기가 끝난 대상은 다른 형식의 문제로 재검증된다(나선형).
2. **자동 채점이 기본, 사람은 예외만.** 형식별로 자동/정규화/하이브리드/수동 4단계 채점을 설계해 강사 채점 부담을 최소화한다.
3. **콘텐츠 파이프라인이 제품의 절반이다.** 출판사별 자료는 원장이 계속 업로드한다 — "업로드 → AI 구조화 → 검수 → 배포"가 반복 가능해야 팩이 쌓인다.
4. **구매 콘텐츠는 서버 뒤에만 둔다.** 저장소가 공개(public)이므로 콘텐츠 데이터는 git에 커밋하지 않고, 원생 코드 인증을 통과한 요청에만 워커가 서빙한다.

## 1. 배경 & 전제

### 1.1 왜 이 서비스인가

| 대상 | Pain Point | 이 서비스가 주는 것 |
|------|-----------|-------------------|
| **학생** | 시험대비 자료가 종이 묶음이라 어디까지 외웠는지, 뭘 틀렸는지 관리가 안 됨. 본문 암기는 "그냥 여러 번 읽기"로 때움 | 단어·본문 암기 진도가 눈에 보이고, 틀린 것만 골라 다시 풀 수 있다 |
| **강사** | 자료 배부·단어시험 출제·채점·재시험·오답 관리가 전부 수작업. 학교(출판사)별로 자료가 달라 반 관리가 복잡 | 팩 배정만 하면 훈련·채점·오답 추적이 자동. 수동 채점은 큐로 모아서 처리 |
| **학원** | 구매한 이그잼포유 자료의 활용도가 "인쇄물 배부" 수준에 머묾. 시험대비 품질이 강사 개인기에 의존 | 자료가 디지털 자산이 되고, 시험대비 루틴이 시스템으로 표준화된다 |
| **학부모** | 시험 2주 전 아이가 뭘 하고 있는지 모름 | (후순위) 암기 완료율·정답률 리포트 |

### 1.2 확정된 전제

- **중학교 영어 내신 시험대비**가 목적이다. 학교별로 교과서 출판사가 다르다 → 콘텐츠 구조의 최상위 축은 **교과서(출판사·저자)**다.
- **출판사별 자료는 원장이 직접 업로드한다.** 이번 분석 대상은 NE능률(김기택) 중2 Lesson 6 팩이고, 다른 출판사·다른 과의 팩이 같은 방식으로 계속 들어온다.
- 이그잼포유가 출판사 라이선스를 받아 제작한 **구매 자료**다. 원내 재원생에게 **무료** 제공하며 **외부 배포는 하지 않는다**.
- 학원에는 태블릿 학습존과 기존 학생 계정 체계(QR 코드 + 강사 승인)가 이미 있다.

### 1.3 기존 자산과의 관계

이 앱은 워드브레인(어휘 SRS)·진로독서와 **같은 기술 계보**를 쓰지만 성격이 다르다. 워드브레인은 "평생 가져갈 어휘를 장기 기억으로"(마감 없음), 이 앱은 **"시험일까지 이 범위를 완성"(마감 있음)**이다. 그래서 별도 앱으로 만들되 엔진(SRS·문제 출제·채점)은 모듈로 재사용하고, **시험이 끝난 단어는 워드브레인 정원으로 이관**해 장기 기억 루프로 넘긴다(§4.4).

**합계: 대문항 약 1,640개 / 채점 단위 약 1,700+ — 이것이 "1개 과" 분량이다.** 시험 범위가 보통 2~3개 과이므로 한 번의 시험대비에 3,000~5,000 채점 단위가 움직인다.

### 2.2 분석에서 나온 핵심 발견 5가지

1. **원천 데이터는 작다.** 1,600문항의 원천은 단어 77개, 본문 문장 25개(대화 6개), 문법 패턴 2개뿐이다. WORD TEST의 TEST 1(영→한)·TEST 2(한→영)·TEST 5(영영풀이)는 단어 마스터의 단순 투영이고, 본문 워크북의 빈칸·배열·영작도 문장 마스터에서 파생된다. → **마스터 저장 + 자동 생성** 구조가 정답이다. 저장이 필요한 건 고유 문항(변형·오류문·객관식 등)뿐이다.
2. **정답·해설이 완비되어 있다.** 6종 모두 정답지가 있고 위첨자 각주번호로 문항과 1:1 연결된다. 객관식(08)은 전 문항 한국어 해설, 주관식은 `knocking[knock]`·`if[whether]` 식의 **복수 정답 표기**까지 있다 → 자동 채점기와 오답 피드백의 재료가 이미 준비돼 있다.
3. **문항 형식은 약 30종으로 수렴한다.** 선택형 계열(단일·복수·짝짓기·조합·개수 세기), 빈칸 계열(단어·구·클로즈), 전환·결합(간접의문문, 두 문장 합치기), 배열, 오류 수정, 영작, 해석 쓰기. 이 형식들은 **출판사가 달라도 동일한 이그잼포유 시리즈 틀**이므로, 형식 스키마를 한 번 잘 만들면 다른 출판사 팩에 그대로 재사용된다.
4. **채점 자동화 가능성이 형식별로 갈린다.** 선택·배열·토큰 빈칸은 완전 자동, 영어 단답·영작은 정규화 채점(대소문자·구두점·복수 정답·굴절형 허용)으로 자동화 가능, 한국어 해석 쓰기만 AI 보조+강사 확인이 필요하다(§5.3).
5. **PDF → 데이터 전환의 난점이 명확하다.** ① 밑줄·색상(빈칸 위치의 원천)이 텍스트 추출에서 소실됨 ② 그림 의존 문항(09에 약 43개) ③ 2단 조판 추출 오류 ④ 원본 오탈자 존재 ⑤ 자료 간 본문 문장 분할 불일치(01은 33문장, 02는 25문장) → **AI 추출 + 사람 검수 게이트가 필수**이고, 정본 문장 마스터를 하나로 확정해야 한다(§7).

## 3. 정보 구조 — 학교·출판사·시험 범위

```
학교 (예: ○○중) ──── 교과서 매핑 ────┐
                                        ▼
교과서 (출판사·저자, 예: NE능률(김기택) 중2)
   └─ 레슨 팩 (과 단위, 예: Lesson 6)
        ├─ 단어 마스터 77 · 문장 마스터 25 · 문법 패턴 2   ← 암기 모드의 원천
        └─ 저장 문항 + 자동 생성 문항                        ← 문제 풀이의 원천

시험 (예: ○○중 2-2 중간) = { 학교, 학년, 시험일, 범위: [Lesson 5, 6] }
   └─ 학생은 자기 학교의 시험에 등록 → 범위 팩만 노출 + D-day 플랜 가동
```

- **학생 프로필**: 기존 원생 코드에 `학교·학년` 필드를 추가. 학교→교과서 매핑은 관리 화면에서 원장·강사가 관리한다(한 번 입력하면 그 학교 학생 전원에 적용).
- **레슨 팩**: 콘텐츠의 배포 단위. 상태를 갖는다 — `추출 중 → 검수 중 → 배포됨`. 검수 통과 전에는 학생에게 보이지 않는다.
- **시험**: 학습의 목표 단위. 시험일이 있어야 D-day 플랜(§5.4)과 "시험 끝난 단어 이관"(§4.4)이 성립한다.

## 4. 기능 기획 A — 단어·본문 암기 모드

### 4.1 단어 암기 (원천: WORD TEST 학습자료부)

워드브레인의 검증된 엔진(`vocab/srs.js`·`quiz.js`)을 재사용하되, **시험 마감형으로 튜닝**한다.

| 요소 | 설계 | 원천 데이터 |
|------|------|------------|
| 카드 | 앞면 영어 / 뒷면 뜻+예문+영영풀이+유의·반의. 다의어 12단어는 **의미별 카드로 분리** | 단어 77 + 예문 68 + 영영풀이 50 + senses 28 |
| 훈련 모드 | 플래시카드(자기 채점) / 노출 깜빡이(워밍업·저마찰 복습) / 스피드 리콜(인출 자동화) — 워드브레인 3종 그대로 | — |
| 판정 퀴즈 | 뜻 4지선다 → 철자 입력(첫 글자 힌트) → 예문 빈칸 → 듣고 고르기(TTS). 오답 보기는 같은 팩의 다른 단어에서 추출 | 자동 생성 |
| 스케줄 | SRS 간격을 **시험일 기준으로 압축**(시험 D-14면 1→2→4→7일 식으로 재배치). "오늘 외울 단어"가 시험일까지 전 범위를 커버하도록 자동 배분 | 시험 엔티티 |
| 진도 | "77개 중 암기 완료 n개 · 위험 m개" — 섹션(대화문/본문)별 필터 | MasteryState |

### 4.2 본문 암기 — 6단계 사다리 (원천: 본문 10단계 워크북 + 내용정리 플러스)

본문 암기는 "여러 번 읽기"가 아니라 **문장 단위 인출 훈련의 사다리**로 설계한다. 최종 목표 두 가지(영→한 해석, 백지 영작)가 사다리의 양 끝을 정의한다 — **해석은 2단계에서 먼저 잡고, 백지 쓰기가 최종 관문**이다.

```
1단계  대역 읽기      영·한 나란히 + TTS 듣기 (워크북1 해석지)              — 입력
2단계  해석 쓰기      영어 문장 보고 한글 해석 입력 → 모범 해석 대조         — 목표① 해석 (영→한)
                     (셀프 체크 + AI 보조 판정, 워크북4)
3단계  핵심어 가리기   문장의 핵심어만 빈칸 (워크북2·3: 한글 힌트→영어)       — 부분 인출
4단계  구 단위 클로즈  빈칸이 구 단위로 확대 (내용정리 플러스 클로즈)          — 확장 인출
       + 순서 배열    어구 토큰 셔플 → 드래그 재조립 (워크북8)               — 구조 인출
5단계  문장 영작      한글만 보고 문장 전체 입력, 정규화 채점 (워크북9)        — 완전 인출
6단계  백지 쓰기      화면에 아무 힌트 없이 단락 → 지문 전체를 통째로 입력      — 목표② 백지 영작
                     문장 단위 자동 대조 채점 + 빠뜨린 문장·틀린 부분 표시
```

- **백지 쓰기 설계**: 단락(8/1 → 8/2 → 8/3) 단위로 먼저 통과한 뒤 지문 전체에 도전한다. 채점은 입력 전문을 문장 단위로 분할·정렬해 정규화 대조(문장 누락·순서 바뀜·표현 오류를 각각 표시)하고, 시험 직전에는 종이 백지 시험과 병행할 수 있게 **강사용 "백지 채점 보조"**(학생이 쓴 종이를 보고 문장별 ○× 입력)도 둔다.
- **문장별 진도**: 25문장 각각이 현재 단계를 가진다. 6단계(백지) 통과 = "암송 완료". 단락 단위 묶음 훈련 제공.
- **연결 학습**: 본문 훈련 중 모르는 단어를 탭하면 해당 단어 카드로 점프(문장 keywords ↔ 단어 마스터가 연결되어 있다).
- **문법 개념 카드**: 패턴 2개(지각동사·간접의문문)의 개념 설명+교과서 예문을 암기 모드의 "개념 탭"에 노출 — 본문 문장 중 해당 패턴 문장에 태그가 붙는다.
- 대화문 6개도 같은 사다리를 축소 적용(1→2→5단계).

### 4.3 하루 루프 (원내 10분 + 가정)

```
(1분) 오늘의 시험 현황 — D-n, 오늘 할당량(단어 x개 · 본문 y문장 · 문제 z개)
(4분) 단어 물 주기 — SRS 큐 (판정 퀴즈)
(4분) 본문 사다리 — 오늘의 문장들 다음 단계 도전
(1분) 오답노트 미리보기 — 내일 풀 문제 확인
(밤 21:00) 푸시 — 오늘 외운 단어·문장 깜빡이 3분 (기존 크론 재사용)
```

### 4.4 연습 모드 · 시험 모드 이원화 (v1.1)

이 앱은 시험기간 전용이 아니다. **시험 전 평상시에 아직 학습이 안 된 학생이 연습하는 용도**가 함께 있다.

| | **연습 모드 (상시)** | **시험 모드 (시험 등록 시)** |
|---|---|---|
| 대상 | 아직 범위 학습이 안 된 학생, 선행 학습 | 시험이 등록된 학생 전원 |
| 스케줄 | 자율 진도 + SRS 표준 간격(마감 없음) | 시험일 역산 D-day 플랜(간격 압축) |
| 진도 순서 | 단어 → 본문 사다리 → 문제 (권장 순서 안내) | **단어 선행 완성 게이트** 적용 |
| 목표 | 사다리 단계·단어 완료 수 자체가 목표 | 시험 범위 완성률 100% |

- **단어 선행 완성 게이트(목표③)**: 시험 모드에서 단어의 마감일은 시험일이 아니라 **시험 D-7(기본값, 조정 가능)**이다. D-day 플랜이 단어를 먼저 끝내도록 할당을 편성하고, 단어 미완성 상태에서는 오늘 할당이 단어 우선으로 자동 재편성된다. 단어가 끝나야 본문 사다리 상위 단계(5·6단계)와 실전 트랙이 열린다 — "단어도 안 외우고 백지 쓰기"를 구조적으로 막는다.
- **모드 전환**: 연습 모드에서 쌓은 진도(단어 숙련도·문장 단계)는 시험 모드에 그대로 승계된다 — 미리 연습한 학생일수록 시험 모드 할당이 가벼워지는 것이 눈에 보이게 한다(연습 동기).

### 4.5 시험 후: 워드브레인 이관

시험일이 지나면 그 팩의 단어 중 **암기 완료된 것을 워드브레인(영어 정원)으로 이관 제안**한다 — "시험 끝났다고 버리는 단어"가 아니라 장기 기억 루프로 넘어간다. 내신 앱은 마감형 단기 루프, 워드브레인은 평생형 장기 루프라는 분업이 완성된다.

### 5.1 트랙 구성 (자료 → 학습 트랙 매핑)

| 트랙 | 원천 | 성격 |
|------|------|------|
| **단어 시험** | WORD TEST 1~6 | TEST 1·2·5는 마스터에서 자동 생성(무한 재출제 가능), TEST 3·4·6은 저장 문항. 강사가 "범위 지정 단어시험"으로도 출제 |
| **문법 기본 훈련** | Grammar 워크북(07) + 주관식(09) 기본편 | 파트별 소단위 세트(10~20문항). 서답형 중심 |
| **문법 실전** | Grammar 객관식(08) + 주관식(09) 실전편 | 내신형. 타이머·즉시 채점·전 문항 해설 |
| **본문 변형** | 본문 워크북 5·6·7·10 + 내용정리 플러스 점검 문항 | 동사형·어법 선택·어색한 곳 찾기·내용 일치 — 본문 암기와 직결 |
| **종합 모의** | 워크북10 Check + 각 자료 실전편 조합 | 시험 직전 D-3 모드. 범위 전체에서 형식 혼합 출제 |

### 5.2 풀이 화면 원칙

- 한 세트 = 10~20문항, 문항 단위 즉시 채점(세트 끝 일괄 채점은 시험 모드만).
- 오답 시 **정답 + 정답지 해설 + 연결된 마스터 카드**(단어/문장/문법 개념)를 함께 보여 준다 — 틀린 순간이 가장 잘 배우는 순간.
- 형식별 입력 UI: 선택형(탭), 빈칸(토큰 입력, 칸 수 힌트), 배열(드래그앤드롭), 서답형(한 줄 입력), 오류 수정(틀린 부분 탭 → 고쳐 쓰기).
- 밑줄·강조는 RichText span으로 복원해 원본 지면과 동일하게 렌더링.

### 5.3 채점 4단계

| 모드 | 대상 형식 | 동작 |
|------|----------|------|
| **auto** | 선택형 전체, 배열형, 토큰 빈칸, 철자 배열, 다의어 번호, O/X | 완전 자동 |
| **auto_norm** | 영어 단답·전환·결합·영작·클로즈 | 정규화 채점기: 대소문자·구두점·축약형(don't=do not)·복수 정답(`knocking[knock]`)·어형 표기 허용. 원본 정답지의 대체 정답 표기를 파싱해 accepted 배열로 |
| **hybrid** | 조건 영작, 문장 전체 재작성형 오류 수정 | 자동 1차 판정 → 불일치 답안만 "검토 큐"로. AI가 정오 소견을 달아 강사가 원터치 확정 |
| **manual** | 한국어 해석 쓰기(워크북4) | AI 보조 채점(루브릭 기반) + 강사 확인. 부담이 크면 이 형식은 "셀프 체크"(모범 해석 보고 스스로 ○×)로 강등하는 선택지도 있다(→ §13) |

### 5.4 오답노트와 나선형 재출제

- 모든 응답은 문항·빈칸 단위로 기록된다(AttemptRecord, append-only).
- 오답 → 오답노트 적립 + 연결된 단어·문장·패턴의 MasteryState 하락 → **암기 큐에 자동 재투입**.
- 재도전은 **같은 타깃의 다른 형식**으로 출제한다(예: TEST 4 빈칸에서 틀린 hug → 플래시카드 재학습 → TEST 1 유형으로 재검증). 같은 문제를 다시 풀어 "답 외우기"가 되는 것을 막는다.
- 오답 클리어 정책: 재도전 2회 연속 정답 시 클리어(정책값, 조정 가능).
- **D-day 플랜**: 시험일 역산으로 "오늘의 할당"을 자동 편성 — D-14~8 암기 중심, D-7~4 기본 훈련, D-3~1 실전·종합 모의 + 오답 총정리. 편성 비율은 강사가 조정 가능.

## 7. 콘텐츠 파이프라인 — "원장이 업로드하면 팩이 된다"

출판사별 자료는 원장이 계속 업로드한다. 이 파이프라인이 반복 가능해야 앱이 자란다.

```
[1] 업로드      원장이 관리 화면에서 과 단위 PDF 묶음 업로드 (01·02·03·07·08·09 시리즈)
[2] AI 추출     시리즈 유형별 추출 템플릿으로 구조화 (Claude API — 기존 AI 파이프라인 재사용)
                · 마스터 추출: 단어(뜻·예문·영영풀이·다의어·유의반의) / 본문 문장(영·한·핵심어) / 문법 개념
                · 문항 추출: 발문·자극·보기·정답·해설 + 복수 정답 파싱 + 각주번호로 정답 병합
[3] 검수 게이트  검수 화면에서 원장·강사가 확인 (AI 초안 → 사람 확정 — 그림검사·진로독서 검증 패턴)
                · 자동 검증: 문항-정답 수 일치, 빈칸-정답 수 일치, 보기 중복, 마스터 참조 무결성
                · 사람 검수: 밑줄 위치 태깅, 그림 문항 대체 텍스트, 오탈자 교정, 표본 채점 테스트
[4] 배포        팩 상태 '배포됨' → 학생 노출. 버전 관리(수정 재배포 가능)
```

- **시리즈 템플릿의 힘**: 이그잼포유 자료는 출판사가 달라도 같은 시리즈 틀(WORD TEST 6종 구성, 본문 10단계, Grammar Build Up 3종)을 쓴다. 추출 템플릿을 시리즈 유형별로 만들어 두면 **새 출판사 팩도 같은 파이프라인으로 처리**된다. NE능률 6과 팩이 템플릿을 다듬는 파일럿이 된다.
- **알려진 난점과 대응**(분석 §2.2-5): 밑줄·색상 소실 → 검수 단계의 span 태깅 UI로 복원(빈칸 위치의 원천이므로 생략 불가). 그림 문항 → 정답에서 역산한 상황 설명 텍스트로 대체(기본값), 필요 시 이미지 크롭. 2단 조판 추출 오류·오탈자 → 자동 검증 + 표본 채점으로 걸러냄. 문장 분할 불일치 → 검수 단계에서 정본 문장 마스터 확정.
- **검수 비용의 현실**: 1개 팩(6종) 완전 검수는 첫 회에 수 시간이 걸린다. 자동 생성 가능한 부분(마스터·파생 문항)을 먼저 배포하고 고유 문항을 증분 배포하는 "부분 배포"를 지원해, 시험 일정에 파이프라인이 병목이 되지 않게 한다.

### 9.2 아키텍처

- **학생 앱 `/naesin/`**: 정적 PWA(vanilla HTML/CSS/JS) — 기존 앱들과 동일 스택. 오프라인 캐시로 태블릿 학습존 대응.
- **관리 화면**: 팩 업로드·검수·시험 관리·검토 큐 — workbench 계열 또는 `/naesin/admin.html`(강사 PIN).
- **서버**: 기존 `wb-reading` 워커에 `naesin-api.mjs` 라우트 모듈 추가(워드브레인의 `vocab-api.mjs` 선례). KV 네임스페이스는 분리를 검토(팩 데이터가 크므로 — §13).
- **콘텐츠 서빙**: 팩 JSON은 **KV에만 존재**하며, 원생 코드 인증을 통과한 요청에 과 단위로 서빙. 정적 자산으로는 절대 노출하지 않는다.
- **채점**: auto·auto_norm은 클라이언트+서버 이중 채점(기록은 서버 판정 기준), hybrid·manual은 서버에서 AI 소견 생성 후 검토 큐로.

### 9.3 저장소가 public이라는 사실의 함의

- **구매 콘텐츠(팩 데이터·PDF 원본·추출 JSON)는 git에 커밋하지 않는다.** 코드와 콘텐츠를 물리적으로 분리한다 — 콘텐츠는 업로드 파이프라인을 통해 KV로만 들어간다.
- 시드·테스트 데이터는 자체 제작 더미 문장으로 만든다(교과서·이그잼포유 문구 사용 금지).
- ※ 참고: 기존 `reading/textbook.json`(교과서 코칭 원문)은 공개 저장소에 커밋된 채 워커에서 서빙만 막고 있다 — GitHub에서는 열람 가능하므로 같은 방식을 답습하지 않고, 별도 정리를 권고한다.

## 10. 저작권·보안

이그잼포유 자료는 "출판사 라이선스를 획득해 제작, 무단 전재·배포 금지" 고지가 있는 구매 콘텐츠다. **원내 재원생 무료 제공**이라는 사용 형태를 지키기 위한 장치:

1. **라이선스 범위 서면 확인(선행 과제).** "구매 학원이 재원생 한정 디지털 학습 도구에 탑재"가 허용 범위인지 이그잼포유에 서면으로 확인한다. 이것이 프로젝트 전체의 전제다 — Phase 0에 배치(§12).
2. **접근 통제**: 원생 코드 인증 없이는 콘텐츠 API가 아무것도 반환하지 않는다. 계정은 QR 배부+강사 승인(기존 체계). 퇴원 처리 시 접근 자동 차단.
3. **노출 최소화**: `noindex,nofollow` + `X-Robots-Tag`(기존 `_headers` 패턴), `Cache-Control: no-store`, 콘텐츠는 과 단위 필요 분량만 서빙(전체 덤프 API 없음).
4. **유출 억제**: 화면에 학생 이름·코드 워터마크(캡처 유출 추적), 인쇄는 강사 권한의 단어시험지만. PDF 원본은 앱에서 제공하지 않는다(구조화 데이터만).
5. **저장 분리**: §9.3 — 공개 저장소에 콘텐츠 불포함.
6. **출처 표기**: 앱 내 자료 화면에 "이그잼포유 제작·본 학원 구매 자료, 원내 학습 전용" 고지 상시 표기.

## 11. KPI

- **North Star: 시험 범위 완성률** — 시험일까지 (암기 완료 단어 + 암송 완료 문장 + 트랙 1회전) 달성 비율.
- 암기: 단어 77개 중 완료 수, 본문 25문장 중 5단계 도달 수, 일일 할당 완수율, 21시 복습 실행률.
- 풀이: 트랙별 정답률 추이(기본→실전), 오답 클리어율, 재출제 통과율(다른 형식 재검증 성공).
- 운영: 팩 추출→배포 소요 시간, 검수에서 잡은 오류 수, 강사 검토 큐 처리 시간, 수동 채점 비중.
- 성과(외부 지표): 시험 점수 입력(선택) → 완성률과 점수의 상관을 학기 단위로 확인.

## 13. 열어 둔 결정 (원장 확인 필요)

1. **라이선스 확인 방법과 시점** — 이그잼포유 서면 확인을 누가·언제. (미확인 상태로 개발은 진행하되 배포는 보류하는 안 vs 확인 후 착수)
2. **한국어 해석 쓰기(워크북4)의 채점 방식** — AI 보조+강사 확인 vs 모범 해석 셀프 체크로 단순화.
3. **서비스명** — 내신브레인 / 시험비서 / 기타. 학생에게 보이는 이름이므로 브랜딩과 함께.
4. **KV 분리 여부** — 기존 wb-reading KV에 얹을지, 내신 전용 네임스페이스(또는 R2)로 분리할지. 팩 데이터 크기(과당 수백 KB~수 MB) 실측 후 결정 권장.
5. **그림 문항 43개 처리** — 상황 설명 텍스트 대체(기본안) vs 이미지 크롭 병행.
6. **`reading/textbook.json` 정리** — 공개 저장소에 커밋된 기존 교과서 원문의 이력 정리 여부(이 앱과 별건이나 같은 성격의 리스크).
7. **시험 점수 입력** — 학생 자가 입력 vs 강사 입력 vs 미수집.
