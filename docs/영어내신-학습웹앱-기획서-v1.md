# 영어 내신 학습 웹앱 기획서 — 단어·본문 암기 + 문제 풀이 (가칭: WB 내신브레인)

> WB 독해력학원 · 웩슬러브레인센터 | 중등 영어 내신 시험대비 웹앱
> 문서 버전 v1.1 · 작성일 2026-09-02
> 이그잼포유(EXAM4YOU)에서 구매한 교과서별 시험대비 자료를 **재원생에게 무료로** 제공하는 **원내 전용** 학습 웹앱.
> 기능 축은 두 개다: **① 단어·본문 암기 ② 문제 풀이.** 외부 배포는 하지 않는다.
> v1.1 — 원장 확정 반영: **최종 도달 목표 3가지**(본문 영→한 해석 / 백지 영어 지문 쓰기 / 시험 전 단어 100% 완성)와 **연습 모드·시험 모드 이원화** (§1.2, §4.2, §4.4).
> v1.2 — 울트라 재점검(5개 관점 독립 검토 → 종합) 결과 반영: **혁신 개선안 5가지 채택** (§14) 및 관련 조항 수정 (§4.1·4.2·4.4·5.4·6·8·11·12·13).
> v1.4 — 본문 암기 재설계 (§16): 독해를 못하는 학생을 전제로 뜻(한글)을 청크 단위로 먼저 세우고 줄 → 단락으로 올리며, 단서를 점진적으로 지운다.
> v1.3 — 운영 투입 전 전면 점검(결함 64건 수정) 후, 앱 밖의 세 축을 보완 과제로 채택 (§15): 성과 검증 루프와 통합 시험 범위 · 팩 제작 스튜디오 · 강사 수업 운영 화면.

### 최종 도달 목표 (v1.1 확정)

학생이 이 앱으로 도달해야 하는 상태는 세 가지다. 모든 기능 설계는 이 세 목표를 향해 정렬된다.

1. **본문 해석** — 영어 본문을 보고 한글로 해석할 수 있다.
2. **백지 영작** — 백지 상태에서 영어 지문을 그대로 쓸 수 있다.
3. **단어 선행 완성** — 영어 단어는 **시험 전에** 학습이 전부 끝나 있다.

그리고 사용 시점이 두 가지다: 시험기간의 시험대비뿐 아니라, **시험 전 평상시에 아직 학습이 안 된 학생이 연습하는 용도**가 함께 있다(§4.5 연습 모드).

## 0. 한 줄 요약

**"PDF 묶음을 나눠 주고 끝나는 시험대비"를 "구조화된 데이터 위에서 암기→풀이→오답→재시험이 자동으로 도는 시험대비"로 바꾼다.**
이그잼포유 자료 6종(1개 과 기준 약 1,600문항)을 분석한 결과, 자료의 본질은 **단어 마스터(77개)·본문 문장 마스터(25문장)·문법 패턴(2개)이라는 적은 원천 데이터가 30여 가지 문항 형식으로 변주된 것**이다. 따라서 문항 1,600개를 통째로 옮기는 게 아니라 **마스터 데이터를 정본으로 만들고, 단순 변주 문항은 자동 생성하며, 고유 문항만 저장**한다. 학교마다 출판사가 다르므로 콘텐츠는 **(교과서, 학년, 과) 단위 "레슨 팩"**으로 관리하고, 학생에게는 자기 학교 교과서의 팩만 보인다.

핵심 원칙 네 가지:
1. **암기와 풀이는 한 루프다.** 문제에서 틀린 단어·문장이 암기 큐로 자동 유입되고, 암기가 끝난 대상은 다른 형식의 문제로 재검증된다(나선형).
2. **자동 채점이 기본, 사람은 예외만.** 형식별로 자동/정규화/하이브리드/수동 4단계 채점을 설계해 강사 채점 부담을 최소화한다.
3. **콘텐츠 파이프라인이 제품의 절반이다.** 출판사별 자료는 원장이 계속 업로드한다 — "업로드 → AI 구조화 → 검수 → 배포"가 반복 가능해야 팩이 쌓인다.
4. **구매 콘텐츠는 서버 뒤에만 둔다.** 저장소가 공개(public)이므로 콘텐츠 데이터는 git에 커밋하지 않고, 원생 코드 인증을 통과한 요청에만 워커가 서빙한다.

## 1. 배경 & 전제

### 1.1 왜 이 서비스인가

| 대상 | Pain Point | 이 서비스가 주는 것 |
|------|-----------|-------------------|
| **학생** | 시험대비 자료가 종이 묶음이라 어디까지 외웠는지, 뭘 틀렸는지 관리가 안 됨. 본문 암기는 "그냥 여러 번 읽기"로 때움 | 단어·본문 암기 진도가 눈에 보이고, 틀린 것만 골라 다시 풀 수 있다 |
| **강사** | 자료 배부·단어시험 출제·채점·재시험·오답 관리가 전부 수작업. 학교(출판사)별로 자료가 달라 반 관리가 복잡 | 팩 배정만 하면 훈련·채점·오답 추적이 자동. 수동 채점은 큐로 모아서 처리 |
| **학원** | 구매한 이그잼포유 자료의 활용도가 "인쇄물 배부" 수준에 머묾. 시험대비 품질이 강사 개인기에 의존 | 자료가 디지털 자산이 되고, 시험대비 루틴이 시스템으로 표준화된다 |
| **학부모** | 시험 2주 전 아이가 뭘 하고 있는지 모름 | (후순위) 암기 완료율·정답률 리포트 |

### 1.2 확정된 전제

- **중학교 영어 내신 시험대비**가 목적이다. 학교별로 교과서 출판사가 다르다 → 콘텐츠 구조의 최상위 축은 **교과서(출판사·저자)**다.
- **출판사별 자료는 원장이 직접 업로드한다.** 이번 분석 대상은 NE능률(김기택) 중2 Lesson 6 팩이고, 다른 출판사·다른 과의 팩이 같은 방식으로 계속 들어온다.
- 이그잼포유가 출판사 라이선스를 받아 제작한 **구매 자료**다. 원내 재원생에게 **무료** 제공하며 **외부 배포는 하지 않는다**.
- 학원에는 태블릿 학습존과 기존 학생 계정 체계(QR 코드 + 강사 승인)가 이미 있다.

### 1.3 기존 자산과의 관계

이 앱은 워드브레인(어휘 SRS)·진로독서와 **같은 기술 계보**를 쓰지만 성격이 다르다. 워드브레인은 "평생 가져갈 어휘를 장기 기억으로"(마감 없음), 이 앱은 **"시험일까지 이 범위를 완성"(마감 있음)**이다. 그래서 별도 앱으로 만들되 엔진(SRS·문제 출제·채점)은 모듈로 재사용하고, **시험이 끝난 단어는 워드브레인 정원으로 이관**해 장기 기억 루프로 넘긴다(§4.4).

**합계: 대문항 약 1,640개 / 채점 단위 약 1,700+ — 이것이 "1개 과" 분량이다.** 시험 범위가 보통 2~3개 과이므로 한 번의 시험대비에 3,000~5,000 채점 단위가 움직인다.

### 2.2 분석에서 나온 핵심 발견 5가지

1. **원천 데이터는 작다.** 1,600문항의 원천은 단어 77개, 본문 문장 25개(대화 6개), 문법 패턴 2개뿐이다. WORD TEST의 TEST 1(영→한)·TEST 2(한→영)·TEST 5(영영풀이)는 단어 마스터의 단순 투영이고, 본문 워크북의 빈칸·배열·영작도 문장 마스터에서 파생된다. → **마스터 저장 + 자동 생성** 구조가 정답이다. 저장이 필요한 건 고유 문항(변형·오류문·객관식 등)뿐이다.
2. **정답·해설이 완비되어 있다.** 6종 모두 정답지가 있고 위첨자 각주번호로 문항과 1:1 연결된다. 객관식(08)은 전 문항 한국어 해설, 주관식은 `knocking[knock]`·`if[whether]` 식의 **복수 정답 표기**까지 있다 → 자동 채점기와 오답 피드백의 재료가 이미 준비돼 있다.
3. **문항 형식은 약 30종으로 수렴한다.** 선택형 계열(단일·복수·짝짓기·조합·개수 세기), 빈칸 계열(단어·구·클로즈), 전환·결합(간접의문문, 두 문장 합치기), 배열, 오류 수정, 영작, 해석 쓰기. 이 형식들은 **출판사가 달라도 동일한 이그잼포유 시리즈 틀**이므로, 형식 스키마를 한 번 잘 만들면 다른 출판사 팩에 그대로 재사용된다.
4. **채점 자동화 가능성이 형식별로 갈린다.** 선택·배열·토큰 빈칸은 완전 자동, 영어 단답·영작은 정규화 채점(대소문자·구두점·복수 정답·굴절형 허용)으로 자동화 가능, 한국어 해석 쓰기만 AI 보조+강사 확인이 필요하다(§5.3).
5. **PDF → 데이터 전환의 난점이 명확하다.** ① 밑줄·색상(빈칸 위치의 원천)이 텍스트 추출에서 소실됨 ② 그림 의존 문항(09에 약 43개) ③ 2단 조판 추출 오류 ④ 원본 오탈자 존재 ⑤ 자료 간 본문 문장 분할 불일치(01은 33문장, 02는 25문장) → **AI 추출 + 사람 검수 게이트가 필수**이고, 정본 문장 마스터를 하나로 확정해야 한다(§7).

## 3. 정보 구조 — 학교·출판사·시험 범위

```
학교 (예: ○○중) ──── 교과서 매핑 ────┐
                                        ▼
교과서 (출판사·저자, 예: NE능률(김기택) 중2)
   └─ 레슨 팩 (과 단위, 예: Lesson 6)
        ├─ 단어 마스터 77 · 문장 마스터 25 · 문법 패턴 2   ← 암기 모드의 원천
        └─ 저장 문항 + 자동 생성 문항                        ← 문제 풀이의 원천

시험 (예: ○○중 2-2 중간) = { 학교, 학년, 시험일, 범위: [Lesson 5, 6] }
   └─ 학생은 자기 학교의 시험에 등록 → 범위 팩만 노출 + D-day 플랜 가동
```

- **학생 프로필**: 기존 원생 코드에 `학교·학년` 필드를 추가. 학교→교과서 매핑은 관리 화면에서 원장·강사가 관리한다(한 번 입력하면 그 학교 학생 전원에 적용).
- **레슨 팩**: 콘텐츠의 배포 단위. 상태를 갖는다 — `추출 중 → 검수 중 → 배포됨`. 검수 통과 전에는 학생에게 보이지 않는다.
- **시험**: 학습의 목표 단위. 시험일이 있어야 D-day 플랜(§5.4)과 "시험 끝난 단어 이관"(§4.4)이 성립한다.

## 4. 기능 기획 A — 단어·본문 암기 모드

### 4.1 단어 암기 (원천: WORD TEST 학습자료부)

워드브레인의 검증된 엔진(`vocab/srs.js`·`quiz.js`)을 재사용하되, **시험 마감형으로 튜닝**한다.

| 요소 | 설계 | 원천 데이터 |
|------|------|------------|
| 카드 | 앞면 영어 / 뒷면 뜻+예문+영영풀이+유의·반의. 다의어 12단어는 **의미별 카드로 분리** | 단어 77 + 예문 68 + 영영풀이 50 + senses 28 |
| 훈련 모드 | 플래시카드(자기 채점) / 노출 깜빡이(워밍업·저마찰 복습) / 스피드 리콜(인출 자동화) — 워드브레인 3종 그대로 | — |
| 판정 퀴즈 | 뜻 4지선다 → 철자 입력(첫 글자 힌트) → 예문 빈칸 → 듣고 고르기(TTS). 오답 보기는 같은 팩의 다른 단어에서 추출 | 자동 생성 |
| 스케줄 | SRS 간격을 **시험일 기준으로 압축**(시험 D-14면 1→2→4→7일 식으로 재배치). "오늘 외울 단어"가 시험일까지 전 범위를 커버하도록 자동 배분 | 시험 엔티티 |
| 진도 | "77개 중 안정화 n개 · 도달 m개 · 위험 k개" — 섹션(대화문/본문)별 필터 | MasteryState |

**v1.2 보강 — 출발선 진단과 안정화 게이지 (§14-1)**

- **2분 사전 인출 진단**: 팩 진입 첫 세션은 카드 학습이 아니라 고속 진단이다(영→한 4지선다, 문항당 5~8초, '모름' 버튼). 이미 아는 단어는 신규 학습 큐를 건너뛰어 "77개 중 31개는 이미 안다 — 새로 외울 것은 46개"처럼 개인 출발선이 첫날부터 보이고, D-day 할당도 그 기준으로 편성된다. 진단 통과 단어도 안정화 트랙에서 철자 입력으로 1회 재검증한다(4지선다 재인의 관대함 보정).
- **암기 '완료'의 재정의**: [기준 도달] = 힌트 없는 완전 인출 1회 성공 / [안정화] = 도달 후 **서로 다른 날 3회** 기준 재도달(successive relearning). 화면은 단어마다 0~3칸 안정도 게이지 — "한 번 외웠다"가 아니라 "시험일에 꺼낼 수 있다"가 완료다.
- **확신도 3버튼**: 모든 인출 응답에 확실/애매/찍음 스와이프 — 정답+찍음이면 간격을 늘리지 않고, 오답+확실(과신 오류)이면 최단 간격으로 우선 재출제한다. 확신도는 UX 장식이 아니라 스케줄러의 입력이다.

### 4.2 본문 암기 — 6단계 사다리 (원천: 본문 10단계 워크북 + 내용정리 플러스)

본문 암기는 "여러 번 읽기"가 아니라 **문장 단위 인출 훈련의 사다리**로 설계한다. 최종 목표 두 가지(영→한 해석, 백지 영작)가 사다리의 양 끝을 정의한다 — **해석은 2단계에서 먼저 잡고, 백지 쓰기가 최종 관문**이다.

```
1단계  대역 읽기      영·한 나란히 + TTS 듣기 (워크북1 해석지)              — 입력
2단계  해석 쓰기      영어 문장 보고 한글 해석 입력 → 모범 해석 대조         — 목표① 해석 (영→한)
                     (셀프 체크 + AI 보조 판정, 워크북4)
3단계  핵심어 가리기   문장의 핵심어만 빈칸 (워크북2·3: 한글 힌트→영어)       — 부분 인출
4단계  구 단위 클로즈  빈칸이 구 단위로 확대 (내용정리 플러스 클로즈)          — 확장 인출
       + 순서 배열    어구 토큰 셔플 → 드래그 재조립 (워크북8)               — 구조 인출
5단계  문장 영작      한글만 보고 문장 전체 입력, 정규화 채점 (워크북9)        — 완전 인출
6단계  백지 쓰기      화면에 아무 힌트 없이 단락 → 지문 전체를 통째로 입력      — 목표② 백지 영작
                     문장 단위 자동 대조 채점 + 빠뜨린 문장·틀린 부분 표시
```

- **백지 쓰기 설계**: 단락(8/1 → 8/2 → 8/3) 단위로 먼저 통과한 뒤 지문 전체에 도전한다. 채점은 입력 전문을 문장 단위로 분할·정렬해 정규화 대조(문장 누락·순서 바뀜·표현 오류를 각각 표시)하고, 시험 직전에는 종이 백지 시험과 병행할 수 있게 **강사용 "백지 채점 보조"**(학생이 쓴 종이를 보고 문장별 ○× 입력)도 둔다.
- **문장별 진도**: 25문장 각각이 현재 단계를 가진다. 6단계(백지) 통과 = "암송 완료". 단락 단위 묶음 훈련 제공.
- **연결 학습**: 본문 훈련 중 모르는 단어를 탭하면 해당 단어 카드로 점프(문장 keywords ↔ 단어 마스터가 연결되어 있다).
- **문법 개념 카드**: 패턴 2개(지각동사·간접의문문)의 개념 설명+교과서 예문을 암기 모드의 "개념 탭"에 노출 — 본문 문장 중 해당 패턴 문장에 태그가 붙는다.
- 대화문 6개도 같은 사다리를 축소 적용(1→2→5단계).

**v1.2 보강 — 해석·백지의 풀 루프 (§14-2·3)**

- **청크(끊어읽기) 해석 판정**: 2단계 해석 채점은 문장 마스터의 `chunks[]`(청크 분할 + 청크별 모범 해석 — 내용정리 플러스의 구문 주석·해석에서 추출)를 기준으로, 청크 단위 [정확/오역/누락] + 오역 유형(수식 관계/다의어 의미/시제·태) **닫힌 enum 판정**만 AI가 출력한다. 실패 청크만 하이라이트+구문 해설이 붙고, 다의어 오류는 의미별 카드로 즉시 점프. 셀프 체크로 남는 응답은 AI가 10~20% 무작위 표본을 재채점해 학생별 '관대함 지수'를 산출한다(관대할수록 표본률 자동 상향) — 셀프 채점의 지표 오염을 막는 장치.
- **일일 브레인덤프**: 매 세션 끝 2분, 오늘 훈련한 문장을 힌트 없이 기억나는 대로 타이핑 — 통과/실패 판정 없이 diff만 보여 준다(사다리 단계 무관, 게이트 무관). 결과는 '문장×날짜' 인출 히트맵으로 쌓여 상습 누락 문장이 드러난다. 백지 인출을 최종 관문에서 **매일의 학습 도구**로.
- **실패 원인 라우팅**: 6단계 백지 도전의 불일치 문장은 AI 4분류로 원인별 회귀한다 — (a)패러프레이즈→4단계 구 클로즈 (b)문법 오류→개념 카드 (c)핵심어 누락→3단계 (d)통째 누락→1~2단계. 사다리가 일직선 진급이 아니라 **문장별 적응 루프**가 된다. 5→6단계 사이에 '키워드 스켈레톤'(문장당 핵심어 1개만 제시하고 전문 복원) 발판을 추가해 낙차를 줄인다.
- **종이 백지시험 왕복**: 인쇄 백지시험지에 QR(학생·팩·지문)을 삽입 → 시험 후 강사가 답안지를 촬영 → AI가 손글씨 전사 + 정본 25문장 대조로 문장별 ○/△/× 초안 생성 → 강사는 틀린 판정만 탭해 뒤집는 원터치 확정 → 즉시 MasteryState 환류, 학생 오답노트에 '내 답안 사진+문장별 첨삭'이 남는다. 종이 관행을 없애지 않고 **종이가 데이터를 낳게** 한다(강사 채점: 학생당 수 분 → 수 초).

### 4.4 연습 모드 · 시험 모드 이원화 (v1.1)

이 앱은 시험기간 전용이 아니다. **시험 전 평상시에 아직 학습이 안 된 학생이 연습하는 용도**가 함께 있다.

| | **연습 모드 (상시)** | **시험 모드 (시험 등록 시)** |
|---|---|---|
| 대상 | 아직 범위 학습이 안 된 학생, 선행 학습 | 시험이 등록된 학생 전원 |
| 스케줄 | 자율 진도 + SRS 표준 간격(마감 없음) | 시험일 역산 D-day 플랜(간격 압축) |
| 진도 순서 | 단어 → 본문 사다리 → 문제 (권장 순서 안내) | **단어 선행 완성 게이트** 적용 |
| 목표 | 사다리 단계·단어 완료 수 자체가 목표 | 시험 범위 완성률 100% |

- **단어 선행 완성 게이트(목표③)**: 시험 모드에서 단어의 **초회 기준 도달** 마감일은 시험일이 아니라 **시험 D-7(기본값, 조정 가능)**이다. D-day 플랜이 단어를 먼저 끝내도록 할당을 편성하고, 단어 미완성 상태에서는 오늘 할당이 단어 우선으로 자동 재편성된다. 단어가 끝나야 본문 사다리 상위 단계(5·6단계)와 실전 트랙이 열린다 — "단어도 안 외우고 백지 쓰기"를 구조적으로 막는다. **D-7 이후 단어는 방치되지 않는다**: D-7~D-1에 하루 2~3분 고속 재인출 세트로 안정화 3회전이 자동 배분된다(§14-1) — 목표③이 "시험일에 가장 취약한 상태"가 되는 망각 사각지대를 없앤다.
- **게이트의 안전판(v1.2, §14-4)**: 강사 원터치 오버라이드와 '병행 모드'(5·6단계를 열되 세션 시작마다 미완성 단어 5개 선차감)를 둔다 — 규율은 유지하되 결석·복귀 학생을 실전 트랙 밖에 가두지 않는다. 판정 없는 브레인덤프(§14-3)는 게이트와 무관하게 항상 열려 있다(저부담 자유 인출은 학습 이벤트이지 관문이 아니다).
- **모드 전환**: 연습 모드에서 쌓은 진도(단어 숙련도·문장 단계)는 시험 모드에 그대로 승계된다 — 미리 연습한 학생일수록 시험 모드 할당이 가벼워지는 것이 눈에 보이게 한다(연습 동기).

### 4.5 시험 후: 워드브레인 이관

시험일이 지나면 그 팩의 단어 중 **암기 완료된 것을 워드브레인(영어 정원)으로 이관 제안**한다 — "시험 끝났다고 버리는 단어"가 아니라 장기 기억 루프로 넘어간다. 내신 앱은 마감형 단기 루프, 워드브레인은 평생형 장기 루프라는 분업이 완성된다.

- 밑줄·강조는 RichText span으로 복원해 원본 지면과 동일하게 렌더링.

### 5.4 오답노트와 나선형 재출제

- 모든 응답은 문항·빈칸 단위로 기록된다(AttemptRecord, append-only).
- 오답 → 오답노트 적립 + 연결된 단어·문장·패턴의 MasteryState 하락 → **암기 큐에 자동 재투입**.
- 재도전은 **같은 타깃의 다른 형식**으로 출제한다(예: TEST 4 빈칸에서 틀린 hug → 플래시카드 재학습 → TEST 1 유형으로 재검증). 같은 문제를 다시 풀어 "답 외우기"가 되는 것을 막는다.
- 오답 클리어 정책(v1.2 수정): **서로 다른 날 2회** 정답 시 클리어 — 같은 세션 내 연속 정답은 단기 기억 재확인일 뿐이라 인정하지 않는다.
- **D-day 플랜**: 시험일 역산으로 "오늘의 할당"을 자동 편성 — D-14~8 암기 중심, D-7~4 기본 훈련 + 단어 안정화 회전, D-3~1 실전·종합 모의 + 오답 총정리. 편성 비율은 강사가 조정 가능.
- **회복 내장 편성(v1.2, §14-4)**: 플랜은 매일 아침 잔여일 기준으로 전면 재편성된다 — 학생 화면에는 "밀린 것 N개"가 아니라 항상 '오늘의 새 플랜'만 보이고(빚 목록은 강사 대시보드에만), 재편성 화면에는 '어제보다 줄어든 총 잔여량' 그래프를 병기해 수렴이 보이게 한다. 복귀 학생의 할당은 targetRefs 역인덱스("그 단어·문장이 몇 개 문항의 타깃인가", 팩 배포 시 1회 사전 계산) 순으로 압축하는 **회복 triage** — "다 못 외우면 시험에 많이 나오는 것부터"를 시스템이 집행한다. 2일 연속 미접속 또는 백지 3연속 실패 시 앱이 먼저 '플랜을 다시 짜자'를 제안하고(할당 하향/목표 하향/게이트 연장 중 학생이 선택), 그 선택이 강사 대시보드 개입 카드로 올라가며, 회복 모드 2일 미실행 시 학부모 알림 후보가 기존 발송 승인 큐에 적재된다. **D-1은 테이퍼링 모드**: 새 학습을 차단하고 "D-12의 너는 14%, 오늘은 92%" 성장 리플레이를 보여 준다. 클리어된 오답은 '이겨낸 오답' 카운트로 쌓인다 — 벌점이 아니라 전리품.

## 7. 콘텐츠 파이프라인 — "원장이 업로드하면 팩이 된다"

출판사별 자료는 원장이 계속 업로드한다. 이 파이프라인이 반복 가능해야 앱이 자란다.

```
[1] 업로드      원장이 관리 화면에서 과 단위 PDF 묶음 업로드 (01·02·03·07·08·09 시리즈)
[2] AI 추출     시리즈 유형별 추출 템플릿으로 구조화 (Claude API — 기존 AI 파이프라인 재사용)
                · 마스터 추출: 단어(뜻·예문·영영풀이·다의어·유의반의) / 본문 문장(영·한·핵심어) / 문법 개념
                · 문항 추출: 발문·자극·보기·정답·해설 + 복수 정답 파싱 + 각주번호로 정답 병합
[3] 검수 게이트  검수 화면에서 원장·강사가 확인 (AI 초안 → 사람 확정 — 그림검사·진로독서 검증 패턴)
                · 자동 검증: 문항-정답 수 일치, 빈칸-정답 수 일치, 보기 중복, 마스터 참조 무결성
                · 사람 검수: 밑줄 위치 태깅, 그림 문항 대체 텍스트, 오탈자 교정, 표본 채점 테스트
[4] 배포        팩 상태 '배포됨' → 학생 노출. 버전 관리(수정 재배포 가능)
```

- **시리즈 템플릿의 힘**: 이그잼포유 자료는 출판사가 달라도 같은 시리즈 틀(WORD TEST 6종 구성, 본문 10단계, Grammar Build Up 3종)을 쓴다. 추출 템플릿을 시리즈 유형별로 만들어 두면 **새 출판사 팩도 같은 파이프라인으로 처리**된다. NE능률 6과 팩이 템플릿을 다듬는 파일럿이 된다.
- **알려진 난점과 대응**(분석 §2.2-5): 밑줄·색상 소실 → 검수 단계의 span 태깅 UI로 복원(빈칸 위치의 원천이므로 생략 불가). 그림 문항 → 정답에서 역산한 상황 설명 텍스트로 대체(기본값), 필요 시 이미지 크롭. 2단 조판 추출 오류·오탈자 → 자동 검증 + 표본 채점으로 걸러냄. 문장 분할 불일치 → 검수 단계에서 정본 문장 마스터 확정.
- **검수 비용의 현실**: 1개 팩(6종) 완전 검수는 첫 회에 수 시간이 걸린다. 자동 생성 가능한 부분(마스터·파생 문항)을 먼저 배포하고 고유 문항을 증분 배포하는 "부분 배포"를 지원해, 시험 일정에 파이프라인이 병목이 되지 않게 한다.

### 9.2 아키텍처

- **학생 앱 `/naesin/`**: 정적 PWA(vanilla HTML/CSS/JS) — 기존 앱들과 동일 스택. 오프라인 캐시로 태블릿 학습존 대응.
- **관리 화면**: 팩 업로드·검수·시험 관리·검토 큐 — workbench 계열 또는 `/naesin/admin.html`(강사 PIN).
- **서버**: 기존 `wb-reading` 워커에 `naesin-api.mjs` 라우트 모듈 추가(워드브레인의 `vocab-api.mjs` 선례). KV 네임스페이스는 분리를 검토(팩 데이터가 크므로 — §13).
- **콘텐츠 서빙**: 팩 JSON은 **KV에만 존재**하며, 원생 코드 인증을 통과한 요청에 과 단위로 서빙. 정적 자산으로는 절대 노출하지 않는다.
- **채점**: auto·auto_norm은 클라이언트+서버 이중 채점(기록은 서버 판정 기준), hybrid·manual은 서버에서 AI 소견 생성 후 검토 큐로.

### 9.3 저장소가 public이라는 사실의 함의

- **구매 콘텐츠(팩 데이터·PDF 원본·추출 JSON)는 git에 커밋하지 않는다.** 코드와 콘텐츠를 물리적으로 분리한다 — 콘텐츠는 업로드 파이프라인을 통해 KV로만 들어간다.
- 시드·테스트 데이터는 자체 제작 더미 문장으로 만든다(교과서·이그잼포유 문구 사용 금지).
- ※ 참고: 기존 `reading/textbook.json`(교과서 코칭 원문)도 같은 원칙으로 2026-09-02에 저장소에서 제거하고 서버 KV로 이전했다(§13-6).

## 10. 저작권·보안

이그잼포유 자료는 "출판사 라이선스를 획득해 제작, 무단 전재·배포 금지" 고지가 있는 구매 콘텐츠다. **원내 재원생 무료 제공**이라는 사용 형태를 지키기 위한 장치:

1. **라이선스 범위 서면 확인(선행 과제).** "구매 학원이 재원생 한정 디지털 학습 도구에 탑재"가 허용 범위인지 이그잼포유에 서면으로 확인한다. 이것이 프로젝트 전체의 전제다 — Phase 0에 배치(§12).
2. **접근 통제**: 원생 코드 인증 없이는 콘텐츠 API가 아무것도 반환하지 않는다. 계정은 QR 배부+강사 승인(기존 체계). 퇴원 처리 시 접근 자동 차단.
3. **노출 최소화**: `noindex,nofollow` + `X-Robots-Tag`(기존 `_headers` 패턴), `Cache-Control: no-store`, 콘텐츠는 과 단위 필요 분량만 서빙(전체 덤프 API 없음).
4. **유출 억제**: 화면에 학생 이름·코드 워터마크(캡처 유출 추적), 인쇄는 강사 권한의 단어시험지만. PDF 원본은 앱에서 제공하지 않는다(구조화 데이터만).
5. **저장 분리**: §9.3 — 공개 저장소에 콘텐츠 불포함.
6. **출처 표기**: 앱 내 자료 화면에 "이그잼포유 제작·본 학원 구매 자료, 원내 학습 전용" 고지 상시 표기.

## 11. KPI

- **North Star: 시험 범위 완성률** — 시험일까지 (**안정화 3회전 완료** 단어 + 백지 통과 문장 + 트랙 1회전) 달성 비율. v1.2: '완료'는 1회 도달이 아니라 안정화 기준(§14-1)이다 — 지표가 관대해지지 않도록 정의 자체를 바꾼다.
- 암기: 단어 77개 중 도달/안정화 수, 본문 25문장 중 해석 통과·백지(6단계) 도달 수, 일일 할당 완수율, 21시 복습 실행률.
- 풀이: 트랙별 정답률 추이(기본→실전), 오답 클리어율(서로 다른 날 기준), 재출제 통과율(다른 형식 재검증 성공).
- 보정(v1.2): 과신 오류율(오답+확실), 예측-실제 점수 갭, 셀프 채점 관대함 지수(AI 표본 감사).
- 운영: 팩 추출→배포 소요 시간, 검수에서 잡은 오류 수, 강사 검토 큐 처리 시간, 수동 채점 비중. v1.2: 학생당 AI 호출 수·시험당 AI 비용(비용 거버넌스 §13-8 상시 가시화).
- 성과(외부 지표): 시험 점수 입력(선택) → 완성률과 점수의 상관을 학기 단위로 확인. v1.2: 학부모 브리핑 열람률·재등록·소개 전환(§14-5).

## 14. 울트라 재점검과 채택된 혁신 개선안 5가지 (v1.2)

5개 관점(학습과학·동기설계·AI 네이티브·학원 운영·차별화/데이터)의 독립 검토를 종합한 결과다.

**재점검 총평 — 발견된 구조적 결함 4가지** (아래 5개 제안이 이를 해소한다):
① '암기 완료'가 1회 도달 이진 상태라 단어 마감(D-7)과 시험일 사이 7일이 **망각 사각지대** — 목표③이 오히려 시험일에 가장 취약한 상태를 만들 수 있었다. ② 플래시카드·해석 셀프 체크 등 판정의 하중이 걸리는 지점마다 중학생의 **관대한 자기 채점**이 놓여 North Star(완성률) 지표 자체가 오염에 노출. ③ 결석·정체 학생이 밀린 큐와 게이트에 갇혀 **조용히 이탈**하는 경로와, 종이 시험 결과가 앱으로 환류되지 않아 §0 원칙 1(한 루프)이 종이 앞에서 끊기는 문제 미설계. ④ AI가 빌드타임 추출에 갇혀 학습 순간의 지능형 피드백이 없고, 해자를 '누구나 살 수 있는 자료'에 두어 **이 학원만의 축적 자산**(학교별 기출 대조 데이터)이 빠져 있었다.

### 14-1. 출발선 진단 + 안정화 스케줄러 — '암기 완료'의 재정의 (목표③) · Phase 1

팩 진입 첫 세션을 2분 사전 인출 진단으로 바꿔 개인별 출발선을 세팅하고(pretesting effect — 진단이 곧 학습), '암기 완료'를 [기준 도달 1회] → [서로 다른 날 3회 재도달 = 안정화]의 2층으로 재정의한다(successive relearning — 최근 10여 년 학습과학에서 실제 교실 성적 향상이 가장 견고하게 재현된 프로토콜). 단어 게이트는 "초회 도달 D-7 마감 + D-7~D-1 하루 2~3분 안정화 3회전 자동 배분"으로 수정. 확신도 3버튼(확실/애매/찍음)이 스케줄러 입력이 된다. 상세 반영: §4.1, §4.4, §5.4, §8, §11. **5개 중 가장 저렴**(신규 인프라·AI 호출 0) — KPI 정의를 바꾸는 제안이라 반드시 Phase 1 처음부터.

### 14-2. 끊어읽기 청크 첨삭 엔진 — 해석 채점의 제3안 (목표①) · Phase 0(데이터)→1(셀프)→2(AI)

해석 채점을 "전수 AI+강사 확인 vs 셀프 체크 강등"(구 §13-2)의 양자택일이 아니라 **닫힌 청크 판정 + 표본 감사**로 재설계한다. 문장 마스터에 `chunks[]`(청크 분할+청크별 모범 해석)를 확보하고, AI는 청크 단위 [정확/오역/누락]+오역 유형 enum만 출력(Haiku급으로 충분, (문장, 해석 해시) KV 캐시로 비용 통제). 셀프 체크 응답은 10~20% AI 표본 감사로 관대함 지수를 산출한다. **끊어읽기·직독직해라는 학원의 커리큘럼 정체성이 앱의 해석 훈련과 같은 언어로 정렬** — 청크별 모범 해석 정본이 없는 범용 앱은 흉내 낼 수 없다. 리스크(맞는 의역을 오역 처리)는 저신뢰 판정의 검토 큐 자동 이관 + 파일럿에서 강사 뒤집기율 측정으로 통제. 상세 반영: §4.2, §8, §13-8.

### 14-3. 백지 영작 풀 루프 — 브레인덤프 + 실패 라우팅 + 종이 왕복 (목표②) · Phase 1(diff)→2(AI)

백지 인출을 최종 관문에서 매일의 학습 도구로 확장한다: ① 일일 브레인덤프(판정 없는 2분 diff, 인출 히트맵 축적) ② 백지 실패 문장의 원인별 라우팅(패러프레이즈/문법/핵심어 누락/통째 누락 → 사다리 해당 단계로 자동 회귀) ③ 종이 백지시험 왕복(QR 시험지 → 답안 촬영 → AI 전사·문장별 ○/△/× 초안 → 강사 원터치 확정 → MasteryState 환류). 세 층이 전부 §4.2에 이미 설계된 문장 대조 채점기 하나를 재사용한다. 자유 인출이 가장 강력한 학습 이벤트라는 시험 효과 연구의 직접 적용이며, **종이 관행을 없애지 않고 종이가 데이터를 낳게** 하는 것이 핵심. D-1은 테이퍼링 모드(새 학습 차단 + 성장 리플레이). 상세 반영: §4.2, §4.4, §5.4.

### 14-4. 회복 내장형 D-day 플래너 — 낙오 차단 · Phase 1(안전판)→2(triage)

마감형 앱의 고전적 붕괴 경로(결석 → 밀린 큐 → 게이트에 갇힘 → 조용한 이탈)를 차단한다: 매일 아침 전면 재편성(학생에겐 '오늘의 새 플랜'만, 빚 목록은 강사에게만) · targetRefs 역인덱스 기반 회복 triage("시험에 많이 변주되는 것부터" — 1,600문항 전수 구조화에서만 공짜로 나오는 우선순위) · 게이트 오버라이드+병행 모드 · 2일 미접속/백지 3연속 실패 시 앱이 먼저 '플랜 다시 짜자' 제안(학생 선택 → 강사 개입 카드 → 학부모 알림 후보). 시험대비 실패 경험은 퇴원 사유이므로 이것은 **리텐션 설계**이기도 하다. 순수 스케줄링 로직이라 AI 불필요. 상세 반영: §4.4, §5.4, §6.

### 14-5. 학부모 'D-day 생중계' 브리핑 + 기출 회수 루프 — 축적형 해자 · Phase 1말~2(브리핑)→2~3(기출)

이미 계산되는 MasteryState 수치를 D-10·D-5·D-1 학부모 브리핑 후보로 결정적(deterministic) 조립해 기존 발송 승인 워크플로우에 태운다 — 문안은 3대 목표 언어로 고정("단어 71/77·안정화 2회전, 본문 18/25 해석 통과·12문장 백지 완료"). 시험 후에는 시험 모드의 종점을 '기출 회수 완료'로 재정의: 학생 복기(보조 신호) + 강사의 실물 시험지 구조화(§7 파이프라인 축소판)로 (학교×교과서×학기×시험) **ExamArchive 출제 경향 프로파일**을 적재하고, 다음 학기 "서술형 5문항 중 4문항이 앱에서 훈련한 형식·문장" 적중 리포트와 D-day 편성 가중에 쓴다. 이그잼포유 자료는 경쟁 학원도 살 수 있지만, **"그 자료가 실제 시험에 어떻게 출제됐는가"는 그 학교 재원생을 보유한 학원만 쌓을 수 있는 시간 축적형 자산**이다. 콘텐츠는 한 글자도 외부로 나가지 않고 자녀의 통계만 나간다(§10 원칙 유지, 기출 원문은 학생 미노출). 상세 반영: §5.4(테이퍼링과 연계), §11, §12, §13-9.

## 15. 세 가지 보완 축 (v1.3)

§14까지가 "앱 안에서 무엇을 어떻게 학습시킬 것인가"였다면, 이 절은 앱 밖의 세 축을 다룬다:
콘텐츠가 어떻게 들어오는가(공급), 수업 시간에 강사가 무엇을 보는가(운영), 이 앱이 실제로
점수를 올렸는가(성과). 셋 다 지금은 비어 있고, 앱의 완성도와 무관하게 병목이 된다.

### 15-1. 성과 검증 루프 + 통합 시험 범위 — 우선 착수

**문제 A(성과)**: 앱의 모든 지표는 앱 안 도달률이다. 실제 학교 시험 점수를 입력할 곳이 없어
원장도 이 앱의 효과를 확인할 수 없고, 학생에게 줄 수 있는 가장 강한 동기(예상 점수대)도 없다.
**문제 B(범위)**: 실제 시험 범위는 보통 2~3개 과인데 D-day 플랜·단어 게이트·성취도·관리
현황판이 모두 팩(과) 하나 단위다. "시험 전 100% 완성"(목표③)이 실제 시험과 다른 단위로
계산되고, 두 과가 범위인 학생은 하루 할당이 두 배가 된다.

**해법**: ① 시험 범위 전체를 한 단위로 배분하는 범위 플랜·범위 게이트·범위 요약을 엔진에
추가하고, 학생 앱은 범위 팩을 모두 열되 과 전환으로 본다. ② 시험 후 강사가 점수와 틀린 문항
유형을 입력하면, 저장 시점의 도달률 스냅샷과 함께 쌓아 도달률↔점수 상관을 보여 준다.
표본이 쌓이면 학생에게 "현재 도달률 기준 예상 점수대"를 참고용으로 제시한다 — 표본이 적을
때는 내지 않는다(적은 표본의 상관을 단정하면 잘못된 결론을 부른다). §11의 "시험 점수 입력(선택)"이
여기서 실제 기능이 된다.

### 15-2. 팩 제작 스튜디오 — 팩이 늘기 시작할 때

**문제**: 학교마다 출판사가 다르고 시험마다 2~3개 과가 범위이므로, 한 학기에 필요한 팩은
출판사 × 학년 × 과로 수십 개다. 지금은 PDF를 AI로 읽어 JSON을 만들고 검증기를 통과시키는
과정이 전부 수작업이라, 앱이 아니라 콘텐츠 공급이 병목이 된다(§7의 실행 형태를 구체화).

**해법**: 관리 웹 안에 PDF 업로드 → 추출 초안 → 원본 페이지와 추출 결과를 나란히 놓고 줄 단위
승인 → 정답지 자동 대조(불일치만 강조) → 검증 → 배포까지의 검수 화면. 여기에 재원생의
학교·학년·시험일 기준 **팩 커버리지 표**(필요한 팩 vs 준비된 팩, 시험 3주 전인데 없는 학교 경고)를
붙인다. 학생 화면의 문항별 「이 문제 이상해요」 신고가 팩 정오표로 쌓여 품질이 수업 중에 올라간다.

**구현됨(2026-09-03)** — 다만 두 가지가 계획과 달라졌다.

① **PDF 업로드가 아니라 텍스트 붙여넣기**다. 워커에는 PDF 파서가 없고 넣으면 CPU 시간 한도에
걸린다. PDF에서 텍스트를 복사해 종류별로 붙이면 그 다음이 전부 자동이다. 추출은 종류마다 따로
돌린다(한 번에 다 돌리면 역시 한도를 넘는다). 서버에 AI 키가 없으면 추출이 `no-key`로 내려가고
「초안 JSON 붙여넣기」로 검수·배포만 쓸 수 있다 — 키 없이도 스튜디오가 죽지 않는다.

② **팩 커버리지는 학교·학년이 아니라 시험의 `packIds` 기준**이다. 학교↔교과서 매핑이 아직
없기 때문이다(§3의 열린 항목). 그리고 서버가 "없는 팩으로 시험 등록"(400)과 "배정된 팩
삭제"(409)를 모두 막으므로, **「시험은 잡혔는데 팩이 없다」는 상태는 정상 운영에서 만들어지지
않는다.** 실제로 나는 구멍은 반대 방향 — 팩은 올렸는데 어느 시험 범위에도 안 넣은 경우다.
팩 업로드와 시험 등록이 별개 화면이라 막을 수가 없고, 그 팩은 학생에게 서빙되지 않는다.
그래서 커버리지 카드는 양방향을 함께 대조하고, 팩 목록도 모든 팩을 '배포됨'으로 보여 주던 것을
배정됨/미배정으로 고쳤다 — 그 딱지가 바로 오해의 출처였다.

검수의 실효성은 「전수 검토를 하지 않는다」는 전제에 걸려 있다. 자동 대조가 잡은 행만 사람이
보고 나머지는 일괄 승인하므로, **검사 규칙의 촘촘함이 곧 팩 품질**이다. 이번에 규칙을 한 모듈
(`naesin/pack-check.js`)로 합치고 CLI 검증기·관리 업로드·스튜디오 배포가 같은 함수를 쓰게 했다.
규칙을 복제하면 "검증기는 통과인데 배포가 막히는" 상태가 생기고, 그건 사람이 검증기를 믿지 않게
만든다. 규칙도 이때 강해졌다 — 청크 연결이 정본과 다르면 오류, 어색한 문장 찾기의 `correction`을
되돌려 정본이 되지 않으면 오류(문항 자신의 정답 근거를 검사한다), 종합 Check는 슬롯별로 실제로
풀 수 있는지까지 본다.

### 15-3. 강사 라이브 보드 — 수업에서 태블릿을 써 본 뒤

**문제**: 관리 웹은 결과 집계용이라 수업 중 강사가 보는 화면이 없다. 누가 어디서 막혔는지
태블릿을 돌아다니며 봐야 한다. 과제 배정은 하루 단위인데 실제 수업은 분 단위로 굴러간다.

**해법**: 강사 노트북용 실시간 반 현황(지금 누가 어느 문항에 있는지, 3분 이상 멈춘 학생, 오늘
백지 정확도 하위 3명) — 상태는 이미 주기적으로 서버에 올라가므로 추가 비용이 거의 없다.
분 단위 **수업 타임박스**(강사가 단계를 넘기면 모든 태블릿이 같은 단계로, 남은 시간 표시)와
TV **투사 모드**(즉석 단어 시험을 화면에 띄우고 학생은 태블릿에서 답만 고른다 — 종이 쪽지시험을
대체하면서 결과가 자동으로 성취도에 들어간다).

**구현됨(2026-09-03)** — 계획에서 한 군데를 일부러 바꿨다.

「강사가 단계를 넘기면 **모든 태블릿이 같은 단계로**」를 그대로 만들지 않았다. 그건 강사 화면이
학생 기기를 원격 조작하는 구조인데, 오작동 한 번이 학생이 풀던 것을 지운다 — 그리고 수업 중에는
그 학생이 항의할 방법도 없다. 대신 「지금 이 단계」라는 **신호**만 서버에 두고 학생 앱이 읽어
상단 띠로 알린다. 학생이 「이 단계로 이동」을 눌러야 옮겨진다. 예외는 하나 두었다: 러너가 닫혀
있고 홈에 멍하니 있으면 3초 뒤 스스로 옮긴다(수업 시간이다). 러너가 열려 있으면 절대 건드리지
않는다 — 풀던 문제가 사라지는 것이 더 나쁘다.

투사 모드는 계획대로다. **정답은 학생 기기로 내려가지 않는다**(`GET /live` 가 공개 전까지
`answerKey` 를 지우고, 지금 띄운 문제 하나만 준다) — TV에 문제를 띄우는 구조가 그 한 줄에
걸려 있다. 문제 생성은 학생 앱과 같은 `gen.js` 로 강사 화면에서 한다: 서버에 규칙을 복제하면
학생이 푸는 문제와 TV에 띄우는 문제가 조용히 갈라진다(§15-2 의 팩 검사 규칙에서 이미 치른 값이다).

실시간 인프라는 만들지 않았다. 학생 상태는 이미 서버에 올라가므로 **5초 폴링**으로 족하다 —
수업 운영에 5초 지연은 영향이 없고, 워커에서 WebSocket 을 띄우는 비용·복잡도가 그보다 크다.
세션은 4시간 뒤 만료된다(방치된 단계가 다음 날 학생 화면에 남으면 안 된다).

**우선순위**: 15-1이 학습 효과에 직결되고 구현이 가장 작다 → 15-2는 팩이 늘기 시작하는 시점 →
15-3은 수업에서 태블릿을 실제로 써 본 뒤 한두 주 안에.
**진행**: 15-1 완료 · 15-2 완료 · 15-3 완료 (모두 2026-09-03).

## 16. 본문 암기 재설계 (v1.4) — 뜻 먼저, 청크 → 줄 → 단락

§4.2의 6단계 사다리는 2단계가 "본문을 한글로 해석해 쓰기"였다. **독해를 못하는 학생이 전제**라면
그 학생은 첫날 두 번째 칸에서 막힌다(3단계는 영어 철자를 직접 써야 해서 더 못 한다). 즉 종전
사다리는 이미 어느 정도 읽는 학생만 오를 수 있었다. 원장 방향은 **한글(해석)을 청크 단위로 먼저
외우고 줄 → 단락으로 올리는 것**이고, 이 절이 그 재설계다. 원천 자료의 10단계 워크북이 이미
같은 순서(워크북2 한글 빈칸 → 워크북3 영어 빈칸)로 설계돼 있어 자료의 설계 의도와도 맞는다.

### 16.1 원칙 셋
1. **의미 먼저** — 영어를 못 읽는 학생에게 영어 본문은 무의미한 글자열이고, 무의미한 것을 외우는
   비용은 의미 있는 것의 몇 배다. 한글 뜻을 먼저 세우면 영어가 "외울 것"에서 "아는 것에 이름
   붙이기"로 바뀌고, 백지 쓰기가 맨땅의 자유 인출이 아니라 **한글 갈고리에 영어를 거는 단서 인출**이 된다.
2. **단서 점진 소거** — 처음엔 답을 보여 주고 조금씩 지운다. 실패부터 시키면 학습이 아니라 회피가 생긴다.
3. **누적 연결** — 부분을 따로 익히고 전체로 뛰면 이어지지 않는다. 각 층에서 1, 1+2, 1+2+3으로 쌓는다.

### 16.2 두 가지 조건 (설계 실패를 막는 안전판)
- **직독직해 한글만 쓴다.** 매끄러운 번역문은 한국어 어순이라 영어 자리와 어긋나 갈고리가 맞지
  않는다. 팩의 `chunks[].ko`(내용정리 플러스 Sentence Study 원천)가 암기용 정본이다.
- **한글은 목적지가 아니라 갈고리다.** 해석문을 시처럼 외우고 정작 영어는 못 읽는 것이 가장 흔한
  실패다. 그래서 한글 청크는 **언제나 영어 자리와 짝지어** 제시하고, 한글만 있는 화면을 만들지 않는다.

### 16.3 세 트랙 (학생 화면에는 「뜻 세우기 / 영어 얹기 / 굳히기」)
| 트랙 | 단위 | 내용 |
|---|---|---|
| 청크 | 단락 | 듣고 짝 맞추기 → 뜻 인출 → 순서 세우기 (영어 입력 0으로 통과 가능) |
| 문장 사다리 | 문장 | 줄 해석(한글 빈칸) → 영어 청크 배열 → 핵심어 빈칸 → 문법 형태 → 줄 영작 → 단락 백지 |
| 관문 | 단락·과 | 단락 줄거리 → 어색한 곳 찾기 → 단락 백지 → 누적 백지 → 종합 Check |

- 청크 트랙 통과가 그 단락 문장 사다리의 열쇠다 — **청크 → 줄 → 단락 순서를 게이트로 강제**한다.
  청크 트랙은 단어 게이트를 받지 않는다(못 읽는 학생의 첫 자리를 막지 않는다).
- 1·3·5단계는 단서 농도(전사 → 첫 글자+글자 수 → 첫 글자 → 빈칸만)를 지우며 오른다. 한 세션 안에서
  통과하면 곧바로 한 겹 낮은 단서로 한 번 더 내므로 문장당 러너 횟수는 종전과 같다.
- 백지 실패는 **원인별로 되돌린다**(누락→1, 어순→2, 낱말→3, 형태→4). §14-3의 실패 라우팅이 여기서 구현됐다.
- 하루 상한은 남은 본문 작업량을 잔여일로 나눠 자동 산정하되, 누적·종합이 하루 한 칸씩 직렬이라는
  제약을 먼저 역산해 그만큼의 날을 뗀다.

### 16.4 자료 활용 회수
그때까지 팩에 들어 있으면서 한 번도 쓰이지 않던 두 자료가 제자리를 얻었다 — **어색한 곳 찾기**는
단락 백지 직전의 재인 관문(정확한 기억이 있어야 바뀐 자리가 보인다), **종합 Check 40슬롯**은 워크북
자신의 최종 관문이므로 과 전체의 마지막 점검. 한글 빈칸(워크북2)도 영어 빈칸 앞 발판으로 들어왔다.

### 16.5 확인된 사실 (구현 후 시뮬레이션·E2E)
- 영어를 한 글자도 입력하지 않는 학생이 **청크 트랙 전량 + 해석 25/25**에 도달한다(재설계 전 5/25).
- D-14 시작 25문장·5단락·77단어가 **누적 백지·종합 Check까지 시험 3일 전에** 끝난다(종전 고정 상한
  5칸에서는 백지 5/25·누적 0에서 멈췄다).
- 하루 부담은 평균 47세션·최대 61세션이고 대부분이 단어다. 60을 넘으면 안내문에 실제 숫자를 띄운다 —
  범위를 줄이거나 시작을 앞당기는 판단은 숫자를 본 강사가 한다.
