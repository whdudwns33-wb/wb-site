## 1. 비밀값 목록

| 이름 | 보관 위치 | 쓰는 곳 | 노출 시 위험 |
|------|-----------|---------|--------------|
| `CLOUDFLARE_API_TOKEN` | GitHub 저장소 Secrets | 워커 배포(deploy-reading.yml), 시크릿 등록(vocab-secrets.yml) | **높음** — 워커 코드 교체·KV 데이터 열람/삭제 가능 |
| `CLOUDFLARE_ACCOUNT_ID` | GitHub 저장소 Secrets | 위와 동일 | 낮음 (식별자일 뿐, 단독으로는 무력) |
| `ANTHROPIC_API_KEY` | GitHub Secrets → 워커 Secret | 워드브레인 AI 연상 생성 | 중간 — 과금 발생 |
| `ADMIN_PIN` | 워커 Secret | 관리 웹·검수 웹 로그인 | **높음** — 학생 기록 전체 열람 |
| `VAPID_PUBLIC_KEY` / `VAPID_PRIVATE_JWK` | 워커 Secret | 밤 9시 물주기 푸시 | 중간 |
| 학부모 열람 토큰 | KV (학생별) | `parent.html?t=…` | 낮음 — 학생 1명분 읽기 전용, 관리 웹에서 재발급하면 즉시 무효 |

**원칙**: 위 값은 대화·커밋·이슈·PR 본문 어디에도 적지 않는다. 필요하면 "어디에 있는지"만 말한다.

## 2. Cloudflare API 토큰 롤 절차

토큰이 유출되었거나, 정기 교체(권장 6개월)할 때 아래 순서로 진행한다.
**순서가 중요하다** — 새 토큰을 먼저 만들고 GitHub에 넣은 뒤에 옛 토큰을 지운다. 반대로 하면 그사이 배포가 막힌다.

### ① 새 토큰 발급 (Cloudflare 대시보드)

1. https://dash.cloudflare.com/profile/api-tokens 접속
2. **Create Token** → 맨 아래 **Create Custom Token** → *Get started*
3. Token name: `wb-reading-deploy-2026-08` (발급 시점을 이름에 남기면 나중에 구분하기 쉽다)
4. **Permissions** — 아래 3줄만 준다. 그 이상은 주지 않는다.

   | 구분 | 항목 | 권한 |
   |------|------|------|
   | Account | Workers Scripts | Edit |
   | Account | Workers KV Storage | Edit |
   | Account | Account Settings | Read |

5. **Account Resources**: Include → 본인 계정 하나만 선택
6. **Zone Resources**: 건드리지 않는다 (workers.dev 주소만 쓰므로 존 권한 불필요)
7. TTL은 비워 두거나 1년 이내로 설정
8. *Continue to summary* → *Create Token* → **화면에 한 번만 보이는 토큰 값을 복사**

### ② GitHub Secret 교체

1. https://github.com/whdudwns33-wb/wb-site/settings/secrets/actions
2. `CLOUDFLARE_API_TOKEN` 행의 **Update** 클릭
3. 복사한 새 토큰을 붙여넣고 저장
4. `CLOUDFLARE_ACCOUNT_ID`는 그대로 둔다 (계정이 바뀐 게 아니므로)

### ③ 배포로 검증

Actions 탭 → **Deploy wb-reading worker** → *Run workflow* → main 선택 → 실행.
초록색으로 끝나면 새 토큰이 정상 동작하는 것이다.

빨간색이면 새 토큰의 권한이 모자란 것이니 ①의 표와 대조한다.
`Authentication error [code: 10000]` = 토큰 값 오류, `[code: 10007]` = 권한 부족.

### ④ 옛 토큰 폐기

③이 초록색인 것을 **확인한 뒤에** 대시보드로 돌아가 옛 토큰 행의 ⋯ → **Delete**.

### ⑤ 마무리

- 워커가 살아 있는지 확인: `curl https://wb-reading.whdudwns33.workers.dev/api/health`
- 이 문서 §4 이력에 교체일을 적는다.

## 3. 관리 PIN 변경

PIN은 워커 Secret이라 대시보드가 아니라 명령으로 바꾼다.

```
cd reading-server
CLOUDFLARE_API_TOKEN=… npx wrangler@4 secret put ADMIN_PIN
# 프롬프트에 새 PIN 입력 (화면에 표시되지 않음)
```

바꾼 뒤 관리 웹(https://wb-reading.whdudwns33.workers.dev/admin)에서 새 PIN으로 로그인되는지 확인한다.
로컬 개발 서버는 `ADMIN_PIN=… node reading-server/server.mjs`로 같은 값을 쓴다.
