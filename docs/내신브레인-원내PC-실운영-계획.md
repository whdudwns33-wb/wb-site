# 내신브레인 원내 PC 실운영 계획

2026-10-12 사용자 요청에 따른 실행 계획이다. 목표는 이 PC를 서버로 사용하면서 원장·강사는 외부에서 관리하고, 재원생은 학원 안에서 이그잼포유 자료로 학습하는 것이다. 기존 관리 전용 터널 계획을 이 목표에 맞춰 확장한다. 실제 운영 전환 전에는 기존 학생 기록과 운영 서비스를 보존한다.

## 사용 조건과 운영 구성

- 사용자 확인: 이그잼포유 자료는 학원 내 사용이 허용되며 반출하지 않는다. 도입 순서는 **중2 → 중3 → 중1**이다. 공급처의 허락 범위에 대한 법률 판단을 이 문서에서 추가하지 않는다.
- 권장 구성: 영어 내신브레인의 학생 기록과 팩은 PC 한 곳을 정본으로 두고, 학생 학습은 원내 접속에서만 허용한다. 외부에는 인증된 원장·강사 관리 기능을 제공한다. 영어 기록을 워커와 PC에 동시에 쓰지 않으며 다른 앱의 기존 워커 운영은 유지한다.
- `WB_INHOUSE_ONLY`의 인증된 학생 Bearer는 영어 `/api/naesin/*`와 연동·토큰 갱신·공용 알림 구독 경로만 사용한다. 독해 `/api/pull`·`PUT /api/state`, 다른 앱의 데이터 경로와 학생 Bearer를 겸한 가족 경로는 변경 전에 403으로 거절한다. 명부의 `apps` 값은 바꾸지 않고 기존 이용 권한 검사도 유지한다. 관리자의 기존 API와 원내 모드를 끈 일반 Node·워커 계약은 유지한다.
- 가족 `ptoken`과 포털의 전용 서비스 Secret은 학생 Bearer와 다른 자격이다. 학생 Bearer를 사용하지 않는 기존 가족·서비스 경로는 이번 학생 권한 제한으로 닫지 않는다. 따라서 다른 앱의 모든 쓰기를 PC에서 금지한 것으로 해석하지 않는다. 학생용 안내와 링크는 영어 입구를 사용하고 기존 다른 앱 안내 주소를 PC 주소로 바꾸지 않는다.
- 영어 학생 연동 입구는 `/?app=naesin`이다. 학생 코드를 요청하고 교사 승인을 받으면 고정 경로 `/naesin/`으로 이동한다. 기존 연동 정보는 `/api/naesin/exam`으로 다시 확인하며 다른 학생 코드를 입력하면 기존 계정을 해제하고 새 승인을 받는다. 이 입구는 독해 학년·프로필 설정, `/api/pull`·`/api/state`, 독해 저장과 서비스 워커 등록을 실행하지 않는다. `app`은 화면의 이동 힌트이며 서버 이용 권한을 대신하지 않는다. 코드가 들어 있는 QR의 주소창에서는 코드를 지우되 영어 힌트는 유지한다.
- 학생 QR은 원내 관리 주소에서 생성한다. 영어 PC의 `/api/admin/overview`가 `studentApp:'naesin'`과 `localPdfReview:true`를 함께 주면 학생 코드에 `app=naesin`을 붙인다. 외부 관리 주소에서는 QR을 만들지 않고 원내 관리 주소를 안내한다. 일반 Node·워커는 해당 메타 없이 기존 QR·연동 계약을 유지한다. 학생 주소를 자동 추측하거나 외부 관리 주소를 학생용으로 배포하지 않는다.
- 원본 PDF와 구매 팩은 저장소·정적 배포·클라우드 백업에 넣지 않는다. PC의 접근 제한된 자료 폴더에 보관한다. 학생 기기에 본문을 영구 저장하거나 오프라인으로 반출하는 현행 동작은 제거한다.
- 사용자 확인: WB1은 학원 내부망의 PC다. 학생 허용망은 실제 Ethernet의 CIDR로 제한하며 가상 어댑터·Tailscale 망을 포함하지 않는다. 브라우저에 표시된 자료의 촬영·복사를 코드만으로 완전히 차단할 수 없으므로 학원 관리 기기 반출 금지도 운영 조건이다.
- 공개 주소는 Cloudflare의 기존 계정·도메인·터널을 먼저 확인해 재사용한다. 다른 앱의 기존 경로나 접속 정책은 바꾸지 않는다. 실제 hostname·학생 명부·비밀번호·터널 토큰은 이 공개 저장소에 기록하지 않는다.

## 1. 반별 시험 배정

기존 학생 코드와 `default` 배정 키를 유지하고 `cls:<반>` 키를 추가한다. 반은 Unicode NFC와 앞뒤 공백만 정규화하며 내부 공백은 보존한다. 빈 값·제어문자·80자 초과는 거절한다. 학생 코드 `cls`도 기존 학생 배정으로 계속 해석한다.

유효한 학생 배정 → 유효한 반 배정 → 공통 배정 순으로 조회한다. 학생·반 배정은 시험일이 KST 오늘보다 이전이면 다음으로 폴백한다. 공통 배정은 지난 날짜도 반환해 기존 시험 종료·자율 학습 동작을 유지한다. 팩 접근, 문제 신고, 시험 결과 스냅샷, 밤 9시 알림과 관리 커버리지도 같은 해석을 사용한다.

관리 화면에는 명부에서 반을 고르는 선택지를 추가한다. 결과 입력 명부에 반 scope를 학생 코드로 넣지 않는다. 학생 응답의 기존 `student`·`default`에 `class`를 추가하며 응답 래핑은 유지한다. 두 저장소는 이미 임의 scope 키를 지원하므로 별도 이관을 만들지 않는다.

완료 검사: 우선순위와 각 만료 조합, 반 변경·배정 해제, 빈 반·한글·NFC·키 충돌, 기존 학생·공통 배정, 로컬 실제 HTTP와 워커 번들.

## 2. 실수업 전에 고칠 데이터 보호

1. 여러 기기의 과별 기록은 최신 저장 시각을 보존한다. 공용 브라우저에서 학생 계정이 바뀌면 이전 학생의 학습·동기화를 중단하며 서버도 기록 소유자를 확인한다.
2. 손상된 기존 DB로 빈 DB를 기동하지 않는다. 학생에게 저장 성공을 알리기 전에 디스크 저장을 확인한다.
3. 같은 날 백업도 복구점을 덮지 않는다. 교과서 지정·신고·검수 등 운영 메타데이터와 PC 원본 자료의 복구 범위를 구분해 실제 복구를 시험한다.
4. 관리 업로드·Aside 반입·스튜디오가 기존 `pack-check.js` 한 관문을 사용한다. 단어와 본문이 없는 팩은 배포하지 않는다.
5. 원내 접속을 벗어나거나 연결 확인에 실패하면 구매 팩을 계속 보여 주지 않는다. 선택 기능인 외부 AI 원천 전송은 이 운영에서는 사용하지 않는다.

초기 수업은 한 반으로 검증한다. 과제와 라이브도 `?scope=cls:<반>`으로 분리했다. 과제는 오늘의 반 과제 → 공통, 라이브는 4시간 내 반 세션 → 공통 순으로 조회한다. 관리 요청에 scope를 생략하면 기존 공통 수업을 유지한다. 투사 문제는 저장된 packId와 학생 시험 범위를 대조하며, packId 없는 옛 투사 내용은 강사가 다시 시작해야 한다. 서로 다른 반의 응답·현황·삭제를 분리하는 실제 HTTP 검사도 포함한다.

## 3. 이그잼포유 자료 반입

Aside의 기존 계정 세션과 구매 내역을 사용한다. 새 결제나 이용권 변경은 금액과 대상을 정한 뒤 승인받는다. 사용자가 첫 검증 대상으로 **2022 개정 NE능률(김기택) 중2 6과**를 선택했다. 다른 교과서 전체를 임의로 받지 않는다.

기존 자료 폴더 표준의 과 단위 packId와 시리즈 번호를 유지하되, 원본 저장 위치는 원내 PC 보관 폴더로 정한다. 필수 입력은 `02_본문워크북`과 `03_단어시험`이며 교과서 본문과 대조한다. 이미 구매한 교사용 정답·해설도 함께 사용한다. 원본 파일은 변경하지 않고 추출 JSON과 검수 자료를 별도로 만든다.

원본 내려받기 → 로컬 추출 → 단어·본문·정답 대조 → `pack-check` 오류 0 → 스튜디오 검수 → PC 서버에 팩 등록 → 반 시험 범위 배정 순서다. 구매 원천을 외부 AI API에 보내지 않는다. 원본을 앱 입력으로 자동 변환할 도구가 없거나 자료가 충분하지 않으면 해당 구간을 미완료로 표시하고 임의 내용을 학생에게 배포하지 않는다.

## 4. PC 서버와 외부 접속

서버의 관리자 인증·자료 폴더·고정 실행 경로를 먼저 준비하고 자동 시작·재시작·백업 복구를 확인한다. 이후 외부 관리 주소에 Cloudflare Tunnel과 접근 정책을 연결한다. 학생 주소와 자료 API가 외부에서 열리지 않는지 실제 비인증·외부 접근으로 검사한다.

2026-10-13 외부 경로를 복구했다. 별도 운영데스크 개발 서버가 `127.0.0.1:8890`을 사용하면서 같은 포트의 내신 서버(`0.0.0.0:8890`)보다 먼저 요청을 받았고, 외부 `/ops/`는 운영데스크로 열리지만 내신 관리와 health는 404였다. 기존 외부 관리 호스트의 Tunnel에 `^/(admin|api|naesin)(/.*)?$` → `http://127.0.0.2:8890` 경로를 기존 호스트 전체 규칙보다 앞에 추가했다. 추가 loopback에서 내신 health 200을 먼저 확인했다. `/ops/`·`/ops/api/*` 등은 기존 개발 서버로 계속 연결하며 프로세스·학생 주소·자료·Access 정책은 바꾸지 않았다. 실제 외부 관리·팩 제작·overview·health와 기존 운영데스크 API는 200, 외부 학생·원본 연결·export는 403, 비인증 관리는 Access 로그인으로 302였다. 이 외부 관리 호스트의 `/ops/`를 내신 관리 입구로 안내하지 않는다. PDF 원본 검수는 원내 PC 주소에서 진행한다.

학원 관리 태블릿에서 로그인 → 반 시험 받기 → 범위 전체 팩 받기 → 단어·본문·문제 학습 → 교사 현황 반영 → 다른 기기 기록 복원 → 계정 교대 → 원내 연결 이탈 차단을 실제로 확인해야 운영 완료다. PC 재시작과 외부 관리 접근까지 확인한 뒤 중3, 중1로 확대한다.

구매 자료의 읽어 주기는 학습 기기에 설치된 해당 언어의 로컬 음성만 사용해야 한다. 음성이 없으면 원격·기본 음성으로 넘기지 않고 기기 음성 설정 안내를 표시한다. 실제 원내 기기의 영어 음성 설치와 재생도 첫 수업 점검에 포함한다.

현재 PC의 Aside 브라우저는 음성 목록 로딩 후에도 로컬 영어 음성 0개·한국어 음성 1개였다. 구매 자료의 영어 읽어 주기는 아직 사용할 수 없다. [Microsoft의 음성 추가 안내](https://support.microsoft.com/en-us/accessibility/windows/narrator/appendix-a-supported-languages-and-voices)에 따라 Windows 음성 설정의 「음성 관리 → 음성 추가」에서 영어(미국)를 설치한 뒤 브라우저에서 로컬 영어 음성과 재생을 다시 확인한다. 설치와 실제 학생 기기의 확인은 남아 있다.

## 완료 기준

- 과제 1 준비도와 과제 2 반별 배정이 같은 시험 범위를 사용하고 관련 회귀 검사가 통과한다.
- 중2의 실제 배정 자료로 원내 기기 학습과 교사 확인이 된다.
- 자료 반출 경로·외부 학생 접속·다른 학생 기록 혼합·저장 실패 성공 응답을 막는다.
- 원본과 기록을 잃지 않고 PC 재시작·백업 복구가 된다.
- 외부에서 원장·강사 관리에 접속되며 기존 운영 서비스가 계속 동작한다.

자료 구매·원본 대조·운영 재시작·실제 학원 기기 확인이 끝나기 전에는 전체 목표를 완료로 표시하지 않는다.

## 진행 결과 (2026-10-12)

- 최종 Windows Node 검사 `node scripts/check.mjs` **312/312**, 26.3초. 실제 HTTP에서 반별 과제·동시 라이브·원내 PDF 후보 관문까지 검증했고 스튜디오의 브라우저 검사도 통과했다. 회귀 검사에는 자체 창작 샘플·가상 학생을 사용했다. 실제 명부 반입과 실자료 검수 초안 저장은 아래에 별도로 기록한다. main 배포는 하지 않았다.
- 관리자 전용 모드 검사의 고정 포트 충돌과 잘못된 서버 준비 판정을 재현해 수정했다. 이제 OS가 소유한 자식 서버에 배정한 포트와 그 자식의 기동 로그·종료를 확인하며, 학생 등록 응답도 검사한다. 서버 기동 로그는 요청 포트 대신 실제 바인딩 포트를 표시한다.
- 준비도 현황판·반별 시험 배정·공통 모듈·기존 호환 검증 완료. 실제 관리 화면에서 배정 저장과 학생 → 반 → 공통 폴백, 1440px·390px 화면을 확인했다.

- 원래 서버 디스크와 다른 내부 물리 디스크에 자료 33개와 DB 스냅샷 1개를 한 번 백업했다. 34개 모두 저장 후 SHA256이 원본과 같고 원본은 변경하지 않았으며, 사본 ACL은 현재 사용자·SYSTEM·Administrators만 허용한다. 관리자 인증 파일은 복사하지 않았다. PC 밖이나 클라우드로 전송하지 않았으며 정기 백업은 아직 설정하지 않았다.
- PDF 단어 교정·핵심어 보완까지 전체 검사 **312/312**(31.3초), 스튜디오 서버 **49/49**·화면 **43/43**·학생 화면 **19/19**, 워커 번들 dry-run(393개 자산·821.24 KiB)이 통과했다. 독립 검토는 실제 HTML과 핸들러를 자체 작성 메모리 자료로 연결해 기존 ID 교정·추가 필드·메모, 실패와 버전 충돌의 입력 보존, 로그아웃 회수와 핵심어별 두 훈련 생성·게시 차단을 확인했다. 실제 브라우저에서도 일반 단어 필드 교정·원천 재연결·직접 핵심어 입력과 검수·자체 팩 게시, 로그아웃 후 단축키의 자료 재표시 차단을 확인했다.
- 실제 Aside 브라우저와 격리 Node 서버에서 자체 작성 단어 1개·본문 1문장을 반입·교정·검수한 뒤 게시 → 반별 배정 → 학생 연동 → 본문·청크 표시 → 단어 연습 상태 저장을 확인했다. 서버 재시작 후 연습 상태도 유지됐다. 원천 파일 재선택 때 기존 교정을 보존하고, 다른 화면의 문장 변경 뒤 오래된 승인을 거절하며 입력을 유지했다. 최신 재조회 후 추가 문장은 변경된 앞 문장을 지우지 않았다. 문장 저장 후 반입 버튼이 비활성 상태로 남는 문제와 과 번호 없는 교재의 `Lundefined` 표시도 수정·확인했다. 이 검증은 실제 구매 자료의 대조·수업을 대신하지 않는다.
- 직전 본문 대응·검수 보호 코드 반영 때 DB와 일치하는 전체 복구점을 만든 뒤 이 앱의 작업·8890 프로세스 소유 경로를 확인해 PC 서버를 재시작했다. 관리자 로그인·health 200, 실제 검수 작업의 무변경, 유효하지 않은 키·상태를 사용한 오래된 요청의 409를 확인했다. Access 인증을 사용한 외부 관리 화면·health는 200이며 원천 검수 capability는 false, 외부 학생·자료 export는 403을 유지했다.
- 단어·핵심어 보완 코드도 같은 전체 복구점 생성·소유 프로세스 확인 절차로 PC 서버에 반영했다. 관리자 로그인·health 200과 실제 학습 데이터의 무변경을 확인했고 외부 학생·export 403도 유지했다. 원내 교사 화면의 첫 단어 일반 편집을 열었으며 실제 자료는 승인하지 않았다. 당시 Aside 도구가 세션 밖 검수 파일 선택을 거절해 자동 연결을 진행하지 않았고 접근 제한을 우회해 다른 폴더로 복사하지 않았다. 이후 아래의 PC 자료 직접 연결을 구현해 일반 검수 흐름에서 파일 선택 요구를 없앴다.
- 실자료의 로컬 변환 결과가 기존에 저장된 단어 후보 배열 74개와 정확히 같고 본문 원천 4열의 줄별 좌표가 모두 유효함을 확인했다. 이 검사는 외부 요청 없이 수행했으며 실제 검수 작업을 변경하거나 자료를 승인하지 않았다.
- Aside 브라우저와 격리 Node 서버의 자체 작성 A·B 학생으로 연동을 검증했다. 교사 승인 뒤 영어 앱으로 자동 이동했고 B 학생은 새 QR로 다시 승인을 받았다. 영어 기록 2건이 남고 독해 기록은 0건이었으며 관리 화면에서 생성한 QR의 영어 힌트와 연동 화면 제목을 확인했다. 이는 실제 명부의 학생 태블릿 수업이나 구매 자료 검수 증거가 아니다.
- 영어 학생 연동·QR·PC 학생 권한 제한까지 전체 검사 **313/313**(25.6초), 연동 화면 **11/11**·학생 화면 **20/20**·원내 실제 HTTP **17/17**, 393개 자산 조립과 워커 번들 dry-run(821.24 KiB)이 통과했다. 중복 승인 확인과 취소·새 계정 뒤 늦은 응답을 검사했으며 새 연동 검사를 기존 배포 CI에도 포함했다. 기존 Worker·일반 Node의 독해 기록 쓰기와 QR 계약은 유지한다.
- 실제 전체 DB와 일치하는 복구점을 만든 뒤 소유 경로가 확인된 이 앱의 서버만 재시작해 학생 연동·권한 제한을 반영했다. 관리자 로그인·health 200과 검수 데이터 무변경(후보 74·미검수 74·검수 0·게시 팩 0)을 확인했다. 실제 외부 Access 인증 브라우저의 관리 overview는 200·영어 PC 모드·학생 QR 허용 false였고 학생 로그인·export는 403이었다.
- 「PC 자료 불러오기」와 원본 PDF 나란히 보기를 구현했다. Node의 원내 관리자 전용 읽기 경로가 작업의 팩 폴더에서 검수 초안과 `02`·`03` 원본만 읽고 파일 종류·크기·경로·원본 SHA256을 검증한다. PDF 요청은 연결 당시 원본 확인값에 고정하며 외부 관리자·학생·워커에는 이 원천 경로를 제공하지 않는다. 화면은 파일·JSON·본문 줄 대응을 「고급 입력」으로 접고 교정 중 열린 상태는 유지한다. 자동 번역·영한 대응·승인·게시는 추가하지 않았다.
- PC 서버에 반영한 뒤 실제 중2 작업에서 후보 74개·본문 원천 4열·PDF 2개를 연결했다. 단어 PDF 표시용 응답과 본문 PDF 200·547,416바이트·no-store를 확인했고 기존 후보·검수·버전은 그대로였다. 외부 Access 관리 health는 200, 원본 연결은 403이었다. 다운로드 당시 이름과 고정 보관 이름이 다를 때는 해당 원본 해시가 맞는 두 고정 이름만 사용한다. 자체 PDF로 데스크톱 1280px·모바일 390px 원본 표시와 가로 넘침 없음을 확인했다. 원천 검사 19/19·화면 51/51 및 전체 314종 검사를 확인했으며, 별도 빌드와 경합한 산출물 검사 1건은 다른 실행 종료 후 8/8로 재검사했다. 최종 393개 자산 조립·워커 dry-run도 통과했다.
- 현재 운영 자료는 여전히 단어 후보 74개·교사 검수 0개·학생용 게시 팩 0개이며 실본문 대응은 하지 않았다. 실제 학생 태블릿 수업·PC 재부팅·영어 로컬 음성 설치와 재생·중3 및 중1 확대도 남아 있다. Windows 음성 설치는 사용자 수동 작업을 기다린다.

교사 검수 순서:

1. 원내 PC 스튜디오에서 기존 검수 작업을 열고 「PC 자료 불러오기」를 누른다. 기존 후보와 정확히 같은 자료는 재업로드 없이 연결하며 기존 단어·교정·검수·메모를 유지한다. 원본 PDF는 후보 옆에 표시하고 「PDF 크게 보기」로 따로 볼 수 있다.
2. 단어 후보를 한 행씩 옆의 원본 PDF와 대조한다. 본문/대화 구분을 포함한 필수 항목까지 맞으면 「승인」, 오류나 누락이 있으면 「편집」에서 표제어·품사·줄별 뜻을 교정하고 실제로 나온 본문/대화를 직접 선택한 뒤 「대조한 교정 저장」을 누른다. 교정 저장도 검수 상태로 기록한다.
3. 본문을 구성할 때는 「고급 입력」을 열고 영어·한글 열과 줄 범위를 각각 골라 「선택 줄로 문장 채우기」를 누른다. 영·한 대응과 수업 묶음을 확인하고 영어 순서의 직독직해 청크, 영어 원문·한글 청크에 대응하는 핵심어 쌍을 직접 넣는다. PDF를 보여 주는 것만으로 학습용 문장 대응이 만들어지는 것은 아니다.
4. 추가한 문장도 원본 위치를 보고 개별 대조·검수한다. 검수 관문에서 미검수와 입력 오류가 없고 본문 두 훈련이 생성되는지 확인한 뒤 팩 게시·반 시험 범위 배정으로 진행한다. 작업 변경 경고가 나오면 최신 자료를 다시 읽어 대조한다.

## PC 실행과 복구

Windows PowerShell에서 `powershell -NoProfile -ExecutionPolicy RemoteSigned -File reading-server/setup-local.ps1`를 실행하면 관리자 아이디·12자 이상 비밀번호를 직접 입력할 수 있다. 승인된 자동 설정은 메모리의 `PSCredential`을 `-AdminCredential`로 전달한다. 둘 다 같은 입력 검증과 DPAPI 저장을 사용하며 기존 인증 파일에 새 계정을 덮어쓰지 않는다. 비밀번호를 명령줄·평문 파일·로그·저장소에 넣지 않는다. RemoteSigned는 해당 프로세스에만 적용하며 시스템·조직 정책을 바꾸지 않는다.
기본 초기 설정은 localhost:8890이다. 이번 PC는 확인된 원내망을 `HostAddress`·`InhouseNetworks`에 지정해 LAN 학습을 허용하고 외부 학생 접속은 차단했다. 자료·DB·DPAPI 인증은 `%LOCALAPPDATA%\WB\naesin-server`에 보관한다.
`start-local.ps1`는 현재 사용자로 시작하며 작업 스케줄러는 사용자 로그인 후 실행한다. PC 로그인 전 가동·절전 방지·정전 복구는 별도 실제 운영 확인 대상이다.
직접 LAN의 HTTP 주소는 브라우저 학습용이다. HTTPS가 필요한 PWA 설치·서비스 워커는 해당 주소에서 검증한 것으로 표시하지 않는다. 학생 자료를 새 공개 터널 주소로 중계하는 구성은 아직 추가하지 않았다.

`backups/`는 API용 메타데이터이고 `private-backups/`는 원본 팩까지 포함한 로컬 장애 복구본이다. 관리 export를 전체 자료 복구본으로 오인하지 않는다.
전체 복구는 서버를 멈추고 선택한 `private-backups/db-<복구ID>.json`을 `db.json`으로 복사한 뒤 서버를 다시 시작한다. 복구 전 현재 DB도 별도로 보존한다.
작업 스케줄러의 작업 중지만으로 자식 Node 서버가 종료되지 않을 수 있다. DB를 복사하기 전에 8890의 리스너 종료를 확인한다. 남아 있다면 실행 파일 `node.exe`와 이 저장소의 `reading-server/server.mjs` 절대 실행 경로를 대조해 이 앱의 프로세스만 종료한다.
