# 내신브레인 원내 PC 실운영 계획

2026-10-12 사용자 요청에 따른 실행 계획이다. 목표는 이 PC를 서버로 사용하면서 원장·강사는 외부에서 관리하고, 재원생은 학원 안에서 이그잼포유 자료로 학습하는 것이다. 기존 관리 전용 터널 계획을 이 목표에 맞춰 확장한다. 실제 운영 전환 전에는 기존 학생 기록과 운영 서비스를 보존한다.

## 사용 조건과 운영 구성

- 사용자 확인: 이그잼포유 자료는 학원 내 사용이 허용되며 반출하지 않는다. 도입 순서는 **중2 → 중3 → 중1**이다. 공급처의 허락 범위에 대한 법률 판단을 이 문서에서 추가하지 않는다.
- 권장 구성: 학생 기록과 팩은 PC 한 곳을 정본으로 두고, 학생 학습은 원내 접속에서만 허용한다. 외부에는 인증된 원장·강사 관리 기능을 제공한다. 워커와 PC에 학생 기록을 동시에 쓰지 않는다.
- 원본 PDF와 구매 팩은 저장소·정적 배포·클라우드 백업에 넣지 않는다. PC의 접근 제한된 자료 폴더에 보관한다. 학생 기기에 본문을 영구 저장하거나 오프라인으로 반출하는 현행 동작은 제거한다.
- 사용자 확인: WB1은 학원 내부망의 PC다. 학생 허용망은 실제 Ethernet의 CIDR로 제한하며 가상 어댑터·Tailscale 망을 포함하지 않는다. 브라우저에 표시된 자료의 촬영·복사를 코드만으로 완전히 차단할 수 없으므로 학원 관리 기기 반출 금지도 운영 조건이다.
- 공개 주소는 Cloudflare의 기존 계정·도메인·터널을 먼저 확인해 재사용한다. 다른 앱의 기존 경로나 접속 정책은 바꾸지 않는다. 실제 hostname·학생 명부·비밀번호·터널 토큰은 이 공개 저장소에 기록하지 않는다.

## 1. 반별 시험 배정

기존 학생 코드와 `default` 배정 키를 유지하고 `cls:<반>` 키를 추가한다. 반은 Unicode NFC와 앞뒤 공백만 정규화하며 내부 공백은 보존한다. 빈 값·제어문자·80자 초과는 거절한다. 학생 코드 `cls`도 기존 학생 배정으로 계속 해석한다.

유효한 학생 배정 → 유효한 반 배정 → 공통 배정 순으로 조회한다. 학생·반 배정은 시험일이 KST 오늘보다 이전이면 다음으로 폴백한다. 공통 배정은 지난 날짜도 반환해 기존 시험 종료·자율 학습 동작을 유지한다. 팩 접근, 문제 신고, 시험 결과 스냅샷, 밤 9시 알림과 관리 커버리지도 같은 해석을 사용한다.

관리 화면에는 명부에서 반을 고르는 선택지를 추가한다. 결과 입력 명부에 반 scope를 학생 코드로 넣지 않는다. 학생 응답의 기존 `student`·`default`에 `class`를 추가하며 응답 래핑은 유지한다. 두 저장소는 이미 임의 scope 키를 지원하므로 별도 이관을 만들지 않는다.

완료 검사: 우선순위와 각 만료 조합, 반 변경·배정 해제, 빈 반·한글·NFC·키 충돌, 기존 학생·공통 배정, 로컬 실제 HTTP와 워커 번들.

## 2. 실수업 전에 고칠 데이터 보호

1. 여러 기기의 과별 기록은 최신 저장 시각을 보존한다. 공용 브라우저에서 학생 계정이 바뀌면 이전 학생의 학습·동기화를 중단하며 서버도 기록 소유자를 확인한다.
2. 손상된 기존 DB로 빈 DB를 기동하지 않는다. 학생에게 저장 성공을 알리기 전에 디스크 저장을 확인한다.
3. 같은 날 백업도 복구점을 덮지 않는다. 교과서 지정·신고·검수 등 운영 메타데이터와 PC 원본 자료의 복구 범위를 구분해 실제 복구를 시험한다.
4. 관리 업로드·Aside 반입·스튜디오가 기존 `pack-check.js` 한 관문을 사용한다. 단어와 본문이 없는 팩은 배포하지 않는다.
5. 원내 접속을 벗어나거나 연결 확인에 실패하면 구매 팩을 계속 보여 주지 않는다. 선택 기능인 외부 AI 원천 전송은 이 운영에서는 사용하지 않는다.

초기 수업은 한 반으로 검증한다. 과제와 라이브도 `?scope=cls:<반>`으로 분리했다. 과제는 오늘의 반 과제 → 공통, 라이브는 4시간 내 반 세션 → 공통 순으로 조회한다. 관리 요청에 scope를 생략하면 기존 공통 수업을 유지한다. 투사 문제는 저장된 packId와 학생 시험 범위를 대조하며, packId 없는 옛 투사 내용은 강사가 다시 시작해야 한다. 서로 다른 반의 응답·현황·삭제를 분리하는 실제 HTTP 검사도 포함한다.

## 3. 이그잼포유 자료 반입

Aside의 기존 계정 세션과 구매 내역을 사용한다. 새 결제나 이용권 변경은 금액과 대상을 정한 뒤 승인받는다. 사용자가 첫 검증 대상으로 **2022 개정 NE능률(김기택) 중2 6과**를 선택했다. 다른 교과서 전체를 임의로 받지 않는다.

기존 자료 폴더 표준의 과 단위 packId와 시리즈 번호를 유지하되, 원본 저장 위치는 원내 PC 보관 폴더로 정한다. 필수 입력은 `02_본문워크북`과 `03_단어시험`이며 교과서 본문과 대조한다. 이미 구매한 교사용 정답·해설도 함께 사용한다. 원본 파일은 변경하지 않고 추출 JSON과 검수 자료를 별도로 만든다.

원본 내려받기 → 로컬 추출 → 단어·본문·정답 대조 → `pack-check` 오류 0 → 스튜디오 검수 → PC 서버에 팩 등록 → 반 시험 범위 배정 순서다. 구매 원천을 외부 AI API에 보내지 않는다. 원본을 앱 입력으로 자동 변환할 도구가 없거나 자료가 충분하지 않으면 해당 구간을 미완료로 표시하고 임의 내용을 학생에게 배포하지 않는다.

## 4. PC 서버와 외부 접속

서버의 관리자 인증·자료 폴더·고정 실행 경로를 먼저 준비하고 자동 시작·재시작·백업 복구를 확인한다. 이후 외부 관리 주소에 Cloudflare Tunnel과 접근 정책을 연결한다. 학생 주소와 자료 API가 외부에서 열리지 않는지 실제 비인증·외부 접근으로 검사한다.

학원 관리 태블릿에서 로그인 → 반 시험 받기 → 범위 전체 팩 받기 → 단어·본문·문제 학습 → 교사 현황 반영 → 다른 기기 기록 복원 → 계정 교대 → 원내 연결 이탈 차단을 실제로 확인해야 운영 완료다. PC 재시작과 외부 관리 접근까지 확인한 뒤 중3, 중1로 확대한다.

## 완료 기준

- 과제 1 준비도와 과제 2 반별 배정이 같은 시험 범위를 사용하고 관련 회귀 검사가 통과한다.
- 중2의 실제 배정 자료로 원내 기기 학습과 교사 확인이 된다.
- 자료 반출 경로·외부 학생 접속·다른 학생 기록 혼합·저장 실패 성공 응답을 막는다.
- 원본과 기록을 잃지 않고 PC 재시작·백업 복구가 된다.
- 외부에서 원장·강사 관리에 접속되며 기존 운영 서비스가 계속 동작한다.

자료 구매·원본 대조·운영 재시작·실제 학원 기기 확인이 끝나기 전에는 전체 목표를 완료로 표시하지 않는다.

- `WB_INHOUSE_ONLY=1`은 외부 학생 API·자료 원천 API·외부 AI 추출을 차단한다. `WB_INHOUSE_NETWORKS`에 실제 학원 CIDR/IP를 등록하기 전에는 직접 localhost 관리만 허용한다. 외부 관리 현황은 별도 관리자 인증을 유지한다.
- 실제 Cloudflare의 기존 도메인·WB1 연결기를 재사용해 새 관리자 경로를 소유자 Access 정책으로 보호했다. 비인증 외부 요청 302, Access 인증 브라우저의 임시 PC 관리자 로그인 200·학생 API 403 확인. 기존 내신 작전표 서비스는 변경하지 않았다. 실제 주소와 계정값은 이 공개 문서에 적지 않는다.
- Windows용 `reading-server/setup-local.ps1`·`start-local.ps1`로 로컬 DPAPI 관리자 인증과 로그인 시 자동 시작을 준비한다. 실제 설치·등록·재부팅 검증 전에는 운영 중이라고 표시하지 않는다.
  PowerShell 5.1 구문·가상 DPAPI 메모리 왕복·숨김 자식 환경과 종료 코드 검사를 통과했다. 가상 자격증명 파일/ACL·설치 전체 검증 명령은 자동 승인 검토의 `blocked by policy`로 실행 전 거절되었으며 우회하지 않았다. 실제 로컬 인증 설정과 자동 시작 등록은 사용자 PC에서 직접 완료해야 한다.
  실제 설정창 실행에서 발견한 Node 중복 경로와 PowerShell 보안 모듈 탐색 실패를 수정했다. 기본 보안 모듈은 설정 프로세스 안에서만 명시적으로 불러오며, 자료 폴더의 기존 소유자·그룹을 보존한다. 메모리 ACL 회귀 검사는 실제 파일 권한을 바꾸지 않는다. 수정본의 실제 실행에서는 자료 폴더 보호와 관리자 입력 단계 도달을 확인했다. 프로세스가 살아 있는 것과 설치 완료를 구분하도록 비밀정보 없는 `state`·`stage`·`pid`·`errorType`만 기록한다. 계정 입력·작업 등록·상시 서버 가동은 아직 완료하지 않았다.

사용자가 PC 위치·첫 교과서·과를 확인하고 Aside에서 이그잼포유 로그인을 완료했다. 요청에 따라 로그인 정보는 Aside Vault에 저장했다. 기존 이용권으로 6과 필수 PDF 두 개를 내려받았고 기존 보관본과 SHA256이 같은 것을 확인했다. 원본은 변경하지 않았다.

로컬 `naesin/extract/draft.py`는 단어 원천 173행을 후보 74개로 묶고 본문 영·한 열을 별도로 보존한다. 모든 후보는 미검수이며 문장 수 불일치는 자동 짝짓기하지 않는다. 결과는 PC의 비공개 자료 폴더에만 둔다. 이 숫자는 완성 팩의 단어 수를 확정한 것이 아니다. 교사 대조·본문 대응·팩 등록·실제 학생 기기 수업과 정본 전환은 남아 있다.

실자료 초안을 실제 스튜디오 변환 함수와 검수 관문에 연결한 메모리 검사에서도 후보 74개가 미검수로 유지되고 게시가 차단됨을 확인했다. 본문 미대응 열 4개와 검수용 메타는 학생 팩으로 들어가지 않았다. 이 검사는 운영 DB에 자료를 등록하거나 교사 대조를 대신한 결과가 아니다.

스튜디오의 「로컬 PDF 검수 초안」은 원내 PC capability를 확인한 뒤 파일을 읽는다. 표제어·뜻·품사 후보와 페이지/좌표·검토 표시만 작업에 넣고, 본문 미대응 열은 현재 브라우저 메모리에만 띄운다. 반입 시 단어 섹션은 추정하지 않으며 모든 후보를 원본과 대조해야 한다. 본문은 기존 초안 입력에서 검수된 영·한 문장 대응을 별도로 넣는다. 작업 이동·로그아웃 때 본문 원천 열을 회수한다.

공용 팩 관문은 학생이 사용하는 필드와 배열 형태를 검증하고 미검수·원천 부속물의 직접 업로드를 거절한다. 스튜디오도 검수용 PDF 메타를 최종 팩에서 제거한다. 편집 → 승인에서 교정값과 검수 메모를 보존한다. 이 관문 변경은 새 업로드와 재발행에 적용되며 기존 저장 팩을 자동으로 변환하지 않는다.

현재 운영 워커가 연결한 KV namespace의 `naesin:` 키를 읽기 전용으로 조회했으며 내신 전용 키는 0개였다. 이전 문서의 첫 팩 업로드 서술을 현재 배포 증거로 사용하지 않는다. 기존 공통 명부 1건은 PC의 비공개 이관 파일로 보존했으며 아직 로컬 서버에 적용하지 않았다. 운영 KV는 변경하지 않았다.

## PC 실행과 복구

Windows PowerShell에서 `powershell -NoProfile -ExecutionPolicy RemoteSigned -File reading-server/setup-local.ps1`를 실행해 이 PC에서 직접 관리자 아이디·12자 이상 비밀번호를 입력한다. RemoteSigned는 이 프로세스에만 적용하며 시스템·조직 정책을 바꾸지 않는다. 채팅으로 비밀번호를 보내지 않는다.
초기 설정은 localhost:8890, 외부 학생 차단, `%LOCALAPPDATA%\WB\naesin-server`에 자료·DB를 보관한다. 실제 학원망이 확인되면 설정의 Host와 InhouseNetworks를 지정한다.
`start-local.ps1`는 현재 사용자로 시작하며 작업 스케줄러는 사용자 로그인 후 실행한다. PC 로그인 전 가동·절전 방지·정전 복구는 별도 실제 운영 확인 대상이다.
직접 LAN의 HTTP 주소는 브라우저 학습용이다. HTTPS가 필요한 PWA 설치·서비스 워커는 해당 주소에서 검증한 것으로 표시하지 않는다. 학생 자료를 새 공개 터널 주소로 중계하는 구성은 아직 추가하지 않았다.

`backups/`는 API용 메타데이터이고 `private-backups/`는 원본 팩까지 포함한 로컬 장애 복구본이다. 관리 export를 전체 자료 복구본으로 오인하지 않는다.
전체 복구는 서버를 멈추고 선택한 `private-backups/db-<복구ID>.json`을 `db.json`으로 복사한 뒤 서버를 다시 시작한다. 복구 전 현재 DB도 별도로 보존한다.
