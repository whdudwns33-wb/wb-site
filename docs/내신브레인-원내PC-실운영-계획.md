## 2026-10-31 전체 자료 대조·추가 반영

아래의 초기 착수 기록보다 이 현황을 우선한다. 사용자가 범위를 확장하고 교사 검수 생략·월수금 반 적용을 지정한 뒤, 로그인된 이그잼포유에서 중1·중2 2022 개정과 중3 2015 개정의 전체 출판사 목록을 다시 조회했다. 현재 공개 PDF는 중1 1,914개·중2 1,869개·중3 2,437개, 합계 6,220개다. 2022 개정 중3은 아직 다운로드 링크가 없는 메뉴이며 고등·수능 자료는 이번 범위에 포함하지 않았다.

- 기존 6,082개와 비교해 신규 138개와 수정 후보 20개를 내려받았다. 실제 PDF 해시 대조에서 수정본은 19개였고, 나머지 1개는 사이트 표시 크기만 달랐다. 누락 파일은 0개다. 현재 원본 6,220개와 이전 판본 19개의 파일 크기·SHA256·PDF 헤더를 모두 확인했다. 구매 원문은 외부 AI에 보내지 않았다.
- 원본 갱신은 23개 단원에 해당하며, 실제 학생 팩 내용이 바뀐 것은 14개다. 문제 997개·단어 495개를 추가하고 기존 문제 202개의 최신 출처와 본문 24문장을 갱신했다. 추가·갱신 문제 1,192개에 정답 페이지를 제외한 원본 이미지 237장을 연결했다. 팩 수는 단원 수와 같은 273개이고 월수금 반의 기존 자율 학습 배정을 유지한다.
- 학생 제공 합계는 중1 84팩·22,431문항, 중2 86팩·29,379문항, 중3 103팩·46,481문항이다. 전체 98,291문항·본문 4,523문장이다. 서로 다른 교사용·학생용·워크북 PDF가 각각 별도 팩이 되는 것은 아니며 같은 단원 팩에서 사용한다.
- 미확정 2문항은 게시하지 않았다. 중3 NE능률(김성곤) 7과의 기존 정답 미대응 1개와 중2 지학사(송미정) 7과 PRE-STEP의 새 문항 본문 미추출 1개다. 후자는 검수 초안에만 보관한다. 기존 문제 ID·본문 순서·교사 교정·학생 기록을 보존하고 원내 백업과 변경 전 작업·팩 사본을 남겼다.
- 원본 목록은 현재 판본만 반환하며, 기존 검수 위치의 ID·SHA256 요청은 보관된 정확한 이전 PDF도 읽을 수 있다. 학생·외부 관리자는 원본 PDF 보관함에 접근하지 못하며 경로·심볼릭 링크·해시 검증은 유지한다. 전체 검사 331/331과 운영 서버의 새·이전 원본 조회를 통과했다.

## 1. 반별 시험 배정

기존 학생 코드와 `default` 배정 키를 유지하고 `cls:<반>` 키를 추가한다. 반은 Unicode NFC와 앞뒤 공백만 정규화하며 내부 공백은 보존한다. 빈 값·제어문자·80자 초과는 거절한다. 학생 코드 `cls`도 기존 학생 배정으로 계속 해석한다.

유효한 학생 배정 → 유효한 반 배정 → 공통 배정 순으로 조회한다. 학생·반 배정은 시험일이 KST 오늘보다 이전이면 다음으로 폴백한다. 공통 배정은 지난 날짜도 반환해 기존 시험 종료·자율 학습 동작을 유지한다. 팩 접근, 문제 신고, 시험 결과 스냅샷, 밤 9시 알림과 관리 커버리지도 같은 해석을 사용한다.

관리 화면에는 명부에서 반을 고르는 선택지를 추가한다. 결과 입력 명부에 반 scope를 학생 코드로 넣지 않는다. 학생 응답의 기존 `student`·`default`에 `class`를 추가하며 응답 래핑은 유지한다. 두 저장소는 이미 임의 scope 키를 지원하므로 별도 이관을 만들지 않는다.

완료 검사: 우선순위와 각 만료 조합, 반 변경·배정 해제, 빈 반·한글·NFC·키 충돌, 기존 학생·공통 배정, 로컬 실제 HTTP와 워커 번들.

## 4. PC 서버와 외부 접속

### 학생 연동 속도 (2026-10-15)

자료가 늘어난 뒤 로그인·연동 요청·승인마다 약 255MB인 `db.json` 전체를 저장해 지연됐다. 로컬 서버는 토큰과 승인 대기만 비공개 `DATA_DIR/auth.json`에 원자적으로 저장한다. 파일이 없는 최초 실행은 기존 DB 인증을 승계하고, 이후에는 인증 파일이 정본이다. 손상 파일은 옛 인증으로 되돌리지 않고 기동을 중단한다. 일반 DB 저장도 인증 파일을 갱신하므로 학생 삭제·권한 회수와 재기동이 일치한다. 인증 파일 저장 실패는 500으로 알리며 토큰·요청 번호를 성공 응답으로 보내지 않는다. 학생의 승인 확인은 중복 요청 없이 1초 간격으로 한다. 교사의 승인 자체는 계속 필요하다.

- 현재 운영 자료는 여전히 단어 후보 74개·교사 검수 0개·학생용 게시 팩 0개이며 실본문 대응은 하지 않았다. 실제 학생 태블릿 수업·PC 재부팅·영어 로컬 음성 설치와 재생·중3 및 중1 확대도 남아 있다. Windows 음성 설치는 사용자 수동 작업을 기다린다.

교사 검수 순서:

1. 원내 PC 스튜디오에서 기존 검수 작업을 열고 「PC 자료 불러오기」를 누른다. 기존 후보와 정확히 같은 자료는 재업로드 없이 연결하며 기존 단어·교정·검수·메모를 유지한다. 원본 PDF는 후보 옆에 표시하고 「PDF 크게 보기」로 따로 볼 수 있다.
2. 단어 후보를 한 행씩 옆의 원본 PDF와 대조한다. 본문/대화 구분을 포함한 필수 항목까지 맞으면 「승인」, 오류나 누락이 있으면 「편집」에서 표제어·품사·줄별 뜻을 교정하고 실제로 나온 본문/대화를 직접 선택한 뒤 「대조한 교정 저장」을 누른다. 교정 저장도 검수 상태로 기록한다.
3. 본문을 구성할 때는 「고급 입력」을 열고 영어·한글 열과 줄 범위를 각각 골라 「선택 줄로 문장 채우기」를 누른다. 영·한 대응과 수업 묶음을 확인하고 영어 순서의 직독직해 청크, 영어 원문·한글 청크에 대응하는 핵심어 쌍을 직접 넣는다. PDF를 보여 주는 것만으로 학습용 문장 대응이 만들어지는 것은 아니다.
4. 추가한 문장도 원본 위치를 보고 개별 대조·검수한다. 검수 관문에서 미검수와 입력 오류가 없고 본문 두 훈련이 생성되는지 확인한 뒤 팩 게시·반 시험 범위 배정으로 진행한다. 작업 변경 경고가 나오면 최신 자료를 다시 읽어 대조한다.

## PC 실행과 복구

Windows PowerShell에서 `powershell -NoProfile -ExecutionPolicy RemoteSigned -File reading-server/setup-local.ps1`를 실행하면 관리자 아이디·12자 이상 비밀번호를 직접 입력할 수 있다. 승인된 자동 설정은 메모리의 `PSCredential`을 `-AdminCredential`로 전달한다. 둘 다 같은 입력 검증과 DPAPI 저장을 사용하며 기존 인증 파일에 새 계정을 덮어쓰지 않는다. 비밀번호를 명령줄·평문 파일·로그·저장소에 넣지 않는다. RemoteSigned는 해당 프로세스에만 적용하며 시스템·조직 정책을 바꾸지 않는다.
기본 초기 설정은 localhost:8890이다. 이번 PC는 확인된 원내망을 `HostAddress`·`InhouseNetworks`에 지정해 LAN 학습을 허용하고 외부 학생 접속은 차단했다. 자료·DB·DPAPI 인증은 `%LOCALAPPDATA%\WB\naesin-server`에 보관한다.
`start-local.ps1`는 현재 사용자로 시작하며 작업 스케줄러는 사용자 로그인 후 실행한다. PC 로그인 전 가동·절전 방지·정전 복구는 별도 실제 운영 확인 대상이다.
직접 LAN의 HTTP 주소는 브라우저 학습용이다. HTTPS가 필요한 PWA 설치·서비스 워커는 해당 주소에서 검증한 것으로 표시하지 않는다. 학생 자료를 새 공개 터널 주소로 중계하는 구성은 아직 추가하지 않았다.

`backups/`는 API용 메타데이터이고 `private-backups/`는 원본 팩까지 포함한 로컬 장애 복구본이다. 관리 export를 전체 자료 복구본으로 오인하지 않는다.
명부·학생별 교재 지정은 `student-admin.json`, 승인·토큰은 `auth.json`, 영어 학습 기록은 `naesin-states.json`, 학생 삭제는 `student-deletions.json`에도 저장한다. 2026-10-17부터 새로 저장·수정·삭제한 영어 팩은 비공개 `naesin-packs/`의 팩별 파일에도 기록하며, 기동 때 기존 DB 위에 반영한다. 파일명은 대소문자가 다른 ID도 구분하도록 ID의 UTF-8 16진수다. 삭제 표시는 예전 DB의 팩이 다시 나타나지 않게 보존한다. 현재 상태 보관은 서버를 멈추고 이 파일들·폴더와 `db.json`을 함께 복사한다. 음성은 별도 비공개 `naesin-audio/`에 있다.
전체 복구는 서버를 멈추고 현재 DB와 위 네 보조 파일·`naesin-packs/`를 별도 비공개 폴더에 보존한 뒤, 선택한 `private-backups/db-<복구ID>.json`을 `db.json`으로 복사한다. 위 네 보조 파일과 팩 폴더는 기존 위치에서 치운 뒤 다시 시작해야 복구 시점보다 최신인 변경이 옛 복구본을 덮지 않는다. 비공개 전체 복구본에는 해당 시점의 팩별 변경까지 들어 있다. 복구본 이후의 학습 기록은 이 복구로 돌아오지 않는다.
학생 등록·일괄 등록·교재 지정은 작은 관리 파일의 저장 완료 뒤 응답한다. 영어 팩 업로드·삭제는 해당 팩 파일만 원자적으로 바꾼 뒤 목록과 메모리에 반영하며 전체 DB 저장을 기다리지 않는다. 같은 팩의 동시 변경은 접수 순서대로 처리한다. 전체 DB 저장과 일일·수동 복구점 생성은 레코드 단위로 나눠 학생 요청 사이에 처리하며, 저장 도중 관리자 변경·삭제가 오면 최신 내용으로 다시 작성한다. 실패한 저장은 성공으로 응답하지 않으며 기존 DB·팩·복구점을 보존한다. 삭제 학생 코드 재등록은 옛 학습 기록 정리가 끝나는 전체 저장까지 기다린다.
작업 스케줄러의 작업 중지만으로 자식 Node 서버가 종료되지 않을 수 있다. DB를 복사하기 전에 8890의 리스너 종료를 확인한다. 남아 있다면 실행 파일 `node.exe`와 이 저장소의 `reading-server/server.mjs` 절대 실행 경로를 대조해 이 앱의 프로세스만 종료한다.
