주간 진로독서 콘텐츠 루틴을 실행해줘. 절차는 wb-site 저장소 `docs/진로독서-운영-소재스캔-루틴.md` **v1.7**을 따른다. 아래는 요약이니, 문서와 다르면 문서가 정답이다.

**이 프롬프트에는 분포 숫자·주차 파일명 같은 「사실」을 적지 않는다.** 두 번 같은 사고가 났다 — 굳어 버린 문장(「humanities 가 얇으니 보강」)을 그대로 따르면 이미 균형 잡힌 분야를 또 늘린다. 숫자는 실행일에 직접 센다.

⓪ 상태 점검: `curl https://wb-reading.whdudwns33.workers.dev/api/health` — 실패 시 즉시 사용자에게 보고하고 원인 파악.

⓪-2 발행 정합: `curl https://wb-reading.whdudwns33.workers.dev/api/pub` 의 pubmap과 reading/articles.json 의 status 가 다르면 git 쪽을 pubmap 에 맞춘다(원장이 review.html 에서 내린 결정이 정답).

⓪-3 링크 점검: `node reading/linkcheck.mjs` — 깨진 링크(✕)는 대체 링크를 찾아 반영, ⚠는 보고만. **출처 URL은 절대 지어내지 말 것** — 검색으로 찾아 curl 로 200을 확인한 주소만 쓴다.

⓪-4 출처 실사: `node reading/srccheck.mjs` (순차, 4~5분). 상태 코드만 보는 ⓪-3 과 달리 **본문까지 받아 근거가 실제로 보이는지** 본다. `✗`(결함)는 발표 부처 누리집 원문으로 교체하고, `⚠`는 브라우저로 열어 보고 판단(외국어 문서·봇 차단은 대개 정상). 정부 누리집은 간헐적으로 끊기니 ⚠ 표본 몇 개를 순차로 다시 받아 보고 판단한다. 규칙만 빠르게 보려면 `--selftest`.

① 소재 스캔: Perplexity MCP 3쿼리(과학·기술·우주·AI / 의약·바이오·환경·에너지 / 사회·경제·역사·문화·미디어), 최근 2~4주, 공식 출처 우선. Perplexity 가 없으면 WebSearch 로 동일 수행.

② 큐 갱신: **이번 주 ISO 주차 파일** `reading/pipeline/queue-YYYY-Www.json` 을 쓴다. 이미 있으면 이어 쓰고, 없으면 `ls reading/pipeline/` 로 가장 최근 주차 파일을 찾아 그 파일의 미사용 항목(`carryover`·`candidate`)을 `carryover` 로 옮겨 담아 새로 만든다. 스캔 결과를 `items` 에 덧붙이고 `scannedAt`·`method` 를 채운다. 큐 파일 규약(`prep.관측` vs `prep.절차`)은 루틴 문서에 있다.

③ 선정 4~5편 — **분야·진로 기준을 문장으로 기억하지 말고 매주 직접 센다.** 먼저 이걸 돌린다:
```
node -e 'const d=require("./reading/articles.json"),c={},r={};for(const a of d.articles){c[a.category]=(c[a.category]||0)+1;for(const x of a.careers||[])r[x]=(r[x]||0)+1;}console.log("분야",c);console.log("진로",r);console.log("시사",d.articles.filter(a=>a.issue).length+"/"+d.articles.length);'
```
판단 순서: ①가장 얇은 분야(편차 2편 이상이면 그쪽) → ②편차가 1편 이하로 고르면 **직전 주 큐 파일을 열어** 그 주 선정 분야를 읽고 로테이션으로 가른다(지난주 0편이던 분야를 넣고, 2편이던 분야는 2편 이하) → ③진로는 카운트가 가장 낮은 쪽부터 태깅하고 가장 높은 두셋은 이번 주 쓰지 않는다 → ④`issue:true` 비율이 20% 미만이면 이번 주 2편을 시사로, 이미 넘었으면 강제 할당 없이 기준에 맞는 것만.

③-2 `issue: true` 는 **근거에 최근 발표가 있고 사안이 아직 진행 중인 글**에만 붙인다. 제도 설명·기술 원리·역사·연구 성과 보도는 최근에 썼어도 시사가 아니다. 근거가 상시 기준표나 개요 페이지면 소재가 시사적이어도 안 붙인다.

④ 집필 — 지문 1편마다 **4개 학년대 전부**(병렬 에이전트 권장). WebSearch 로 사실 재검증 필수, 산출물은 일단 `status "draft"`.
 · L1(7세~초2): 180~380자·3문단·어휘 3(한자 병기 없이 뜻풀이만)·문항 3(main/detail/vocab)·심화 2·minutes 3. ~예요/~해요체, 한 문장 40자 이하, 환경·의료는 겁주지 말고 '우리가 할 수 있는 일'로 마무리. 영어 대역 없음.
 · L2(초3~6): 450~750자·어휘 4·문항 4·심화 2·minutes 4 + 영어 대역(CEFR A1~A2, 한 문장 14단어 이하 — 중등판을 줄이지 말고 새로 쓸 것).
 · L3(중1~3): 650~1050자·어휘 5·문항 4·심화 2·minutes 5 + 영어 대역(중등).
 · L4(고1~3): 900~1450자·어휘 5·문항 5(critical 가능)·심화 2·minutes 6 + 영어 대역(고등).
 · 심화는 infer/critical/apply — 본문만으로 풀리되 문단 종합·적용·전제 비판으로 어렵게. 오답은 본문 어휘를 재사용한 매력적 선지.
 · 영어 대역은 `en`(문단 수 일치) + `enseg`(join('')===en[i]) + `envocab` 5~6개 `{word,ko,base}`.

④-2 끊어 읽기 — **규격이 강제된다. content.test.cjs 가 오류로 막으니 통과 못 하면 배포가 안 된다.**

  조각 평균: L1 3.3 · L2 3.7 · L3 4.1 · L4 4.5 어절 (지문별·학년대별 **±0.8**)
  한 조각 최대: **8어절** — 예외 없음

  **반드시 `node reading/chunk.mjs --band L4 "문단"` 으로 초안을 받아 시작한다.** 초안은 규격에서 ±0.4 안쪽으로 나오므로 손질할 여유가 ±0.4 더 있어 자연히 통과한다. 손으로만 끊으면 한쪽으로 쏠린다 — 8-31에 한꺼번에 쓴 17편이 실제로 그랬고(L4 평균 5.4), 8어절 넘는 조각이 133개 나와 나중에 손으로 다 쪼개야 했다. 초안은 과하게 끊는 쪽이라 **지우는 방향으로** 손질한다.

  걸렸을 때: `node reading/chunk.mjs --style` (지문마다 조각 길이 — 어디가 쏠렸나) · `node reading/fix-long.mjs` (8어절 초과와 쪼갤 자리).

  **`reading/chunk-baseline.json` 에 새 지문을 넣지 말 것.** 그건 규격 이전에 쓴 35편 면제 목록이고, 새 글을 넣으면 검사가 무의미해진다.

  규칙은 `docs/의미단위-끊어읽기-규격.md`. **조사 뒤에서 끊는 규칙은 쓰지 말 것** — 은·는 뒤 끊김률 22.1%는 기저 22.3%와 같아 무작위나 마찬가지이고, 관형어를 갈라 놓는다(「매우 높은 ∕ 상태로」). 기준은 구·절 경계다.

⑤ 검증: `node reading/content.test.cjs` 통과(오류 0·경고 0 목표).

⑤-2 **분할 빌드 — 빠뜨리면 이번 주 지문이 학생 화면에 안 나온다.** 앱은 articles.json 이 아니라 학년대별 articles-L1~L4.json·hanja.json 을 받아 읽고 version.json 으로 캐시를 깬다. articles.json 을 고쳤으면 반드시 **articles.json 의 `version` 을 오늘 날짜로 올리고**(예 `2026-09-14.1`) → `node reading/build-split.mjs` (산출물도 커밋 — 미러에는 빌드 단계가 없다) → `node reading/split.test.cjs`. 버전을 안 올리면 이미 앱을 깐 학생은 옛 지문을 계속 본다.

⑥ 커밋·푸시 → PR·머지 — main 머지 시 CI 가 워커에 자동 배포. **CI 는 PR 이 아니라 main 푸시에서만 돈다**(워크플로 트리거가 `push: main`). 그러니 머지 전에 워크플로의 테스트 목록을 로컬에서 전부 돌려 보고 올린다. 배포 후 curl 로 version.json 갱신 확인. **주의: main 에 다른 팀(workbench·consult·sync·task·desk) 작업이 자주 들어온다.** 머지 충돌이 나면 `git merge origin/main` 후 내 파일만 --ours 로 풀고, 다른 팀 파일이 main 과 동일한지 `git diff --quiet origin/main -- <경로>` 로 하나씩 확인한 뒤 커밋한다.

⑥-2 미러 동기화(wb-reading, main·gh-pages 두 브랜치): reading/ 의 index.html·articles.json·**articles-L1~L4.json·hanja.json·version.json**·sw.js·manifest·icon·review.html·parent.html·linkcheck.mjs·srccheck.mjs·chunk.mjs·**fix-long.mjs·long-cuts.json·chunk-baseline.json**·content.test.cjs·split.test.cjs·build-split.mjs·_headers + `docs/의미단위-끊어읽기-규격.md` + `shared/voice.js`(빠지면 미러에서 소리가 안 남)를 **저장소 루트**로 복사. 미러는 평평하므로 문서·스크립트 안의 `reading/` 경로를 지우고, 규격서 머리말의 「이 저장소는 미러다」 안내는 되살릴 것. **gh-pages 는 로컬 참조가 낡을 수 있으니 `git ls-remote origin gh-pages` 로 실제 tip 을 받아 그 위에 얹을 것**(`git fetch origin +refs/heads/gh-pages:refs/remotes/origin/gh-pages` 로 받아야 체크아웃된다).

⑦ 검수·발행: 지문별로 ①핵심 수치·발표 주체 웹 교차 확인 ②출처 URL curl 접속 확인(죽은 링크는 실동작 공식 페이지로 교체) ③문항 정답·해설 정합 ④금지 소재·편향 점검. 4항목을 통과한 지문만 발행 — 워커 `/api/admin/pub`(`authorization: Bearer <토큰>`, 토큰은 `/api/admin/login` 에 PIN) 와 git status 를 함께 published 로. **status 를 고쳤으면 ⑤-2 를 다시 돌린다**(분할본에 status 가 따라 들어가고 한자 카드는 발행된 지문만 모은다).
 ⚠ 수치 교차 확인은 **문장 단위로** 한다. 2026-09-07 에 결핵 지문의 「신규 환자 약 1만 7천 명」이 출처에 없는 것을 이 단계에서 잡았는데, 출처에는 비슷한 크기의 「1만 7,464명」이 있었고 그건 **가족접촉자 수**라는 다른 양이었다. 상태 코드도 제목 대조도 통과하는 종류다.
 ⚠ 다음 중 하나라도 걸리면 발행하지 말고 draft 로 두고 원장에게 보고: 핵심 수치 교차 확인 실패, 정치·사회 쟁점의 찬반이 갈리는 사안, 진행 중 수사·재판·미확정 의학 효능, 지역·집단 간 갈등 소지.
