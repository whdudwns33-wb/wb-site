# 맥에서 쓰는 별도 작업 폴더·별도 프로젝트 (2026-11-10)

이 문서 한 장이면 맥에 **이번 작업만 쓰는 폴더 하나**와 **그 폴더만 보는 프로젝트 하나**가 생긴다.
기존 Windows PC 두 대(WB1·WB2)의 폴더는 하나도 건드리지 않는다 —
그 폴더들의 역할은 `docs/코덱스-외부작업-인수인계-2026-10-14.md` §2 표에 그대로 있다.

저장소: `https://github.com/whdudwns33-wb/wb-site` (public — 받을 때 비밀번호가 필요 없다)

## 0. 왜 폴더를 새로 만드는가

한 폴더를 두 사람(또는 두 에이전트)이 같이 쓰면, 한쪽이 브랜치를 바꾼 순간
다른 쪽이 보던 파일이 조용히 달라진다. 그 차이는 며칠 뒤 "어제는 됐는데"로 돌아온다.
그래서 **맥에는 맥 폴더, PC에는 PC 폴더** — 같은 저장소를 각자 따로 받아 쓴다.
서로 주고받는 자리는 폴더가 아니라 GitHub 하나다.

## 1. 만들 폴더 모양

```
~/wb/
├── 메모-wb-codex-mac.md        ← 이 폴더가 무엇인지 적어 두는 쪽지 (git 밖)
└── wb-codex-mac/               ← 저장소 clone = 프로젝트 뿌리
    ├── AGENTS.md               ← 에이전트가 가장 먼저 읽는 규칙
    ├── naesin-ko/              ← 국어브레인
    ├── reading-server/         ← 워커·Node 서버·관리 웹
    └── docs/                   ← 기획서·인수인계서
```

`~/wb/wb-codex-mac` — 이 경로가 **프로젝트 뿌리**다. 프로젝트를 열 때 이 폴더를 고른다.
(`~`는 맥의 내 사용자 폴더다. Finder에서는 `시프트+커맨드+H`.)

## 2. 터미널에 한 번 붙여넣기

먼저 둘이 있어야 한다. 없으면 설치부터 한다.

```bash
git --version     # 없다고 나오면: xcode-select --install
node -v           # v22 이상. 없거나 낮으면: https://nodejs.org 에서 LTS 설치
```

둘 다 뜨면 아래를 그대로 붙여넣는다.

```bash
mkdir -p ~/wb && cd ~/wb
git clone https://github.com/whdudwns33-wb/wb-site.git wb-codex-mac
cd wb-codex-mac
git checkout -b codex/mac-work-20261110
node scripts/check.mjs
```

마지막 줄이 **초록(모두 passed)**으로 끝나면 폴더가 제대로 섰다는 뜻이다.
빨강이 나오면 그 메시지를 그대로 들고 온다 — 고치기 전에 원인을 먼저 본다.

쪽지도 같이 만들어 둔다(반년 뒤의 나를 위해서다).

```bash
cat > ~/wb/메모-wb-codex-mac.md <<'NOTE'
# ~/wb/wb-codex-mac — 맥 전용 작업 폴더 (2026-11-10 만듦)
- 무엇: wb-site 저장소의 맥 clone. 이번 작업(금고·국어브레인)만 여기서 한다.
- 브랜치: codex/mac-work-20261110 (main 에 직접 푸시하지 않는다 — 푸시가 곧 배포다)
- 먼저 읽을 것: AGENTS.md → docs/맥-작업폴더-설정-2026-11-10.md §5 (지금 살아 있는 일 넷)
- 고친 뒤 반드시: node scripts/check.mjs 초록
- WB1·WB2(윈도) 폴더와 섞지 않는다. 주고받는 자리는 GitHub 하나.
NOTE
```

## 3. 「별도 프로젝트」로 여는 자리

폴더가 하나 생겼으면, 그 폴더만 보는 프로젝트를 따로 연다. 쓰는 도구에 따라 세 갈래다.

| 도구 | 어떻게 | 프로젝트가 되는 것 |
|---|---|---|
| Codex CLI | `cd ~/wb/wb-codex-mac && codex` | 폴더 뿌리의 `AGENTS.md` 를 저절로 읽는다 |
| VS Code · Cursor | `파일 → 폴더 열기` 에서 `~/wb/wb-codex-mac` | 창 하나 = 프로젝트 하나 |
| ChatGPT 프로젝트 | 새 프로젝트를 하나 더 만들고 아래 §4 글을 지침에 붙여넣는다 | 기존 프로젝트와 섞이지 않는다 |

세 갈래 모두 **폴더를 새로 만든 뒤**에 연다. 기존 프로젝트의 설정을 고쳐 쓰지 않는다 —
그러면 또 한 폴더를 두 작업이 같이 쓰는 처음 문제로 돌아간다.

## 4. 새 프로젝트 지침에 붙여넣을 글

```text
이 프로젝트는 wb-site 저장소의 맥 작업 폴더 하나만 다룬다.
- 작업 폴더: ~/wb/wb-codex-mac   (다른 폴더·다른 PC 의 clone 은 건드리지 않는다)
- 작업 브랜치: codex/mac-work-20261110. main 에 직접 푸시하지 않는다 — main 푸시가 곧 배포다.
- 고치기 전에 읽는다: 뿌리 AGENTS.md → 그 앱의 README.md → docs/코덱스-인수인계-금고-국어브레인-2026-10-13.md
- 고친 뒤 반드시 `node scripts/check.mjs` 가 초록이어야 한다. 빨강인 채로 PR 을 올리지 않는다.
- 저장소는 public 이다. 라이선스 자료(족보닷컴 팩·교재 원문)·학생 개인정보·시크릿 값을
  어떤 파일에도 넣지 않는다. 시드·테스트 데이터는 자체 창작만 쓴다.
- CLAUDE.md 를 고쳤으면 `cp CLAUDE.md AGENTS.md` (반대도 같다). 한쪽만 고치면 검사가 막는다.
- 사람 확인이 필요한 것: 운영 데이터 삭제, 시크릿 교체, 가정에 나가는 문구·링크, 라이선스가 걸린 자료.
```

## 5. 이 폴더에서 집을 일

**먼저**: 금고 인수인계서(2026-10-13) §3 「바로 집을 수 있는 것」 **네 건은 2026-11-10 기준으로
이미 코드에 있다.** 그 네 건을 다시 집지 않는다. 실제 코드로 확인한 자리는 이렇다.

| §3 | 상태 | 확인한 자리 |
|---|---|---|
| ① `/admin/scrub` 관리 웹 버튼 | 들어감 | `reading-server/public/naesin-ko-admin.html` 의 `#scrubCard`·`scrubCount()` |
| ② 지문 보드 + 렌더러 분리 | 들어감 | `naesin-ko/render.js` (학생·관리 보드가 함께 쓴다) |
| ③ 루트 지도에 빠진 폴더 | 들어감 | `CLAUDE.md` 지도 표 + `scripts/docs-sync.test.mjs` 역방향 검사 통과 |
| ④ 학생 기기 청소 수단 | 들어감 | `naesin-ko/index.html` 의 `#clearDevice` 「이 기기에서 지우기」·`removeItem(LS)` |

그래서 **지금 살아 있는 일**은 아래 넷이다. 순서도 이대로다.

1. **원장 확인 4건** — `docs/로컬-서버-외부공개-터널.md` §1.5 「남은 것」 1번.
   (a) 금고가 at rest 한정인 것이 의도인가 (b) 오버레이 2칸을 금고로 보낼 것인가
   (c) 두 PC 를 동시에 켜 두는 시간대가 있는가 (d) **운영 KV 의 기존 발문 청소 승인**.
   **코드로 풀 수 없다.** 라우트(`GET/POST /api/naesin-ko/admin/scrub`)와 관리 버튼은 이미 있고,
   GET 은 세어만 본다. 누르는 것은 운영 데이터 삭제라 원장 확인 사항이다(절대규칙 7).
2. **관리 웹(`/admin/*`)에도 Access** — §1.5 「남은 것」 2번. 금고 호스트에만 걸면 사본이
   관리 브라우저로 계속 흘러나간다. 원장 문서에 "관리 웹을 금고 PC 밖에서 열면 그 기기에
   자료가 남는다" 한 줄을 같이 적는다.
3. **국어 `state` 화이트리스트를 스칼라만 통과시키기** — §1.5 「남은 것」 4번. 지금은 알려진
   누출(`wrong[].label`)만 겨냥해 뗀다. **필드 목록을 먼저 확정**해야 한다 — 정당한 필드를
   떨어뜨리면 학생 진도가 사라진다.
4. **전사 규칙·운영앱 묶음** — `docs/코덱스-인수인계-남은작업-2026-10-11.md`.
   **집기 전에 그 문서의 「그 뒤 바뀐 것」을 읽고 현재 코드와 대조한다.** 한 달이 지나는 동안
   닫힌 항목이 적지 않다(위 표가 그 예다). `task/index.html` 리팩터는 이 묶음이 아니다 —
   앱 코드이고 분리 여부가 원장 판단이다.

금고를 손대기 전에 §1.5 「착수 전에 정해 둔 네 줄」을 읽는다. 1번이 오기 전에 먼저 돌아가지 않는다.

## 6. 클라우드 세션에서는 이 폴더를 만들 수 없다

이 문서를 쓴 세션은 원장 맥이 아니라 **클라우드 컨테이너**에서 돌았다.
맥의 폴더를 원격으로 쓰려면 맥에서 폴더를 먼저 내줘야 하는데,
그 목록이 비어 있어 요청할 폴더가 없었다(클라우드 세션에서 내 컴퓨터 폴더를 쓰는 기능은
아직 모든 계정에 열려 있지 않다). 그래서 §2 의 명령을 맥 터미널에서 한 번 붙여넣는 쪽이
지금 되는 방법이고, 그 뒤로는 GitHub 하나로 주고받으면 된다.
