# HubSpot 고객 목록 벤치마킹 — 2026-10-16

대상은 원장이 로그인한 Chrome의 HubSpot 연락처 목록이다. 적용 앱은 `wb-site/crm/` 세일즈데스크이며 초기 4300 프로토타입·컨트롤타워는 변경하지 않았다. HubSpot의 연락처·설정·저장된 보기는 수정하지 않고 검색과 패널 열기/닫기만 관찰했다.

## 실제 관찰

| HubSpot에서 확인한 동작 | 세일즈데스크 적용 |
|---|---|
| 모든 연락처·열린 기회·후속 조치 필요·진행 중 보기 탭 | 기존 업무 규칙에 맞춘 전체·진행/보류·내 담당·오늘/지연 팔로업 |
| 검색, 연락처 소유자·날짜·리드 상태 조건, 고급 필터 패널 | 기존 검색·상태·채널·담당에 파이프라인·상담 단계·팔로업 조건 추가 |
| 속성 선택 및 A→Z/Z→A 정렬 패널 | 최신/오래된 등록·이름·다음 팔로업 순 |
| 결과 표와 25개 표시·이전/다음 페이지 | 기존 PC 표·모바일 카드에 25/50/100명 페이지와 결과 범위 표시 |
| 존재하지 않는 합성 검색어 입력 시 0건 안내 | 0건 안내·조건별 해제·전체 초기화 |

검색어를 지우고 연 패널을 닫았다. HubSpot 화면은 관찰 당시 한국어로 표시되었다. 브랜드 자산·소스 코드는 복사하지 않고 세일즈데스크의 글꼴·색·내비게이션·컴포넌트를 재사용했다.

## REA 증거와 한계

REA 6.5.0 `inspect_web_network_capture`로 Chrome에서 수집한 개인정보 제거 HAR를 분석했다. 별도 디버깅 포트로 Chrome을 실행하는 준비는 자동 승인 검토에서 거절되어 실행하지 않았다. 기존 Chrome 연결의 지원되는 네트워크 관찰 기능으로 메타데이터만 추출했다.

- 312개 브라우저 이벤트 중 완료된 관련 요청/응답 메타데이터 19건을 보존했다. 원본 이벤트 창은 `truncated:true`여서 전체 통신 기록이 아니다.
- 연락처 일괄 조회·CRM GraphQL·검색 제한 확인·스키마/속성·업데이트 스트림 경로와 HTTP 200을 확인했다. 헤더·쿠키·본문·쿼리 값·계정/고객 식별자는 보존하지 않았다. 시간 값도 성능 근거로 사용할 수 없다.
- HAR SHA-256: `114acafef9c454df44ffaa0cdf1bf3dd9db50b159fa4b584e581e665dbd6e15b`.
- REA 증거: `ev_831cded3ce74b5f02d76d6eefd5bec236a945934d38af3c5df845abf0c2132ef`, 요약 `ev_5f1d0083858c537aba21a6d4a4a355ec01e20eb2ce71b7c9ae7b538fbd67b8da`.
- 증거 분류는 `historical-reference`/`derived`, 실행 주체 연결은 `unknown`이다. 실시간 내부 로직 분석이나 운영 인증 증거로 간주하지 않는다. 화면 관찰은 Chrome UI, 통신 요약은 REA의 사후 분석이다.
- 요청 본문을 제외했으므로 각 클릭과 요청의 인과관계·서버 정렬/필터 구현·권한별 동작·요금제 차이는 미확인이다. 비공개 API를 우리 앱에서 호출하지 않는다.

HAR와 화면 증거는 저장소 밖에 보관하며 저장소에는 고객 정보가 없는 이 요약만 둔다.

## 자체 코드에서 확인한 데이터 흐름

기존 `/api/docs` 응답 → 메모리의 `state.leads` → 공통 `queryLeads`로 AND 필터·안정 정렬 → 현재 페이지 렌더링. `nextLeadFollowup`은 유효한 미완료 날짜 중 가장 이른 날짜로 목록 표시·오늘/지연 조건·정렬 기준을 통일한다. 이것은 우리 코드에서 확인한 구조이며 HubSpot 내부 구현을 추정한 설명이 아니다.

기존 200건 화면 절단을 없앴다. 읽기 조건 변경은 원본 배열·고객 기록·저장 큐·HubSpot 큐를 바꾸지 않는다. 목록 상태는 메모리에만 있고 상세 왕복 때 유지한다. 로그아웃·인증 만료 시 검색어와 필터를 지운다. 기존 고객별 권한·전화 가림·센터앱 연결 보호는 유지한다.

## 검증

- 순수 목록 규칙 12개: 복합 조건, 잘못된 입력, 날짜, 정렬, 200건 초과, 원본 불변.
- 실제 app.js 이벤트 회귀 13개: 페이지, 조건 해제, 빠른 보기, 직원/원장 표시, 전화 가림·문자열 이스케이프, 상세 왕복, 한글 조합 이벤트, 로그아웃·인증 만료.
- 전체 저장소 검사 314/314 통과. CRM 자산 조립 통과.
- Chrome에서 합성 고객 205명으로 조건 결합·정렬·페이지 이동·빈 결과·초기화를 확인했다. 375px 화면에서 문서 폭 375px로 가로 넘침이 없고 기존 카드 배치를 유지했다. 실제 운영 고객을 검증용으로 수정하지 않았다.
- 디자인 탐지기의 경고 3개는 변경하지 않은 기존 강조 테두리 규칙이었다. 신규 목록 스타일 경고는 없었다.

저장된 사용자 지정 보기, 열 편집, 미리보기 패널, 서버 페이지 조회, 완전 자동 HubSpot 양방향 동기화는 이번 범위에 포함하지 않았다. 많은 고객 전체를 메모리로 읽는 기존 구조는 유지하므로 대규모 데이터의 성능 검증은 별도다. 실제 Windows IME 키 입력은 재현하지 않았고 조합 이벤트와 한글 문자열 검색을 검증했다.
